# 17.2 生成模型推理优化

> 学习目标：掌握生成模型推理优化的四大工具箱——步数压缩（蒸馏/求解器）、CFG 优化、缓存复用、低精度与编译——以及它们的组合策略与质量代价。

## 1. 优化地图

```text
省算力（主战场）
  ├── 步数压缩：求解器（DPM-Solver）→ 蒸馏（LCM/Turbo/schnell）→ 1-8 步
  ├── CFG 优化：引导蒸馏（单前向）/ 引导区间裁剪
  └── 缓存复用：DeepCache / TeaCache / PAB / token caching
省带宽/显存
  ├── 量化：FP8/INT8 权重，SageAttention 用于 DiT attention
  └── 显存管理：VAE 分块解码、CPU offload、文本编码器用后卸载
工程加速
  ├── 编译：torch.compile / TensorRT / 算子融合
  └── 并行：见 17.3（xDiT）
```

核心原则：生成模型优化的每一步都要回答**质量代价是什么**——这与 LLM 量化的"精度换性能"是同一个三角，只是质量维度更主观（人眼/美学评价）。

## 2. 步数压缩（性价比最高的方向）

**求解器路线（免训练）**：DDIM → DPM-Solver(++) 等高阶 ODE 求解器，用更少的函数评估达到相同去噪终点（50 步 → 20 步），零训练成本、几乎无质量损失——是所有优化的第一步。

**蒸馏路线（要训练，收益大）**：
- **一致性蒸馏**（LCM，Latent Consistency Model）：训练模型一步预测任意步的终点，1-4 步出图（SDXL-Turbo 即此路线）。
- **渐进蒸馏**：学生模型把教师的多步合并成更少步（FLUX.1 schnell 是 1-4 步的蒸馏版）。
- **rectified flow / 少步原生**：新模型（SD3/FLUX 系）用流匹配训练，轨迹更直，天然需要的步数更少。

代价：蒸馏模型的引导系数可调范围变窄、风格多样性略有损失；极低步数（1-2 步）下细节质量可感知下降。

## 3. CFG 优化

- **引导蒸馏（guidance distillation）**：把"有条件+无条件两次前向的外插结果"蒸馏进单次前向——直接省掉 CFG 的 2 倍开销，是 FLUX 等模型的标配。
- **引导区间裁剪**：只在关键的去噪阶段施加 CFG（早期大步不用），实测质量损失小。
- 工程注意：关 CFG 后 prompt 遵循度依赖蒸馏质量，负向提示词能力会丧失（这是真实的产品取舍）。

## 4. 缓存复用（视频生成的杀手锏）

去噪相邻步之间，模型的中间表示高度相似——缓存在此处发力：

| 方法 | 思路 | 加速量级 |
|------|------|---------|
| **DeepCache** | 相邻步复用 UNet 高层特征，只算低层 | 约 2 倍（免训练） |
| **TeaCache** | 用 timestep embedding 的相似度估计"这步值不值得重算"，相似则整步复用 | 1.5-2 倍（免训练） |
| **PAB**（Pyramid Attention Broadcast） | 相邻步 attention 输出按金字塔策略广播复用 | 视频场景 1.3-1.5 倍 |
| **token/块缓存** | 只重算变化大的 patch/token（视频相邻帧大片静止） | 依内容而定 |

工程要点：缓存是**免训练**的（即插即用），但阈值是质量-速度旋钮，需要按内容类型标定；与步数蒸馏叠加时收益会互相稀释（步数少了，可复用的相邻步也少了）。

## 5. 低精度与编译优化

- **量化**：DiT 权重 FP8/INT8 可行，但有两处敏感区——第一层/最后一层与时间步嵌入层（对量化敏感，常保高精度）；attention 部分可用 SageAttention 系 kernel（12.5 论文的方法直接迁移）。
- **编译**：torch.compile / TensorRT 对 DiT 收益显著（固定 shape 的迭代结构是编译器的理想目标）；注意动态分辨率会破坏编译缓存（分档编译）。
- **kernel 复用**：FlashAttention/RMSNorm/RoPE 与 LLM 完全同栈——这就是为什么 LLM Infra 工程师转入生成方向的迁移成本低。

## 6. 显存管理

- **文本编码器用后卸载**：T5-XXL（9GB+）编码完 prompt 即可 offload 出 GPU。
- **VAE 分块/分帧解码**：高分辨率/长视频解码是显存峰值点，tile 化解码把它压平。
- **CPU offload 链**：消费卡单卡跑视频模型的标准技巧（transformer 层逐层 offload），用 PCIe 带宽换显存容量（延迟换可行性）。

## 7. 组合策略（生产级推荐顺序）

```text
1. 换高阶求解器（免费，先做）
2. 换蒸馏模型或自研步数蒸馏（收益最大）
3. 引导蒸馏去 CFG 双倍开销
4. 加缓存（视频场景）
5. FP8 量化 + torch.compile/TensorRT
6. 仍不够：并行（17.3）或级联生成（低分辨率草稿+超分）
```

每一步都要带质量回归：固定 prompt 集 + 人评/自动美学分 + 业务指标，量化"省了多少算力、掉了多少质量"。

## 9. 面试视角

- **Q：生成模型推理优化有哪些手段？** A：四层——步数压缩（求解器/蒸馏，收益最大）、CFG 优化（引导蒸馏省 2 倍）、缓存复用（相邻步复用，免训练）、低精度与编译（FP8/TensorRT）；每层都要讲质量代价。
- **Q：TeaCache 的原理？** A：利用相邻去噪步中间表示的高度相似性——用 timestep embedding 差值估计本步与上步的相似度，相似则整步复用跳过计算，免训练拿 1.5-2 倍加速。
- **Q：步数蒸馏的代价？** A：引导系数可调范围收窄、多样性略降、极低步数细节受损；且与缓存类方法叠加收益互相稀释。
