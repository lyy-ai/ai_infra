# 17.1 生成模型推理基础

> 学习目标：理解扩散/流匹配生成模型（DiT 架构）的推理过程与负载特征，以及它和 LLM 推理在系统层面的本质差异——这决定了优化方法的同与不同。

## 1. 生成模型的推理过程

现代图像/视频生成模型（SD3/FLUX/Wan/HunyuanVideo）的统一形态是**三段式**：

```text
文本提示 → [文本编码器 T5/LLM] → 条件向量
                                   ↓
随机噪声 → [DiT 主干] × T 步去噪（每步一次完整前向）
                                   ↓
              隐空间表示 → [VAE 解码器] → 像素输出
```

1. **文本编码器**：把 prompt 编码为条件（T5-XXL 可达 4.7B 参数，是一笔不可忽略的固定开销）。
2. **DiT（Diffusion Transformer）主干**：在隐空间 patch 序列上做 T 步（典型 20-50 步）迭代去噪，每步是完整 transformer 前向。
3. **VAE 解码**：把隐空间表示解码成像素——分辨率越高这块越贵，且显存峰值常出现在这里。

推理的总计算量 ≈ T 步 × 单步 DiT 前向 FLOPs（+ CFG 时再 ×2）。

## 2. CFG：一个隐藏的 2 倍成本

**Classifier-Free Guidance**（无分类器引导）是生成质量的关键技术：每步同时跑"有条件前向"和"无条件前向"两次，按引导系数外插。这意味着：

- 默认配置下每步是 **2 次完整前向**——推理计算量直接翻倍。
- 这也给了一个白送的并行机会：两个前向互相独立（17.3 节的 CFG 并行）。

## 3. 序列长度爆炸：视频为什么贵

DiT 的输入序列是隐空间 patch 序列：

```text
seq_len ≈ (帧数 F) × (H/8/p) × (W/8/p)      （8 为 VAE 下采样，p 为 patch 边长）
```

- 一张 1024×1024 图（p=2）：序列约 1k-4k——轻松。
- 一段 5 秒 720p 视频（81 帧）：序列可达 30k-100k+——attention 是**二次方**，这就是视频生成比图像贵一个数量级的根源。
- 成本对分辨率与帧数都接近平方敏感：720p→1080p 不是 1.5 倍而是 2 倍以上的成本。

配套脚本 `dit_cost_estimator.py` 可定量观察序列长度与 attention FLOPs 随分辨率/帧数的爆炸曲线。

## 4. 与 LLM 推理的系统对比（核心认知）

| 维度 | LLM 推理 | 生成模型推理 |
|------|---------|------------|
| 计算形态 | prefill 计算密、decode 访存密 | **全程计算密集**（每步都是大前向） |
| 迭代结构 | 逐 token 自回归（步数=输出长度） | 固定 T 步去噪（步数与输出大小无关） |
| 单次延迟 | 亚秒-秒级 | 秒级（图）- 分钟级（视频） |
| 显存大头 | 权重 + KV cache（随上下文增长） | 权重 + 激活（attention map/中间层，随序列爆炸） |
| 批处理 | continuous batching 成熟 | 难：分辨率/时长/步数异构，batch 语义不同 |
| 并发模式 | 在线流式 | 多为异步任务（提交-轮询/webhook） |
| 优化主战场 | 带宽（量化/KV/投机） | **算力（步数/CFG/cache/并行）** |

一句话：LLM 推理的主要矛盾是**显存与带宽**，生成模型推理的主要矛盾是**算力与延迟**——优化工具箱因此不同。

## 7. 面试视角

- **Q：扩散模型推理为什么贵？** A：三个乘法因子叠加——T 步迭代 × 每步完整前向 × CFG 双倍计算，再乘上序列长度随分辨率/帧数的平方增长。
- **Q：DiT 推理和 LLM 推理的系统差异？** A：DiT 全程计算密集、固定步数、显存瓶颈在激活而非 KV cache、批处理因输出规格异构而困难；优化主战场从"省带宽"变成"省算力"。
- **Q：视频生成成本的主要驱动？** A：序列长度 ≈ 帧数×高×宽/patch²，attention 随其平方增长；720p→1080p 成本翻倍以上。
