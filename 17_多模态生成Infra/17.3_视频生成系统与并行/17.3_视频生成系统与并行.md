# 17.3 视频生成系统与并行

> 学习目标：掌握视频生成推理的并行技术（xDiT 的 USP/CFG 并行/PipeFusion）、视频生成 serving 的架构特点（异步任务、异构负载、显存峰值）、以及 ComfyUI 生态的工程价值。

## 1. 视频生成的并行问题

视频 DiT 的规模压力：14B 级模型 + 30k-100k+ 的序列长度 → 单卡既算不动也放不下（attention 激活随序列平方增长）。并行是唯一出路，且比 LLM 更迫切——LLM 单卡还能跑小模型，视频生成的高规格输出**单卡根本不存在可行解**。

## 2. xDiT：视频/图像生成并行的开源标准

**xDiT**（github.com/xdit-project/xDiT，浣熊/上交等团队）是 DiT 推理并行的主流开源框架，提供四种可组合的并行方式：

1. **USP（Unified Sequence Parallel）**：把 patch 序列切到多卡——是 ring attention（5.12 章）与 ulysses（按 head 切分 + all-to-all 换维度）在 DiT 上的组合实现。序列维是视频生成最天然的切分轴（帧与空间都可切）。
2. **CFG 并行（CFG Parallel）**：把"有条件前向"和"无条件前向"分到两组卡上同时跑——白送的 2 倍加速（见 17.1，两次前向天然独立），代价是卡数翻倍。
3. **PipeFusion**：把去噪的相邻步组织成流水线——不同卡处理序列的不同段，跨步流水起来（类似 PP 的 microbatch 思想在去噪步维度的应用），通信与计算重叠。
4. **混合并行**：USP × CFG × PipeFusion 正交组合，xDiT 给出不同卡数/模型/输出规格下的配置建议。

配套脚本 `parallel_dit_sim.py` 模拟了 CFG 并行与序列并行在不同卡数下的加速比与通信暴露。

## 3. 与 LLM 并行的对照（迁移认知）

| DiT 并行 | LLM 对应 | 差异点 |
|----------|---------|--------|
| USP（序列切分） | Context Parallel / Ring Attention | DiT 无因果掩码，负载天然均衡（不需要 zigzag） |
| CFG 并行 | 无对应（LLM 没有天然双前向） | DiT 特有，零通信 |
| PipeFusion | Pipeline Parallel | 流水维度是去噪步而非层 |
| 层内 TP | Tensor Parallel | 同样存在但因通信频繁少用 |

好消息：**LLM 长上下文的并行技术几乎全套可迁移**——这是两个领域工程师互相流通的技术基础。

## 4. 视频生成 Serving 的架构特点

与 LLM 在线 serving 不同，视频生成是典型的**异步任务型负载**：

```text
提交任务（prompt+规格）→ 队列 → 调度器 → 生成 worker（GPU 池）
                                    → 产物存储（对象存储）→ 回调/轮询取结果
```

1. **队列与调度**：任务按规格（分辨率/时长/步数）分桶调度——规格决定显存需求与并行拓扑，同规格任务才能有效组 batch。
2. **批处理的困境**：输出规格异构（有人要 480p 3 秒，有人要 1080p 10 秒）使 continuous batching 难以直接套用；主流做法是按规格分池 + 池内小 batch。
3. **显存峰值管理**：DiT 前向、VAE 解码、多模型共存的峰值叠加——worker 需要显式显存准入（接任务前预估显存，类似 5.10 的端侧准入）。
4. **弹性与成本**：生成任务是延迟不敏感（秒级排队可接受）的**理想填谷负载**——可与在线推理混部（9.6 章混部逻辑的直接应用）。
5. **SLA 形态**：不是 TTFT/TPOT 而是"排队时间 + 生成时间"——监控指标与告警体系要重建（9.5 章方法论的迁移）。

## 5. ComfyUI：生成工作流的事实标准

**ComfyUI**（github.com/comfyanonymous/ComfyUI）是节点图式的生成工作流工具，已成为图像/视频生成生态的中心：

- **节点图编程**：模型加载、采样、控制（ControlNet/LoRA）、后处理都是节点，工作流以 JSON 保存可复现——生产管线的"可视化 DAG"。
- **生态**：海量自定义节点（优化、视频、3D）与微调模型社区（Civitai 等）——新论文技术通常先出现在 ComfyUI 节点里。
- **生产化路径**：ComfyUI 提供 API 模式（无头运行），工程上常以"ComfyUI 作为执行引擎 + 自建队列/网关"搭建生成服务；也有 Diffusers 直跑的代码优先路线（更可控，适合深度定制）。
- **选型经验**：原型与内容生产用 ComfyUI；大规模、深度优化的生产 serving 用 Diffusers/xDiT 直跑 + 自研调度。

## 7. 面试视角

- **Q：视频生成为什么必须多卡并行？怎么并？** A：14B 模型 + 100k 级序列，单卡算不动也放不下；xDiT 四件套——USP 序列并行（主力）、CFG 并行（白送 2 倍）、PipeFusion（去噪步流水）、TP（少用）。
- **Q：生成类负载的 serving 和 LLM 有什么本质不同？** A：异步任务型而非流式——队列+按规格分桶调度、batch 受规格异构限制、SLA 是排队+生成时间；但它是延迟不敏感的理想混部填谷负载。
- **Q：ComfyUI 在工程里的位置？** A：生成工作流的事实标准（节点图 + JSON 可复现 + API 模式），原型与中等规模生产可直接用它当执行引擎；超大规模深度优化则 Diffusers/xDiT 直跑。
