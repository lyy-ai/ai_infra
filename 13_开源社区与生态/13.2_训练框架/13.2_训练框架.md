# 13.2 训练框架

> 学习目标：摸清分布式训练开源框架的格局与选型逻辑，理解 Megatron-LM / DeepSpeed / FSDP / torchtitan 各自的生态位。

## 1. 格局总览

训练框架的分层现实（2024 后）：

- **超大规模预训练**：Megatron-LM 系（3D 并行的代名词）是绝对主流，各家大厂内部框架多是它的 fork 或思想继承者。
- **开源社区微调/中规模训练**：DeepSpeed（ZeRO 发源地）与 PyTorch FSDP（原生）两强。
- **新趋势**：PyTorch 原生栈（FSDP2 + torchtitan + torch.compile）正在吃掉越来越多份额——"框架越来越薄，能力进 PyTorch 主干"。

## 2. 主要项目档案

| 项目 | 背景 | 定位与特点 | 仓库 |
|------|------|-----------|------|
| **Megatron-LM** | NVIDIA | TP/PP/SP/EP/CP 全家桶，超大模型训练事实标准；代码量大、工程复杂 | github.com/NVIDIA/Megatron-LM |
| **DeepSpeed** | 微软 | ZeRO 系列发源地，训练+推理（DeepSpeed-Inference）一体 | github.com/microsoft/DeepSpeed |
| **PyTorch FSDP2** | Meta/PyTorch | 原生方案，per-parameter sharding，与 compile 深度整合 | pytorch.org（主干） |
| **torchtitan** | PyTorch 团队 | "极简大模型预训练参考实现"，展示 PyTorch 原生并行原语的组合用法 | github.com/pytorch/torchtitan |
| **veScale / 各家内部框架** | 字节等 | 大厂内部训练栈的开源影子，可窥见工业界设计取舍 | 各公司 GitHub |
| **FlagScale** | 智源研究院（FlagOS 社区） | "框架的框架"：统一配置与 CLI 封装训练/RL/推理全流程，多芯片插件化适配（Megatron-LM-FL / VeRL-FL / vllm-plugin-FL），"一次开发，多芯迁移" | github.com/flagos-ai/FlagScale |

### FlagScale / FlagOS：多芯统一的国产开源栈

FlagScale 是智源 FlagOS 生态的核心组件，2026 年 3 月发布 v1.0.0 稳定版。它对本仓库读者的独特价值在于**多芯片适配的工程化答案**：

1. **插件化架构**：不自研框架，而是把上游主流框架改造成硬件插件——训练用 Megatron-LM-FL + TransformerEngine-FL、RL 用 VeRL-FL、推理用 vllm-plugin-FL。硬件差异被收拢到插件层，上层配置与 CLI 统一。这是"适配 N 种芯片"唯一可持续的工程路线：**不 fork，做插件**。
2. **FlagCX 跨芯通信库**：多芯片集群（甚至异构混训）的集合通信层，是 6.8 章通信优化在非 NVIDIA 互联上的对应实现。
3. **覆盖主流开源模型**：DeepSeek-V3/R1（671B）、Kimi-K2（1T）、Qwen3、Grok2 等都有开箱配置，训练与 serving 双侧覆盖。
4. **学习价值**：读它的插件机制（如何在上游框架上挂接新硬件后端）比读框架本身更有迁移价值——这套方法论直接适用于任何"让 X 框架跑在 Y 芯片上"的工作（对应第 8 章）。

局限：多芯支持的实际成熟度取决于各插件的维护状态；插件模式意味着版本跟随上游的节奏与兼容性风险。

## 3. 选型决策树

```text
目标是超大模型预训练（>70B，千卡以上）？
  └─ 是 → Megatron-LM（或基于它的内部框架）；MoE 场景确认 EP 支持版本
目标是大模型微调 / 中等规模训练？
  ├─ 重度依赖 HuggingFace 生态 → DeepSpeed（ZeRO 配置开箱即用）
  └─ 想要长期维护 + 原生体验 → FSDP2
目标是学习"现代训练框架怎么设计"？
  └─ torchtitan：几千行代码展示完整预训练栈，最适合通读
```

## 4. 读源码建议

- **Megatron-LM**：先读 `megatron/core/parallel_state.py`（并行进程组划分，一切的地基）→ `core/tensor_parallel/`（TP 的 column/row parallel 实现）→ `core/pipeline_parallel/`（1F1B 调度）。Megatron 代码工业味重，读之前先复习 6.4-6.6 章概念。
- **FSDP2**：读 PyTorch 源码 `torch/distributed/fsdp/` 的 fully_shard 实现，理解 per-parameter sharding 与 all-gather 时序。
- **torchtitan**：整个仓库通读（train loop、并行组合、checkpoint、metrics），是面试"手撕训练框架"的最佳范本。

## 5. 通信层

训练框架之下还有一层通信库值得知道：

- **NCCL**（NVIDIA）：GPU 集合通信事实标准，训练框架的底座；读它的文档与 nccl-tests 比读源码更实用。
- **DeepEP / DeepGEMM**（DeepSeek 开源）：MoE all-to-all 通信库与 FP8 GEMM 库，DeepSeek-V3 系统创新的开源部分——读 DeepEP 的 README 与 kernel 接口就能理解 6.9 章的工程细节。
- **NVSHMEM**：GPU 间共享内存编程模型，DeepEP 类库的地基。

## 7. 面试视角

- **Q：Megatron 和 FSDP 的本质区别？** A：Megatron 是"显式切分"（TP/PP 手工定义并行语义，上限高、侵入深）；FSDP 是"数据并行的显存优化"（把参数也分片，侵入小、易用）；现代方案常混用。
- **Q：ZeRO 是哪个项目的贡献？** A：微软 DeepSpeed（ZeRO-1/2/3、Offload、Infinity 系列）。
- **Q：MoE 训练选什么框架？** A：Megatron-LM（EP 支持最成熟）+ DeepEP（通信库）；轻量实验可用 Tutel 等研究型项目。
