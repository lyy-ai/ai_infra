# 13.1 推理与 Serving 引擎

> 学习目标：摸清 LLM 推理开源引擎的格局、各项目的生态位与架构特点，知道"什么场景选什么框架"、"读源码从哪个文件开始"。

## 1. 为什么引擎格局值得单独学

推理引擎是 AI Infra 中**迭代最快、工程密度最高**的开源领域：PagedAttention、Continuous Batching、PD 分离、Speculative Decoding 这些技术都是先在引擎社区落地，再进入教科书。理解引擎格局 = 理解这个领域的技术风向。

选择引擎时的四个判断维度：

1. **生态位**：通用 serving / 极致性能 / 端侧 / 特定硬件。
2. **架构路线**：Python 原生（迭代快）vs C++ 后端（性能上限高）。
3. **社区健康度**：响应速度、发版频率、背后组织（社区型 vs 厂商型）。
4. **与你目标岗位的匹配度**：面试国内大厂推理岗，vLLM/SGLang 源码经验是硬通货。

## 2. 主要项目档案

| 项目 | 背景 | 定位与特点 | 仓库 |
|------|------|-----------|------|
| **vLLM** | UC Berkeley 起家，社区驱动 | 事实标准。PagedAttention 发源地，功能最全（PD 分离、EP、多模态、硬件后端最多），Python 优先 + CUDA kernel | github.com/vllm-project/vllm |
| **SGLang** | LMSYS（伯克利系） | RadixAttention 发源地，结构化输出强，MoE/长上下文优化激进，RL rollout 场景事实标准 | github.com/sgl-project/sglang |
| **TensorRT-LLM** | NVIDIA | 性能上限最高（深度绑定 NVIDIA 硬件），C++ 运行时 + Python API，工程门槛也最高 | github.com/NVIDIA/TensorRT-LLM |
| **LMDeploy** | 上海 AI Lab（InternLM） | 国内团队代表，TurboMind 后端（类 TRT 路线），量化支持好，中文社区友好 | github.com/InternLM/lmdeploy |
| **Mooncake** | 月之暗面 | PD 分离 + KVCache 中心化存储的生产级开源实现（见 12.1 论文解读） | github.com/kvcache-ai/Mooncake |
| **LMCache** | U Chicago 等 | KV cache 复用与分层 offload 引擎，可作为 vLLM 插件 | github.com/LMCache/LMCache |
| **llama.cpp** | 社区（Georgi Gerganov 发起） | 端侧/CPU 推理事实标准，GGUF 格式，纯 C/C++ 无依赖 | github.com/ggml-org/llama.cpp |

## 3. vLLM 源码阅读地图（重点）

vLLM 是推理引擎岗位面试的默认基准，建议按以下路径读（v1 架构）：

```
vllm/
├── v1/engine/            # 引擎主循环：LLMEngine / Processor / OutputProcessor
│   └── core/             #   调度器 Scheduler（continuous batching 决策点）
│       └── kv_cache_manager.py  # KV block 分配（PagedAttention 核心）
├── v1/worker/            # GPU worker：模型执行、CUDA graph 捕获
├── v1/attention/         # attention 后端抽象（flashinfer/flashattn/triton）
├── v1/sample/            # 采样与 logit 处理
├── model_executor/       # 模型定义与权重加载
└── entrypoints/          # OpenAI 兼容 API server
```

**推荐读法**：先跑通 `examples/` 离线推理 → 从 `LLM.generate()` 入口跟一遍完整调用链 → 重点读 Scheduler（5.3 章的 continuous batching 在这里落地）→ 再读 kv_cache_manager（5.2 章的 PagedAttention 落地）。

## 4. SGLang 与 vLLM 的差异（面试高频）

| 维度 | vLLM | SGLang |
|------|------|--------|
| 起家技术 | PagedAttention（显存分页） | RadixAttention（前缀树复用） |
| 编程模型 | OpenAI API + 离线 batch | 前端 DSL（程序化 LLM 调用）+ API |
| 强项 | 通用性、硬件覆盖、生态最大 | 结构化输出、MoE、RL rollout 集成 |
| 典型用户 | 通用 serving 首选 | 长上下文/Agent/后训练场景 |

实际趋势：两者功能高度互卷（vLLM 也有 prefix cache，SGLang 也有分页 KV），选型更多是生态与团队熟悉度问题。

## 5. 厂商引擎的定位

- **TensorRT-LLM**：NVIDIA 硬件上追求极致性能（in-flight batching、FP8 深度优化、与 NIM 微服务集成）；代价是 CUDA 绑定深、二次开发门槛高。面试 NV 系公司或性能敏感岗位必提。
- **LMDeploy**：国内 InternLM 生态，TurboMind C++ 后端设计干净，读 C++ 推理引擎源码它比 TRT-LLM 友好得多。
- **llama.cpp**：端侧圣经。学习 GGUF 量化格式、CPU SIMD kernel、内存映射加载的好地方。

## 7. 面试视角

- **Q：vLLM 和 SGLang 选哪个？** A：通用 serving 选 vLLM（生态最大、硬件支持最全）；长上下文/前缀重复高/RL rollout 场景 SGLang 更优；追求极限性能且全 NVIDIA 栈考虑 TRT-LLM。
- **Q：vLLM 的 V1 架构核心组件？** A：Processor → Scheduler（continuous batching）→ KVCacheManager（block 分配）→ Worker（模型执行 + CUDA Graph）→ OutputProcessor。
- **Q：你怎么跟进推理引擎的新特性？** A：盯 vLLM/SGLang 的 release note 和 RFC issue，重要特性先看对应论文再读实现 PR。
