# 13.3 RL 与后训练框架

> 学习目标：摸清 RLHF/RLVR 开源框架的格局——这是 2025 年后增长最快的开源子领域，也是面试中区分"了解推理"和"了解全栈"的分水岭。

## 1. 格局总览

RL 后训练框架 = 训练系统 + 推理系统 + 编排层的三合一。2025 年的演进线：**同步流水线（verl/OpenRLHF）→ 异步化（AReaL/LlamaRL 思路）→ agentic RL（多轮环境交互）**。选型核心看三点：

1. rollout 引擎的集成质量（vLLM/SGLang 支持度）。
2. 训练后端的并行能力（FSDP / Megatron 后端）。
3. 异步与 agentic 支持（多轮环境、工具调用）。

## 2. 主要项目档案

| 项目 | 背景 | 定位与特点 | 仓库 |
|------|------|-----------|------|
| **verl** | 字节跳动 | HybridFlow 论文实现（见 12.6），混合控制器 + 3D-HybridEngine，FSDP/Megatron 双后端，社区最活跃 | github.com/volcengine/verl |
| **OpenRLHF** | 社区开源 | Ray + vLLM + DeepSpeed 组件拼装，上手最快的完整 RLHF 实现 | github.com/OpenRLHF/OpenRLHF |
| **slime** | 清华（THUDM） | SGLang 原生深度集成的 RL 框架，为 MoE/大规模 RL 设计（GLM 系列使用后训练栈） | github.com/THUDM/slime |
| **NeMo-RL** | NVIDIA | NeMo 生态的 RL 模块，与 Megatron 后端深度绑定 | github.com/NVIDIA/NeMo-RL |
| **TRL** | HuggingFace | 轻量教学/研究向，PPO/DPO/GRPO 全家桶，适合跑通流程而非大规模生产 | github.com/huggingface/trl |
| **ROLL** | 阿里巴巴 | agentic RL 导向（见 12.6 论文解读），环境/奖励 worker 抽象 | github.com/alibaba/ROLL |
| **AReaL** | 蚂蚁/清华 | 全异步 RL（见 12.6 论文解读），staleness 控制 | github.com/inclusionAI/AReaL |

## 3. 上手路径建议（按目标）

```text
目标：跑通第一个 RLHF 实验，理解全流程
  → TRL（GRPO 几十行跑起来）→ OpenRLHF（理解 Ray 编排 + vLLM rollout）
目标：做可写进简历的 RL 系统项目
  → verl：租 4-8 卡，GRPO 训一个 1.5B-7B 模型，记录 rollout 占比、
    权重同步耗时、吞吐曲线（对应仓库 6.11 章的知识验证）
目标：研究前沿系统设计
  → 读 AReaL（异步）与 slime（SGLang 原生）的架构文档
```

## 4. 读源码建议（verl 为例）

```
verl/
├── single_controller/   # 混合控制器的单控制器面（对应 12.6 论文）
├── workers/             # actor/critic/rollout 各角色 worker
│   ├── fsdp_workers.py  # FSDP 后端
│   └── megatron_workers.py
├── trainer/             # PPO/GRPO 主循环（数据流编排）
└── third_party/         # vLLM/SGLang rollout 集成
```

重点跟一条链路：**trainer 发 rollout 请求 → vLLM 生成 → 权重从 FSDP gather 并同步给 vLLM → 训练消费数据**。这条链路就是 6.11 章 `rlhf_pipeline_sim.py` 模拟的真实版本。

## 5. 社区动态观察点

- RL 框架迭代极快（月级大版本），关注各项目的 Roadmap issue 与 release note。
- 异步化是明确趋势：跟踪 verl 的异步 rollout 支持进展与 AReaL 的后续工作。
- Agentic RL（多轮 + 工具环境）是下一个战场：slime/ROLL 在这个方向投入最大。
- 与推理社区合流：SGLang/vLLM 都在原生支持 RL workload（如 SGLang 的 router 与 verl/slime 的协同）。

## 7. 面试视角

- **Q：主流的 RLHF 框架有哪些，怎么选？** A：verl（功能全、社区最活跃、双后端）、OpenRLHF（上手快）、slime（SGLang 原生、MoE 友好）、NeMo-RL（Megatron 生态）；选型看 rollout 引擎与训练后端的组合需求。
- **Q：RL 框架的核心工程难题？** A：权重在训练/推理布局间的 resharding、rollout 长尾、训练推理 colocate 的显存管理、异步化的 staleness 控制。
- **Q：GRPO 流行后框架设计有什么变化？** A：去掉 critic 模型 → 省一份训练负载与显存，组内采样的 rollout 模式（同 prompt 多采样）使 prefix 复用和批调度更重要。
