# 13.4 Kernel 与底层库

> 学习目标：摸清算子/编译/通信层的关键开源项目——这是 AI Infra 中"硬功夫"最集中的层，也是 CUDA 能力简历的直接证据来源。

## 1. 格局总览

底层库按抽象层级分四档：

```text
硬件指令 (PTX/SASS)
  ↑ CUTLASS（C++ 模板，贴近硬件，性能上限）
  ↑ Triton（Python DSL，tile 级，开发效率）
  ↑ 领域库（FlashAttention / FlashInfer / DeepGEMM：特定算子做到极致）
  ↑ 框架集成层（torch.compile Inductor / TVM：自动生成 kernel）
```

职业路径含义：**CUDA 手写 → Triton → CUTLASS** 是算子岗能力的三级台阶（对应仓库 2.4、2.9、2.10 章）。

## 3. 读源码的建议路径

1. **FlashAttention（FA2）**：先读论文算法（2.5 章），再看 CUDA 实现中 `flash_fwd_kernel.h` 的分块与 online softmax——理解"IO 感知"如何变成代码。
2. **Triton**：从官方 tutorials（vector-add → fused-softmax → matmul → attention）逐级复现，再去看 vLLM 里的 fused MoE Triton kernel 这种生产级用法。
3. **CUTLASS**：先读懂 GEMM 的 collective/mainloop 抽象（2.4 章手写 GEMM 的工业版），Hopper 的 warp specialization 示例代码是理解 2.10 章的最佳材料。
4. **DeepEP/DeepGEMM**：README + 核心 kernel 接口即可，重点是理解它们解决的通信/精度问题（对应 6.9、7.11 章）。

## 4. 如何跟进新硬件特性

新 GPU 架构发布后，跟进顺序：

1. NVIDIA 官方架构白皮书与 CUTLASS release（新特性如何被模板化）。
2. FlashAttention 作者与社区的 kernel 适配（FA3 之于 Hopper、FA4/FP4 注意力之于 Blackwell，见 12.5 论文）。
3. Triton 版本 release note（新硬件后端支持进度）。
4. vLLM/SGLang 的 kernel 后端切换动态。

## 6. 面试视角

- **Q：FlashAttention 的核心思想？** A：IO 感知——用分块 + online softmax 避免把 N×N 注意力矩阵写回 HBM，把 attention 从 memory-bound 变成接近 compute-bound。
- **Q：推理和训练的 attention kernel 需求差异？** A：训练要反向传播与高吞吐规整形状；推理 decode 是 q_len=1 的极端 memory-bound（FlashDecoding 类按 KV 维再切分），且要支持 paged KV、变长、投机采样。
- **Q：什么时候自己写 kernel，什么时候用库？** A：标准算子（GEMM/attention/归一化）用库；业务特有融合模式（如 BEV fusion、特定稀疏结构）先 Triton 原型，性能不够再 CUTLASS/CUDA。
