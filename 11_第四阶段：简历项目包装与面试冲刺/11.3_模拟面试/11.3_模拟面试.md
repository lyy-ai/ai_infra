# 11.3 模拟面试

## 本节目标

按照真实面试节奏做专项演练：每个岗位方向一套高频问题清单 + 答题框架，外加系统设计面试的完整流程。目标是把知识变成**口头表达**的肌肉记忆。

---

## 一、专项模拟面试

### 1.1 算子开发岗（45 分钟）

| 环节 | 时长 | 内容 |
|------|------|------|
| 自我介绍 | 5min | 突出 HPC kernel 项目 |
| 项目深挖 | 15min | BEV Pooling 怎么写的？warp reduce 细节？为什么快 65%？ |
| 手写题 | 15min | 写一个简单 kernel（如 vector add 优化到 float4）或画出 GEMM tiling |
| 基础知识 | 10min | bank conflict、occupancy、内存层次、Tensor Core |

**高频追问**：
- 你的 kernel 怎么测的？benchmark 方法？（warmup、多次取均值、nsys 验证）
- shared memory 不够怎么办？（减小 tile、增加 block 数、用寄存器复用）
- FP16 累加精度问题怎么处理？（FP32 accumulator）

### 1.2 AI 编译器岗（45 分钟）

| 环节 | 时长 | 内容 |
|------|------|------|
| 自我介绍 | 5min | 突出 Laser/TVM 编译项目 |
| 项目深挖 | 15min | 编译流水线怎么搭的？图优化 pass 顺序？兼容性问题怎么解决？ |
| 技术问答 | 15min | TVM 架构、Relay vs Relax、动态 shape、schedule 原语 |
| 场景题 | 10min | 一个新算子要接入编译器，流程是什么？（前端导入→合法性检查→lowering→codegen→测试） |

**高频追问**：
- 算子融合的合法条件？（无 side effect、数据依赖允许、shape 兼容）
- 编译产物怎么保证可复现？（版本锁定、seed 固定、checksum）

### 1.3 推理框架 / LLM Serving 岗（45 分钟）

| 环节 | 时长 | 内容 |
|------|------|------|
| 自我介绍 | 5min | 突出推理引擎、vLLM 相关经验 |
| 项目深挖 | 15min | 推理引擎架构？continuous batching 怎么实现的？ |
| 技术问答 | 15min | PagedAttention、KV Cache 管理、TTFT/TBT 权衡、Speculative Decoding |
| 场景题 | 10min | 设计一个支持 1000 并发的 LLM serving 系统 |

**高频追问**：
- TTFT 和 TBT 冲突时怎么取舍？（交互场景保 TTFT：chunked prefill；吞吐场景保 batch）
- 长序列请求挤占资源怎么办？（max_len 限制、分级队列、swap）

### 1.4 分布式训练岗（45 分钟）

| 环节 | 时长 | 内容 |
|------|------|------|
| 自我介绍 | 5min | 突出 ZeRO/3D 并行项目 |
| 项目深挖 | 15min | 拓扑怎么设计的？通信优化做了什么？ |
| 技术问答 | 15min | ZeRO 三阶段、流水线气泡、Ring AllReduce、显存计算 |
| 场景题 | 10min | 512 卡训练 70B，设计并行方案并估算显存与吞吐 |

## 二、系统设计面试模拟

### 2.1 通用流程（45 分钟）

```text
1. 澄清需求（5min）：规模？延迟要求？精度要求？硬件约束？
2. 高层架构（10min）：画出数据流与组件
3. 关键模块深入（20min）：面试官指定 1-2 个模块展开
4. 权衡与扩展（5min）：瓶颈在哪？怎么 scale？
5. 总结（5min）：回顾设计决策
```

### 2.2 经典题目 1：设计 LLM 在线推理服务

**澄清**：7B 模型？A100×8？100 QPS？P99 < 2s？

**架构**：

```text
Client → LB → API Gateway → Scheduler（continuous batching）
                                ↓
                    GPU Workers（TP 组，vLLM-like runtime）
                                ↓
                    KV Cache（PagedAttention + prefix cache）
                                ↓
                    Monitoring（TTFT/TBT/吞吐/显存）
```

**深入点**：
- Scheduler：iteration 级调度、max batch 动态调整。
- KV Cache：分页 + prefix caching + swap 策略。
- 容错：worker 故障 → 请求重试 + 健康检查。

### 2.3 经典题目 2：设计跨平台模型部署系统

**澄清**：3 个平台、20 个模型、每天多次发版？

**架构**：

```text
模型仓库 → 编译流水线（分平台 backend）→ 精度验证（Tensor Diff）
        → 性能回归（Benchmark 门禁）→ 产物仓库 → 灰度发布 → 监控告警
```

**深入点**：
- 编译队列：GPU 资源调度、失败重试。
- 门禁设计：精度阈值、性能退化阈值。
- 版本追踪：model + backend + precision + commit 四元组。

### 2.4 系统设计得分点

| 得分点 | 说明 |
|--------|------|
| 主动澄清 | 不急着给方案，先问约束 |
| 画架构图 | 边讲边画，组件清晰 |
| 数据流 | 说清一个请求从进到出的完整路径 |
| 量化估算 | 显存、QPS、带宽随手算 |
| 权衡意识 | 每个决策说出 trade-off |

## 本节小结

- 专项面试的核心是"项目深挖 + 手写/场景题"，知识题只是入场券。
- 系统设计面试考的是结构化思维：澄清 → 架构 → 深入 → 权衡。
- 每次面试后复盘，把新问题补进题库，面试能力滚雪球。
