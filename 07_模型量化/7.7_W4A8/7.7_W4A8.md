# 7.7 W4A8 / GPTQ-Int4：Qwen3.5-35B-A3B 在 MLC-LLM 中的 TVM 导出与推理

## 1. 什么是 W4A8

**W4A8** 是比 W4A16 更激进的低比特推理方案：

| 组件 | 精度 | 作用 |
|------|------|------|
| 权重（Weights） | 4-bit | 占模型 90% 以上显存，进一步压缩到 1/4 |
| 激活（Activations） | 8-bit | 推理中间值也量化，进一步降低带宽和显存 |
| 计算时 | 4-bit / 8-bit 混合 GEMM | 在 INT8 Tensor Core 上完成矩阵乘，最后再反量化 |

### 核心目标

- **极限压缩**：相比 FP16 显存占用降到约 25%，相比 W4A16 再省约 20%
- **用算力换显存**：INT8 矩阵乘通常有比 FP16 更高的峰值吞吐
- **服务化降本**：在相同硬件上部署更大模型或承载更高并发

### 与 GPTQ-Int4 的关系

你给的链接 `Qwen/Qwen3.5-35B-A3B-GPTQ-Int4` 是 **GPTQ 4-bit 权重量化**，默认保持激活为 FP16，因此严格来说是 **W4A16**（4-bit 权重 + 16-bit 激活）。

MLC-LLM 中通常把它映射为 `q4f16_1`（或 `q4f16_2`）。如果进一步把激活压到 8-bit，就得到 **W4A8**。本节以该模型为例，同时讲清楚：

1. GPTQ-Int4 的量化原理（等价于 W4A16 的权重部分）
2. W4A8 在激活侧再压缩的原理
3. 如何在 MLC-LLM 里把该模型导出为 TVM 格式并做推理

## 2. 数学定义：W4A8 线性层

### 2.1 权重量化（GPTQ group-wise，对称）

设权重矩阵 $W \in \mathbb{R}^{O \times I}$，沿输入维度按 `group_size=128` 分组。对每组 $g$：

$$
\text{max\_abs}_g = \max_{i \in \text{group } g} |W_i|
$$

$$
\text{scale}_g = \frac{\text{max\_abs}_g}{2^{4-1}-1} = \frac{\text{max\_abs}_g}{7}
$$

$$
q_i = \mathrm{clip}\Big(\mathrm{round}\big(\tfrac{W_i}{\text{scale}_g}\big),\; -7,\; 7\Big)
$$

GPTQ 的改进在于：**不是独立逐层量化，而是用 OBS（Optimal Brain Surgeon）风格的层内优化，让权重 $\Delta W$ 尽量落在对激活不敏感的方向上**，从而显著降低 4-bit 的精度损失。

### 2.2 激活量化（per-token / per-tensor）

输入激活 $x \in \mathbb{R}^{B \times I}$：

$$
s_x = \frac{\max(|x|)}{127}, \quad x_q = \mathrm{round}\Big(\frac{x}{s_x}\Big)
$$

$x_q \in [-128, 127]$，用 INT8 存储。

### 2.3 W4A8 GEMM

$$
C = s_x \cdot s_W \cdot (X_{\text{INT8}} \times W_{\text{INT4}/\text{INT8}})
$$

实际实现中 $W_{\text{INT4}}$ 会先解包成 INT8 或直接在 INT4 专用 kernel（如 Marlin、Tensor Core INT4 路径）上与 INT8 激活相乘，累加器用 INT32，最后乘 scale 反量化到 FP16/FP32。

### 3.1 模型结构要点

- **MoE 架构**：总专家数 256，每 token 激活 8 个专家，另有 1 个 shared expert
- **Linear Attention + Full Attention 交替**：`layer_types` 里 3 层 linear attention 接 1 层 full attention，降低长上下文计算量
- **GQA**：`num_attention_heads=16`, `num_key_value_heads=2`，KV Cache 压缩
- **多模态**：含 `vision_config`，但 GPTQ 配置里 `visual` 相关层被动态排除量化

### 3.2 量化配置要点

| 字段 | 含义 | 说明 |
|------|------|------|
| `bits=4` | 每权重 4-bit | 16 个量化等级 |
| `group_size=128` | 每 128 个权重共享一个 scale | 平衡精度与显存开销 |
| `sym=true` | 对称量化 | 零点为 0，不存 zero_point |
| `desc_act=false` | 不按激活顺序重排 | 推理速度更快，精度略低于 desc_act=true |
| `damp_percent=0.01` | GPTQ 阻尼系数 | 稳定 Hessian 逆 |
| `true_sequential=true` | 严格顺序处理层 | 与 GPTQ 原始论文一致 |
| `dynamic` | 动态排除某些模块 | 注意力、embedding、lm_head、visual 等保持原精度 |

## 4. MLC-LLM 中的量化模式

MLC-LLM 使用 Relax/TVM 作为编译后端，常用量化模式如下：

| MLC 模式 | 权重 | 激活 | 说明 |
|----------|------|------|------|
| `q0f16` | FP16 | FP16 | 无量化 |
| `q0f32` | FP32 | FP32 | 无量化 |
| `q4f16_1` | INT4 group-wise | FP16 | W4A16，MLC 默认 group-quant |
| `q4f16_2` | INT4 group-wise | FP16 | 不同 weight layout |
| `q4f32_1` | INT4 | FP32 | 精度更高，但更慢 |
| `q8f16_1` | INT8 | FP16 | W8A16 |

> 注：MLC-LLM 仓库当前没有 `q4f16_gptq` 量化模式。对于 GPTQ/AWQ 预量化模型，通常需要用 `q4f16_1`/`q4f16_2` 重新导出，或先将其权重转换为 MLC 支持的格式；具体支持的预量化格式请查看对应 MLC-LLM 版本的文档与配置。

对于 `Qwen3.5-35B-A3B-GPTQ-Int4`，因其本质为 W4A16 权重量化，首选 MLC-LLM 的 `q4f16_1` 或 `q4f16_2` 进行导出。如果 MLC-LLM 暂不支持 `qwen3_5_moe` 类型，需要先确认社区是否已经提供该模型的 MLC 配置。

## 7. 代码示例

### 7.1 W4A8 / GPTQ 分组量化实现：`w4a8_gptq_quantize.py`

```python
# w4a8_gptq_quantize.py
import torch
import torch.nn as nn
import numpy as np


def pack_int4_to_uint8(int4_weights):
    """
    将 int4 权重打包成 uint8。
    每 2 个 int4 打包成 1 个 uint8。
    """
    shape = int4_weights.shape
    last_dim = shape[-1]
    assert last_dim % 2 == 0, "最后一维必须是 2 的倍数"
    packed_shape = list(shape[:-1]) + [last_dim // 2]
    w = int4_weights.reshape(packed_shape + [2])
    shifts = torch.tensor([0, 4], device=w.device, dtype=torch.uint8)
    packed = (w.to(torch.uint8) << shifts).sum(dim=-1)
    return packed


def unpack_uint8_to_int4(packed_weights):
    """将 uint8 解包成两个 int4"""
    q_low = packed_weights & 0xF
    q_high = (packed_weights >> 4) & 0xF
    q = torch.stack([q_low, q_high], dim=-1)
    return q.reshape(*packed_weights.shape[:-1], -1)


class GPTQInt4Linear:
    """模拟 GPTQ-Int4 线性层（对称、group-wise，不含 GPTQ 优化）"""

    def __init__(self, in_features, out_features, group_size=128):
        self.in_features = in_features
        self.out_features = out_features
        self.group_size = group_size
        self.num_groups = (in_features + group_size - 1) // group_size

        weight = torch.randn(out_features, in_features, dtype=torch.float16)
        self.quantize_weight(weight)

    def quantize_weight(self, weight):
        out_c, in_c = weight.shape
        pad_len = (self.group_size - in_c % self.group_size) % self.group_size
        if pad_len > 0:
            weight = torch.nn.functional.pad(weight, (0, pad_len), value=0)

        w_groups = weight.reshape(out_c, self.num_groups, self.group_size)
        max_abs = w_groups.abs().max(dim=-1, keepdim=True).values
        max_abs = torch.where(max_abs == 0, torch.ones_like(max_abs), max_abs)

        self.scales = (max_abs / 7.0).to(torch.float16)
        q = torch.round(w_groups / self.scales + 7).clamp(0, 14).to(torch.uint8)
        q = q.reshape(out_c, self.num_groups * self.group_size)
        self.qweight = pack_int4_to_uint8(q)

    def forward(self, x):
        q = unpack_uint8_to_int4(self.qweight)
        q = q[:, :self.in_features]
        q = q.reshape(self.out_features, self.num_groups, self.group_size)
        w_deq = self.scales * (q.to(torch.float32) - 7.0)
        w_deq = w_deq.reshape(self.out_features, -1)[:, :self.in_features]
        w_deq = w_deq.to(torch.float16)
        return torch.matmul(x, w_deq.t())


class W4A8Linear(GPTQInt4Linear):
    """在 GPTQ-Int4 权重基础上，把激活也量化到 INT8"""

    def quantize_activation(self, x):
        max_abs = x.abs().max()
        scale = max_abs / 127.0 if max_abs > 0 else 1.0
        x_q = torch.round(x / scale).clamp(-128, 127).to(torch.int8)
        return x_q, scale

    def forward(self, x):
        x_q, x_scale = self.quantize_activation(x)
        # 反量化后做 FP16 计算（真实 W4A8 kernel 会直接在 INT8 上 GEMM）
        x_deq = x_q.to(torch.float16) * x_scale
        return super().forward(x_deq)


def test_w4a8():
    torch.manual_seed(42)
    in_f, out_f = 256, 128
    group_size = 128
    x = torch.randn(2, 8, in_f, dtype=torch.float16)

    fc = nn.Linear(in_f, out_f, dtype=torch.float16)
    w4a8_fc = W4A8Linear(in_f, out_f, group_size=group_size)
    w4a8_fc.quantize_weight(fc.weight.data)

    y_fp16 = fc(x)
    y_w4a8 = w4a8_fc(x)
    mse = torch.mean((y_fp16 - y_w4a8) ** 2).item()

    print(f"FP16 vs W4A8 MSE: {mse:.6f}")
    fp16_bytes = fc.weight.numel() * 2
    qweight_bytes = w4a8_fc.qweight.numel()
    scales_bytes = w4a8_fc.scales.numel() * 2
    total_bytes = qweight_bytes + scales_bytes
    print(f"Compression ratio: {fp16_bytes / total_bytes:.2f}x")


if __name__ == "__main__":
    test_w4a8()
```

### 7.2 W4A8 推理流程演示：`w4a8_inference_flow.py`

```python
# w4a8_inference_flow.py
import torch


def simple_matmul_w4a8(w_q4, scales, x, group_size=128):
    """
    W4A8 推理流程：
    1. 量化激活 x -> INT8
    2. 解包 4-bit 权重 -> INT8/FP16
    3. 按组反量化为 FP16
    4. FP16 矩阵乘法
    """
    # 激活量化（per-token）
    max_abs = x.abs().max(dim=-1, keepdim=True).values
    max_abs = torch.where(max_abs == 0, torch.ones_like(max_abs), max_abs)
    x_scale = max_abs / 127.0
    x_q = torch.round(x / x_scale).clamp(-128, 127).to(torch.int8)
    x_deq = x_q.to(torch.float16) * x_scale

    # 权重反量化
    out_c, num_groups, gs = w_q4.shape
    w_deq = scales * (w_q4.to(torch.float32) - 7.0)
    w_deq = w_deq.reshape(out_c, num_groups * group_size).to(torch.float16)

    # GEMM
    return torch.matmul(x_deq, w_deq.t())


def demo_w4a8_flow():
    torch.manual_seed(42)
    in_f, out_f = 256, 128
    group_size = 128
    batch = 4
    seq_len = 8

    w_fp16 = torch.randn(out_f, in_f, dtype=torch.float16)
    num_groups = in_f // group_size
    w_groups = w_fp16.reshape(out_f, num_groups, group_size)
    max_abs = w_groups.abs().max(dim=-1, keepdim=True).values
    max_abs = torch.where(max_abs == 0, torch.ones_like(max_abs), max_abs)
    scales = (max_abs / 7.0).to(torch.float16)
    w_q4 = torch.round(w_groups / scales + 7).clamp(0, 14).to(torch.uint8)

    x = torch.randn(batch, seq_len, in_f, dtype=torch.float16)
    y_fp16 = torch.matmul(x, w_fp16.t())
    y_w4a8 = simple_matmul_w4a8(w_q4, scales, x, group_size)

    mse = torch.mean((y_fp16 - y_w4a8) ** 2).item()
    print(f"FP16 output shape: {y_fp16.shape}")
    print(f"W4A8 output shape: {y_w4a8.shape}")
    print(f"MSE: {mse:.6f}")


if __name__ == "__main__":
    demo_w4a8_flow()
```

## 10. W4A8 vs W4A16 vs GPTQ-Int4

| 方案 | 权重精度 | 激活精度 | 压缩比 | 生成质量 | 适用场景 |
|------|---------|---------|--------|---------|---------|
| FP16 | 16-bit | 16-bit | 1x | 最高 | 训练、高质量推理 |
| W8A16 | 8-bit | 16-bit | ~2x | 较高 | 权重敏感任务 |
| **GPTQ-Int4** | **4-bit** | **16-bit** | **~3.2x** | **较高** | **大模型推理主流** |
| W4A8 | 4-bit | 8-bit | ~4x | 中 | 极限压缩、高吞吐 |
| W2A16 | 2-bit | 16-bit | ~6x | 低 | 实验性 |

GPTQ-Int4 模型（如 Qwen3.5-35B-A3B-GPTQ-Int4）本质上是 **W4A16 的权重部分**，在 MLC-LLM 中通常以 `q4f16_1` 或 `q4f16_2` 运行。如果硬件和框架支持，还可以在运行时把激活进一步压到 8-bit，实现 W4A8。

## 12. 本节小结

1. **W4A8 = 4-bit 权重 + 8-bit 激活**，是 W4A16 的进一步压缩方案，用精度换显存和吞吐
2. **GPTQ-Int4 是 W4A16 的权重实现**：`group_size=128`、`sym=true`、`desc_act=false` 是常见配置
3. **Qwen3.5-35B-A3B** 是 MoE 模型，256 专家、每 token 8 专家，具有 linear attention 与 full attention 交替结构
4. **MLC-LLM 导出流程**：`gen_config` -> `convert` -> `compile`，最终得到 TVM 可加载的模型目录
5. **推理**：可用 `ChatModule` 同步生成，也可用 `MLCEngine` 流式生成
6. 实际部署时，如果 MLC-LLM 暂不支持 `qwen3_5_moe`，请关注社区更新或先用 vLLM / TensorRT-LLM 等框架验证
