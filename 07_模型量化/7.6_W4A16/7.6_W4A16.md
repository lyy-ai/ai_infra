# 7.6 W4A16：4-bit 权重 + 16-bit 激活量化

## 1. 什么是 W4A16

W4A16 是大模型推理部署中业界主流的「4-bit 权重量化 + 16-bit 激活计算」低比特推理方案，专门针对 DeepSeek、Kimi 这类超大规模 MoE 模型。

### 核心目标

- **用显存换算力**：把权重从 FP16 压到 4-bit，显存占用降到约 1/4
- **用精度换吞吐**：激活保持 FP16，避免生成质量大幅下降
- **让大模型能在更少 / 更便宜的卡上跑起来**，同时提升单机并发和上下文长度

### 核心思想

| 组件 | 精度 | 原因 |
|------|------|------|
| 权重（Weights） | 4-bit | 占模型 90% 以上显存，砍成 1/4 直接大幅降显存 |
| 激活（Activations） | 16-bit | 推理中间值，保持浮点精度，避免生成质量下降 |
| 计算时 | 4-bit → 16-bit 反量化 | 和 16-bit 激活做矩阵乘法，速度和精度平衡 |

### 业界典型表示

MLC-LLM 中的 `q4f16_1`：

```python
"q4f16_1": GroupQuantize(
    name="q4f16_1",
    kind="group-quant",
    group_size=32,
    quantize_dtype="int4",
    storage_dtype="uint32",
    model_dtype="float16",
    linear_weight_layout="NK",
    quantize_embedding=True,
    quantize_final_fc=True,
)
```

含义：
- `q4`：W-INT4 权重量化
- `f16`：激活 / scale / 反量化结果都是 FP16
- `_1`：分组量化，group_size=32
- 对称无零点分组量化

---

## 2. 数学定义

设某个权重矩阵沿输入维度 `K` 有 `K` 个元素，按 `group_size=32` 切成若干组。对每一组独立计算：

### 第 1 步：求该组绝对值最大值

$$\text{max\_abs}_g = \max_{i \in \text{group } g} |W_i|$$

### 第 2 步：计算该组 scale（FP16）

$$\text{scale}_g = \frac{\text{max\_abs}_g}{\text{max\_int}} = \frac{\text{max\_abs}_g}{7}$$

这是对称量化：用最大幅值映射到 4-bit 能表示的最大幅值 7。

### 第 3 步：把每个权重量化成 0~14 的整数

$$q_i = \mathrm{clip}\Big(\mathrm{round}\big(\tfrac{W_i}{\text{scale}_g} + 7\big),\; 0,\; 14\Big)$$

注意 **`+ max_int(=7)` 是一个固定零点偏移**：把对称区间 `[-7, +7]` 平移到无符号区间 `[0, 14]`，方便用 `uint32` 存储。所以虽然 dtype 叫 `int4`，物理存储是无符号的、范围 0~14（15 这个码点没用到）。

### 反量化

$$\hat{W}_i = \text{scale}_g \cdot (q_i - 7)$$

---

## 3. 显存布局与压缩比

以 MLP 的 down_proj 为例（假设 intermediate_size=I，hidden_size=H，NK 布局，权重逻辑形状 [H, I]，沿 I 分组）：

| 形态 | 形状 | 类型 | 显存 |
|------|------|------|------|
| 原始权重 | [H, I] | fp16 | 2*H*I 字节 |
| 量化后权重 | [H, ceil(I/32)] 的 uint32 打包 | uint32 | ≈ H*I/2 字节 |
| scale | [H, ceil(I/32)] | fp16 | ≈ H*I/16 字节 |

- 4-bit 权重本体：约为 fp16 的 1/4
- scale 额外开销：每 32 个权重多一个 fp16，约占原始的 1/16（≈6.25%）
- **合计 ≈ 原 fp16 的 ~31%，即压缩比约 3.2x**

位宽换算速记：`q4f16` 平均每权重 ≈ `4 + 16/32 = 4.5 bit`

## 4. 代码示例

### 4.1 W4A16 分组量化实现：`w4a16_group_quantize.py`

```python
# w4a16_group_quantize.py
import torch
import torch.nn as nn
import numpy as np


def pack_int4_to_uint32(int4_weights):
    """
    将 int4 权重打包成 uint32。
    假设 int4_weights 最后一个维度大小是 8 的倍数。
    每 8 个 4bit 打包成 1 个 uint32。
    """
    shape = int4_weights.shape
    last_dim = shape[-1]
    assert last_dim % 8 == 0, "最后一维必须是 8 的倍数"
    
    # reshape 成 [..., last_dim//8, 8]
    packed_shape = list(shape[:-1]) + [last_dim // 8, 8]
    w = int4_weights.reshape(packed_shape)
    
    # 每个 int4 占据 4 bit，低位到高位
    shifts = torch.arange(0, 32, 4, device=w.device, dtype=torch.uint32)
    packed = (w.to(torch.uint32) << shifts).sum(dim=-1)
    return packed


def unpack_uint32_to_int4(packed_weights, group_size):
    """
    将 uint32 解包成 int4 权重。
    """
    shape = packed_weights.shape
    # 每个 uint32 包含 8 个 int4
    unpacked_shape = list(shape[:-1]) + [shape[-1] * 8]
    shifts = torch.arange(0, 32, 4, device=packed_weights.device, dtype=torch.uint32)
    shifts = shifts.view(1, 1, -1)
    
    w = (packed_weights.unsqueeze(-1) >> shifts) & 0xF
    return w.reshape(unpacked_shape)


class W4A16Linear:
    """手动实现 W4A16 线性层"""

    def __init__(self, in_features, out_features, group_size=32):
        self.in_features = in_features
        self.out_features = out_features
        self.group_size = group_size
        self.num_groups = (in_features + group_size - 1) // group_size

        # 模拟 fp16 权重
        weight = torch.randn(out_features, in_features, dtype=torch.float16)
        self.quantize_weight(weight)

    def quantize_weight(self, weight):
        """对权重进行 group-wise 4bit 对称量化"""
        out_c, in_c = weight.shape
        # padding 到 group_size 整数倍
        pad_len = (self.group_size - in_c % self.group_size) % self.group_size
        if pad_len > 0:
            weight = torch.nn.functional.pad(weight, (0, pad_len), value=0)
        
        # reshape: [out_c, num_groups, group_size]
        w_groups = weight.reshape(out_c, self.num_groups, self.group_size)
        
        # 每组求 max_abs
        max_abs = w_groups.abs().max(dim=-1, keepdim=True).values
        max_abs = torch.where(max_abs == 0, torch.ones_like(max_abs), max_abs)
        
        # scale = max_abs / 7
        self.scales = (max_abs / 7.0).to(torch.float16)
        
        # 量化：qi = clip(round(Wi / scale + 7), 0, 14)
        q = torch.round(w_groups / self.scales + 7).clamp(0, 14).to(torch.uint8)
        
        # reshape 回 [out_c, num_groups * group_size]
        q = q.reshape(out_c, self.num_groups * self.group_size)
        
        # 打包成 uint32
        self.qweight = pack_int4_to_uint32(q)
        self.qweight_shape = q.shape

    def forward(self, x):
        """x: [B, in_features], fp16"""
        # 解包 int4
        q = unpack_uint32_to_int4(self.qweight, self.group_size)
        q = q[:, :self.in_features]  # 去掉 padding
        
        # reshape 到 [out_c, num_groups, group_size]
        q = q.reshape(self.out_features, self.num_groups, self.group_size)
        
        # 反量化：W_hat = scale * (q - 7)
        w_deq = self.scales * (q.to(torch.float32) - 7.0)
        w_deq = w_deq.reshape(self.out_features, self.num_groups * self.group_size)
        w_deq = w_deq[:, :self.in_features].to(torch.float16)
        
        # 矩阵乘法
        out = torch.matmul(x, w_deq.t())
        return out


def test_w4a16():
    torch.manual_seed(42)
    in_f, out_f = 128, 64
    group_size = 32
    
    # FP16 参考
    fc = nn.Linear(in_f, out_f, dtype=torch.float16)
    
    # W4A16 量化版
    w4a16_fc = W4A16Linear(in_f, out_f, group_size=group_size)
    with torch.no_grad():
        w4a16_fc.quantize_weight(fc.weight.data)
    
    x = torch.randn(4, in_f, dtype=torch.float16)
    y_fp16 = fc(x)
    y_w4a16 = w4a16_fc.forward(x)
    
    mse = torch.mean((y_fp16 - y_w4a16) ** 2).item()
    print(f"FP16 vs W4A16 Linear MSE: {mse:.6f}")
    
    # 计算压缩比
    fp16_bytes = fc.weight.numel() * 2
    qweight_bytes = w4a16_fc.qweight.numel() * 4
    scales_bytes = w4a16_fc.scales.numel() * 2
    total_bytes = qweight_bytes + scales_bytes
    ratio = fp16_bytes / total_bytes
    print(f"FP16 size: {fp16_bytes} bytes")
    print(f"W4A16 size: {total_bytes} bytes")
    print(f"Compression ratio: {ratio:.2f}x")


if __name__ == "__main__":
    test_w4a16()
```

### 4.2 W4A16 推理流程演示：`w4a16_inference_flow.py`

```python
# w4a16_inference_flow.py
import torch
import torch.nn as nn


def simple_matmul_fp16(w_fp16, x_fp16):
    """标准 FP16 矩阵乘法"""
    return torch.matmul(x_fp16, w_fp16.t())


def simple_matmul_w4a16(w_q4, scales, x_fp16, group_size=32):
    """
    W4A16 推理流程：
    1. 从存储中解包 4-bit 权重
    2. 按组反量化为 FP16
    3. 与 FP16 激活做矩阵乘法
    """
    out_c, num_groups, gs = w_q4.shape
    # 反量化
    w_deq = scales * (w_q4.to(torch.float32) - 7.0)
    w_deq = w_deq.reshape(out_c, num_groups * group_size)
    w_deq = w_deq.to(torch.float16)
    return torch.matmul(x_fp16, w_deq.t())


def demo_inference_flow():
    torch.manual_seed(42)
    in_f, out_f = 256, 128
    group_size = 32
    batch = 8
    
    # 原始 fp16 权重
    w_fp16 = torch.randn(out_f, in_f, dtype=torch.float16)
    
    # 量化
    num_groups = in_f // group_size
    w_groups = w_fp16.reshape(out_f, num_groups, group_size)
    max_abs = w_groups.abs().max(dim=-1, keepdim=True).values
    max_abs = torch.where(max_abs == 0, torch.ones_like(max_abs), max_abs)
    scales = (max_abs / 7.0).to(torch.float16)
    w_q4 = torch.round(w_groups / scales + 7).clamp(0, 14).to(torch.uint8)
    
    # fp16 激活
    x_fp16 = torch.randn(batch, in_f, dtype=torch.float16)
    
    # 标准 FP16 推理
    y_fp16 = simple_matmul_fp16(w_fp16, x_fp16)
    
    # W4A16 推理
    y_w4a16 = simple_matmul_w4a16(w_q4, scales, x_fp16, group_size)
    
    mse = torch.mean((y_fp16 - y_w4a16) ** 2).item()
    print(f"FP16 output shape: {y_fp16.shape}")
    print(f"W4A16 output shape: {y_w4a16.shape}")
    print(f"MSE between FP16 and W4A16: {mse:.6f}")


if __name__ == "__main__":
    demo_inference_flow()
```

### 4.3 AWQ / GPTQ 风格 W4A16 加载伪代码：`w4a16_model_demo.py`

```python
# w4a16_model_demo.py
import torch
import torch.nn as nn


class W4A16Layer(nn.Module):
    """简化的 W4A16 线性层，演示模型级集成"""

    def __init__(self, in_features, out_features, group_size=128):
        super().__init__()
        self.in_features = in_features
        self.out_features = out_features
        self.group_size = group_size
        self.num_groups = (in_features + group_size - 1) // group_size
        
        # 量化权重：用 uint8 存 int4，每元素 4bit 语义
        self.register_buffer(
            "qweight",
            torch.zeros(out_features, self.num_groups * group_size // 2, dtype=torch.uint8)
        )
        self.register_buffer(
            "scales",
            torch.ones(out_features, self.num_groups, dtype=torch.float16)
        )

    def forward(self, x):
        # 从 uint8 解出两个 int4
        q_low = self.qweight & 0xF
        q_high = (self.qweight >> 4) & 0xF
        q = torch.stack([q_low, q_high], dim=-1).reshape(
            self.out_features, self.num_groups, self.group_size
        )
        q = q[:, :, :self.in_features]
        
        # 反量化
        w_deq = self.scales.unsqueeze(-1) * (q.to(torch.float16) - 7.0)
        w_deq = w_deq.reshape(self.out_features, -1)[:, :self.in_features]
        
        return torch.matmul(x, w_deq.t())


class TinyW4A16Model(nn.Module):
    """一个微型 W4A16 MLP 模型"""

    def __init__(self, hidden_size=512, intermediate_size=1024, group_size=128):
        super().__init__()
        self.gate_proj = W4A16Layer(hidden_size, intermediate_size, group_size)
        self.up_proj = W4A16Layer(hidden_size, intermediate_size, group_size)
        self.down_proj = W4A16Layer(intermediate_size, hidden_size, group_size)
        self.act = nn.SiLU()

    def forward(self, x):
        gate = self.act(self.gate_proj(x))
        up = self.up_proj(x)
        return self.down_proj(gate * up)


def demo_model():
    torch.manual_seed(0)
    model = TinyW4A16Model(hidden_size=256, intermediate_size=512, group_size=32).half()
    x = torch.randn(2, 10, 256, dtype=torch.float16)
    y = model(x)
    print(f"Input shape:  {x.shape}")
    print(f"Output shape: {y.shape}")
    
    # 统计参数量
    total_params = sum(p.numel() for p in model.parameters())
    print(f"Total parameters (logical): {total_params}")


if __name__ == "__main__":
    demo_model()
```

## 5. MLC-LLM 中 W4A16 的具体实现与 TVM 导出流程

> **本节是汇报重点**：MLC-LLM 以 Apache TVM / Relax 作为编译后端，把 HuggingFace / Safetensors 权重转换为 TVM 可加载的参数，再编译出针对目标硬件（CUDA、Metal、Vulkan 等）的 model library。W4A16 在 MLC-LLM 中对应 `q4f16_1` 量化模式。

### 5.1 MLC-LLM 的 W4A16 量化配置：`q4f16_1`

```python
from mlc_llm.quantization import GroupQuantize

q4f16_1 = GroupQuantize(
    name="q4f16_1",
    kind="group-quant",
    group_size=32,
    quantize_dtype="int4",
    storage_dtype="uint32",
    model_dtype="float16",
    linear_weight_layout="NK",
    quantize_embedding=True,
    quantize_final_fc=True,
)
```

字段含义：

| 字段 | 含义 | 对 W4A16 的影响 |
|------|------|----------------|
| `name` | 量化模式标识 | `q4f16_1` 表示 W4A16、group_size=32 |
| `kind` | 量化类型 | `group-quant` 分组对称量化 |
| `group_size` | 每组元素数 | 32 个权重共享一个 FP16 scale |
| `quantize_dtype` | 逻辑量化位宽 | `int4`：每个权重 4-bit |
| `storage_dtype` | 物理存储类型 | `uint32`：每 8 个 int4 打包成一个 uint32 |
| `model_dtype` | 激活 / KV Cache 精度 | `float16`：激活与 KV Cache 保持 FP16 |
| `linear_weight_layout` | 权重布局 | `NK`：按输出维度 O × 分组维度存储 |
| `quantize_embedding` | 是否量化 embedding | True：embedding 也参与量化 |
| `quantize_final_fc` | 是否量化 lm_head | True：lm_head 也参与量化 |

### 5.2 导出流程：gen_config → convert → compile

MLC-LLM 导出 TVM 模型分为三步：

```bash
export HF_MODEL=/path/to/your-hf-model
export MLC_OUT=/path/to/mlc-output

# 1. 生成 mlc_chat_config.json（conversation template、quantization、tokenizer 元信息）
mlc_llm gen_config $HF_MODEL \
    --quantization q4f16_1 \
    --conv-template llama-2 \
    --output $MLC_OUT

# 2. 权重转换：把 HF / Safetensors 参数转换为 MLC / TVM 参数格式
mlc_llm convert $HF_MODEL \
    --quantization q4f16_1 \
    --output $MLC_OUT

# 3. 编译 TVM model library：生成 lib.so / lib.dylib / lib.dll
mlc_llm compile $MLC_OUT \
    --device cuda \
    --output $MLC_OUT/lib.so
```

三步分别完成：

1. **`gen_config`**：解析 HF `config.json`，生成 `mlc_chat_config.json`，包含模型结构、量化参数、对话模板、tokenizer 路径等元信息
2. **`convert`**：读取 HF 权重（PyTorch `.bin` 或 Safetensors），按 `q4f16_1` 规则做 group-wise 4-bit 量化，并打包成 TVM NDArray 格式存到 `params/`
3. **`compile`**：以 Relax 描述模型图，经过量化、算子融合、调度、TVM codegen，最终编译为设备相关的动态库 `lib.so`

### 5.5 Relax / TVM 内部实现简介

MLC-LLM 使用 **Apache TVM** 的 **Relax** 前端描述计算图，W4A16 的关键路径如下：

1. **Frontend**：读取 HF 模型结构，为每个 layer 构建 Relax 函数（attention、MLP、RMSNorm 等）
2. **Quantization Pass**：在 IR 层把 `nn.Linear` 的 FP16 权重替换为 `GroupQuantize` 参数，插入 `unpack`（uint32 → int4）和 `dequantize`（int4 → fp16）算子
3. **Lower & Optimize**：把 Relax 函数 lower 到 TensorIR，做算子融合、常量折叠、内存规划、调度（schedule）
4. **Code Generation**：根据 `--device` 生成 CUDA / Metal / Vulkan C++ kernel，编译成 `lib.so`
5. **Runtime**：TVM runtime 加载 `lib.so` 和 `params/` 中的 NDArray，执行推理

### 5.7 常见注意事项

1. **量化模式与硬件匹配**：`q4f16_1` 需要设备支持 FP16 和 INT4/INT8 矩阵乘；NVIDIA sm75+ 支持较好，低端卡需用 `q0f16` 或 `q8f16_1`
2. **group_size 一致**：MLC-LLM 默认 32；若加载 AutoGPTQ/AutoAWQ 预量化模型，需保证和原模型 `group_size` 一致（常见 32、64、128），并用 `q4f16_1`/`q4f16_2` 重新导出。注意 MLC-LLM 仓库当前没有 `q4f16_gptq` 这一量化模式。
3. **conversation template**：`gen_config` 时必须指定正确的模板（如 `llama-2`、`qwen2`、`mistral`），否则对话格式错误导致输出异常
4. **长上下文**：`compile` 时会对 batch size、sequence length 做调优，长上下文需要设置足够大的 `max_sequence_length`
5. **预量化模型**：对于 AutoGPTQ/AutoAWQ 等预量化模型，MLC-LLM 通常需要用 `q4f16_1`/`q4f16_2` 重新导出，或先将其权重转换为 MLC 支持的格式，无需重新训练，具体取决于 MLC-LLM 版本对该预量化格式的原生支持程度

│   │     y = x @ W_hat.T                     │                       │

│                     │                                               │
│                     ▼                                               │

## 8. W4A16 vs 其他量化方案

| 方案 | 权重精度 | 激活精度 | 压缩比 | 适用场景 |
|------|---------|---------|--------|---------|
| FP16 | 16-bit | 16-bit | 1x | 训练、高质量推理 |
| INT8 | 8-bit | 8-bit | ~2x | 通用推理加速 |
| W8A16 | 8-bit | 16-bit | ~2x | 权重敏感、激活不敏感 |
| **W4A16** | **4-bit** | **16-bit** | **~3.2x** | **大模型推理主流** |
| W4A8 | 4-bit | 8-bit | ~4x | 极限压缩，质量下降明显 |
| W2A16 | 2-bit | 16-bit | ~6x | 实验性，质量损失大 |

## 11. 本节小结

1. W4A16 = 4-bit 权重 + 16-bit 激活，是大模型推理的主流低比特方案
2. 核心优势：显存压缩比约 3.2x，同时保持较好的生成质量
3. 分组量化（group_size=32/128）是 W4A16 的核心实现方式
4. 推理流程：加载 4-bit 权重 → 解包 → 反量化为 FP16 → 与 FP16 激活做 GEMM
5. **MLC-LLM 实现：W4A16 对应 `q4f16_1`，通过 `gen_config` → `convert` → `compile` 三步导出 TVM 模型**
6. 主流工具：AWQ、GPTQ、MLC-LLM、TensorRT-LLM、vLLM
