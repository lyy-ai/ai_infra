# 7.11 FP8 量化：E4M3/E5M2 格式、细粒度 Scaling 与 FP8 训练/推理

## 1. 背景与动机

前面几节讨论的 INT8 / INT4 量化本质上是**推理侧的降本技术**：用更低位宽的整数表示权重和激活，换取显存减半、带宽减半、Tensor Core 峰值翻倍。但 INT8 有一笔绕不开的成本——**校准**：需要校准数据、要选校准算法（minmax / percentile / KL / MSE），对 outlier 敏感的模型还要做 SmoothQuant、AWQ 之类的补救，工程链路长、精度风险高。

FP8 的出现改变了这个局面。NVIDIA Hopper（H100/H800）架构在 Tensor Core 中原生支持 FP8，峰值算力约为 FP16/BF16 的 2 倍。更重要的是，FP8 是一种**浮点格式**，天然适配神经网络数据的钟形分布，通常**不需要校准**，直接 cast 精度损失就很小。DeepSeek-V3 进一步证明了 FP8 不仅能做推理，还能支撑**全量大模型训练**。

沿用本仓库的核心思维看 FP8：它依然在**计算 / 通信 / 显存**不可能三角上做取舍——

- **计算**：FP8 Tensor Core 峰值 2 倍于 BF16，但累加精度不足，要拿工程手段（分块提升累加）换回来；
- **通信**：训练时把通信数据也压到 FP8，通信量减半，代价是额外的量化/反量化开销和精度风险；
- **显存**：权重、激活、梯度减半，但 master weight、优化器状态仍要高精度保留，实际省不了"整整一半"。

## 2. FP8 数据格式：E4M3 与 E5M2

FP8 并不是一种格式，而是 OCP（Open Compute Project）标准定义的**两种** 8-bit 浮点格式：

| 格式 | 符号位 | 指数位 | 尾数位 | 指数偏置 | 最大正规格化数 | 最小正数（次正规） | 用途 |
|------|--------|--------|--------|----------|----------------|--------------------|------|
| E4M3 | 1 | 4 | 3 | 7 | 约 ±448 | 2^-9 | 权重、激活（前向） |
| E5M2 | 1 | 5 | 2 | 15 | 约 ±57344 | 2^-16 | 梯度（反向） |

要点：

- **E4M3 精度高、范围窄**：3 位尾数带来约 2 位十进制精度，但最大值只有 ±448。前向传播中权重和激活的动态范围通常不大，用 E4M3。
- **E5M2 范围大、精度低**：指数范围和 FP16 对齐（最大值约 ±57344），但 2 位尾数精度很粗。反向传播中梯度分布更"重尾"、动态范围更大，用 E5M2。
- **特殊编码**：E4M3 **没有 INF**，指数全 1 时尾数全 1 的编码（S.1111.111）被用作 NaN，这是它和 IEEE 754 风格格式的最大区别；E5M2 则保留了类似 IEEE 的 INF / NaN 编码。
- 两种格式的**次正规数（subnormal）**都是正规化的延伸，保证 0 附近的表示是连续渐变的，这对量化小数值很重要。

直观理解：**FP8 用"指数+尾数"换来了非均匀的数值分辨率**——在 0 附近非常稠密，在大数值处非常稀疏。这恰好匹配神经网络张量的统计特性。

## 3. 为什么 FP8 比 INT8 好做

### 3.1 浮点格式天然适配钟形分布

神经网络训练好的权重和激活，绝大多数服从以 0 为中心的钟形（近似正态/Laplace）分布：大量值集中在小数值区域，少数值很大。

- **INT8 是均匀量化**：128 个正值等间距铺满 [0, max]。对钟形分布来说，小数值区域（信息量最大）分到的码本太少，大数值区域（几乎没数据）浪费大量码本。
- **FP8 是非均匀的**：E4M3 在 2^-9 附近就有可表示值，码本密度随数值增大指数下降——**码本分布和数据分布形状一致**，所以量化误差天然更小。

本节配套的 `fp8_format_demo.py` 会数值验证这一点：同样的正态分布数据，E4M3 的 SNR 显著高于 per-tensor INT8。

### 3.2 通常不需要校准流程

INT8 PTQ 的标准流程是：准备校准集 → 统计激活范围 → 选 scale → 评估精度 → 不行就换算法/混合精度。而 FP8 因为范围由指数自适应（E4M3 覆盖 2^-9 到 448，跨约 18 个数量级），**PTQ 直接 cast 损失就很小**，很多场景下一个全局 scale 甚至不用 scale 就能用。这省掉的是一整套校准工程链路。

### 3.3 DeepSeek-V3：FP8 可以支撑全量训练

此前业界普遍认为 8-bit 只能做推理、训练必须 BF16。DeepSeek-V3（2024 年底）用 FP8 混合精度框架完成了 671B MoE 模型的完整预训练，训练损失与 BF16 baseline 的差距在千分位量级，证明了 FP8 训练的可行性。这是 FP8 从"推理优化"升级为"训练基础设施"的标志性事件。

## 4. 量化粒度：per-tensor 的局限与细粒度 Scaling

### 4.1 per-tensor scaling 的局限

FP8 训练通常仍然需要一个 **scaling factor**：把张量先乘一个 scale 再 cast 到 FP8，让数据尽量撑满 E4M3 的动态范围（amax 接近 448）。最朴素的做法是**整个张量共享一个 scale（per-tensor）**。

问题出在 **outlier**：LLM 的激活中普遍存在少量极大值通道（magnitude 比其他元素大几十甚至上百倍，参见 7.1/7.2 节）。一旦用整个张量的 amax 定 scale：

$$\text{scale} = \frac{\max(|x|)}{448}$$

outlier 会把 scale 撑得很大，于是其余 99.9% 的正常值被压到 FP8 码本的最底端，尾数精度全丢——**一个 outlier 毁掉整个张量**。

### 4.2 DeepSeek-V3 的细粒度量化

DeepSeek-V3 的解法是把 scaling 的粒度做细：

- **激活：1×128 的 per-tile scaling**。按 token 维度，每 128 个通道为一组（1 行 × 128 列的 tile）单独计算 scale。outlier 通道的影响被限制在它所在的 128 通道块内。
- **权重：128×128 的 per-block scaling**。每 128×128 的权重块单独一个 scale，与 Tensor Core MMA 的分块天然对齐。

代价是**元数据开销和 kernel 复杂度**：每个块要存一个 FP32 scale，GEMM kernel 里要做"块内 FP8 乘、按块 scale 反量化后累加"的融合逻辑。这是典型的**用计算复杂度换精度**的取舍。

配套的 `fp8_scaling_granularity.py` 模拟了含 outlier 的激活，对比 per-tensor / per-channel / per-1x128-block 三种粒度下的 SNR。

## 5. FP8 训练的工程细节（DeepSeek-V3 混合精度框架）

把 FP8 用于全量训练，光有好的数据格式远远不够，DeepSeek-V3 的技术报告里有一串关键工程决策：

### 5.1 GEMM 输入在线量化

前向和反向的所有 GEMM，输入（权重、激活、梯度）都在 kernel 内**在线量化**为 FP8：读入 BF16 数据 → 块内求 amax → 乘 scale → cast FP8 → Tensor Core 计算。不做离线预量化，保证每一轮迭代的 scale 都跟随当前数据分布。

### 5.2 Tensor Core 累加精度不足：分块提升累加

H100 上 FP8 MMA 的累加器精度有限——累加结果大约只保留 **14 位左右**的有效精度（远低于 FP32 的 24 位尾数）。K 维一大，累加误差会吞掉梯度信息。

解法：**每累加若干次（约每 128 个元素的间隔）就把 Tensor Core 的部分和提升到 CUDA Core 的 FP32 寄存器里继续累加**。即"FP8 做乘法、短链条 FP8 累加、长链条 FP32 累加"。代价是一部分计算从 Tensor Core 溢出到 CUDA Core，实测带来约几个百分点的算力损耗——用少量计算换累加精度。

### 5.3 高精度保留的关键组件

不是所有东西都能 FP8：

- **master weight**：优化器更新的是高精度（FP32）主权重，FP8 权重只是前向/反向时的临时投影。否则小梯度更新会被量化噪声淹没。
- **对精度敏感的组件保留 BF16**：embedding、最终输出头（LM head）、MoE 的 router 等参数量小但精度敏感的部分不量化——它们的显存占比小，量化收益低、风险高。这是"量化收益/风险比"思维的典型应用。

### 5.4 通信也压缩

训练通信是另一笔大头（呼应第 6 章）：DeepSeek-V3 把 MoE all-to-all 通信的激活在发送前量化到 FP8，通信量直接减半。注意通信压缩和计算量化共享同一个逻辑：**先量化再传输/计算，收到后反量化**，scale 元数据跟着数据一起走。

## 6. FP8 推理：W8A8 FP8

推理侧的 FP8 比训练简单得多：**W8A8 FP8**（权重和激活都是 FP8），vLLM、SGLang、TensorRT-LLM 均已支持，通常是离线把权重 cast 到 E4M3（可选 per-channel/block scale），激活运行时在线量化。

理论收益：

- **显存减半**：权重从 BF16 的 2 字节降到 1 字节，同样显存可以部署双倍参数量的模型，或者把 KV Cache 空间让出来加大 batch。
- **计算翻倍**：Hopper 上 FP8 Tensor Core 峰值约为 BF16 的 2 倍。

但实际端到端加速**通常远低于 2 倍**，原因是 Amdahl 定律在起作用（呼应 1.9 节 roofline）：

- FP8 只加速 **GEMM**；attention（尤其 decode 阶段的 memory-bound attention）、LayerNorm、采样、通信都是非 GEMM 开销，不被加速；
- 小 batch 下 GEMM 本身也是 memory-bound 的，瓶颈在搬运权重而不是计算——这时 FP8 的主要收益其实是**显存带宽减半**而不是算力翻倍；
- 量化/反量化、kernel launch 等固定开销进一步稀释收益。

所以 FP8 推理的真实收益画像：**大 batch / 大模型 compute-bound 场景接近算力收益；小 batch decode 场景主要吃到的是显存和带宽收益**。

## 7. 不可能三角视角下的对比与选型

### 7.1 FP8 vs INT8 vs INT4 对比表

| 维度 | INT8 (W8A8) | INT4 (W4A16) | FP8 (W8A8) |
|------|-------------|--------------|------------|
| 精度损失 | 中（需校准控制） | 较大（通常 weight-only + 分组） | 小（通常直接 cast） |
| 校准需求 | 需要校准集 + 校准算法 | 需要（GPTQ/AWQ 等更重） | 通常不需要 |
| 硬件要求 | 广泛（Turing 起均有 INT8 Tensor Core） | 广泛（软件 unpack） | **Hopper+ / Ada / 国产新芯片** |
| 显存收益 | 权重减半 | 权重 1/4 | 权重减半 |
| 计算收益 | 2× FP16 | 通常不加速计算（省带宽） | 2× FP16 |
| 训练支持 | 困难 | 不支持 | **DeepSeek-V3 已验证全量训练** |
| 适用场景 | 老卡推理、端侧 | 极致显存压缩、单卡部署 | 新卡训练 + 推理默认选项 |

### 7.2 更新 7.9 决策树的一个视角

7.9 节的量化决策树以 INT8/INT4 为主线。2024 年之后需要补一条新分支：**如果手里是 Hopper 及更新的卡（或支持 FP8 的国产芯片），FP8 应该成为默认起点**——先 FP8 直接 cast 评估精度，损失可接受就不用碰 INT8 那套校准流程；只有需要把权重压到 4-bit（显存硬约束）时才走 INT4/AWQ 路线。硬件代际在改写量化选型的默认值。

### 7.3 三角权衡小结

- FP8 vs BF16：牺牲少量精度（靠细粒度 scaling 和高精度累加兜底），换计算 2×、显存 1/2、通信 1/2——**三边同时赚**，代价全在工程复杂度上；
- FP8 vs INT8：用**硬件要求**（必须有 FP8 Tensor Core）换掉了**校准成本**；
- FP8 训练的 master weight / BF16 组件：用一部分显存换回训练稳定性。

## 8. 展望：Blackwell 的 FP4 / MXFP4

Blackwell（B200）把这条路继续往前走了一格：原生支持 **FP4** 计算。

- 4-bit 浮点（E2M1：1 符号 + 2 指数 + 1 尾数）单靠自身范围完全不够用，所以采用 **MXFP4（microscaling，微缩放）格式**：**每 32 个元素共享一个 E8M0（8 位纯指数）scale**，块内元素存 E2M1。相当于"块级浮点"——用少量共享指数位换取整块数据的动态范围。
- MX 系列（MXFP8/MXFP6/MXFP4/MXINT8）是 OCP 标准化的微缩放家族，思路与 DeepSeek-V3 的 per-block scaling 一脉相承：**量化粒度越做越细，并且把"细粒度 scale"从软件 trick 变成了硬件原生格式**。
- 趋势判断：未来的低精度计算会沿着"更低位宽 + 硬件原生块缩放"的方向走，软件侧的校准和 scale 管理会越来越多地被硬件格式吸收。

## 10. 面试高频问题

**Q1：FP8 的 E4M3 和 E5M2 分别用在哪里，为什么？**

一句话：E4M3（1+4+3，最大 ±448）精度高范围窄，用于权重和激活；E5M2（1+5+2，最大 ±57344）范围大精度低，用于梯度。

展开：前向的权重/激活分布集中、动态范围小，需要尾数精度，用 E4M3；反向梯度重尾、动态范围大，溢出比精度损失更致命，用 E5M2。E4M3 没有 INF 编码，NaN 用特殊位模式表示。

**Q2：为什么 FP8 比 INT8 更容易落地？**

一句话：浮点格式的非均匀码本天然匹配神经网络数据的钟形分布，通常不需要校准，直接 cast 精度损失就很小。

展开：INT8 均匀量化把大量码本浪费在没数据的大数值区域，必须靠校准选 scale、甚至 SmoothQuant 迁移量化难度；FP8 的指数自适应范围（E4M3 跨约 18 个数量级）让小数值拿到稠密码本，省掉了校准工程链路。DeepSeek-V3 进一步证明 FP8 可支撑全量训练。

**Q3：DeepSeek-V3 的 FP8 训练是怎么解决激活 outlier 的？**

一句话：细粒度 scaling——激活按 1×128 token 块 per-tile 量化，权重按 128×128 per-block 量化，把 outlier 的影响限制在小块内。

展开：per-tensor 共用一个 scale 时，outlier 会撑大 scale 把正常值压到码本底部。分块后每块独立 amax/scale，代价是每个块要存 FP32 scale、GEMM kernel 要做块内反量化累加的融合。

**Q4：FP8 训练中 Tensor Core 的累加精度问题怎么解决？**

一句话：H100 的 FP8 MMA 累加器只有约 14 位有效精度，DeepSeek-V3 每累加若干次（约 128 元素间隔）就把部分和提升到 CUDA Core 的 FP32 寄存器继续累加。

展开：FP8 乘法 + 短链 FP8 累加 + 长链 FP32 累加，用少量 CUDA Core 计算换累加精度；同时 master weight 保持 FP32，embedding/输出头等敏感组件保留 BF16。

**Q5：FP8 推理为什么端到端加速到不了 2 倍？**

一句话：FP8 只加速 GEMM，attention、通信、kernel launch 等非 GEMM 开销按 Amdahl 定律稀释收益；小 batch 下 GEMM 本身还是 memory-bound 的。

展开：大 batch compute-bound 场景接近 2 倍算力收益；decode 场景主要收益是权重显存/带宽减半，体现在能跑更大 batch 或更长上下文，而不是单请求延迟。

**Q6：2024 年之后量化选型有什么变化？**

一句话：有 Hopper 及以上硬件时 FP8 成为默认起点，INT8/INT4 退居老卡或极致显存压缩场景。

展开：FP8 免校准、精度损失小、训练推理通吃；只有显存硬约束需要 4-bit 权重（单卡部署大模型）时才走 INT4 weight-only 路线。

## 11. 小结

1. FP8 是两种浮点格式：E4M3（精度型，权重/激活）和 E5M2（范围型，梯度）；浮点码本天然匹配钟形分布，**免校准**是它相对 INT8 的最大工程优势。
2. outlier 是 FP8 训练的核心敌人，解法是**细粒度 scaling**：激活 1×128 per-tile、权重 128×128 per-block。
3. FP8 训练是系统工程：在线量化、分块提升 FP32 累加（绕开约 14 位的 Tensor Core 累加器）、master weight 高精度、敏感组件 BF16、通信前量化。
4. FP8 推理收益要看清结构：GEMM 2 倍、显存减半，但端到端被非 GEMM 开销稀释。
5. 演进方向：Blackwell FP4 / MXFP4 把"块级 scaling"固化进硬件格式——量化粒度越做越细，是 FP8 故事的延续。
