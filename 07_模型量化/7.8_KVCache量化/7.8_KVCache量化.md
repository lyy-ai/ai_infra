# 7.8 KV Cache 量化：让长上下文推理成为可能

## 1. 什么是 KV Cache

在 Transformer  decoder 的**自回归生成**过程中，模型每次只生成一个新 token，但 attention 需要回顾之前所有 token 的 Key（K）和 Value（V）。

为了避免重复计算，推理框架会把历史 token 的 K、V 张量缓存起来，这就是 **KV Cache**。

### 1.1 KV Cache 的组成

一个 token 在第 $l$ 层、第 $h$ 个头上有：

- 一个 Key 向量：$K \in \mathbb{R}^{d_{head}}$
- 一个 Value 向量：$V \in \mathbb{R}^{d_{head}}$

对于整个 batch：

$$\text{KV Cache} = [K_1, K_2, \dots, K_L] \cup [V_1, V_2, \dots, V_L]$$

其中 $L$ 是已生成的序列长度，每层有 $n_{heads}$ 个头。

### 1.2 KV Cache 显存公式

单条序列的 KV Cache 显存占用约为：

$$\text{Bytes} = 2 \times n_{layers} \times n_{heads} \times d_{head} \times L \times \text{bytes\_per\_element}$$

- 系数 2：K 和 V 各一份
- $n_{layers}$：Transformer 层数
- $n_{heads}$：注意力头数
- $d_{head}$：每个头的维度
- $L$：序列长度
- `bytes_per_element`：每个元素占用的字节数（FP16 = 2，INT8 = 1，2-bit = 0.25）

## 2. KV Cache 量化的动机：长上下文场景

### 2.1 为什么长上下文这么耗显存

以 Llama-2-7B 为例：

| 参数 | 数值 |
|------|------|
| 层数 | 32 |
| 头数 | 32 |
| head_dim | 128 |
| 总参数量 | 7B |

当序列长度 $L = 8192$ 时，FP16 KV Cache 占用：

$$2 \times 32 \times 32 \times 128 \times 8192 \times 2 = 4.29\ \text{GB}$$

当 $L = 128K$ 时：

$$2 \times 32 \times 32 \times 128 \times 131072 \times 2 = 68.7\ \text{GB}$$

这已经接近或超过一张 A100 40GB 的显存容量。如果还要放模型权重、激活、workspace，显然不够。

### 2.2 长上下文带来的挑战

| 问题 | 说明 |
|------|------|
| 显存爆炸 | KV Cache 随序列长度线性增长 |
| 批大小受限 | 长序列下 batch_size 只能降到 1 |
| 上下文换页 | 需要把 KV Cache 在 CPU/GPU 间搬运 |
| 推理延迟 | 注意力计算量和访存量都增大 |

### 2.3 量化的核心收益

- **FP16 → INT8**：KV Cache 显存减半，可支持 2 倍序列长度。
- **FP16 → 2-bit（KIVI）**：KV Cache 显存压缩到 1/8，128K 上下文成为可能。
- **更高 batch size**：省下的显存可以并发更多请求。

---

## 3. KIVI 2-bit 量化方案

### 3.1 KIVI 是什么

**KIVI**（Key-Vaclue 2-bit Quantization）是一种针对 KV Cache 的极低比特量化方案，由论文《KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache》提出。

核心观察：

- **Key 的分布**：同一个 channel（head_dim 维度）内数值范围相对稳定，适合 **per-channel 量化**。
- **Value 的分布**：同一个 token 内数值范围相对稳定，适合 **per-token 量化**。

### 3.2 KIVI 的量化策略

| 组件 | 量化粒度 | 原因 |
|------|---------|------|
| Key | per-channel | 同一通道数值范围稳定，outlier 少 |
| Value | per-token | 同一 token 内数值分布相对一致 |
| 位宽 | 2-bit | 极大压缩，同时保留可接受的精度 |
| 类型 | 非对称量化 | 分布不关于 0 对称，需要 zero point |

### 3.3 2-bit 非对称量化公式

2-bit 可以表示 4 个离散值：$\{0, 1, 2, 3\}$。

对张量 $x$ 按某个维度分组量化：

$$\text{scale} = \frac{x_{\max} - x_{\min}}{3}$$

$$\text{zero\_point} = \mathrm{round}\Big(-\frac{x_{\min}}{\text{scale}}\Big)$$

$$x_q = \mathrm{clip}\Big(\mathrm{round}\big(\frac{x}{\text{scale}} + \text{zero\_point}\big),\; 0,\; 3\Big)$$

反量化：

$$\hat{x} = \text{scale} \cdot (x_q - \text{zero\_point})$$

### 3.4 KIVI 为什么能 work

1. **注意力对 K/V 的精度要求低于权重**：softmax 会把注意力分数归一化，小幅误差会被平滑。
2. **per-channel / per-token 粒度足够细**：不同 head、不同 token 的分布差异被单独处理。
3. **非对称量化保留分布偏移**：比对称量化更适合 KV Cache 的分布。

## 4. 量化对生成质量的影响

### 4.1 评价维度

KV Cache 量化对生成质量的影响通常从三个维度衡量：

| 维度 | 说明 | 常用指标 |
|------|------|---------|
| 困惑度 | 下一个 token 预测概率的负对数 | Perplexity (PPL) |
| 长文本检索 | 在长上下文中找到特定信息 | Pass@1, Recall |
| 文本生成质量 | 语义连贯性、事实正确性 | 人工评估、ROUGE、BLEU |

### 4.2 典型现象

- **FP16 → INT8**：PPL 通常上升 < 1%，基本无感知。
- **FP16 → KIVI 2-bit**：PPL 上升 1–5%，在 4K 以上上下文可能开始感知。
- **极端压缩（1-bit 或 group_size 很小）**：PPL 显著上升，长文本检索能力下降。

### 4.3 长上下文“大海捞针”测试

这是目前评估 KV Cache 量化的经典方法：

1. 在超长上下文（如 100K tokens）中随机藏入一条关键信息。
2. 模型生成时，问题指向这条关键信息。
3. 检查模型是否能正确回答。

量化越激进，模型在超长序列中“遗忘”关键信息的概率越大。

```python
# kvcache_memory_analysis.py
import torch


def compute_kv_cache_bytes(
    batch_size,
    seq_len,
    num_layers,
    num_heads,
    head_dim,
    dtype_bytes=2,
):
    """计算 KV Cache 显存占用（字节）"""
    return 2 * batch_size * num_layers * num_heads * head_dim * seq_len * dtype_bytes


def print_model_kv_cache(name, batch_size, num_layers, num_heads, head_dim, seq_lens):
    """打印不同序列长度、不同精度下的 KV Cache 大小"""
    print(f"\n{name}: batch={batch_size}, layers={num_layers}, heads={num_heads}, head_dim={head_dim}")
    print(f"{'seq_len':>10} {'FP16(GB)':>10} {'INT8(GB)':>10} {'KIVI2(GB)':>10}")
    for seq_len in seq_lens:
        fp16 = compute_kv_cache_bytes(batch_size, seq_len, num_layers, num_heads, head_dim, 2)
        int8 = compute_kv_cache_bytes(batch_size, seq_len, num_layers, num_heads, head_dim, 1)
        kivi2 = compute_kv_cache_bytes(batch_size, seq_len, num_layers, num_heads, head_dim, 0.25)
        print(f"{seq_len:>10} {fp16/1024**3:>10.2f} {int8/1024**3:>10.2f} {kivi2/1024**3:>10.2f}")


def main():
    seq_lens = [2048, 8192, 32768, 100000, 200000]

    # Llama-2-7B 风格配置
    print_model_kv_cache(
        "Llama-2-7B-style",
        batch_size=1,
        num_layers=32,
        num_heads=32,
        head_dim=128,
        seq_lens=seq_lens,
    )

    # Llama-2-70B 风格配置
    print_model_kv_cache(
        "Llama-2-70B-style",
        batch_size=1,
        num_layers=80,
        num_heads=8,
        head_dim=128,
        seq_lens=seq_lens,
    )

    # 展示 batch size 的影响
    print("\n\nBatch size 对 KV Cache 的影响（Llama-2-7B-style, seq_len=32768）")
    print(f"{'batch':>6} {'FP16(GB)':>10} {'INT8(GB)':>10} {'KIVI2(GB)':>10}")
    for bs in [1, 4, 8, 16]:
        fp16 = compute_kv_cache_bytes(bs, 32768, 32, 32, 128, 2)
        int8 = compute_kv_cache_bytes(bs, 32768, 32, 32, 128, 1)
        kivi2 = compute_kv_cache_bytes(bs, 32768, 32, 32, 128, 0.25)
        print(f"{bs:>6} {fp16/1024**3:>10.2f} {int8/1024**3:>10.2f} {kivi2/1024**3:>10.2f}")


if __name__ == "__main__":
    main()
```

### 5.2 KIVI 2-bit 量化实现：`kivi_2bit_quantize.py`

```python
# kivi_2bit_quantize.py
import torch


def kivi_quantize_2bit(x, scheme='per-channel'):
    """
    KIVI 风格的 2-bit 非对称量化。

    Args:
        x: 输入张量，形状通常为 [batch, seq_len, num_heads, head_dim]
        scheme: 'per-channel' 用于 Key（沿 head_dim），
                'per-token' 用于 Value（沿 seq_len）
    """
    if scheme == 'per-channel':
        # Key: 每个 head_dim 通道独立量化
        dim = -1
        x_min = x.min(dim=dim, keepdim=True).values
        x_max = x.max(dim=dim, keepdim=True).values
    elif scheme == 'per-token':
        # Value: 每个 token 独立量化
        dim = 1
        x_min = x.min(dim=dim, keepdim=True).values
        x_max = x.max(dim=dim, keepdim=True).values
    else:
        raise ValueError(f"Unknown scheme: {scheme}")

    # 2-bit 只有 4 个码点: 0, 1, 2, 3
    qmax = 3
    scale = (x_max - x_min) / qmax
    scale = torch.where(scale == 0, torch.ones_like(scale), scale)
    zero_point = torch.round(-x_min / scale).clamp(0, qmax)

    x_q = torch.round(x / scale + zero_point).clamp(0, qmax).to(torch.uint8)
    return x_q, scale, zero_point


def kivi_dequantize_2bit(x_q, scale, zero_point):
    """KIVI 2-bit 反量化"""
    return scale * (x_q.to(torch.float32) - zero_point)


def demo_kivi_quantize():
    """演示 KIVI 2-bit 对 Key 和 Value 的量化效果"""
    torch.manual_seed(42)
    batch_size = 1
    seq_len = 1024
    num_heads = 32
    head_dim = 128

    # 模拟 Key 和 Value
    k = torch.randn(batch_size, seq_len, num_heads, head_dim)
    v = torch.randn(batch_size, seq_len, num_heads, head_dim)

    # Key 使用 per-channel 量化
    k_q, k_scale, k_zp = kivi_quantize_2bit(k, scheme='per-channel')
    k_deq = kivi_dequantize_2bit(k_q, k_scale, k_zp)

    # Value 使用 per-token 量化
    v_q, v_scale, v_zp = kivi_quantize_2bit(v, scheme='per-token')
    v_deq = kivi_dequantize_2bit(v_q, v_scale, v_zp)

    k_mse = torch.mean((k - k_deq) ** 2).item()
    v_mse = torch.mean((v - v_deq) ** 2).item()

    print(f"Key  per-channel 2-bit quantization MSE: {k_mse:.6f}")
    print(f"Value per-token   2-bit quantization MSE: {v_mse:.6f}")
    print(f"Original FP16 size: {k.numel() * 2 / 1024**2:.2f} MB per KV tensor")
    print(f"KIVI 2-bit size:    {k_q.numel() * 1 / 8 / 1024**2:.2f} MB per KV tensor (uint8 packed)")
    print(f"Compression ratio: 8x")


if __name__ == "__main__":
    demo_kivi_quantize()
```

### 5.3 量化对注意力输出的影响：`generation_quality_impact.py`

```python
# generation_quality_impact.py
import torch
import torch.nn.functional as F


def kivi_quantize_2bit(x, scheme='per-channel'):
    """KIVI 2-bit 量化（复用自 kivi_2bit_quantize.py）"""
    if scheme == 'per-channel':
        dim = -1
    elif scheme == 'per-token':
        dim = 1
    else:
        raise ValueError(scheme)

    x_min = x.min(dim=dim, keepdim=True).values
    x_max = x.max(dim=dim, keepdim=True).values
    qmax = 3
    scale = (x_max - x_min) / qmax
    scale = torch.where(scale == 0, torch.ones_like(scale), scale)
    zero_point = torch.round(-x_min / scale).clamp(0, qmax)
    x_q = torch.round(x / scale + zero_point).clamp(0, qmax).to(torch.uint8)
    return x_q, scale, zero_point


def kivi_dequantize_2bit(x_q, scale, zero_point):
    return scale * (x_q.to(torch.float32) - zero_point)


def synthetic_attention(q, k, v, k_quant_scheme=None, v_quant_scheme=None):
    """
    简化的单头注意力，可选择对 K 和 V 做 KIVI 量化。
    """
    if k_quant_scheme:
        k_q, k_scale, k_zp = kivi_quantize_2bit(k, k_quant_scheme)
        k = kivi_dequantize_2bit(k_q, k_scale, k_zp)
    if v_quant_scheme:
        v_q, v_scale, v_zp = kivi_quantize_2bit(v, v_quant_scheme)
        v = kivi_dequantize_2bit(v_q, v_scale, v_zp)

    scores = torch.matmul(q, k.transpose(-2, -1)) / (k.shape[-1] ** 0.5)
    attn = F.softmax(scores, dim=-1)
    out = torch.matmul(attn, v)
    return out


def demo_quality_impact():
    """对比 FP16 KV Cache vs KIVI 2-bit KV Cache 的注意力输出差异"""
    torch.manual_seed(42)
    seq_len = 2048
    head_dim = 128

    # 模拟查询向量和长序列的 K/V
    q = torch.randn(1, 1, head_dim)
    k = torch.randn(1, seq_len, head_dim)
    v = torch.randn(1, seq_len, head_dim)

    # FP16 baseline
    out_fp16 = synthetic_attention(q, k, v, None, None)

    # INT8 量化（对称量化后反量化）
    k_scale_int8 = k.abs().max() / 127
    v_scale_int8 = v.abs().max() / 127
    k_int8 = (torch.round(k / k_scale_int8).clamp(-128, 127) * k_scale_int8)
    v_int8 = (torch.round(v / v_scale_int8).clamp(-128, 127) * v_scale_int8)
    out_int8 = synthetic_attention(q, k_int8, v_int8, None, None)

    # KIVI 2-bit
    out_kivi = synthetic_attention(q, k, v, 'per-channel', 'per-token')

    mse_int8 = torch.mean((out_fp16 - out_int8) ** 2).item()
    mse_kivi = torch.mean((out_fp16 - out_kivi) ** 2).item()
    cos_int8 = F.cosine_similarity(out_fp16, out_int8, dim=-1).mean().item()
    cos_kivi = F.cosine_similarity(out_fp16, out_kivi, dim=-1).mean().item()

    print(f"Attention output comparison (seq_len={seq_len}, head_dim={head_dim})")
    print(f"  INT8  vs FP16: MSE={mse_int8:.6f}, Cosine Similarity={cos_int8:.6f}")
    print(f"  KIVI2 vs FP16: MSE={mse_kivi:.6f}, Cosine Similarity={cos_kivi:.6f}")

    # 模拟“大海捞针”：某个 token 的 K 和 V 都包含关键信息
    needle_idx = seq_len // 2
    k_needle = k.clone()
    v_needle = v.clone()
    # 让 needle 位置的 key 与 query 高度对齐，value 设置强信号
    k_needle[0, needle_idx, :] = q[0, 0, :] * 5.0
    v_needle[0, needle_idx, :] = 10.0
    out_fp16_needle = synthetic_attention(q, k_needle, v_needle, None, None)
    out_kivi_needle = synthetic_attention(q, k_needle, v_needle, 'per-channel', 'per-token')

    # 查看注意力是否仍然聚焦到 needle 位置
    scores_fp16 = torch.matmul(q, k_needle.transpose(-2, -1)) / (head_dim ** 0.5)
    attn_fp16 = F.softmax(scores_fp16, dim=-1)
    scores_kivi = torch.matmul(q, k_needle.transpose(-2, -1)) / (head_dim ** 0.5)
    attn_kivi = F.softmax(scores_kivi, dim=-1)

    print(f"\nNeedle retrieval test (needle at index {needle_idx})")
    print(f"  FP16  attention peak index: {attn_fp16.argmax(dim=-1).item()}")
    print(f"  KIVI2 attention peak index: {attn_kivi.argmax(dim=-1).item()}")
    print(f"  FP16  attention mass at needle: {attn_fp16[0, 0, needle_idx].item():.4f}")
    print(f"  KIVI2 attention mass at needle: {attn_kivi[0, 0, needle_idx].item():.4f}")


if __name__ == "__main__":
    demo_quality_impact()
```

## 7. KV Cache 量化 vs 权重量化

| 维度 | 权重量化 | KV Cache 量化 |
|------|---------|--------------|
| 量化对象 | 模型权重 W | 推理中间状态 K、V |
| 是否需要校准 | 通常需要 | 通常不需要，动态统计 |
| 数据动态性 | 静态 | 动态增长 |
| 主要收益 | 减模型体积、加载快 | 支持长上下文、提并发 |
| 典型精度 | 4-bit / 8-bit | 8-bit / 2-bit |
| 对生成质量影响 | 中 | 在短上下文小，长上下文增大 |

## 9. 主流 KV Cache 量化方案对比

| 方案 | Key 量化 | Value 量化 | 位宽 | 特点 | 代表工作 |
|------|---------|-----------|------|------|---------|
| FP16 KV | 16-bit | 16-bit | 16-bit | 基准，无精度损失 | 原始 Transformer |
| INT8 KV | 8-bit | 8-bit | 8-bit | 显存减半，精度损失小 | vLLM, TensorRT-LLM |
| **KIVI** | **per-channel** | **per-token** | **2-bit** | **8x 压缩，长上下文友好** | KIVI (2024) |
| H2O | 动态驱逐 | 动态驱逐 | - | 保留重要 token 的完整 KV | H2O (2023) |
| Heavy Hitter | 稀疏 + 量化 | 稀疏 + 量化 | - | 重要 token 高精度 | StreamingLLM |
| SnapKV | 稀疏选择 | 稀疏选择 | - | 选择关键 KV 保留 | SnapKV (2024) |

## 12. 本节小结

1. **KV Cache** 是 Transformer 自回归生成中缓存历史 K、V 的机制，显存随序列长度线性增长。
2. 长上下文下，FP16 KV Cache 可能占用几十 GB 显存，成为推理瓶颈。
3. **KIVI 2-bit** 通过 Key 的 per-channel 量化和 Value 的 per-token 量化，将 KV Cache 压缩 8 倍。
4. 量化对生成质量的影响：INT8 几乎无感知，2-bit 在短上下文下可接受，超长上下文需要配合稀疏、驱逐等策略。
5. KV Cache 量化与权重量化互补，共同支撑大模型长上下文推理。
