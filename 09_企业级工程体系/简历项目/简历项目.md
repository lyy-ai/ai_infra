# 简历项目：企业级工程体系

## 项目一：AI Infra CI/CD 与自动化平台

### 一句话描述

设计并落地 AI Infra 的 CI/CD 流水线，实现模型编译、精度验证、性能回归、产物发布的全流程自动化。

### 简历写法

> **AI Infra CI/CD 与自动化平台**
> - 设计包含 lint、build、精度验证、性能回归、release 五个阶段的 CI/CD 流水线，覆盖 TensorRT、CANN、自研芯片三种编译后端。
> - 实现模型版本命名规范 `model-v{version}-{backend}-{precision}-{parallel}`，统一追踪代码、模型、产物、依赖镜像版本。
> - 引入失败重试、产物隔离、环境隔离机制，编译失败率从 12% 降至 2%。
> - 集成 Tensor Diff 与 Benchmark 门禁，异常 PR 自动 block，平均问题发现时间从 2 天缩短到 30 分钟。

### 可量化的指标

| 指标 | 数值 |
|------|------|
| CI 阶段 | 5 |
| 支持后端 | TensorRT / CANN / 自研芯片 |
| 编译失败率 | 12% → 2% |
| 问题发现时间 | 2 天 → 30 分钟 |

### 面试常问点

- AI Infra 的 CI/CD 与传统软件有什么不同？
- 如何保证模型编译产物的可复现性？
- 版本管理中除了代码还要管理哪些东西？

## 项目二：性能回归与 Profiling 平台

### 一句话描述

构建自动 benchmark 与性能回归平台，实现退化自动 block、git bisect 定位根因、Nsight 数据可视化。

### 简历写法

> **性能回归与 Profiling 平台**
> - 搭建自动 benchmark 系统，支持 A100 / Orin / Ascend 多平台定时触发与 PR 触发，统一采集 TTFT、TBT、吞吐、显存、功耗指标。
> - 实现性能回归门禁：吞吐/延迟退化超 5% 自动 block PR，并自动生成 diff 报告。
> - 集成 Nsight Systems / Nsight Compute，设计统一 profiling schema，支持跨平台 timeline 对比与历史趋势查询。
> - 配合 git bisect 自动定位退化 commit，平均定位时间从 1 天缩短到 2 小时。

### 可量化的指标

| 指标 | 数值 |
|------|------|
| 支持平台 | A100 / Orin / Ascend |
| 回归阈值 | 延迟/吞吐退化 > 5% block |
| 定位时间 | 1 天 → 2 小时 |
| 监控指标 | TTFT / TBT / 吞吐 / 显存 / 功耗 |

### 面试常问点

- 如何区分真实性能退化与环境抖动？
- git bisect 在性能回归中怎么用？
- Nsight Systems 和 Nsight Compute 的区别是什么？

## 项目三：质量保障与监控系统

### 一句话描述

建设结构化日志、Tensor Diff、多平台一致性验证与 SLO 监控，形成生产级质量保障闭环。

### 简历写法

> **AI Infra 质量保障与监控系统**
> - 设计结构化 JSON 日志规范，覆盖编译、推理、benchmark 全链路，支持按 run_id / commit / model / platform 多维检索。
> - 开发 Tensor Diff 系统，自动对比 FP32 / FP16 / INT8 与参考输出的 max abs diff、relative diff、cosine similarity，输出逐层热力图。
> - 建立多平台编译一致性验证流程，覆盖 TensorRT / CANN / 自研芯片，端到端误差从 1e-2 收敛到 1e-4。
> - 搭建 GPU 利用率、显存、温度、推理 SLO 监控与告警，P99 延迟异常 1 分钟内触达值班通道。

### 可量化的指标

| 指标 | 数值 |
|------|------|
| 日志检索维度 | run_id / commit / model / platform |
| 跨平台端到端误差 | 1e-2 → 1e-4 |
| 告警延迟 | < 1 分钟 |
| 覆盖平台 | TensorRT / CANN / 自研芯片 |

### 面试常问点

- Tensor Diff 的阈值怎么设定？
- 如何处理跨平台浮点累加顺序导致的微小差异？
- 监控告警如何避免告警疲劳？
