# 9.4 质量保障系统

## 课程概述

AI Infra 上线前的最后一道防线是质量保障。质量不仅指“不崩溃”，还包括**精度一致、日志完整、结果可审计**。本节介绍企业级质量保障系统的三个核心组件：日志系统、Tensor Diff 系统、多平台编译一致性验证。

学完本节后，你应该能够：

- 设计结构化日志系统，支持问题定位与审计。
- 实现 Tensor Diff 系统，自动检测量化/编译前后的精度变化。
- 建立多平台编译结果一致性验证流程。
- 把质量保障嵌入 CI/CD 流水线。

---

## 1. 日志系统

### 1.1 日志分级

| 级别 | 用途 |
|------|------|
| DEBUG | 开发调试，生产可关闭 |
| INFO | 关键流程节点：开始编译、开始推理、完成 benchmark |
| WARNING | 潜在风险：精度接近阈值、资源使用率过高 |
| ERROR | 明确错误：编译失败、推理异常、测试失败 |
| CRITICAL | 需要立即处理：OOM、服务不可用 |

### 1.2 结构化日志

推荐 JSON 格式，便于 ELK / Loki / ClickHouse 查询：

```json
{
  "timestamp": "2025-01-20T10:23:45.123Z",
  "level": "INFO",
  "module": "tensorrt_builder",
  "run_id": "abc-123",
  "commit": "a1b2c3d",
  "message": "engine build succeeded",
  "metadata": {
    "model": "llama-7b",
    "precision": "fp16",
    "latency_ms": 12.3
  }
}
```

### 1.3 日志采集与查询

- 使用 `loguru` / `structlog` 等库统一日志格式。
- 通过 Fluentd / Promtail 采集到集中存储。
- 支持按 run_id、commit、model、platform 多维检索。

## 2. Tensor Diff 系统

### 2.1 为什么需要 Tensor Diff

模型在转换、量化、编译后，输出可能发生变化。Tensor Diff 系统自动对比这些变化：

```text
原始模型输出  vs  量化后模型输出
     ↓                ↓
   max_abs_diff
   max_relative_diff
   cosine_similarity
   per-layer diff heatmap
```

### 2.2 对比维度

| 对比 | 目的 |
|------|------|
| FP32 vs FP16 | 确认 FP16 精度损失可接受 |
| FP16 vs INT8 | 确认量化方案精度可接受 |
| PyTorch vs ONNX | 确认导出过程无 bug |
| ONNX vs TensorRT | 确认编译过程无 bug |
| Platform A vs B | 确认跨平台结果一致 |

### 2.3 判定标准

| 精度 | 绝对误差阈值 | 相对误差阈值 |
|------|--------------|--------------|
| FP32 | 1e-5 | 1e-5 |
| FP16 | 1e-3 | 1e-3 |
| INT8 | 1e-2 ~ 1e-1 | 业务相关 |

### 2.4 Diff 报告

- 全局指标：max / mean / median diff、cosine similarity。
- 逐层指标：定位哪一层开始出现较大 diff。
- 可视化：diff 热力图、分布直方图。

## 3. 多平台编译结果一致性验证

### 3.1 验证流程

```text
同一模型 + 同一输入
    ↓
Platform A 输出
    ↓
Platform B 输出
    ↓
Tensor Diff 比较
    ↓
通过 / 失败
```

### 3.2 覆盖场景

- NVIDIA TensorRT vs ONNX Runtime
- TensorRT vs Ascend CANN
- 自研芯片 vs 参考平台
- 不同精度（FP16 / INT8 / INT4）之间

### 3.3 一致性阈值管理

- 不同模型、不同任务设定不同阈值。
- 阈值纳入版本管理，变更需审批。
- 失败时自动 attach diff 报告到 PR。

## 5. 本节小结

- 日志是问题定位与审计的基础，必须结构化。
- Tensor Diff 是量化/编译后精度保障的核心工具。
- 多平台一致性验证确保不同硬件上模型行为一致。
- 质量保障必须与 CI/CD 紧密结合，自动 block 异常变更。
