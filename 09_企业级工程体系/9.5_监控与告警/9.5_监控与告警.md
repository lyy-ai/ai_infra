# 9.5 监控与告警

## 课程概述

生产环境的 AI 推理服务需要持续监控：GPU 是否充分利用、显存是否泄漏、延迟是否超标、服务是否可用。监控与告警是保障 SLO 的最后一道防线，也是性能优化的重要数据来源。

学完本节后，你应该能够：

- 设计 GPU / 显存 / 温度等基础设施监控。
- 建立推理服务 SLO 监控体系。
- 实现异常检测与自动告警。
- 把监控数据反馈给性能回归与容量规划。

---

## 1. GPU 利用率 / 显存 / 温度监控

### 1.1 关键指标

| 指标 | 说明 | 告警阈值参考 |
|------|------|--------------|
| GPU Utilization | 计算利用率 | < 30% 持续 5min → 资源浪费 |
| GPU Memory Used | 显存使用 | > 90% → OOM 风险 |
| GPU Temperature | 温度 | > 85°C → 降频风险 |
| Power Draw | 功耗 | 持续接近 TDP → 散热/供电关注 |
| PCIe Bandwidth | 数据搬运 | 长期高占用 → CPU/GPU 交互问题 |

### 1.2 采集方式

- **DCGM（NVIDIA）**：企业级 GPU 监控，提供 exporter。
- **nvidia-smi**：简单场景，命令行或 pynvml。
- **Ascend msprof / 驱动接口**：NPU 监控。
- **自研芯片**：通过驱动或 BMC 接口暴露指标。

### 1.3 Prometheus + Grafana 方案

```text
nvidia-dcgm-exporter  →  Prometheus  →  Grafana Dashboard
                                ↓
                           Alertmanager
                                ↓
                            钉钉 / Slack / 邮件
```

## 2. 推理服务 SLO 监控

### 2.1 SLO 指标体系

| 指标 | 含义 | 典型目标 |
|------|------|----------|
| P99 Latency | 99% 请求延迟 | < 200ms |
| TTFT P99 | 首 token 延迟 | < 500ms |
| TBT P99 | 每 token 延迟 | < 50ms |
| Throughput | tokens/s | 根据容量 |
| Error Rate | 错误率 | < 0.1% |
| Queue Time | 请求排队时间 | < 50ms |

### 2.2 监控维度

- 按模型、版本、平台、机房、集群分组。
- 区分 prefill / decode 阶段。
- 区分在线实时请求与离线批处理。

### 2.3 数据采集

- 服务端埋点：每个请求记录开始/结束时间、token 数、错误码。
- Agent 侧上报：通过 OpenTelemetry / Prometheus client。
- 日志后处理：从结构化日志中提取指标。

## 3. 异常检测与自动告警

### 3.1 异常类型

| 类型 | 表现 |
|------|------|
| 延迟突增 | 延迟从 50ms 涨到 500ms |
| 吞吐下降 | 同样负载下吞吐掉 30% |
| 显存泄漏 | 显存持续增长，最终 OOM |
| 错误率上升 | 5xx / timeout 增加 |
| GPU 温度异常 | 温度快速升高 |
| 静默退化 | 指标缓慢恶化，超过阈值才被发现 |

### 3.2 告警策略

- **静态阈值**：P99 latency > 200ms。
- **动态基线**：同比上周同一时间，偏差 > 20%。
- **变化率**：5 分钟内指标上涨 > 50%。
- **多指标组合**：latency 上升 + GPU util 下降 → 可能是请求堆积。

### 3.3 告警收敛

- 同一问题 5 分钟内只发一次。
- 按严重级别分级：P0 电话、P1 钉钉、P2 邮件。
- 告警必带 context：run_id、commit、最近变更、相关 dashboard 链接。

## 4. 监控驱动优化

### 4.1 从监控到优化

```text
监控发现 GPU util 低
  ↓
分析 timeline：CPU 预处理耗时高
  ↓
优化：异步 tokenizer + 数据 prefetch
  ↓
重跑 benchmark，确认 GPU util 提升
  ↓
上线并持续监控
```

### 4.2 容量规划

- 根据吞吐与延迟趋势预测扩容时机。
- 结合业务增长曲线做 GPU 采购/调度决策。

## 6. 本节小结

- 监控覆盖基础设施、服务 SLO、业务指标三个层面。
- 告警需要合理阈值、分级、收敛，避免告警疲劳。
- 监控数据应回流到性能优化与容量规划中。
- 一个好的监控体系能提前发现问题，而不是等用户投诉。
