# 9.3 Profiling 平台

## 课程概述

性能问题不能只靠 benchmark 数字来猜，必须靠 profiling 看到时间花在哪里。企业级 Profiling 平台需要把不同硬件、不同框架、不同工具采集到的性能数据统一起来，提供可视化、对比分析、历史追踪能力。

学完本节后，你应该能够：

- 理解统一性能分析平台的架构。
- 集成 Nsight Systems / Nsight Compute 到工作流。
- 设计性能数据存储与可视化方案。
- 利用历史 profiling 数据定位性能回归。

---

## 1. 统一性能分析平台

### 1.1 为什么需要统一平台

| 工具 | 适用场景 | 数据格式 |
|------|----------|----------|
| Nsight Systems | 系统级 timeline | .nsys-rep |
| Nsight Compute | 单个 kernel 分析 | .ncu-rep |
| PyTorch Profiler | Python 层调用栈 | chrome trace |
| CANN msprof | Ascend 平台 | json / sqlite |
| 自研 profiler | 自研芯片 | 自定义格式 |

统一平台的价值：

- 不同硬件/工具的结果可以放在同一张 timeline 上对比。
- 自动提取关键指标，减少人工看 timeline 的时间。
- 历史数据可追溯，定位回归有依据。

### 1.2 平台架构

```text
Profiler Agent（各节点运行 nsys / ncu / pyprof）
        ↓
数据上传（trace / report / summary）
        ↓
Parser（提取 kernel、API、内存、通信事件）
        ↓
Normalized DB（统一 schema）
        ↓
Query & Visualization（timeline、flamegraph、对比）
        ↓
Alert & Report
```

### 1.3 统一 Schema 示例

| 字段 | 含义 |
|------|------|
| `run_id` | 一次 profiling 运行的唯一 ID |
| `commit` | 对应代码 commit |
| `platform` | A100 / Orin / Ascend |
| `event_type` | kernel / memcpy / api / sync |
| `name` | 事件名称 |
| `start_us` | 开始时间（微秒） |
| `duration_us` | 持续时间 |
| `stream` | CUDA stream / NPU queue |

## 2. Nsight Systems / Nsight Compute 集成

### 2.1 Nsight Systems

用于看整体 timeline：

```bash
nsys profile -o report.nsys-rep python infer.py
nsys-ui report.nsys-rep
```

关注：

- CPU 与 GPU 的同步开销。
- kernel launch gap。
- memcpy / memset 占比。
- 多卡通信耗时。

### 2.2 Nsight Compute

用于深入单个 kernel：

```bash
ncu --kernel-name regex:.*gemm.* -o report.ncu-rep python infer.py
ncu-ui report.ncu-rep
```

关注：

- Memory bandwidth utilization。
- Compute utilization。
- Occupancy / block / warp。
- Instruction mix。

### 2.3 CI 集成

```bash
# 在 CI 中自动采集
nsys profile -o trace.nsys-rep python scripts/benchmark.py
python scripts/parse_nsys.py trace.nsys-rep --output summary.json
```

## 3. 性能数据可视化与历史追踪

### 3.1 可视化视图

- **Timeline**：CPU / GPU / NPU 事件时间线。
- **Flamegraph**：调用栈耗时分布。
- **Kernel Top-N**：耗时最多的 kernel。
- **Memory Timeline**：显存分配与释放。
- **对比视图**：选择两次 run 进行 side-by-side 对比。

### 3.2 历史追踪

- 每次 benchmark 自动关联 profiling 数据。
- 趋势图：关键 kernel 耗时随 commit 变化。
- 退化提醒：某个 kernel 耗时突然上涨时自动告警。

## 5. 本节小结

- Profiling 平台要统一数据 schema，兼容多工具、多硬件。
- Nsight Systems 看系统 timeline，Nsight Compute 看 kernel 细节。
- 可视化 + 历史追踪是性能回归定位的核心基础设施。
- 每次 benchmark 都应自动采集 profiling 数据，做到“有数据、可追溯”。
