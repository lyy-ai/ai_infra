# 9.2 性能回归平台

## 课程概述

性能回归是 AI Infra 工程化中最容易“偷偷恶化”的问题：一次算子优化、一次框架升级、一次模型结构改动，都可能让线上推理延迟上涨 20%。性能回归平台的目标就是**自动、持续、可追踪地发现并定位性能退化**。

学完本节后，你应该能够：

- 设计自动 Benchmark 系统。
- 实现性能回归门禁：退化超阈值自动 block。
- 用 git bisect + profiling 对比定位退化根因。
- 输出可追踪的性能趋势报告。

---

## 1. 自动 Benchmark 系统

### 1.1 系统架构

```text
代码提交 / 定时触发
        ↓
Job Scheduler（按 GPU/NPU 资源排队）
        ↓
Benchmark Runner（各平台独立执行）
        ↓
Metrics Collector（延迟、吞吐、显存、功耗）
        ↓
Result Database（时序数据）
        ↓
Dashboard / Alert / Report
```

### 1.2 核心组件

| 组件 | 职责 |
|------|------|
| Trigger | git push、PR、定时 cron、手动触发 |
| Scheduler | 资源分配、任务排队、并发控制 |
| Runner | 在目标硬件上执行 benchmark |
| Metrics Store | 存储历史结果，支持趋势查询 |
| Comparator | 对比当前与 baseline |
| Notifier | 发送报告、告警 |

### 1.3 关键设计点

- **环境隔离**：每次 benchmark 在干净容器中进行。
- **固定随机性**：输入、seed、warmup 全部固定。
- **多次采样**：去极值，取中位数或平均。
- **baseline 选择**：main 分支最新稳定结果，或上一个 release tag。

## 2. 性能回归门禁

### 2.1 退化判定规则

- 单指标退化超过阈值 → block PR。
- 多个指标轻微退化叠加 → 警告但不 block。
- 新功能引入的性能下降需有明确审批。

### 2.2 常见阈值策略

| 指标 | 阈值 | 动作 |
|------|------|------|
| TTFT 退化 | > 5% | block |
| 吞吐退化 | > 5% | block |
| 显存上涨 | > 10% | warn |
| 端到端延迟退化 | > 3% | block |

### 2.3 门禁流程

```text
PR 提交
  ↓
Benchmark 运行
  ↓
对比 baseline
  ↓
退化 <= threshold → 通过
  ↓
退化 > threshold  → 标记 failure，要求解释或回滚
```

## 3. 回归定位：git bisect + Profiling

### 3.1 快速定位退化 commit

```bash
# 自动化 bisect 脚本
# bad=当前退化 commit, good=上一个稳定 commit
git bisect start HEAD v2.1.0
git bisect run python scripts/check_regression.py --metric throughput --threshold 0.05
```

### 3.2 Profiling 对比

找到退化 commit 后，用 profiling 工具对比前后 timeline：

- **Nsight Systems**：看 kernel 执行、CPU/GPU 同步、通信耗时。
- **Nsight Compute**：看具体 kernel 的 occupancy、memory bandwidth、instructions。
- **PyTorch Profiler**：看 Python 层调用栈与算子耗时。

### 3.3 定位流程

```text
发现退化
  ↓
确认非环境抖动（重跑 3 次）
  ↓
git bisect 定位 commit
  ↓
Nsight / Profiler 对比退化前后 timeline
  ↓
定位到具体算子 / kernel / 同步点
  ↓
修复 + 重跑 benchmark
```

## 4. 性能趋势与报告

### 4.1 趋势图内容

- 各指标随 commit / 日期的变化曲线。
- 每次 release 的标记点。
- 退化点高亮 + 对应 PR/commit。

### 4.2 自动报告

- 每个 PR 自动生成 benchmark diff 报告。
- 每周/每月输出性能健康度报告。

---

## 6. 本节小结

- 性能回归平台 = 自动 benchmark + 门禁 + 定位 + 趋势追踪。
- 门禁阈值要合理，避免误 block，也不能漏掉真实退化。
- git bisect 是快速定位退化 commit 的神器，配合 profiling 能找到根因。
- 可视化趋势图是团队沟通性能变化的最好方式。
