# 16.5 向量数据与 RAG 基础设施

> 学习目标：掌握 RAG 场景下的数据基础设施——嵌入管线、向量数据库选型、索引与召回质量评估、以及向量数据与 LLM 数据管线的关系。

## 1. RAG 数据管线的全景

```text
文档摄入 → 解析（PDF/HTML/表格）→ 切分（chunking）→ 嵌入（embedding）
  → 向量索引（向量 DB）→ 检索召回（+ 重排 rerank）→ 上下文装配 → LLM
```

RAG 的系统问题一半是数据问题：**切分策略、嵌入质量、索引结构决定了检索上限**，而检索质量直接决定生成质量（"garbage in, garbage out"的 RAG 版）。

## 2. 切分（Chunking）策略

| 策略 | 机制 | 适用 |
|------|------|------|
| 定长切分 | 按固定 token 数 + 重叠滑窗 | 快速起步，通用兜底 |
| 结构切分 | 按标题/段落/表格等文档结构边界 | 结构化文档（技术文档、论文） |
| 语义切分 | 按嵌入相似度找语义断点 | 叙事/长段落文本 |
| 父子切分 | 小 chunk 负责召回，命中后返回其所属大 chunk（上下文完整） | 精度与上下文兼顾的主流方案 |

工程要点：chunk 大小是召回精度（小 chunk 聚焦）与上下文完整性（大 chunk 信息全）的权衡，典型 256-1024 token + 10-20% 重叠；表格与代码必须特殊处理（不能按文本流切断）。

## 3. 嵌入与召回

1. **嵌入模型选型**：通用嵌入（BGE/E5/multilingual-e5 等开源系列）vs 领域微调嵌入；中文场景 BGE 系是主流起点。嵌入维度与检索质量/存储成本成正比（1024 维 vs 256 维，存储差 4 倍）。
2. **召回方式**：
   - 稠密向量召回（语义相似）——主力；
   - 稀疏召回（BM25/关键词）——对专有名词、编号、代码符号更可靠；
   - **混合召回**（稠密+稀疏加权融合）是生产标配，单一路线都有明显盲区。
3. **重排（rerank）**：召回 top-50 后用交叉编码器精排到 top-5——成本换精度的标准动作，提升通常显著。

## 4. 向量数据库选型

| 系统 | 类型 | 特点 | 适用 |
|------|------|------|------|
| **FAISS** | 库（Meta） | 索引算法全集（IVF/HNSW/PQ 量化），嵌入应用内部自建检索层 | 嵌入式、研究、定制管线 |
| **Milvus** | 专用向量 DB | 功能最全的开源向量数据库，分布式、GPU 索引、标量过滤 | 生产级大规模向量检索 |
| **Qdrant** | 专用向量 DB | Rust 实现，易用性好，过滤与 payload 强 | 中小规模生产 |
| **pgvector** | PG 扩展 | 向量进 PostgreSQL，与业务数据同库 JOIN | 已有 PG 栈、规模中等 |
| **LanceDB** | 嵌入式 + 列存 | 基于 Lance 列存格式，多模态数据友好 | 嵌入式/多模态 |

**索引算法常识**：HNSW（图索引，召回高内存大）是默认选择；IVF-PQ（倒排+乘积量化）在大规模下省内存但损失召回；标量预过滤（按租户/时间过滤后再向量搜）与后过滤的召回差异是常见坑。

## 5. 召回质量评估

- **指标**：Recall@K（正确答案所在 chunk 是否进入 top-K）、MRR、nDCG；端到端再看生成质量（faithfulness）。
- **方法**：先建"问题→正确 chunk"的评测集（百级样本即可起步），每次改切分/嵌入/索引参数都回归——**没有评测集的 RAG 调优是盲人摸象**。
- **badcase 分析分类**：没召回（chunk 问题/嵌入问题）、召回了但排不进 top（rerank 问题）、召回对了但生成错（模型/prompt 问题）——三类问题三条修复路径，先归因再动手。

## 6. 向量数据与 LLM 数据管线的关系

- 嵌入模型的训练数据管线与 LLM 数据处理同源（去重/过滤/难负例挖掘）。
- RAG 的语料更新需要**增量索引**管线（新文档进来不必全量重建）。
- Agent 时代的演进：RAG 从"一问一检索"变成"agent 多轮检索"（deep research 场景），向量 infra 的查询负载也随之 agent 化（见 15 章）。

## 8. 面试视角

- **Q：RAG 效果不好怎么排查？** A：三分归因——检索没召回（查 chunking/嵌入/索引）、召回但排序不对（rerank）、检索对了生成错（prompt/模型）；每类问题修复路径不同，先建评测集定位。
- **Q：向量库怎么选？** A：嵌入式定制用 FAISS，生产大规模用 Milvus，中小规模快速上手用 Qdrant，已有 PG 栈且规模中等的用 pgvector；索引默认 HNSW，内存受限上 IVF-PQ。
- **Q：混合召回为什么必要？** A：稠密向量对语义泛化好但对专有名词/编号弱，BM25 恰好互补——生产系统单一路线都有明显盲区。
