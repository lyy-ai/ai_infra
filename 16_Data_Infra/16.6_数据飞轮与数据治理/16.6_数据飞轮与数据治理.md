# 16.6 数据飞轮与数据治理

> 学习目标：掌握生产环境的数据飞轮（日志→筛选→训练→上线→日志）设计、数据版本管理与血缘追踪、以及数据合规治理的工程实现。

## 1. 数据飞轮（Data Flywheel）

模型上线不是数据工作的终点，而是起点——**真实流量是最高价值的数据来源**：

```text
线上服务 → 全量请求日志（输入/输出/上下文/用户反馈）
  → 数据筛选（badcase 挖掘、高价值样本提取）
  → 标注/增强（人工 + 模型预标）
  → 进入训练集（SFT 补充 / 偏好对 / RLVR 题库）
  → 新模型上线 → 新的日志（飞轮转起来）
```

飞轮的关键组件：

1. **日志管线**：请求级日志（注意隐私分级）的采集、脱敏、存储；日志即资产——Kimi/各家报告中的线上数据回用都依赖这条管线。
2. **Badcase 挖掘**：负反馈信号（点踩、重试、会话中断）聚类归因，定向补充训练数据——比随机采样高效一个量级。
3. **难度采样**：按模型当前能力筛选"刚好做错"的样本（与 RLVR 的难度筛题同理）。
4. **反馈闭环的指标**：飞轮每转一圈，badcase 率/用户满意度应有可测量改善——没有度量就没有飞轮，只有数据堆积。

## 2. 数据版本管理与血缘

数据集像代码一样需要工程化管理：

| 工具 | 定位 | 仓库 |
|------|------|------|
| **DVC** | 数据版本控制（Git 语义管理数据文件） | github.com/iterative/dvc |
| **lakeFS** | 数据湖的 Git 式分支/合并/回滚 | github.com/treeverse/lakeFS |
| **HuggingFace Datasets** | 数据集托管与版本标签（数据集社区事实标准） | huggingface.co/datasets |
| **WebDataset / Lance / Parquet** | 存储格式层面：训练 IO 效率与列式查询 | 各格式文档 |

核心原则：

- **可复现**：任何一次训练必须能回答"用的是数据的哪个版本、经过哪些处理"——训练配置里引用数据集版本号（而非路径），处理管线代码与数据版本绑定。
- **血缘追踪（lineage）**：每条样本能回溯到原始来源与处理历史——合规审计与 badcase 倒查都依赖它。
- **不可变原则**：已用于训练的数据集版本永不修改，修改即新版本。

## 3. 数据合规与治理

1. **版权**：Common Crawl 衍生品的版权灰区（网页可爬取 ≠ 可商用训练）；FineWeb/DCLM 的许可证要逐条读；代码数据的 license 传染性（GPL 系列）。
2. **隐私**：PII 清洗（16.2 节）是底线；GDPR 的"被遗忘权"要求 opt-out 能传导到已训练数据的后续版本。
3. **安全对齐数据**：有害内容过滤（CSAM 等非法内容的检测与清除，这是法律红线）与对齐数据的平衡。
4. **数据出境与地域**：跨国业务的训练数据合规边界（国内业务的数据合规要求更严格）。

**工程实现**：合规不是法务文档而是管线组件——license 标注字段、opt-out 黑名单的过滤器、PII 检测的处理算子，全部编码进数据处理管线并可审计。

## 4. 数据成本核算（给管理层看的账）

- 采集成本（爬虫/授权采购）、处理成本（Spark/GPU 过滤的算力账单）、标注成本（人工标注每条 0.1-10 元不等）、存储成本、合规成本。
- 关键比率：**数据处理成本 / 训练算力成本**——行业经验约 5-15%，但数据质量对模型能力的影响远超这个比例，这是向管理层要数据预算的核心论据。
- 合成数据的成本结构变化：标注费 → 生成模型的推理费（这正是 15.6 节成本模型的应用场景）。

## 5. 数据团队的组织形态（参考）

大模型公司里数据团队的常见分工：

- **数据平台**：管线基建（采集/处理/存储/版本）——infra 属性最强。
- **数据质量**：过滤策略、质量评估、消融实验——研究属性最强。
- **数据生产**：合成数据、标注管理、领域数据（代码/数学/多语专项）。
- **数据治理**：合规、安全、血缘。
小团队里这些角色合一，但能力项都要有——这正是 Data Infra 岗位 JD 普遍"什么都要会"的原因。

## 7. 面试视角

- **Q：什么是数据飞轮？** A：线上日志 → badcase/高价值样本挖掘 → 标注增强 → 回灌训练 → 模型上线产生新日志的闭环；核心是每圈有可测量的改善，否则只是数据堆积。
- **Q：怎么保证训练数据可复现？** A：训练配置引用数据集版本号而非路径、处理管线代码与数据版本绑定、数据集版本不可变（改即新版）。
- **Q：数据合规在工程上怎么落地？** A：把合规编码进管线——license 字段、opt-out 过滤器、PII 检测算子、全链路血缘可审计；合规是组件不是文档。
