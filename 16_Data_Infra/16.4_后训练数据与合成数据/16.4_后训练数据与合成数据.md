# 16.4 后训练数据与合成数据

> 学习目标：掌握后训练数据的三大形态（SFT/偏好/RLVR）、合成数据的方法论与陷阱（蒸馏/self-instruct/persona/拒绝采样/模型坍缩）、以及 agentic 轨迹数据这一最新形态。

## 1. 后训练数据的三大形态

| 形态 | 数据长什么样 | 用在哪 | 关键质量指标 |
|------|------------|--------|------------|
| **SFT 指令数据** | (指令, 回答) 对 | 监督微调 | 回答质量、指令多样性、格式一致 |
| **偏好数据** | (指令, 优选回答, 劣选回答) | DPO/奖励模型训练 | 偏好标注一致性、区分度 |
| **RLVR 数据** | (问题, 可验证答案) | GRPO/PPO 的 rollout 环境 | 答案可验证性、难度分布 |

三者的量级差异巨大：预训练 token 以 T 计，SFT 数据以百万条计，偏好数据以十万条计——**后训练数据的单位价值极高，因此"每条的质量"远比预训练苛刻**。

## 2. SFT 数据的工程要点

1. **质量 >> 数量**：LIMA（"Less Is More for Alignment"，1000 条精选数据即可对齐）与 Alpaca（52k 蒸馏数据）的两极实验证明——万级精选数据通常优于百万级噪声数据。
2. **多样性覆盖**：指令数据要覆盖任务类型分布（写作/问答/代码/数学/角色扮演...），用标签体系做配额管理（与预训练配比同样的思想，只是粒度更细）。
3. **格式与模板一致**：聊天模板（chat template）的错误是 SFT 最常见事故源——训练与推理模板不一致会直接废掉模型。
4. **长度分布**：目标场景需要长回答就必须有长回答数据（短答案数据训不出长报告能力）。

## 3. 偏好数据与奖励模型数据

- **人工标注 vs AI 标注**：人工偏好贵但准；RLAIF（用强模型标偏好）便宜可规模化但引入标注模型的偏好偏差——主流是混合（AI 预标 + 人工抽检校准）。
- **偏好对的设计**：chosen/rejected 的区分度要清晰（同一 prompt 的两个候选差异过小则噪声大）； rejected 一侧常见来源是弱模型输出或规则破坏版本。
- **公开数据集**：UltraFeedback 等是常见起点；生产级偏好数据多为自建（业务场景的偏好分布无法外购）。

## 4. RLVR 数据（可验证奖励）

RLVR 是 2025 年后训练的主线（DeepSeek-R1 路线），其数据工程有独特要求：

1. **可验证性**：答案必须能被程序化判定（数学的标准答案、代码的测试用例）——数据生产的核心是"造得出题 + 造得出判题器"。
2. **难度分布**：太简单没有学习信号（通过率 100%），太难也没有（通过率 0%）——**有效样本是通过率中间的区间**；实践上按模型的当前通过率动态筛题（在线课程学习）。
3. **防泄漏**：题目不能与公开 benchmark 重叠（否则 RL 直接学 benchmark）。
4. **代码类数据**：每题配测试用例 + 沙箱判题——这直接复用 15.6 节的沙箱基础设施。

## 5. 合成数据（Synthetic Data）方法论

数据墙压力下，合成数据从"补充"变成"主力"之一。主要生产方式：

1. **蒸馏（Distillation）**：用强模型生成回答训练弱模型——最简单也最普遍；风险是把弱模型训成"强模型的复读机"，多样性丧失。
2. **Self-Instruct / Magpie 类**：让模型自己生成指令（Magpie 利用聊天模板的前缀让模型"自言自语"出题），再自答或互答——低成本扩充指令多样性。
3. **Persona 驱动**：用海量 persona 描述（"一个教初中物理的乡村教师...") 驱动模型生成多样化数据——解决合成数据多样性坍缩的主流方案。
4. **拒绝采样（Rejection Sampling）**：模型对同一问题采样多个回答，用验证器/奖励模型筛选最优的留作 SFT 数据——RFT/STaR 路线，数学与代码的主力方法。
5. **Agentic 轨迹数据**（最新形态）：让 agent 在真实工具环境中跑任务，筛选成功轨迹作为训练数据（Kimi K2 报告中的大规模 agentic 数据合成流水线）——这是 15 章 Agent 与 16 章的交汇点。

**模型坍缩（Model Collapse）警示**：反复用模型输出训练模型会导致分布尾部消失、能力退化（Nature 2024 封面话题）。工程对策：合成数据与真实数据混合、控制合成比例、多样性显式监控（n-gram 分布/嵌入覆盖度）。

## 6. 合成数据的质量管线（生产级）

```text
种子设计（persona/任务分布）→ 生成（强模型批量产出）
  → 过滤（规则 + 验证器 + 去重）→ 多样性检查（分布覆盖）
  → 小规模消融验证（训小模型看效果）→ 入库存版本
```

关键原则：**合成数据的每一步过滤都要有"如果不过滤会怎样"的对照**——合成管线的成本很低，随意堆砌未经验证的合成数据是常见事故。

## 9. 面试视角

- **Q：合成数据的风险与对策？** A：模型坍缩（分布尾部消失）与自我强化偏差；对策——与真实数据混合、多样性显式监控、persona 驱动保多样、每批合成数据过小模型消融验证。
- **Q：RLVR 数据的核心要求？** A：可程序化判分（答案验证器）、难度落在模型通过率中间区、与评测集零泄漏。
- **Q：SFT 数据多少够？** A：质量优先——万级精选常优于百万级噪声（LIMA 实验）；关键是任务覆盖、模板一致与长度分布匹配目标场景。
