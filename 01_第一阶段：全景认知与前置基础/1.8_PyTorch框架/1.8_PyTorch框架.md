# 1.8 PyTorch 框架

## 课程概述

PyTorch 是 AI Infra 的主战场：训练用它，模型从它导出，自定义算子接入它。本节聚焦 Infra 工程师最常用的四个面：Tensor/autograd、Module 组织、checkpoint、性能调试。

---

## 1. Tensor 操作与自动微分

### 1.1 Tensor 要点

- `dtype`：float32 / float16 / bfloat16 / int8——显存与精度的一切权衡从 dtype 开始。
- `device`：cpu / cuda——`.to()` 搬运是同步点，频繁搬运是性能杀手。
- 视图 vs 拷贝：`view/reshape` 共享内存，`clone/contiguous` 产生拷贝。

### 1.2 autograd

```python
x = torch.randn(4, 4, requires_grad=True)
y = (x * x).sum()
y.backward()
print(x.grad)  # dy/dx = 2x
```

- 每个算子记录梯度函数，backward 沿计算图链式回传。
- 工程含义：计算图保存中间激活 → 训练显存大头；`torch.no_grad()` / `inference_mode` 推理时必须加。

## 2. Module / Parameter 与训练循环

```python
model = MyModel().cuda()
opt = torch.optim.AdamW(model.parameters(), lr=1e-4)
for x, y in loader:
    opt.zero_grad(set_to_none=True)
    loss = model(x).loss(y)
    loss.backward()
    opt.step()
```

- `model.parameters()` 收集全部 Parameter（注册在 Module 树上）。
- `zero_grad(set_to_none=True)`：释放梯度显存而非清零，省一次写。

## 3. 模型保存与加载

```python
torch.save(model.state_dict(), "model.pt")   # 推荐：只存权重
model.load_state_dict(torch.load("model.pt", map_location="cpu"))
```

- `state_dict`：{name: tensor}，跨设备加载用 `map_location`。
- checkpoint 完整训练状态：`model + optimizer + epoch + rng_state`（断点续训必需）。
- 分布式保存：FSDP/ZeRO 下需要合并分片（`full_state_dict` / sharded 格式）。

## 4. 基本调试

### 4.1 显存

```python
print(torch.cuda.memory_summary())
torch.cuda.max_memory_allocated()   # 峰值
torch.cuda.reset_peak_memory_stats()
```

用途：定位 OOM、验证内存池/量化收益。

### 4.2 profiler

```python
with torch.profiler.profile(activities=[torch.profiler.ProfilerActivity.CPU,
                                        torch.profiler.ProfilerActivity.CUDA]) as prof:
    model(x)
print(prof.key_averages().table(sort_by="cuda_time_total", row_limit=10))
```

用途：找出 top 耗时算子——一切性能优化的第一步。

## 本节小结

- dtype/device/视图是 Tensor 三大坑，也是显存与性能问题的常见根源。
- autograd 保存中间激活 → 训练显存 ≈ 参数+梯度+优化器+激活的直觉来源。
- state_dict + map_location 是模型迁移/部署导出的标准动作。
- `memory_summary` 和 `profiler` 是 Infra 工程师的听诊器，必须熟练。
