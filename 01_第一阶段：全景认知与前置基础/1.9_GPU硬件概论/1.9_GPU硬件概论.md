# 1.9 GPU 硬件概论

## 课程概述

不懂硬件的优化是玄学。本节讲清 GPU 与 CPU 的架构差异、SM 内部结构、存储层次、Memory Wall，以及主流 GPU 规格与互联拓扑——这些是后面所有性能优化的物理基础。

---

## 1. GPU vs CPU 架构差异

| 维度 | CPU | GPU |
|------|-----|-----|
| 设计目标 | 低延迟、复杂控制 | 高吞吐、简单并行 |
| 核心数 | 几个到几十个 | 数千个（CUDA Core） |
| 控制逻辑 | 复杂（分支预测、乱序） | 简单（SIMT 锁步） |
| 缓存占比 | 大 | 小 |
| 适用 | 串行/逻辑复杂任务 | 大规模数据并行 |

一句话：**CPU 是几个聪明的工人，GPU 是几千个听话的工人。**

## 2. SM 架构、CUDA Core、Tensor Core

```text
GPU = N × SM（Streaming Multiprocessor）
SM = 寄存器 + Shared Memory/L1 + CUDA Core（若干组）+ Tensor Core + 调度器
```

- **CUDA Core**：通用 FP32/INT 计算单元，按 warp（32 线程）调度执行。
- **Tensor Core**：专用矩阵乘单元（如 16×16×16 FP16 MMA），峰值算力比 CUDA Core 高一个数量级。
- SIMT：同一 warp 内线程执行同一指令，分支发散（divergence）会串行化。

## 3. 存储层次结构

| 层级 | 容量（A100） | 带宽 | 延迟 |
|------|-------------|------|------|
| 寄存器 | 256KB/SM | ~20+ TB/s | 1 cycle |
| Shared Memory/L1 | 192KB/SM | ~19 TB/s | ~30 cycles |
| L2 Cache | 40MB | ~5+ TB/s | ~200 cycles |
| HBM（显存） | 40/80GB | 1.5-2 TB/s | ~400+ cycles |
| 主机内存（DDR） | TB 级 | ~50 GB/s（PCIe） | ~微秒级 |

**优化第一性原理：让数据尽量停留在离计算近的地方。** GEMM tiling、kernel fusion、FlashAttention 都是在不同层级上做文章。

## 4. Memory Wall：为什么带宽先成为瓶颈

- 算力增长远快于带宽：A100 FP16 312 TFLOPS，HBM 带宽 1.5TB/s。
- 算术强度（arithmetic intensity）= FLOPs / 访存字节数。
- 当算术强度 < 算力/带宽比（A100 ≈ 200 FLOP/byte）时，程序是 **memory-bound**。
- LLM decode 每 token 读全部权重只算 2P FLOPs → 算术强度极低 → 典型 memory-bound。
- 结论：**衡量 kernel 先看 bound 类型，再决定优化方向（省访存 or 提算力利用率）。**

## 5. 主流 GPU 规格对比

| 规格 | A100 | H100 | H200 | Orin AGX |
|------|------|------|------|----------|
| 架构 | Ampere | Hopper | Hopper | Ampere |
| 显存 | 40/80GB HBM2e | 80GB HBM3 | 141GB HBM3e | 32/64GB（统一内存） |
| 带宽 | 1.6/2 TB/s | 3.35 TB/s | 4.8 TB/s | ~200 GB/s |
| FP16 算力 | 312 TFLOPS | 989 TFLOPS | 989 TFLOPS | ~170 TOPS(INT8) |
| FP8 | 无 | 有 | 有 | 无 |
| NVLink | 600 GB/s | 900 GB/s | 900 GB/s | - |
| 功耗 | 250-400W | 700W | 700W | 15-60W |

## 6. GPU 互联拓扑

| 互联 | 带宽 | 场景 |
|------|------|------|
| PCIe 4.0 x16 | 64 GB/s 双向 | 普通多卡、H2D/D2H |
| NVLink 3 (A100) | 600 GB/s | 节点内 8 卡全互联 |
| NVLink 4 (H100) | 900 GB/s | 节点内 8 卡 |
| NVSwitch | 全互联交换 | 节点内任意两卡直连 |
| InfiniBand HDR/NDR | 200/400 Gbps | 跨节点 |

**并行策略的物理约束**：TP 通信量大 → 必须在 NVLink 域内；PP 通信量小 → 可以跨机走 IB。这就是 3D 并行"TP 节点内、PP 跨节点"的硬件原因。

## 本节小结

- GPU = 高吞吐 SIMT 机器；warp 调度、Tensor Core、存储层次是性能三要素。
- 存储层次决定优化方向：寄存器 > shared > L2 > HBM > 主机，逐级慢一个数量级。
- Memory Wall：先看算术强度定 bound 类型，memory-bound 就省访存，compute-bound 就上 Tensor Core。
- 互联拓扑决定并行拓扑：NVLink 内做 TP，IB 上做 PP/DP。
