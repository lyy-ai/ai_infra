# 1.11 工程工具链

## 课程概述

工具是 Infra 工程师的第二双手。本节覆盖性能调试四件套（GDB/Perf/nsys/ncu）、Git 协作，以及主流 AI 芯片架构入门。

---

## 1. 性能调试工具

### 1.1 GDB

- 用途：C++ 段错误、推理引擎 crash、core dump 分析。
- 常用：`bt`（调用栈）、`info threads`、`watch`、attach 运行中进程。
- CUDA 场景：`cuda-gdb` 调试 kernel；`CUDA_LAUNCH_BLOCKING=1` 把异步错误变同步便于定位。

### 1.2 Perf

- 用途：CPU 侧热点（预处理、tokenizer、Python 瓶颈）。
- 常用：`perf top`、`perf record -g ./app && perf report`、火焰图（配合 FlameGraph）。

### 1.3 Nsight Systems（nsys）

- 用途：**系统级 timeline**：CPU/GPU 活动、kernel、memcpy、NCCL、stream 并发。
- 用法：`nsys profile -o rep python train.py` → GUI 或 `nsys stats`。
- 看什么：GPU 空隙（idle gap）、H2D/D2H 占比、kernel 密集度、通信耗时。

### 1.4 Nsight Compute（ncu）

- 用途：**单 kernel 深度分析**。
- 用法：`ncu --set full -k <kernel_name> python app.py`。
- 看什么：occupancy、memory throughput、bank conflict、Tensor Core 利用率。

### 1.5 工具选择流程

```text
整体慢？ → nsys 看 timeline（找空隙/通信/热点 kernel）
单个 kernel 慢？ → ncu 看细节（occupancy/带宽/conflict）
CPU 慢？ → perf / py-spy 看热点
崩了？ → gdb + CUDA_LAUNCH_BLOCKING
```

## 2. Git 与团队协作

| 场景 | 命令/实践 |
|------|-----------|
| 分支模型 | feature 分支 + PR review + squash merge |
| 常用操作 | rebase 保持线性、cherry-pick、stash、bisect 定位回归 |
| 协作规范 | commit message 规范、PR 关联 issue、CI 通过才能合入 |
| 大文件 | 模型/数据用 Git LFS 或对象存储，不进仓库 |

`git bisect` 在性能回归定位中尤其重要（见第九章）。

## 3. 主流 AI 芯片架构入门

| 芯片 | 架构要点 | 软件栈 | 典型场景 |
|------|----------|--------|----------|
| A100 | 108 SM、HBM2e、NVLink3 | CUDA/TensorRT | 训练+推理 |
| Orin | Ampere 架构 + 统一内存 + 低功耗 | JetPack/TensorRT | 车端/边缘 |
| P1X | 自研推理芯片（示例） | 自研 runtime | 数据中心推理 |
| Ascend 800/910B | 达芬奇架构、AICore | CANN/AscendCL/TBE | 国产化训练推理 |
| PPU | 自研架构（示例） | 自研编译器+算子库 | 特定业务加速 |

### 适配共性

- 模型 → 中间表示（ONNX/IR）→ 平台编译器 → 可执行产物。
- 算子对齐：接口语义对齐 PyTorch，数值在容差内一致。
- 性能调优路径相通：找 bound → 算子优化/融合 → 内存/调度优化。

## 本节小结

- 调试决策树：nsys 看全局、ncu 看 kernel、perf 看 CPU、gdb 看崩溃。
- Git 是协作基础，bisect 是回归定位神器。
- 芯片虽多，适配方法论相通：IR → 编译 → 算子对齐 → 一致性验证 → 调优。
