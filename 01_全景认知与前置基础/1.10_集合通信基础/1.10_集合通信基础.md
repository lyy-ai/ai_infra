# 1.10 集合通信基础

## 课程概述

分布式训练/推理的本质是"计算 + 通信"。集合通信原语与算法是理解 DDP、ZeRO、TP 通信开销的钥匙。本节讲清通信原语、Ring/Tree AllReduce、NCCL、以及单机 NVLink 与多机 IB 的带宽差异。

---

## 1. 通信原语

| 原语 | 语义 | 典型用途 |
|------|------|----------|
| Broadcast | 1 → N 广播 | 参数初始化同步 |
| Reduce | N → 1 规约 | 老版梯度同步 |
| **AllReduce** | N → N 全部得到规约结果 | DDP 梯度平均 |
| **AllGather** | 各自片段 → 全部得到完整数据 | ZeRO-3/FSDP 参数收集、TP 输出拼接 |
| **ReduceScatter** | 规约 + 结果分片 | ZeRO-2/3 梯度分片 |
| AllToAll | 两两交换 | MoE 专家路由、序列并行 |

记忆：**AllReduce = ReduceScatter + AllGather**（这也是 Ring AllReduce 的实现方式）。

## 2. 通信算法

### 2.1 Ring AllReduce

```text
N 个 rank 排成环，数据切成 N 块
阶段1 Scatter-Reduce（N-1 步）：每步传递一块，逐步规约
阶段2 AllGather（N-1 步）：每步传递已完成的块，逐步收齐
```

- 每 rank 通信量：`2·(N-1)/N·S ≈ 2S`（S 为总数据量）——与 rank 数无关！
- 优点：带宽最优；缺点：延迟随 N 线性增长（2(N-1) 步）。
- 适用：**大数据量**（梯度同步），带宽 dominated。

### 2.2 Tree AllReduce（Recursive Doubling / Halving）

- log₂N 步完成，延迟低；但小 rank 数时带宽利用率不如 Ring。
- 适用：**小数据量 / 延迟敏感**（如 barrier、小张量同步）。

### 2.3 选择规律

| 场景 | 算法 |
|------|------|
| 大梯度同步 | Ring |
| 小消息/控制信息 | Tree |
| NVLink 全互联 | 也可直接 P2P 多次 |

NCCL 内部按消息大小与拓扑自动选择。

## 3. NCCL

- NVIDIA Collective Communications Library：GPU 集合通信的事实标准。
- 特点：拓扑感知（自动发现 NVLink/PCIe/IB）、多流并发、与 CUDA stream 集成。
- PyTorch DDP/FSDP 的 `backend="nccl"` 就是它。
- 调试：`NCCL_DEBUG=INFO` 看拓扑与通道；`nccl-tests`（all_reduce_perf）测带宽。

## 4. 单机 NVLink vs 多机 InfiniBand

| 维度 | 节点内 NVLink (A100) | 跨节点 IB HDR |
|------|----------------------|----------------|
| 带宽 | 600 GB/s（每 GPU） | 25 GB/s（200Gbps） |
| 延迟 | ~微秒 | ~几微秒 |
| 拓扑 | NVSwitch 全互联 | 交换机组网 |
| 适用通信 | TP（每层 AllReduce/AllGather） | DP（每步一次梯度 AllReduce）、PP（stage 间点对点） |

**量化感受**：8 卡 TP 每层通信几 MB×高频 → 必须 NVLink；DP 梯度同步每步一次几百 MB → IB 可承受但已是瓶颈之一（这就是梯度 bucket 化 + overlap 的原因）。

## 本节小结

- 三个核心原语：AllReduce（DDP）、AllGather（FSDP/TP）、ReduceScatter（ZeRO）；AllReduce = RS + AG。
- Ring 带宽最优（≈2S 与 N 无关），Tree 延迟最优（log N）。
- NCCL 是 GPU 集合通信标准，拓扑感知 + 自动算法选择。
- NVLink（600GB/s）与 IB（25GB/s）差一个数量级 → 决定了"TP 节点内、DP/PP 跨节点"的部署铁律。
