# 1.1 什么是 AI Infra

## 课程概述

AI Infra（AI Infrastructure）是连接 AI 算法与硬件算力的中间层：算法团队关心模型效果，芯片团队关心硬件性能，AI Infra 团队负责让模型在硬件上**跑得起来、跑得快、跑得稳、跑得便宜**。

学完本节后，你应该能够：

- 说清楚 AI Infra 的定义与技术栈全貌。
- 区分训练 / 推理 / 编译 / Runtime / 多芯片适配五个方向的职责。
- 理解"计算、通信、显存"不可能三角这个核心矛盾。

---

## 1. AI Infra 的定义与技术栈全貌

### 1.1 分层视角

```text
应用层：自动驾驶感知 / 推荐系统 / LLM 对话
    ↓
框架层：PyTorch / TensorFlow / JAX
    ↓
══════ AI Infra ══════
训练 Infra：分布式并行、通信优化、容错
推理 Infra：推理引擎、Serving、量化部署
编译 Infra：图优化、算子生成、多后端
Runtime Infra：内存管理、调度、Stream/Graph
多芯片适配：算子库、一致性、Benchmark
    ↓
硬件层：GPU / NPU / 自研芯片
```

### 1.2 技术栈关键词

| 方向 | 关键词 |
|------|--------|
| 训练 | DDP、FSDP、ZeRO、Megatron、NCCL、MFU |
| 推理 | TensorRT、vLLM、PagedAttention、Continuous Batching、KV Cache |
| 编译 | TVM、Relay/Relax、MLIR、XLA、图优化、Codegen |
| Runtime | 内存池、CUDA Graph、Stream、动态调度 |
| 芯片适配 | CUDA、CANN、TBE、算子库、一致性验证、Benchmark |

---

## 2. 五大方向职责对比

| 方向 | 核心问题 | 代表产出 |
|------|----------|----------|
| 训练 Infra | 大模型怎么在千卡上训得动、训得快 | 分布式训练框架、并行方案 |
| 推理 Infra | 模型怎么低延迟、高吞吐地服务 | 推理引擎、Serving 系统 |
| 编译 Infra | 模型怎么自动变成高效 kernel | 编译器、算子自动生成 |
| Runtime Infra | 推理过程怎么省内存、少开销 | Runtime、内存池、调度器 |
| 多芯片适配 | 同一模型怎么在 N 种芯片上跑 | 算子库、适配层、Benchmark |

---

## 3. 核心矛盾：计算、通信、显存的不可能三角

### 3.1 三个维度

```text
        计算 (Compute)
       /            \
      /              \
通信 (Comm) ────── 显存 (Memory)
```

- **计算**：FLOPS，决定理论速度上限。
- **通信**：带宽，决定多卡协作效率。
- **显存**：容量与带宽，决定能装多大模型、激活。

### 3.2 典型权衡

| 优化手段 | 牺牲 | 换取 |
|----------|------|------|
| ZeRO 分片 | 更多通信 | 更少显存 |
| Activation Checkpointing | 更多计算（重算） | 更少显存 |
| 梯度累积 | 更慢迭代（计算串行） | 更小激活显存 |
| TP 张量并行 | 通信量大增 | 单卡显存下降 |
| INT8 量化 | 精度 | 显存减半 + 计算加速 |
| CUDA Graph | 灵活性（shape 固定） | launch 开销消除 |

### 3.3 核心思维

> **AI Infra 的每一个技术决策，都是在三角之间做取舍。面试时回答任何优化问题，先想清楚：牺牲了什么，换取了什么。**

## 本节小结

- AI Infra = 算法与硬件之间的工程层，五大方向各有分工又相互配合。
- 技术栈跨度大：从 CUDA kernel 到分布式系统，从编译器到线上 Serving。
- 不可能三角是理解一切优化的总纲：没有免费的午餐，只有取舍。
