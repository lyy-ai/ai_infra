## MoE 方向

### Q1：DeepSeek-V3 的架构与系统创新点一口气讲完。

- 难度：深入（必考级）
- 一句话：架构上 MLA + 细粒度 MoE（256 路由专家+1 共享、top-8）+ MTP 训练目标；系统上 FP8 混合精度训练 + DualPipe 通信重叠 + aux-loss-free 负载均衡，2.788M H800 小时训完 671B。
- 展开：按"计算（FP8）/通信（DualPipe）/显存（MLA+重计算）/稳定性（零回滚）"四个维度组织回答；每个点给数字（见 12.2 论文解读）。
- 追问：MTP（multi-token prediction）对推理有什么用？——训练目标产出的 MTP 头可直接用作投机解码的 draft，一石二鸟。

### Q2：MoE 推理为什么 decode 阶段难做？

- 难度：进阶
- 一句话：decode 时 batch 内 token 少，256 个专家中很多收不到 token → 专家负载严重不均，GPU 利用率被最忙的专家拖死。
- 展开：解法——冗余专家（热门专家多副本）、EPLB 负载均衡器、动态路由 bias；DeepEP 的 low-latency 模式（纯 RDMA + SM 隔离重叠）专为 decode 设计（见 5.11 章）。
- 追问：prefill 阶段也有这个问题吗？——轻得多，prefill token 量大，统计上负载天然更均匀。

### Q3：EP（专家并行）和 TP 的关系与组合策略？

- 难度：进阶
- 一句话：EP 切专家（token 在专家间路由，all-to-all 通信），TP 切单个算子内部（每层 allreduce）；大 MoE 训练/推常见"小 TP + 大 EP"或"DP attention + EP MoE"。
- 展开：TP 通信频率太高不宜跨节点；EP 通信在层边界、量与路由 token 数成正比；MLA 类 attention 不适合 TP（latent 不可切）所以用 DP attention 复制。
- 追问：EP=64 时通信在哪一层网络跑？——超出单机 8 卡，必须跨节点 RDMA，这就是 DeepEP 要解决的问题（见 6.9 章估算脚本）。

### Q4：aux-loss-free 负载均衡怎么做？

- 难度：进阶
- 一句话：不在 loss 里加均衡项，而是给每个专家的路由打分加一个动态偏置 bias——负载高的专家 bias 调低、低的调高，路由本身保持"按能力选专家"。
- 展开：aux loss 的问题是与主任务目标冲突（强迫路由选不该选的专家）；bias 只影响选择不影响梯度方向；DeepSeek-V3 验证了其效果（见 6.9 章与 12.2 论文）。
- 追问：bias 更新频率太快会怎样？——路由震荡、训练不稳定；需要慢于主参数的时间尺度更新。

## FP8 / 低精度训练方向

### Q5：FP8 训练为什么 2024 年才跑通大规模？卡点在哪？

- 难度：进阶
- 一句话：卡点是数值精度——累加器位宽不足（H100 FP8 MMA 累加约 14 位）、激活 outlier 撑爆 per-tensor scale、长训中误差累积；DeepSeek-V3 用细粒度 scaling + 定期高精度累加 + 敏感组件回退解决。
- 展开：FP8-LM（2310.18313）先探路、COAT 补显存侧、DeepSeek-V3 全链路验证；2025 后 MXFP8/NVFP4 配方公开（见 12.5 论文）。
- 追问：FP8 训练相比 BF16 的实际收益？——GEMM 算力翻倍，但端到端加速受非 GEMM 部分稀释，叠加显存与通信压缩后整体成本显著下降。

### Q6：FP4 时代来了吗？

- 难度：进阶（2025-2026 热点）
- 一句话：硬件已到（Blackwell FP4 Tensor Core），方法正在成熟——NVFP4 已验证 12B/10T token 预训练，均值偏置的发现（2603.10444）解决了稳定性主因，FP4 注意力 kernel（SageAttention3/FA4 路线）已可用。
- 展开：microscaling 格式（32 元素共享 E8M0 scale）是 FP4 可用的基础；目前推理侧成熟度高于训练侧。
- 追问：FP4 和 FP8 的关系类似历史上哪次迁移？——类似 FP16→INT8：先推理后训练，先小模型验证后大规模。

## RL 后训练系统方向

### Q7：画一个 RLHF/GRPO 训练系统的完整数据流。

- 难度：进阶（必考级）
- 一句话：actor rollout（vLLM/SGLang 生成）→ reward/规则打分 → advantage 计算 → actor 训练（FSDP/Megatron）→ 权重 resharding 同步回推理引擎，循环。
- 展开：PPO 需四个模型（actor/critic/ref/reward），GRPO 去 critic 用组内相对优势；每轮迭代的耗时大头通常在 rollout（50-80%）；见 6.11 章 rlhf_pipeline_sim.py。
- 追问：GRPO 为什么省？——去掉 critic 的训练负载与显存，且组内采样让 prefix 复用率高（同 prompt 多个样本共享前缀 KV）。

### Q8：权重同步（train → inference）为什么这么贵？怎么优化？

- 难度：深入
- 一句话：训练侧的权重是分片的（FSDP flatten / Megatron TP 切分），推理侧布局不同，每轮要 gather + reshape + 广播，大模型一次同步可达数十秒级。
- 展开：优化——分桶流水（同步与训练/rollout 重叠）、GPU-GPU 直传绕过 CPU、只同步变化的参数（LoRA 场景天然便宜）；verl 的 3D-HybridEngine 专门解决 resharding（见 12.6 论文）。
- 追问：colocate（训推同卡）的代价？——省机器但要处理训练/推理的显存切换与峰值，工程复杂度高。

### Q9：rollout 长尾问题与解法？

- 难度：进阶
- 一句话：同一批内 response 长度差异大，同步系统里最慢的样本决定一轮耗时——推理模型长思维链使长尾更严重。
- 展开：解法——动态批处理（边完成边补位）、partial rollout（超长样本截断挂起下轮续跑）、全异步架构（AReaL：rollout 与训练彻底解耦 + staleness 控制，吞吐 2.77 倍）。
- 追问：全异步的代价？——数据陈旧（staleness）：训练样本来自旧版本模型，破坏 on-policy 假设，需要算法侧修正（staleness-enhanced PPO）。

### Q10：主流 RL 框架的格局？

- 难度：基础
- 一句话：verl（字节，混合控制器 + 双后端，社区最活跃）、OpenRLHF（Ray+vLLM+DeepSpeed 拼装，上手快）、slime（SGLang 原生，MoE 友好）、NeMo-RL（Megatron 生态）、AReaL（全异步）、ROLL（agentic 导向）、TRL（教学轻量）。
- 展开：详见 13.3 章；选型看 rollout 引擎集成、训练后端、异步与 agentic 支持。
- 追问：agentic RL 对框架的新要求？——多轮环境交互（工具调用）、环境作为新资源池管理、轨迹级（而非样本级）的数据流。

### Q11：为什么推理优化能力在 post-training 时代更值钱？

- 难度：基础（观点题）
- 一句话：RL 训练中 rollout（纯推理负载）占迭代时间 50-80%，推理引擎的吞吐直接决定 RL 训练速度——推理优化从"serving 成本问题"升级为"模型能力迭代速度问题"。
- 展开：持续批处理、投机解码、FP8、prefix 复用在 rollout 场景全部适用且收益放大；这就是为什么 RL 框架深度绑定 vLLM/SGLang。
- 追问：rollout 和线上 serving 的需求差异？——rollout 吞吐优先、无在线 SLO、前缀重复率极高（同 prompt 组内采样），优化配比不同。

## 长上下文方向

### Q12：长上下文的三条技术路线对比？

- 难度：进阶
- 一句话：稀疏注意力（NSA/Quest，保结构减计算）、线性/混合注意力（Kimi Linear/MiniCPM-SALA，改架构换 O(L)）、KV 分层存储（Mooncake/LMCache，不改计算改存储）。
- 展开：对比维度——是否需重训、精度风险、TTFT/吞吐收益、实现复杂度（见 5.12 章对比表与 12.4 论文）；趋势是混合架构+系统手段组合。
- 追问：1M 上下文落地最大的单一瓶颈？——KV cache 显存（GQA 模型单请求可达数百 GB），架构没换之前系统手段（offload/CP）是主力。

### Q13：NSA 为什么强调 "hardware-aligned"？

- 难度：深入
- 一句话：稀疏注意力的理论稀疏率兑现不了真实加速——不规则 gather 打爆带宽；NSA 把选择/压缩都按连续块（对齐 tensor core 与显存事务）设计，让稀疏变成真提速。
- 展开：对比"推理时稀疏"（Quest 类），NSA 原生可训练所以训练成本同降且效果不降（见 12.4 论文）。
- 追问：稀疏注意力研究常见误区？——只报 FLOPs 降低不报墙钟时间；块大小不对齐硬件导致实测无加速。

### Q14：Ring Attention / Context Parallelism 的原理与适用边界？

- 难度：进阶
- 一句话：序列维切到 P 卡，ring 传递 K/V block，通信与计算重叠，支持百万级上下文训练/推理；效率取决于块大小是否能让通信被计算掩盖。
- 展开：因果注意力导致负载不均，需要 zigzag/双 ring 切分；短序列大卡数时通信暴露效率骤降（见 5.12 章 ring_attention_sim.py 的可扩展性表）。
- 追问：CP 和 TP 怎么选？——CP 按序列切（通信量正比于激活）、TP 按头/隐藏维切；超长序列场景 CP 更划算，常组合使用。

## 行业与生态方向

### Q15：你关注最近哪些 AI Infra 的进展？（开放题）

- 难度：基础（必考级，考察技术热情与信息渠道）
- 一句话答题框架：按"模型系统报告（DeepSeek-V3/Kimi K2/GLM-4.5）+ 引擎动态（vLLM/SGLang 新特性）+ 编排层（llm-d）+ 硬件代际（Blackwell/FP4）"四条线各举一个具体例子，并说明它改变了什么。
- 展开：本仓库 12 章（论文）与 13 章（社区）就是素材库；关键是讲出"所以呢"——对工程实践的影响。
- 追问：怎么判断一个新工作值不值得跟进？——是否被主流框架采纳、是否改变关键指标数量级、是否有高质量开源实现。

### Q16：PD 分离、前缀缓存、KV 分层这些技术在生产上怎么组合？（以 llm-d 为例）

- 难度：进阶（2025 后新题）
- 一句话：llm-d 把它们产品化为 K8s 原生编排层——智能路由（前缀感知+预测延迟）决定请求去哪、PD 分离决定实例角色、分层 KV 决定数据放哪、SLO 感知扩缩容决定实例多少。
- 展开：官方数据——前缀路由吞吐 3 倍、PD 分离最高 +70%、分层 KV offload 250 并发下 13.9 倍（见 13.1 章 llm-d 节）；组合的收益来自"调度跟着数据走"。
- 追问：llm-d 和 vLLM 的关系？——编排层与模型服务器的关系，不是竞品（llm-d 调用 vLLM/SGLang 执行）。

### Q17：MoE 模型的总参数和激活参数，哪个决定推理成本？

- 难度：基础（陷阱题）
- 一句话：都决定，但维度不同——总参数决定显存（装不装得下、要多少卡），激活参数决定每 token 计算量；decode 带宽瓶颈下两者共同决定速度。
- 展开：671B/37B 的模型，显存按 671B 算、FLOPs 按 37B 算；"省计算不省显存"是 MoE 的核心 tradeoff（见 OLMoE 解读）。
- 追问：MoE 推理为什么显存是第一瓶颈？——所有专家都必须常驻显存，token 路由到谁不能预测（除非离线蒸馏出静态路由）。

### Q18：DeepEP 解决什么问题？

- 难度：进阶
- 一句话：MoE 的 all-to-all 通信库——normal 模式（高吞吐，prefill 用）与 low-latency 模式（纯 RDMA、与计算 SM 隔离重叠，decode 用），是 DeepSeek 大 EP 部署的开源底座。
- 展开：all-to-all 是 EP 的命门（6.9 章）；DeepEP 的关键设计是通信 kernel 占用独立 SM 与计算并行，避免抢计算资源。
- 追问：为什么不用 NCCL 的 all-to-all？——NCCL 通用原语不感知 MoE 语义（变长、per-expert 路由），且无法做到与 SM 计算的细粒度重叠。

### Q19：MuonClip（Kimi K2）对训练稳定性的启示？

- 难度：深入
- 一句话：训练不稳定（loss spike）不一定靠容错系统兜底——优化器设计（Muon + QK-clip 抑制 logit 爆炸）可以源头消除一整类故障，K2 实现 15.5T token 零 spike。
- 展开：infra 视角的稳定性分两层——系统层（容错/恢复，6.10 章）与算法层（不发散）；最好的容错是不需要恢复。
- 追问：QK-clip 大概做什么？——裁剪 attention 中 Q/K 投影的输出幅度，防止注意力 logit 爆炸（logit 爆炸是 Muon 类优化器长训后期的已知风险）。

### Q20：Intellect-2 证明了什么？

- 难度：进阶（新方向）
- 一句话：证明全球去中心化、无许可的异构算力可以完成 32B 级推理模型的 RL 训练——关键是 PRIME-RL 异步框架 + TOPLOC 可验证 rollout（解决信任问题）。
- 展开：RL 的 rollout/训练天然解耦所以适配公网；预训练的高频梯度同步则不行；去中心化的核心创新是信任机制而非分布式算法（见 12.6 论文）。
- 追问：TOPLOC 解决什么？——验证不可信节点提交的 rollout 确实由指定模型生成，防止伪造数据毒化训练。

## 综合理解题

### Q21：用"计算/通信/显存三角"分析任意一个你熟悉的优化技术。

- 难度：进阶（考察思维框架）
- 答题模板：先说优化了什么（收益），再说牺牲了什么（代价），最后说什么场景下划算。示例：投机解码——用 draft 的额外计算换 decode 串行步数，大 batch 时不划算；量化——用精度余量换带宽，精度敏感任务不划算。
- 展开：这是本仓库的核心思维（README 核心思维节）；能现场套用到面试官给出的任何技术上。
- 追问：有没有"纯白赚"的优化？——少见；接近白赚的是消除 bug 级的浪费（如未对齐访存修复），真正的技术选型都有代价。

### Q22：一个模型的训练成本怎么估算？

- 难度：基础（手算题）
- 一句话：训练 FLOPs ≈ 6 × 参数量 × token 数；GPU 小时 = 总 FLOPs /（卡峰值 × MFU）；再乘卡时单价。
- 展开：例——70B 模型 2T token：6×70e9×2e12=8.4e23 FLOPs；H100 按 989 TFLOPS × MFU 40% ≈ 4e14 FLOPS/卡，需约 2.1e9 秒 ≈ 58 万卡时。锚点：DeepSeek-V3 只花 2.788M H800 小时（671B MoE、激活 37B，MoE 按激活参数计 FLOPs）。
- 追问：MoE 模型按哪个参数量算？——激活参数（每 token 实际计算量），但注意 router/共享专家与通信开销。

### Q23：如果让你把一个 70B 模型的推理成本降一半，你的思路？

- 难度：进阶（开放题）
- 一句话：先量化瓶颈（decode 带宽 or prefill 算力 or 利用率），再对症——FP8/INT4 量化、提高 batch 利用率、prefix cache、投机解码、PD 分离调配比，按收益/风险排序逐个落地并 A/B 验证。
- 展开：答题要点是先测量再动手（9.2/9.3 章方法论）；给一个量级感：FP8 权重大约直接减半 decode 的权重读取，是最直接的一刀。
- 追问：怎么证明你降本了？——固定负载的 SLO 约束下对比每百万 token 的 GPU 小时（成本口径必须含 SLO 约束，否则是耍流氓）。

### Q24：Blackwell（NVL72）对系统设计的影响？

- 难度：进阶
- 一句话：scale-up 域从 8 卡扩到 72 卡全互联（NVLink 5，每 GPU 1.8TB/s）——大 EP/大 TP 可整个放进高速域，MoE 部署的通信约束被重写；FP4/FP8 Tensor Core 改变算力账。
- 展开：72 卡域内跑大 EP 推理（llm-d 的 wide-EP 已在 B200 上验证 50k tok/s 集群吞吐）；机柜级供电散热成为新约束；详见 2.10 章。
- 追问：NVL72 会淘汰跨节点通信优化吗？——不会，训练万卡仍要跨机柜；但推理单实例的规模上限被大幅推高。

### Q25：2026 年你眼中 AI Infra 最重要的三个趋势？

- 难度：开放（考察判断力）
- 参考答案框架（言之成理即可）：
  1. 编排层崛起——单引擎优化见顶，llm-d 类 K8s 原生编排成为新战场；
  2. 后训练算力反超预训练——RL/agentic 负载成为 infra 主要增量（rollout 优化、环境工程）；
  3. 低精度进入 FP4 时代——Blackwell 硬件 + NVFP4/均值偏置等方法成熟，训练侧开始迁移。
- 展开：每个趋势给一个具体证据（项目/论文/数据），避免空谈。
- 追问：哪个趋势和你投的岗位最相关？——把回答落到应聘团队的具体业务上。
