# 14.7 手写代码题

> 共 15 题。现场编程题（45-60 分钟）。每题给出：题面 → 考点 → 参考实现要点。平时练习建议配合本仓库对应章节的可运行代码动手写一遍。

---

### Q1：手写一个归一化的 Softmax kernel（CUDA 或伪代码）。

**考点**：数值稳定 + 归约 + warp 原语。

**要点**：
1. 先减行最大值（防 exp 溢出）。
2. block 内归约：warp 内 `__shfl_down_sync` 树形归约 → warp 首线程写 shared → 第一个 warp 再归约。
3. 两遍或 online（边遍历边维护 running max/sum）。
4. 边界：行宽非 32 倍数时的掩码。

**加分**：主动提 online softmax（一遍完成）与向量化加载。

### Q2：手写 Reduce（数组求和）并逐版优化。

**考点**：归约的经典演进路径（2.3 章）。

**要点**：naive 原子加 → shared memory 树形（注意 bank conflict 与 divergent 归约）→ warp shuffle → 多元素每线程（grid-stride loop + 向量化）→ 两级归约处理大数组。

**加分**：说出每一版消除了什么瓶颈（原子冲突 → 全局访存次数 → 同步开销）。

### Q3：实现 PagedAttention 的 block 分配器（伪代码/C++）。

**考点**：5.2 章核心数据结构。

**要点**：
1. 空闲 block 池（free list）；sequence → block table 映射。
2. `allocate(seq_len)`：按 token 数算 block 数（向上取整），不足时触发抢占/拒绝。
3. `append_token`：当前 block 满了才申请新 block（按需分配）。
4. `fork`（共享前缀）：block 引用计数 + copy-on-write。
5. `free`：引用计数归零回池。

**加分**：讨论 prefix cache 如何做（block 内容哈希 → 复用命中）。

### Q4：写一个 Continuous Batching 调度器的状态机。

**考点**：5.3 章。

**要点**：三个队列——waiting / running / swapped；每个迭代：从 running 移除完成的 → 尝试从 waiting 准入（KV 预算检查）→ 显存不足时按策略抢占（swap out 或 recompute）→ 组 batch 执行一步。

**加分**：讨论抢占策略的公平性（先到的先被抢占会饿死）与 SLO 感知准入。

### Q5：实现 Speculative Decoding 的验证逻辑（伪代码）。

**考点**：5.4 章 rejection sampling。

**要点**：
1. draft 生成 k 个 token 及其概率 q(x)。
2. target 一次前向得 p(x)（k+1 个位置的分布）。
3. 逐位接受：以 min(1, p/q) 概率接受；第一个被拒绝的位置从修正分布（norm(max(0, p-q))）采样一个 token，后续丢弃。
4. 全接受时从 p 的第 k+1 个分布额外采一个 bonus token。

**加分**：证明输出分布与 target 一致；讨论接受率与 k 的权衡。

### Q6：实现 Ring AllReduce（伪代码）。

**考点**：6.8 章。

**要点**：N 卡，数据切 N 块；阶段一 reduce-scatter：N-1 步，每步向右发一块收一块并累加；阶段二 all-gather：N-1 步，直接转发。每卡总通信量 2(N-1)/N × D。

**加分**：指出为什么带宽最优（每步每卡只传 D/N，链路满载）以及失败处理（环上一卡挂掉的重建）。

### Q7：手写一个 top-k / top-p 采样实现。

**考点**：采样逻辑 + 数值细节。

**要点**：top-k：排序/部分排序取前 k，softmax 重归一化后采样；top-p：按概率降序累积到 p 截断；温度在 softmax 前除 logits；注意 logits 里 -inf 的处理（mask）。

**加分**：讨论 GPU 上 top-k 的高效实现（不用全排序：radix select / 分块阈值）。

### Q8：实现 KV cache 的显存估算函数。

**考点**：5.1/5.11 章的手算能力代码化。

**要点**：`kv_bytes = 2 × n_layers × n_kv_heads × d_head × dtype_bytes × seq_len × batch`；支持 MHA/GQA/MLA 三种结构参数；输出随 seq_len 的扫描表。

**加分**：顺手实现"给定显存预算，反推最大并发 × 上下文"（本仓库 `kv_cache_compare.py` 就是这个）。

### Q9：写一个算子融合的前后对比 demo（如 bias+GeLU 融进 GEMM epilogue）。

**考点**：融合的动机（省中间显存读写）与验证方法。

**要点**：未融合版：GEMM 写回 → 读回加 bias → 再读回做 GeLU（三次访存）；融合版：epilogue 里一次完成。用 roofline 估算访存节省，nsys/计时验证。

**加分**：说出"融合的收益边界"——访存占比高的算子融合收益大，纯计算融合收益小。

### Q10：实现一个简单的 Roofline 分析器。

**考点**：2.8 章。

**要点**：输入 kernel 的 FLOPs 与访存字节数、硬件峰值算力与带宽 → 输出理论耗时上限、判断 memory/compute bound、离峰值的距离百分比。扩展：扫一组 batch size 画拐点曲线。

**加分**：主动讨论实测与理论的差距来源（kernel launch、访存未合并、occupancy）。

### Q11：手写（伪代码）一个 ZeRO-3/FSDP 的层前向流程。

**考点**：6.3 章分片机制。

**要点**：前向进入层前 `all-gather` 该层参数 → 计算 → 释放非本 rank 分片；反向同理再加梯度 `reduce-scatter`；预取下一层参数与当前层计算重叠。

**加分**：指出显存峰值出现在 all-gather 完成的瞬间，以及预取策略对显存的影响。

### Q12：实现 MoE 的路由与 dispatch/combine（伪代码）。

**考点**：6.9 章。

**要点**：router 打分 → top-k 选专家 → 按目标专家所在 rank 分组 → all-to-all dispatch → 各专家 FFN → all-to-all combine（加权求和回去）。讨论 capacity factor 的截断逻辑。

**加分**：指出负载不均监控指标（每专家 token 数的 max/mean）与 aux-loss-free bias 的更新伪代码。

### Q13：写一个异步 checkpoint 的流程伪代码。

**考点**：6.10 章。

**要点**：训练主线程把状态快照到 CPU  pinned 内存（快）→ 后台线程写盘/对象存储（慢但不阻塞）→ 写完成前禁止覆盖该快照 → 失败时回滚到最近完成的快照。

**加分**：讨论一致性（快照必须在 step 边界、优化器状态与参数同一版本）与双层存储（本地+远端防节点丢失）。

### Q14：实现一个按 SLO 的准入控制器（admission control）。

**考点**：5.8/12.1（Mooncake 早期拒绝）。

**要点**：新请求到达时预测其资源占用（输入长度 → prefill 时间、预估输出长度 → KV 占用）→ 检查接纳后现有请求的 TPOT 是否仍满足 SLO → 不满足则拒绝/排队/降级（限制 max_tokens）。

**加分**：讨论预测误差的处理（保守系数）与优先级租户。

### Q15：写一个简化版 W4A16 dequant GEMM kernel 的思路（伪代码）。

**考点**：7.5/7.6 章。

**要点**：权重按 INT4 打包存储（两个 4bit 挤一字节）→ kernel 加载时 unpack → 乘 scale（per-group）→ 转 FP16 进 Tensor Core；关键是 unpack+scale 融合进加载路径，避免中间写回。

**加分**：讨论 group size（64/128）对精度与额外开销的影响，以及为什么 decode 收益大、prefill 可能无收益。
