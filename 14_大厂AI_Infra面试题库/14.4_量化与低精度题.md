# 14.4 量化与低精度题

> 共 22 题。公司画像缩写：**LLM**=大模型公司、**芯片**=芯片厂、**车**=自动驾驶/具身智能、**云**=云厂商。对应仓库第 7 章与 12.5 论文。

---

### Q1：对称量化与非对称量化的区别？各用在哪？

- 画像：全部；难度：基础
- 一句话：对称量化零点为 0（q = round(x/s)），计算简单，适合分布以 0 为中心的权重；非对称量化带 zero_point，能更好覆盖偏移分布，适合激活（如 GeLU 后全正）。
- 展开：对称量化的硬件实现更简单（无零点修正项）；非对称在反量化时多一个零点减法；实践中权重常用对称、激活常用非对称。
- 追问：zero_point 在 GEMM 里带来什么额外计算？——交叉项修正（zero_point × 另一方数据的和），可以预计算合并。

### Q2：per-tensor 和 per-channel 量化的取舍？

- 画像：全部；难度：基础
- 一句话：per-tensor 一个张量共享 scale（省存储省计算但 outlier 通道拖累整体精度）；per-channel 每通道独立 scale（精度好但实现复杂）。
- 展开：权重的输出通道间分布差异大，per-channel 收益明显；激活的 outlier 问题更复杂（token 维 outlier）；FP8 时代进一步细化为 per-tile/per-block（见 Q13）。
- 追问：per-channel 量化对 GEMM kernel 有什么要求？——反量化要在累加后按通道乘 scale，epilogue 里融合即可，开销很小。

### Q3：PTQ 和 QAT 的区别？什么时候必须 QAT？

- 画像：全部；难度：基础
- 一句话：PTQ 训练后用小校准集直接量化（便宜快）；QAT 在训练中模拟量化（fake quant + STE 回传梯度），让模型适应量化噪声（贵但精度高）。
- 展开：INT8 权重量化 PTQ 通常够用；INT4 或激活也低比特时误差大，常需 QAT 或至少 QAT 风味的方法（如 QLoRA 微调恢复）。
- 追问：STE（straight-through estimator）是什么？——前向用量化值、反向把量化函数当作恒等映射传梯度，绕开 round 不可导的问题。

### Q4：为什么 LLM 的激活难量化？outlier 问题怎么处理？

- 画像：LLM、芯片；难度：进阶（高频）
- 一句话：LLM 激活存在幅度巨大的 outlier 通道（比中位数大两个量级），per-tensor 量化时它们撑爆 scale，其余值被压进很少的量化级。
- 展开：处理方案谱系——混合精度保留 outlier（LLM.int8()）、平滑迁移（SmoothQuant 把激活难度转给权重）、旋转变换（QuaRot/Hadamard 旋转把 outlier 能量打散）、细粒度粒度化（per-token/group）。
- 追问：SmoothQuant 的数学依据？——Y = (X·diag(s)⁻¹)·(diag(s)·W)，按通道把激活的动态范围除下来、乘进权重里，两者难度趋于均衡。

### Q5：GPTQ 和 AWQ 的核心区别？

- 画像：LLM；难度：进阶
- 一句话：GPTQ 用二阶信息（Hessian 近似）逐列量化并误差补偿；AWQ 用"保护重要权重"思想——按激活幅度挑出少量 salient 权重做 per-channel 缩放保护。
- 展开：GPTQ 需要校准数据前向传播算 Hessian，压缩精度好但流程重；AWQ 只需激活统计，流程轻；两者都是 weight-only INT4 的主流，vLLM/AutoGPTQ/AutoAWQ 均支持。
- 追问：weight-only 量化为什么 decode 提速明显？——decode 是 memory-bound，权重字节数减半带宽需求减半，dequant 的计算开销被掩盖。

### Q6：W4A16 的 kernel 开销在哪？为什么不总快？

- 画像：LLM、芯片；难度：进阶
- 一句话：权重 4bit 存储但要反量化到 16bit 再算——省的是显存带宽，多的是 dequant 指令；batch 大时（compute-bound）dequant 开销暴露，可能反而变慢。
- 展开：收益曲线随 batch 变化：小 batch（decode）提速明显，大 batch（prefill）可能无收益；kernel 实现要把 dequant 融合进加载路径（位 unpacking + scale）。
- 追问：怎么判断自己的场景用 W4A16 划不划算？——看 batch 和 roofline：decode 密集场景（小 batch）划算，吞吐优先的大 batch 场景考虑 W8A8/FP8。

### Q7：KV Cache 量化的特殊考虑？

- 画像：LLM；难度：进阶
- 一句话：KV cache 是长上下文显存大头，量化它省的是容量+带宽；但 K 有 outlier 通道（适合 per-channel）、V 相对平滑（per-token 即可），K/V 要用不同策略。
- 展开：KIVI 等工作的核心观察就是 K/V 分布特性不同；INT4 KV cache 通常可接受，配合 error 补偿更稳；注意量化后 attention kernel 要支持低比特读取。
- 追问：KV cache 量化对什么任务风险最大？——精确检索类（大海捞针），低比特噪声可能淹没个别关键 token。

### Q8：FP8 的两种格式 E4M3/E5M2 分别用在哪？

- 画像：LLM、芯片；难度：进阶（2024 后高频）
- 一句话：E4M3（4 位指数 3 位尾数，范围 ±448）精度高，用于前向的权重与激活；E5M2（5 位指数 2 位尾数，范围 ±57344）范围大，用于反向梯度。
- 展开：梯度分布长尾、动态范围需求大所以用 E5M2；FP8 无 inf（编码空间让给数值）；硬件上 H100 第四代 Tensor Core 起支持。
- 追问：FP8 相比 INT8 的优势？——浮点格式天然适配神经网络的钟形分布，通常免校准直接 cast 损失就小；INT8 需要校准流程（见 7.11 章 fp8_format_demo.py 的定量对比）。

### Q9：DeepSeek-V3 的 FP8 训练方案关键点？

- 画像：LLM；难度：深入
- 一句话：细粒度 scaling（激活按 1×128 tile、权重按 128×128 block）+ Tensor Core 累加精度补偿（FP8 累加器位宽不足，定期提升到 CUDA core 做 FP32 累加）+ 敏感组件回退高精度。
- 展开：per-tensor scaling 会被激活 outlier 撑爆，细粒度让每块的 scale 适配局部范围；master weight、embedding、输出头保 BF16；通信前也量化。
- 追问：为什么细粒度 scaling 有效？——FP8 相对精度与 scale 无关，问题只在 outlier 元素自身的误差；1×128 tile 让 outlier 成为块内 amax，不再连坐其他元素（见 7.11 章 fp8_scaling_granularity.py 实验）。

### Q10：FP4 训练的现状与关键障碍？

- 画像：LLM、芯片；难度：深入（2025-2026 新热点）
- 一句话：Blackwell 原生支持 FP4 Tensor Core；NVFP4（2509.25149）首次公开 12B/10T token 的 FP4 预训练对齐 FP8 基线；关键障碍是激活各向异性导致的动态范围爆炸。
- 展开：FP4 训练不稳定的主因被归结为秩一均值偏置（2603.10444），一次减均值操作即可大幅消除；microscaling（每 32 元素共享 E8M0 scale）是格式层基础。
- 追问：FP4 和 INT4 的区别？——FP4 有指数位（E2M1），动态范围远好于 INT4 的均匀网格，对长尾分布更鲁棒；配合 microscaling scale 才可用。

### Q11：SageAttention 系列解决了什么问题？

- 画像：LLM；难度：进阶
- 一句话：把量化从线性层扩展到 attention 本身——SageAttention2 用 per-thread 粒度 INT4 QK + FP8 PV（配 Q 平滑与两级累加）在 4090 上比 FA2 快约 3 倍；SageAttention3 用 Blackwell FP4 Tensor Core 达 1038 TOPS。
- 展开：attention 难量化因为 P 矩阵动态生成无法校准、Q/K 有 outlier；三件套方法论：细粒度 + 平滑 + 高精度累加（见 12.5 论文解读）。
- 追问：为什么注意力量化比线性层量化收益更大？——长上下文下 attention 是 O(L²) 的主瓶颈，而线性层已有成熟量化方案。

### Q12：量化对 TTFT 和 TPOT 的影响分别是什么？

- 画像：LLM、车；难度：进阶
- 一句话：weight-only 量化主要改善 TPOT（decode 带宽瓶颈）和部分 TTFT；W8A8/FP8 全量化同时改善两者（GEMM 计算也加速，但 prefill 受益受限于 kernel 与硬件支持）。
- 展开：decode 是 memory-bound，权重字节减半近似 TPOT 减半；prefill 是 compute-bound，weight-only 帮不上忙，需要 W8A8 类的计算侧加速。
- 追问：量化后 TTFT 没变化正常吗？——正常（weight-only 时 prefill 仍是 FP16 计算）；要改善 TTFT 需要计算侧量化或缩短输入（prefix cache）。

### Q13：量化粒度的演进路线？

- 画像：LLM、芯片；难度：进阶
- 一句话：per-tensor → per-channel → per-token/group → per-tile(1×128)/per-block(128×128) → microscaling（32 元素共享 scale），粒度越来越细以适配更低比特。
- 展开：粒度越细 scale 存储/计算开销越大，kernel 复杂度越高；FP8 时代细粒度成为标配（DeepSeek-V3），FP4 时代 microscaling 是硬件原生格式。
- 追问：粒度加细的代价？——scale 的存储与加载、kernel 里额外的缩放指令、校准/统计复杂度上升。

### Q14：量化误差的评估方法？

- 画像：全部；难度：基础
- 一句话：指标层——SNR/MSE（张量级）、perplexity（模型级）、下游任务分数（业务级）；三层都要看，张量误差小不代表任务不掉点。
- 展开：perplexity 对量化敏感适合快速筛查；下游任务（MMLU 等）才是最终标准；长文本/推理链任务对量化更敏感（误差沿生成累积）。
- 追问：为什么量化模型在短答案评测上不掉点、长链推理上掉？——生成是自回归的，每步误差会沿链条累积放大。

### Q15：QLoRA 是什么？和全量微调的显存差异？

- 画像：全部；难度：基础
- 一句话：基座权重量化到 4bit（NF4）冻结不训，只训练注入的 LoRA 低秩矩阵——显存从"全量微调 7B 需百 GB 级"降到单卡 24GB 可训。
- 展开：LoRA 的 A/B 低秩矩阵参数量极小（<1%），优化器状态只覆盖它们；反向传播时冻结权重只参与前向与梯度回传不更新。
- 追问：NF4 是什么？——为正态分布权重设计的信息论最优 4bit 数据类型，量化级按正态分位数放置。

### Q16：量化后模型怎么验证数值一致性（CI 里怎么卡）？

- 画像：云、芯片；难度：进阶
- 一句话：双层门禁——张量级（固定输入对比量化前后输出的 SNR/余弦相似度阈值）+ 模型级（固定评测集 perplexity/下游分数回归阈值）。
- 展开：跨平台（CPU/GPU/NPU）的对齐验证要定容差策略（见 8.4 章 cross_platform_consistency.py）；随机性控制（固定 seed、关闭 dropout）。
- 追问：量化模型的回归阈值怎么定？——先跑一轮基线统计自然波动范围（不同 seed），阈值设在波动范围之外。

### Q17：int8 GEMM 的 dequant 融合怎么做？

- 画像：芯片、LLM；难度：进阶
- 一句话：INT8×INT8 累加得 INT32，在 epilogue 里乘 scale（float）转回 FP16 输出，dequant 与 bias/activation 一起融进 GEMM 尾部。
- 展开：Tensor Core INT8 累加是 INT32（无精度损失）；per-channel 时 epilogue 按列乘 scale 向量；关键是避免中间结果写回显存再读回（全程寄存器/shared memory）。
- 追问：为什么 INT8 GEMM 速度可能翻倍？——INT8 Tensor Core 的峰值 OPS 是 FP16 的 2 倍（A100：624 vs 312 TOPS），且操作数带宽减半。

### Q18：端侧量化（INT8/INT4）和云端量化有什么不同侧重？

- 画像：车；难度：进阶
- 一句话：端侧优先确定性延迟与功耗——静态 shape、全整型推理（INT8 输入输出都不回浮点）、QAT 保精度；云端优先吞吐与 SLO——混合精度更常见。
- 展开：端侧 NPU/DSP 常只支持整型，要求全图量化（包括激活，校准质量关键）；云端 GPU FP8/混合精度灵活；端侧还有内存带宽与发热的硬约束。
- 追问：全整型推理对算子有什么要求？——所有算子（含 LayerNorm/Softmax）都要有整型近似实现，这是端侧部署的主要工程量。

### Q19：量化方案选型决策树怎么走？

- 画像：全部；难度：进阶
- 一句话：先看硬件（Hopper+ → FP8 优先；Ada/Ampere → INT8/INT4），再看场景（decode 密集 → weight-only W4A16；吞吐优先大 batch → W8A8/FP8；长上下文 → 加 KV cache 量化），最后看精度预算（不够就上 QAT/混合精度）。
- 展开：本仓库 7.9 章有完整决策树；7.11 章补充了 2024 后变化：有 Hopper 卡时 FP8 是默认起点。
- 追问：为什么"有 Hopper 卡时 FP8 优先"？——硬件原生加速（算力 2×FP16）+ 免校准 + 精度损失小，三个优势叠加。

### Q20：量化和投机解码/量化和其他优化手段能叠加吗？

- 画像：LLM；难度：进阶
- 一句话：大多正交可叠加（量化 + prefix cache + 投机解码），但要注意交互——量化后的 draft 模型接受率会变化，KV cache 量化会轻微影响投机验证的 logits 一致性。
- 展开：叠加时逐个开启做消融，确认每步收益；组合过多时 debug 难度上升，回归门禁要覆盖组合配置。
- 追问：组合优化时先上哪个？——按"收益/风险比"排序：通常先量化（收益大、风险低），再投机解码（收益看接受率），最后动 KV 量化（精度最敏感）。

### Q21：COAT 论文的核心贡献？

- 画像：LLM；难度：深入
- 一句话：FP8 训练不止压 GEMM——用 Dynamic Range Expansion 压优化器状态、混合粒度压激活，端到端训练显存比 BF16 降 1.54 倍且几乎无损（见 12.5 论文解读）。
- 展开：优化器状态与激活是训练显存大头，只压 GEMM 拿不到显存收益；COAT 补上了 DeepSeek-V3 路线"显存侧"的拼图。
- 追问：训练显存的大头是什么？——优化器状态（Adam m/v）+ 激活，参数反而不是最大的；这决定了压缩优先级。

### Q22：怎么向面试官讲清"量化不是免费的"？

- 画像：全部；难度：基础（表达题）
- 一句话：量化是用精度余量换显存/带宽/算力——讲清三个代价：精度损失（及恢复手段）、kernel 复杂度（dequant 开销、粒度管理）、工程约束（硬件要求、校准流程、回归测试）。
- 展开：好的回答要带数字口径："INT8 通常无损、W4A16 在 decode 提速约 1.5-1.8 倍但长链任务可能掉点、FP8 要 Hopper+"——有数字有边界条件。
- 追问：什么时候不该量化？——精度余量已被榨干的模型（已蒸馏/已剪枝过）、对数值一致性有硬性合规要求的场景、以及硬件根本不支持对应低比特路径时。
