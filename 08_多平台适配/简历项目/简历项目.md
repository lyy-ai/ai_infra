# 简历项目：多平台适配

## 项目一：LLM 端侧部署

### 一句话描述

将 7B 模型部署到 Jetson Orin，实现端侧流式推理，满足实时性要求。

### 简历写法

> **LLM 端侧部署（Jetson Orin）**
> - 将 7B 模型通过 INT4 量化 + KV Cache 压缩部署到 Jetson Orin，权值占用从 14GB 降至 4GB 以内。
> - 设计流式 decode pipeline，实现首 token 延迟 < 500ms、每 token 延迟 < 80ms。
> - 通过 TensorRT + JetPack SDK 优化 kernel，单卡功耗控制在 25W 以内。
> - 使用自研 benchmark 框架对比 llama.cpp / TensorRT-LLM / MLC-LLM，TensorRT-LLM 吞吐提升 35%。

### 可量化的指标

| 指标 | 数值 |
|------|------|
| 模型大小 | 7B |
| 量化精度 | INT4 / AWQ |
| 峰值显存 | < 6GB |
| TTFT | < 500ms |
| TBT | < 80ms |
| 功耗 | < 25W |

### 面试常问点

- 为什么 INT4 量化后端侧还能保持可用精度？
- 流式推理中如何降低 TBT？
- Jetson Orin 与 A100 在内存架构上的差异对部署有什么影响？

## 项目二：多平台算子性能基准工具

### 一句话描述

开发支持 A100 / Orin / Ascend 的算子性能测试框架，自动生成对比报告，测试效率提升 40%。

### 简历写法

> **多平台算子性能基准工具**
> - 设计跨平台 benchmark 框架，统一 A100（TensorRT）、Jetson Orin（TensorRT）、Ascend（CANN）的测试输入与指标口径。
> - 实现自动化 warmup、多轮采样、异常值过滤，输出 TTFT、TBT、吞吐、功耗、峰值内存等指标。
> - 自动生成 Markdown / CSV / 图表对比报告，支持历史 commit 趋势追踪。
> - 工具覆盖 30+ 核心算子与 5 个典型 LLM 模型，测试效率提升 40%，成为团队部署选型标准流程。

### 可量化的指标

| 指标 | 数值 |
|------|------|
| 支持平台 | A100 / Orin / Ascend |
| 算子覆盖 | 30+ |
| 模型覆盖 | 5 |
| 报告格式 | Markdown + CSV + 图表 |
| 效率提升 | 40% |

### 面试常问点

- 如何保证跨平台 benchmark 的公平性？
- 不同精度（FP16/INT8/INT4）下如何对比？
- benchmark 中如何排除 CPU、内存、散热等环境抖动？

## 项目三：自研芯片算子迁移与一致性验证

### 一句话描述

为自研 PPU/P1X 芯片完成核心算子迁移，并建立跨平台一致性验证体系。

### 简历写法

> **自研 AI 芯片算子迁移**
> - 负责 PPU/P1X 芯片上 MatMul、LayerNorm、Attention、RoPE 等 20+ 核心算子的接口对齐与 kernel 适配。
> - 基于 PyTorch 语义编写 CPU reference 实现，作为跨平台黄金标准。
> - 设计一致性验证框架，自动对比 NVIDIA / Ascend / PPU 三平台输出，使用 max abs diff、relative diff、cosine similarity 多维度判定。
- 修复 5 个精度偏差根因（浮点累加顺序、激活函数近似、量化缩放因子），模型端到端误差从 1e-2 降至 1e-4。

### 可量化的指标

| 指标 | 数值 |
|------|------|
| 适配算子 | 20+ |
| 验证平台 | NVIDIA / Ascend / PPU |
| 端到端误差 | 从 1e-2 降至 1e-4 |
| 修复根因 | 5 个 |

### 面试常问点

- 如何设计算子接口，使得上层框架改动最小？
- 跨平台一致性中，为什么不要求 bit-wise 一致？
- 如果某个算子在 PPU 上精度通过但性能差，怎么排查？
