# 8.4 自研芯片算子适配

## 课程概述

当公司业务规模足够大、或需要特定功耗/成本优势时，往往会自研 AI 芯片（例如代号 PPU / P1X 等）。自研芯片的核心挑战不是训练模型，而是**把模型中的每一个算子高效地映射到自家硬件上**，并保证与主流平台的结果一致。本节介绍自研芯片算子适配的流程、规范与一致性验证方法。

学完本节后，你应该能够：

- 理解自研芯片算子适配的整体流程。
- 制定算子开发规范与接口对齐方案。
- 设计跨平台一致性验证框架。
- 定位并修复算子精度与性能问题。

---

## 1. 自研芯片平台概览

### 1.1 为什么自研芯片

- **成本**：数据中心大量推理时，自研芯片 TCO 更低。
- **功耗**：边缘/车载场景对功耗有极致要求。
- **差异化**：针对自家业务模型做专用加速（稀疏、特定 attention 变体等）。

### 1.2 自研芯片常见架构

| 组件 | 作用 |
|------|------|
| 计算核 | 矩阵乘、向量运算、激活函数 |
| 存储层次 | SRAM / HBM / DDR，决定数据搬移策略 |
| DMA | 数据在 host/device 间搬运 |
| 指令集 | 算子最终编译为微码或 kernel |

### 1.3 软件栈抽象

```text
业务框架：PyTorch / ONNX / 自定义 IR
        ↓
图编译器：图优化、算子拆分、内存规划
        ↓
算子库：CPU reference / GPU reference / 自研芯片 kernel
        ↓
运行时：内存分配、kernel 调度、同步
        ↓
硬件：计算核 + 存储 + DMA
```

## 2. 算子开发规范与接口对齐

### 2.1 算子接口设计原则

- **与 PyTorch / ONNX 对齐**：减少上层框架改动。
- **显式 shape / dtype / memory layout**：避免隐式转换。
- **错误码与日志规范**：便于定位问题。
- **最小可复现单元测试**：每个算子必须有 reference 实现对比。

### 2.2 推荐算子接口模板

```cpp
// 伪代码：自研芯片算子接口
OpStatus MyMatmul(const Tensor& a, const Tensor& b, Tensor* out,
                  bool trans_a, bool trans_b,
                  DataType dtype, ComputeStream stream);
```

关键字段：

- 输入输出 Tensor（含 shape、stride、dtype、device ptr）。
- 属性参数（transpose、padding、dilation 等）。
- 计算流 / stream（异步执行）。
- 返回值：错误码。

### 2.3 算子开发流程

```text
1. 明确算子语义：与 PyTorch/ONNX 对齐
2. 写 CPU reference 实现（黄金标准）
3. 写自研芯片 kernel
4. 单元测试：与 reference 对比
5. 集成到图编译器
6. 端到端模型验证
7. 性能 profiling 与优化
```

## 3. 跨平台一致性验证

### 3.1 一致性验证的必要性

- 同一模型在 NVIDIA / Ascend / 自研芯片上运行，结果应“一致”。
- 这里的“一致”通常指在设定 tolerance 内相等，不是 bit-wise 一致。
- 不一致的常见原因：
  - 浮点累加顺序不同。
  - 激活函数实现差异（如 GELU 近似）。
  - 算子融合后中间结果未保留。
  - 量化策略不同。

### 3.2 验证框架设计

```text
模型 + 固定输入
    ↓
Platform A (Reference) → output_A
Platform B (Target)    → output_B
    ↓
比较：max_abs_diff、max_relative_diff、cosine_similarity
    ↓
生成对比报告
```

### 3.3 推荐 tolerance

| 场景 | 绝对误差 | 相对误差 |
|------|----------|----------|
| FP32 | 1e-5 | 1e-5 |
| FP16 | 1e-3 | 1e-3 |
| INT8 | 1e-2 ~ 1e-1 | 视业务 |

## 5. 本节小结

- 自研芯片的核心竞争力在于算子库与编译器。
- 算子开发必须先有 CPU reference，再写芯片 kernel，最后做一致性验证。
- 接口对齐遵循 PyTorch / ONNX 语义，减少上层迁移成本。
- 一致性验证要用绝对误差、相对误差、余弦相似度等多维度指标。
