# 8.2 边缘部署 - Jetson Orin

## 课程概述

边缘设备与数据中心 GPU 的最大区别是：**功耗、算力、显存都受到严格限制**。Jetson Orin 系列是 NVIDIA 面向边缘 AI 的主流平台，需要在精度、延迟、功耗之间做大量权衡。本节介绍 Orin 的硬件架构特点、模型轻量化方法、以及如何在端侧实现流式实时推理。

学完本节后，你应该能够：

- 说明 Jetson Orin 与数据中心 GPU 的核心差异。
- 使用量化、剪枝、蒸馏等方法压缩模型。
- 设计端侧流式推理 pipeline，满足实时性要求。
- 用 latency / power / accuracy 三维度评估边缘部署方案。

---

## 1. Jetson Orin 平台架构特点

### 1.1 硬件规格

| 型号 | Orin Nano | Orin NX | Orin AGX |
|------|-----------|---------|----------|
| AI TOPS (INT8) | 20 - 40 | 70 - 100 | 170 - 275 |
| GPU CUDA Cores | 512 - 1024 | 1024 - 2048 | 2048 |
| Memory | 4GB - 8GB | 8GB - 16GB | 32GB - 64GB |
| 功耗 | 7 - 15W | 10 - 25W | 15 - 60W |
| Tensor Core | 有 | 有 | 有 |

### 1.2 与数据中心 GPU 的差异

- **统一内存（Shared Memory）**：CPU 与 GPU 共享内存，不需要显式拷贝，但也更容易出现内存竞争。
- **功耗墙严格**：必须关注 MAXQ / 15W / 30W / 60W 等功耗模式。
- **算力有限**：大模型需要极致压缩才能跑起来。
- **TensorRT + Jetson SDK**：官方推荐 `jetson-inference`、`TensorRT`、`CUDA` 组合。

## 2. 模型轻量化与精度-性能权衡

### 2.1 常用轻量化手段

| 手段 | 原理 | 收益 | 代价 |
|------|------|------|------|
| INT8 量化 | 权值/激活用 INT8 | 显存减半，吞吐提升 | 精度轻微下降 |
| FP16 | 半精度推理 | 显存减半 | 对精度影响小 |
| 剪枝 | 去除不重要权重 | 模型变小 | 需重训练或稀疏支持 |
| 蒸馏 | 大模型教小模型 | 精度接近大模型 | 训练成本高 |
| KV Cache 限制 | 控制最大序列长度 | 避免 OOM | 上下文长度受限 |

### 2.2 TensorRT on Jetson

Jetson 上的 TensorRT 与 x86 版接口一致，但需注意：

- 使用 JetPack 自带 TensorRT，不要混用 x86 版本。
- 模型转换在 Jetson 上直接做，避免架构不兼容。
- 使用 `trtexec` 做 benchmark：

```bash
/usr/src/tensorrt/bin/trtexec --onnx=model.onnx --fp16 --saveEngine=model.plan
```

### 2.3 LLM 端侧部署的特殊性

7B 模型即便 INT4 也要 3.5GB+ 权值 + KV Cache。要在 Jetson Orin 上跑 7B：

- 使用 llama.cpp / mlc-llm / TensorRT-LLM 等端侧推理框架。
- 开启 4-bit 量化（Q4_0 / Q4_K_M / AWQ）。
- 限制 max_seq_len，减少 KV Cache。
- 用流式生成：首 token 可以慢一点，但后续 token 延迟要低。

## 3. 端侧实时性保障

### 3.1 实时性指标

- **首 token 延迟（TTFT）**：从输入到第一个输出生成的时间，与 prefill 阶段相关。
- **每 token 延迟（TBT / inter-token latency）**：连续 token 之间的间隔，与 decode 阶段相关。
- **端到端延迟**：= TTFT + (N - 1) × TBT。
- **功耗**：同样延迟下，功耗越低越好。

### 3.2 流式推理 Pipeline

```text
用户输入
  ↓
Tokenizer（CPU）
  ↓
Prefill（GPU，可一次处理全部 prompt）
  ↓
Decode Loop（GPU，每次生成一个 token）
  ↓
Detokenizer（CPU，流式输出）
  ↓
用户看到逐字输出
```

### 3.3 优化技巧

- **动态 batch**：端侧通常是单用户，但有时可合并短时间内的多个请求。
- **异步 Tokenizer / Detokenizer**：避免阻塞 GPU。
- **预热**：启动时先跑几次推理，避免 cold start。
- **固定 shape**：避免动态 shape 导致 TensorRT engine 重编译。

---

## 5. 本节小结

- Jetson Orin 是功耗受限的统一内存平台，与数据中心 GPU 调优目标不同。
- 端侧大模型必须做 4-bit / INT8 量化 + KV Cache 限制 + 序列长度控制。
- 实时性看 TTFT、TBT、功耗三个指标，流式输出主要优化 TBT。
- 端侧部署通常用 llama.cpp / TensorRT-LLM / MLC-LLM 等框架，配合 JetPack SDK。
