# 8.3 Ascend NPU 适配

## 课程概述

华为昇腾（Ascend）NPU 是国内 AI 推理训练的重要硬件平台。与 NVIDIA GPU 相比，昇腾采用达芬奇架构，软件栈以 CANN 为核心，编程模型与 CUDA 有显著差异。本节介绍 CANN 编程框架、算子迁移、以及如何在 Ascend 上完成模型部署与性能调优。

学完本节后，你应该能够：

- 理解 Ascend NPU 的达芬奇架构与 CANN 软件栈。
- 使用 ATC 工具完成模型转换与部署。
- 识别并修复 CUDA → CANN 迁移中的常见算子差异。
- 掌握 Ascend 性能调优的基本方法。

---

## 1. Ascend NPU 与 CANN 软件栈

### 1.1 硬件架构

| 特性 | Ascend 910B | Ascend 310P |
|------|-------------|-------------|
| 定位 | 训练/推理 | 推理 |
| 算力（FP16） | 320 TFLOPS | 22 - 88 TOPS INT8 |
| 内存 | 32GB / 64GB HBM | 8GB / 16GB LPDDR4 |
| 架构 | 达芬奇 3D Cube | 达芬奇 |
| 典型集群 | Atlas 800 / 900 | Atlas 300I Pro |

### 1.2 CANN 软件栈

```text
应用层：PyTorch / TensorFlow / MindSpore
       ↓
框架适配层：torch_npu / tf_adapter
       ↓
运行时：AscendCL / Runtime
       ↓
算子库：TBE / AICPU / AIV
       ↓
驱动层：Driver & Firmware
```

### 1.3 核心概念

- **AscendCL**：推理应用开发接口（类似 CUDA Runtime）。
- **ATC（Ascend Tensor Compiler）**：将 ONNX / Caffe / TensorFlow 模型编译为 `.om` 离线模型。
- **TBE（Tensor Boost Engine）**：自定义算子开发框架，使用 TVM-like DSL。
- **AICore**：达芬奇核心，负责矩阵/向量计算。

## 2. 算子迁移与适配

### 2.1 CUDA → CANN 常见映射

| CUDA/ONNX | CANN/ATC | 备注 |
|-----------|----------|------|
| Conv2d | Conv2D | 通常直接支持 |
| MatMul | MatMul / BatchMatMul | 注意 shape |
| LayerNorm | LayerNorm | 需确认版本 |
| Softmax | Softmax | 支持 |
| RoPE / RotaryEmbedding | 可能需自定义 | 大模型常见 |
| FlashAttention | 昇腾自研算子 | 需对应 CANN 版本 |

### 2.2 迁移流程

```text
PyTorch 模型
    ↓
导出 ONNX / TorchScript
    ↓
ATC 转换（.om）
    ↓
算子不支持？
    ├─ 是：修改模型结构 / 自定义 TBE 算子 / 用 AICPU 兜底
    └─ 否：继续
    ↓
AscendCL 推理 / torch_npu 在线运行
```

### 2.3 常见适配问题

- **数据排布**：CANN 默认 NCHW，但部分算子支持 NHWC；ONNX 通常是 NCHW。
- **数据类型**：BF16 / FP16 支持程度与 CANN 版本相关。
- **动态 shape**：ATC 对动态 shape 支持有限，通常需固定 batch / seq_len。
- **算子精度**：某些算子在不同平台上数值有微小差异，需设定 tolerance。

## 3. 性能调优方法

### 3.1 调优方向

| 方向 | 手段 |
|------|------|
| 算子融合 | 用 ATC 的图融合能力，减少内存搬移 |
| 精度选择 | FP16 / BF16 / INT8 / INT4 |
| 内存排布 | 使用 NHWC 或 16 字节对齐 |
| 流水并行 | 预处理后处理与推理并行 |
| 多卡并行 | HCCL 集合通信 |

### 3.2 性能分析工具

- **msprof**：CANN 提供的性能分析工具，可采集算子耗时、内存、带宽。
- **AscendCL profiling API**：在应用代码中打点。
- **Modelarts / MindStudio**：可视化 timeline。

### 3.3 调优 checklist

1. 确认 CANN / Driver / Firmware 版本一致。
2. 用 `atc --op_debug_level=3` 查看算子选择。
3. 检查是否有算子 fallback 到 AICPU（AICPU 通常比 AICore 慢）。
4. 打开算子融合与图优化选项。
5. 用 msprof 找到 top 耗时算子，针对性替换或重写。

---

## 5. 本节小结

- Ascend NPU 使用达芬奇架构，软件栈核心是 CANN。
- 模型迁移常用 ATC 转换 + AscendCL 推理，或 torch_npu 在线运行。
- 算子迁移要关注数据排布、动态 shape、精度差异三个问题。
- 性能调优从算子融合、精度、内存排布、流水并行四个方向入手。
