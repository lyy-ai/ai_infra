# 8.1 NVIDIA GPU 部署

## 课程概述

NVIDIA GPU 仍是当前大模型推理训练最主流的硬件平台。A100/H100 凭借 Tensor Core、高显存带宽、NVLink / NVSwitch 等硬件特性，能够支撑从 7B 到 175B+ 参数规模的模型。本节聚焦如何把模型在 NVIDIA GPU 上“跑起来”并且“跑得快”，覆盖 TensorRT 优化、多卡部署、显存与吞吐量权衡。

学完本节后，你应该能够：

- 说明 A100/H100 的关键硬件特性对推理的影响。
- 使用 TensorRT / TensorRT-LLM 进行模型部署与性能优化。
- 设计单卡/多卡/多机 GPU 推理方案。
- 针对 batch size、精度、KV Cache 做吞吐与延迟权衡。

---

## 1. A100 / H100 硬件特性

### 1.1 关键规格对比

| 特性 | A100 | H100 |
|------|------|------|
| 架构 | Ampere | Hopper |
| 显存 | 40GB / 80GB HBM2e | 80GB HBM3 |
| 显存带宽 | 1555 GB/s (80GB) | ~3 TB/s |
| Tensor Core | 第三代 | 第四代 |
| FP16 TFLOPS | 312 / 624 (with sparsity) | 989 / 1979 |
| FP8 支持 | 无 | 有 |
| NVLink 带宽 | 600 GB/s | 900 GB/s |
| 典型用途 | 训练 + 推理 | 推理 / 训练 |

### 1.2 对推理部署的影响

- **高显存带宽**决定大模型 decode 阶段的 token 生成速度，属于 memory-bound 场景。
- **Tensor Core** 适合大 batch 矩阵乘，提升 prefill / GEMM 阶段。
- **FP8 / INT8** 可显著降低显存占用与提升吞吐，但需校准精度。
- **NVLink / NVSwitch** 是卡间高速通信基础，多卡 TP / PP 部署依赖于此。

## 2. TensorRT 部署优化

### 2.1 为什么用 TensorRT

PyTorch eager 模式推理虽然方便，但存在以下开销：

- Python 调用开销、GIL。
- 算子未做算子融合（conv/bn/relu、layernorm 等）。
- 未针对目标 GPU 做 kernel 调优。

TensorRT 做的工作：

- 层融合（Layer Fusion）。
- 精度校准（FP16 / INT8 / BF16）。
- 内存池与显存复用。
- kernel auto-tuning（选择最优 CUDA kernel）。

### 2.2 TensorRT 基本流程

```text
ONNX / TorchScript / TensorRT-LLM checkpoint
    ↓
Parser / Converter
    ↓
TensorRT Builder
    ↓
Engine Plan (serialized .plan)
    ↓
Runtime Infer
```

### 2.3 TensorRT-LLM

大语言模型直接使用 TensorRT 构建 engine 非常复杂（涉及 GPT 结构、KV Cache、paged attention 等）。NVIDIA 提供了 **TensorRT-LLM**，内置：

- 常见 LLM 架构（GPT、LLaMA、ChatGLM、Baichuan 等）。
- FP8 / INT4 / AWQ / GPTQ 量化支持。
- PagedAttention / In-flight Batching。
- 多卡 TP / PP 支持。

典型命令（以 LLaMA 7B 为例）：

```bash
cd tensorrt_llm/examples/llama
python build.py --model_dir ./llama-7b-hf \
                --dtype float16 \
                --use_gpt_attention \
                --use_gemm_plugin float16 \
                --output_dir ./llama_7b_trt_engines
```

### 2.4 性能调优维度

| 维度 | 建议 |
|------|------|
| 精度 | FP16 通用；FP8 需 Hopper + 校准；INT8/INT4 用 AWQ/GPTQ |
| Batch Size | 测吞吐-延迟曲线，找到拐点 |
| In-flight Batching | 高并发场景启用，提升 GPU 利用率 |
| KV Cache | 用 paged attention 避免显存碎片 |
| 多卡 | TP 用于降低单卡显存；PP 用于超大规模 |

## 3. 多卡部署方案

### 3.1 单卡放不下模型时的选择

| 方案 | 适用场景 | 通信要求 |
|------|----------|----------|
| 量化 | 单卡勉强差一点点 | 无 |
| TP（张量并行） | 单卡放不下，卡间 NVLink 好 | 卡间高带宽 |
| PP（流水线并行） | 模型层数多，序列短 | 节点间也可 |
| TP + PP | 超大规模 + 长序列 | 节点内 TP，节点间 PP |

### 3.2 部署拓扑示例：A100 8×80GB

```text
Node: 8 × A100 80GB
        ┌─────────────┐
        │ NVSwitch    │
        │ 全互联       │
        └─────────────┘
       / / / / / / / /
    GPU0 ... GPU7

LLaMA2-70B FP16 约 140GB：
  - TP=4 每卡约 35GB，可放
  - 若 batch 大，可 TP=8 进一步均摊
```

### 3.3 TensorRT-LLM 多卡启动

```bash
mpirun -n 4 --allow-run-as-root \
    python ../run.py --engine_dir ./llama_70b_tp4_pp1
```

---

## 5. 本节小结

- A100/H100 的核心优势：高显存带宽 + Tensor Core + NVLink。
- TensorRT / TensorRT-LLM 是 NVIDIA GPU 部署性能优化的核心工具。
- 多卡部署优先节点内 TP，节点间 PP；量化是降低单卡占用的快捷手段。
- 部署调优要同时看延迟、吞吐、显存占用三个指标。
