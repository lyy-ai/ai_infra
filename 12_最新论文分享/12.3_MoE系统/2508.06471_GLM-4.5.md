# GLM-4.5: Agentic, Reasoning, and Coding (ARC) Foundation Models

> 论文信息：arXiv 2508.06471 / 智谱 AI（Z.ai）/ 2025-08 / 一句话概括：355B/32B 的 MoE 旗舰模型技术报告，系统展示了"大模型后训练工厂"的完整形态——专家模型迭代（Expert Model Iteration）+ RL 的多阶段后训练流水线。

## 1. 背景与要解决的问题

2025 年后半年的模型竞争范式：**预训练趋同，后训练决胜**。GLM-4.5 的报告价值在于完整披露了一个前沿实验室的后训练生产体系：

1. 如何让模型同时具备思考（thinking）与直出（direct response）两种模式？
2. Agentic / Reasoning / Coding（ARC）三类能力如何在一锅后训练里不互相伤害？
3. 大模型后训练的数据与 RL 流水线怎么组织？

## 2. 核心设计（infra 视角）

1. **混合推理架构**：单一模型支持 thinking/direct 双模式——对 serving 意味着负载特征多变（思考模式输出长、直出模式输出短），调度与容量规划要同时覆盖两种分布。
2. **专家模型迭代（Expert Model Iteration）**：先分别训练各领域专家模型，再蒸馏/合并回统一模型——后训练从"一个流程"变成"多产线 + 汇合"的工厂模式。
3. **多阶段 RL**：推理、agentic、通用能力分阶段 RL，每阶段的 rollout 环境与奖励设计不同——RL 基础设施需要支持多任务、多环境的灵活编排。
4. **规模配置**：355B 总参 / 32B 激活（另有 106B 的 GLM-4.5-Air），延续"超大总参 + 小激活"的 MoE 主流配置。

## 3. 关键数据（论文报告）

- 23T token 多阶段训练；TAU-Bench 70.1%、AIME 24 达 91.0%、SWE-bench Verified 64.2%。
- 在参数量远小于若干竞品的情况下，综合排名第 3、agentic 榜单第 2（论文口径）。
- 开源 GLM-4.5 与 GLM-4.5-Air（106B）双版本。

## 4. 计算/通信/显存三角取舍分析

- **换来的**：能力侧——分专家产线各自做到极致再汇合，避免多任务一锅炖的互相干扰；部署侧——32B 激活保持推理成本可控。
- **牺牲的**：系统复杂度——专家迭代 + 多阶段 RL 意味着后训练集群要同时维护训练、推理、环境三类负载；双模式使 serving 的容量规划复杂化。
- 本质：后训练时代的算力消耗从"一次预训练"变成"持续运转的后训练工厂"，infra 的重心跟着迁移。

## 6. 局限性与启发

- 局限：报告侧重流程与结果，系统实现细节（RL 框架、rollout 基础设施）披露有限；专家迭代的成本核算未公开。
- 启发：
  - "专家模型迭代"提示了一种组织方式：后训练可以并行化成多条产线，infra 要支持的是产线编排而非单个任务。
  - 与 Kimi K2 报告对照读：两家在同期的路线选择（优化器创新 vs 后训练工厂）反映了不同的竞争策略。

## 7. 面试视角

- **Q：GLM-4.5 的后训练和经典 RLHF 有什么区别？** A：从"单次 RLHF"演进为"多专家产线 + 多阶段 RL"的工厂模式，数据、环境、奖励都按领域专业化。
- **Q：混合推理（thinking/direct 双模式）对 serving 有什么影响？** A：输出长度分布变成双峰，batching、容量规划和 SLA 设计都要同时适配两种负载。
- **Q：355B/32B 部署要多少卡？** A：FP8 权重约 355GB，EP 铺开 + KV cache，生产级至少 8-16 张高端卡起步（视并发与上下文长度而定）。
