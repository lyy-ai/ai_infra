# Seed1.5-Thinking: Advancing Superb Reasoning Models with Reinforcement Learning

> 论文信息：arXiv 2504.13914 / 字节跳动 Seed / 2025-04 / 一句话概括：200B/20B 的 MoE 推理模型技术报告——除了模型能力，更值得注意的是其 RL 训练系统（流式 rollout、混合奖励、基础设施工程）作为"推理模型规模化训练"的工业参照。

## 1. 背景与要解决的问题

DeepSeek-R1 之后，"RL 训出推理能力"成为主赛道，但工程问题被低估：

1. **长思维链 rollout 的成本**：推理模型每轮 rollout 生成数千到数万 token，rollout 耗时主导整个 RL 迭代。
2. **奖励的多样性**：数学/代码有可验证答案（RLVR），通用任务没有——奖励体系要混合设计。
3. **训练稳定性**：RL 阶段的长训不稳定（熵塌缩、reward hacking 等）是规模化障碍。

## 2. 核心设计（系统视角）

1. **MoE 高效基座**：200B 总参 / 20B 激活——激活参数小直接降低 rollout 生成成本（RL 吞吐的决定性因素），这是"模型架构为 RL 系统设计"的案例。
2. **流式/分阶段 rollout 基础设施**：报告中 RL 系统针对长生成做了工程优化（rollout 与训练的流水线化、长尾处理），把长思维链的生成成本摊薄。
3. **混合奖励体系**：可验证任务（数学/代码）用规则奖励，通用任务用奖励模型，两者加权组合——奖励计算本身也是需要工程化的分布式负载。
4. **稳定性工程**：针对 RL 长训的熵管理与 KL 控制，避免后期崩坏。

## 3. 关键数据（论文报告）

- AIME 2024 达 86.7、Codeforces 55.0、GPQA 77.3。
- 非推理任务上 win rate 超 DeepSeek-R1 约 8%——推理能力的泛化而非过拟合。
- 200B/20B 的 MoE 配置在同期推理模型中属于"小激活"档位，RL 训练成本相对可控。

## 4. 计算/通信/显存三角取舍分析

- **换来的**：计算侧——20B 激活使 rollout 成本远低于同能力 dense 模型，RL 迭代速度直接受益。
- **牺牲的**：推理部署侧——200B 权重铺开仍需多卡 EP；奖励体系的工程复杂度（规则 + 模型混合）上升。
- 本质：推理模型时代，**RL 系统的吞吐 ≈ rollout 引擎的吞吐**，模型架构选型（激活参数大小）成为 RL 系统性能的前置变量。

## 6. 局限性与启发

- 局限：RL 基础设施的实现细节披露有限（不如 DeepSeek 系报告对系统的展开）；奖励模型与数据配方仍是半黑盒。
- 启发：
  - 读推理模型报告时，把"激活参数量"当作 RL 成本的一阶近似——这是评估各家方案经济性的快捷方式。
  - 混合奖励（规则 + 模型）的工程化是被低估的 infra 话题。

## 7. 面试视角

- **Q：推理模型的 RL 训练为什么贵？** A：长思维链 rollout——每轮迭代要生成数千到数万 token，rollout 阶段占迭代时间大头，且样本间长度差异大造成长尾。
- **Q：怎么降低推理模型的 RL 成本？** A：小激活 MoE 架构（降单 token 成本）+ 高效 rollout 引擎（动态批处理/投机解码）+ rollout-训练流水线化与异步化。
- **Q：RLVR 和奖励模型怎么选？** A：有标准答案的任务（数学/代码）用规则奖励（便宜、不可hack）；开放任务用奖励模型（覆盖广但可被 hack）；生产上混合使用。
