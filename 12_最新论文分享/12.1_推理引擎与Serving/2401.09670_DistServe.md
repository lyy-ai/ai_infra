# DistServe: Disaggregating Prefill and Decoding for Goodput-optimized Large Language Model Serving

> 论文信息：arXiv 2401.09670 / 北京大学、UCSD（OSDI 2024）/ 2024-01 / 一句话概括：把 Prefill 和 Decode 拆到不同 GPU 上，消除两阶段互相干扰，在同时满足 TTFT 和 TPOT SLO 的前提下大幅提升单卡可承载的请求速率（goodput）。

## 1. 背景与要解决的问题

LLM 推理一次请求分两个阶段：

- **Prefill**：并行处理全部输入 token，计算密集（compute-bound），决定 TTFT（Time To First Token）。
- **Decode**：逐 token 自回归生成，访存密集（memory-bound），决定 TPOT（Time Per Output Token）。

传统 serving 系统（如当时的 vLLM）把两个阶段混在同一批 GPU 上，用 continuous batching 混跑。DistServe 指出这带来两个问题：

1. **阶段间干扰**：一个长 prompt 的 prefill 插进来，正在 decode 的请求 TPOT 立刻恶化；反之 decode 请求多了会拖慢 prefill。两种 SLO 互相打架。
2. **资源与并行策略耦合**：prefill 和 decode 的最优并行方式不同（prefill 倾向大 TP 压延迟，decode 倾向小 TP 大 batch 提吞吐），混部时只能共用一套配置，必然不是各自最优。

## 2. 核心设计

1. **阶段解耦部署**：prefill 实例与 decode 实例跑在不同的 GPU 组上，各自独立做 continuous batching；prefill 完成后把 KV cache 传输给 decode 实例接管生成。
2. **按 SLO 反向求解资源配置**：给定 TTFT/TPOT 要求和负载特征，为两个阶段分别搜索最优的并行策略（TP/PP 度数）与实例数量配比，而不是拍脑袋平分机器。
3. **拓扑感知放置**：把有 KV 传输关系的 prefill/decode 实例尽量放在高带宽互联（NVLink/同机）范围内，最小化解耦引入的通信开销。
4. **目标函数是 goodput**：不是裸吞吐，而是"同时满足 TTFT 和 TPOT SLO 时每 GPU 能稳定服务的最大请求速率"——这是面向产品的指标。

## 3. 关键数据

- 论文报告：在多种模型与负载上，满足相同 TTFT+TPOT 约束时，DistServe 相比当时最强基线可服务最多约 4 倍以上的请求数，或在相同请求数下收紧 SLO 一个数量级（具体倍数随模型和 SLO 档位变化）。
- 验证了 KV cache 传输开销在合理放置下只占 decode 时间的很小比例，解耦的收益远大于代价。

## 4. 计算/通信/显存三角取舍分析

- **换来的**：计算侧——prefill/decode 各自用最优并行策略，GPU 利用率提升；SLO 维度——两种延迟指标不再互相污染。
- **牺牲的**：通信侧——引入 prefill→decode 的 KV cache 跨实例传输（这是 PD 分离的核心新增通信）；显存侧——系统层面需要额外的调度与传输缓冲。
- 本质：用一次性的 KV 传输成本，换两个阶段持续性的互不干扰。请求越长、并发越高，这笔交换越划算。

## 6. 局限性与启发

- 局限：解耦使系统复杂度显著上升（两套实例、KV 传输、调度联动）；短请求场景下解耦收益有限甚至为负；论文评测基于当时模型规模，对今天的超大 MoE 模型需要重新校准。
- 启发：
  - "干扰"本身就是性能问题，隔离有时比优化代码更直接有效。
  - 面向 SLO 做资源规划（goodput）而非面向裸吞吐，是生产系统与学术系统的分水岭。
  - 这篇论文开启了此后两年 PD 分离的工业浪潮：vLLM、SGLang、TensorRT-LLM 全部跟进支持。

## 7. 面试视角

- **Q：Prefill 和 Decode 为什么要分开部署？**
  A：因为两阶段计算特性相反（计算密集 vs 访存密集）、SLO 不同（TTFT vs TPOT）、最优并行策略不同；混部互相干扰且配置互相妥协，拆开可以各自最优化，代价只是一次 KV 传输。
- **Q：PD 分离的代价是什么？** A：KV cache 跨实例传输（新增通信）、系统复杂度、短请求场景收益有限。
- **Q：goodput 和 throughput 的区别？** A：goodput 是满足 SLO 约束下的有效吞吐，生产系统真正关心的是它。
