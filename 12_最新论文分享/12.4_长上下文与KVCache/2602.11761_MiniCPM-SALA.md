# MiniCPM-SALA: Hybridizing Sparse and Linear Attention for Efficient Long-Context Modeling

> 论文信息：arXiv 2602.11761 / 面壁智能、清华 / 2026-02 / 一句话概括：9B 混合架构——把稀疏注意力（InfLLM-V2）与线性注意力（Lightning Attention）按 1:3 混层，配合低成本持续训练框架把已有 Transformer 转成混合架构（省 75% 训练成本），单卡 A6000D 上 256K 上下文推理提速 3.5 倍、支持 1M 上下文。

## 1. 背景与要解决的问题

长上下文架构的两条效率路线各有短板：

- **稀疏注意力**（如 InfLLM、NSA 类）：保真度高，但仍要存完整 KV cache，显存随长度增长。
- **线性注意力**（如 Lightning Attention）：显存固定，但长距离精确回忆保真度不足。

问题：能否**按层混合**两者，让稀疏层负责精确回忆、线性层负责全局效率？以及——能不能不从零训练，把现成的全注意力模型"转换"过来？

## 2. 核心设计

1. **1:3 混层结构**：通过层选择算法决定哪些层用稀疏注意力（InfLLM-V2，高保真长程建模）、哪些层用线性注意力（Lightning Attention，全局高效），1:3 的比例是搜索出的性价比甜点。
2. **HyPE 混合位置编码**：为两类注意力机制设计兼容的混合位置编码，保证转换后位置信息一致。
3. **低成本持续训练转换框架**：从已训练好的 Transformer 出发做 continual training 转成混合架构，训练成本相比从零训练降低约 75%——架构升级的"低成本换壳"路径。
4. **面向端侧/单卡的定位**：9B 规模 + 1M 上下文可在单张 A6000D（48GB 级）运行，瞄准"单卡长上下文"这一实用场景。

## 3. 关键数据（论文报告）

- 单张 NVIDIA A6000D 上：256K token 推理速度达全注意力模型的 3.5 倍；支持最长 1M token 上下文（同规模全注意力 8B 模型因显存限制无法运行该长度）。
- 持续训练转换相比从零训练省约 75% 训练成本；通用能力与全注意力基线相当。

## 4. 计算/通信/显存三角取舍分析

- **换来的**：显存侧——线性层（3/4 的层）零 KV 增长，稀疏层只存块级索引，1M 上下文进入单卡射程；成本侧——转换而非重训，架构升级成本数量级下降。
- **牺牲的**：实现复杂度——两类注意力的 kernel、位置编码、推理框架支持都要维护；稀疏层仍保留部分 KV 增长（不是纯线性架构的 O(1)）。
- 本质：不追求"一种注意力统治所有层"，而是承认不同层职责不同——层粒度混合是效果/效率帕累托前沿上的实用解。

## 6. 局限性与启发

- 局限：9B 规模验证，向更大规模外推待验证；1:3 混层比例是搜索所得，不同任务/规模下最优比例可能漂移；两类 kernel 的推理框架支持仍是工程负担。
- 启发：
  - 2026 年长上下文架构的共识逐渐清晰：**混合 > 单一路线**（稀疏保真 + 线性保效率 + 少量全注意力保回忆）。
  - "转换而非重训"让架构创新可以被工业界低成本采纳——研究架构时同步研究"转换路径"是新范式。

## 7. 面试视角

- **Q：稀疏注意力和线性注意力互补在哪？** A：稀疏注意力保真度高但 KV 仍随长度增长；线性注意力显存固定但精确回忆弱；混层让稀疏层负责"需要记住的"，线性层负责"整体效率"。
- **Q：SALA 为什么能省 75% 训练成本？** A：不从零训练，而是把已有全注意力模型经持续训练转换成混合架构（配合 HyPE 保持位置编码一致）。
- **Q：单卡跑 1M 上下文的关键是什么？** A：3/4 层是线性注意力（显存与长度无关）+ 稀疏层只存块级结构，KV 总量被压到单卡 48GB 级显存可容纳。
