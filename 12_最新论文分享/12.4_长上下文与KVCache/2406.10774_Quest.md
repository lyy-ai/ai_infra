# Quest: Query-Aware Sparsity for Efficient Long-Context LLM Inference

> 论文信息：arXiv 2406.10774 / MIT、清华等 / 2024-06 / 一句话概括：推理时的动态稀疏注意力——用每个 KV page 的 min/max 元数据做 query 感知的关键页筛选，只加载少量关键 page 计算注意力，自注意力提速约 7 倍且几乎不损失精度。

## 1. 背景与要解决的问题

长上下文推理 decode 阶段的核心瓶颈：每个新 token 都要读取全部历史 KV cache（memory-bound）。但注意力本身是高度稀疏的——对当前 query 真正重要的历史 token 只有一小部分。

已有稀疏方法的缺陷：**静态稀疏**（固定滑窗/锚点）丢失关键信息；**训练时稀疏**需要改训练流程。Quest 问的是：能不能在推理时、不改模型、按 query 动态选出最重要的 KV 页？

## 2. 核心设计

1. **页级元数据**：把 KV cache 按 page 组织（与 PagedAttention 天然兼容），离线为每页预计算 Key 的逐通道 min/max 两个向量——这是该页 key 取值范围的紧凑"边界盒"。
2. **Query 感知的关键性估计**：decode 时用当前 query 向量与每页的 min/max 快速算出该页注意力分数的**上界**（不需要读完整 K），按上界选出 top-k 关键页。
3. **稀疏计算**：只对选中的页加载完整 K/V 做注意力，其余页直接跳过——显存读取量从 O(全长) 降到 O(top-k)。
4. **即插即用**：纯推理时方法，不改训练、不改权重，可与已有模型直接组合。

## 3. 关键数据（论文报告）

- 自注意力（self-attention）阶段提速约 7 倍，端到端推理提速约 2 倍以上（长上下文场景），精度损失可忽略。
- 与"静态滑窗"基线对比，Quest 在长上下文检索类任务（如大海捞针）上保持接近全注意力的召回能力。

## 4. 计算/通信/显存三角取舍分析

- **换来的**：访存侧——decode 每步的 KV 读取量从全序列降到 top-k 页，直击 memory-bound 瓶颈。
- **牺牲的**：显存侧——每页要额外存 min/max 元数据（开销小）；精度侧——上界估计选页有漏选风险（用 top-k 冗余缓解）；计算侧——多一步页筛选计算（远小于省下的读取）。
- 本质：把"注意力稀疏性"从观察变成可利用的系统资源——decode 的显存带宽从"瓶颈"变成"按需分配的资源"。

## 6. 局限性与启发

- 局限：收益随上下文长度增长（短上下文无意义）；上界估计在某些注意力模式（分数分布平坦）下区分度不足；top-k 是固定超参，理想情况应按 query 自适应。
- 启发：
  - 推理时稀疏（Quest）与训练时稀疏（NSA）是两条互补路线，工程上前者的即插即用性价值巨大。
  - "给数据结构附加廉价元数据，用元数据做快速筛选"是通用系统设计模式（类似数据库索引）。

## 7. 面试视角

- **Q：Quest 怎么实现 query 感知的 KV 筛选？** A：每页预存 Key 的逐通道 min/max，用 query 算出每页注意力分数上界，选 top-k 页做完整注意力。
- **Q：为什么选"页"为粒度？** A：与 PagedAttention 的 KV 组织天然对齐，页级元数据开销小，页级 gather 对 GPU 友好。
- **Q：Quest 和 NSA 的本质区别？** A：Quest 是推理时动态稀疏（不改模型，即插即用）；NSA 是训练时原生稀疏（效果上限更高，但要重训）。
