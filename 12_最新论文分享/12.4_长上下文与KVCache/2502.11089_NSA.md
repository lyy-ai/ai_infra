# NSA: Native Sparse Attention — Hardware-Aligned and Natively Trainable Sparse Attention

> 论文信息：arXiv 2502.11089 / DeepSeek-AI / 2025-02 / 一句话概括：可训练的稀疏注意力——压缩（看全局概貌）+ 选择（看关键细节）+ 滑窗（看局部）三分支动态组合，全程硬件对齐设计，64k 序列上相比全注意力大幅提速且效果不降。

## 1. 背景与要解决的问题

长上下文的注意力成本是二次方的。此前稀疏注意力的两大路线各有硬伤：

1. **推理时稀疏**（Quest、H2O 等）：训练与推理不一致，效果有天花板，且无法省训练成本。
2. **训练时稀疏的旧方案**：稀疏模式不规则，理论提速落不到硬件上（不规则 gather 打爆显存带宽），"稀疏了但不快"。

NSA 的目标：**从训练起就是稀疏的（native），且每一刀都切在硬件友好的粒度上**。

## 2. 核心设计

1. **三分支层级稀疏**：
   - **Compression**：把 KV 序列压缩成粗粒度块表示——低成本获取全局概貌。
   - **Selection**：按重要性选出细粒度的关键 token 块——保住关键细节。
   - **Sliding window**：保留最近 token 的完整注意力——局部精度。
   三个分支通过门控动态加权组合。
2. **硬件对齐设计**：块大小按 GPU tensor core / 显存事务对齐，选择操作以连续块为单位（而非散点），保证理论稀疏率能兑现为真实墙钟提速——这就是标题里 "hardware-aligned" 的含义。
3. **端到端可训练**：稀疏选择是可微/可训练的一部分，模型从预训练起就学习"该看哪里"，而不是推理时猜。

## 3. 关键数据（论文报告）

- 在 64k 长度序列上，NSA 相比全注意力在 decode/prefill 各阶段均取得大幅提速（论文 Figure 1 给出随长度增长的加速曲线）。
- 用 NSA 从头预训练的模型在通用 benchmark、长上下文任务、指令推理任务上**持平或超过**全注意力基线——稀疏不再是"用效果换速度"。

## 4. 计算/通信/显存三角取舍分析

- **换来的**：计算侧——attention 从 O(L^2) 降到近线性（压缩+选择+滑窗各自低成本）；训练成本同步下降（这是推理时稀疏做不到的）。
- **牺牲的**：显存/结构复杂度——三套分支的 KV 表示与门控增加实现复杂度；灵活性——块大小等超参与硬件耦合。
- 本质：NSA 代表稀疏注意力从"算法论文"走向"系统-算法协同设计"——论文标题本身就是方法论宣言。

## 6. 局限性与启发

- 局限：需要从头训练（存量模型无法直接受益）；块稀疏模式相对固定，极端不规则的依赖结构可能损失；开源实现与生产级 kernel 的完善需要时间。
- 启发：
  - "理论 FLOPs 降低 ≠ 真实提速"——稀疏模式必须对齐硬件（连续块、tensor core 形状、合并访存）。
  - 训练时稀疏 > 推理时稀疏是行业共识方向，NSA 是分水岭式的论文（DeepSeek 后续模型采用了相关技术）。

## 7. 面试视角

- **Q：NSA 的三分支各自解决什么？** A：压缩分支看全局概貌（便宜），选择分支保关键细节（准确），滑窗分支保局部连续（语言特性），门控动态组合。
- **Q：什么叫 hardware-aligned 稀疏？** A：稀疏粒度按硬件友好单位（连续块、对齐 tensor core/显存事务）设计，使理论稀疏率兑现为真实墙钟加速。
- **Q：NSA 为什么强调可训练？** A：推理时稀疏受限于"训练时没见过稀疏"的分布失配；原生可训练让模型学会在稀疏视野下工作，效果不降且训练成本同降。
