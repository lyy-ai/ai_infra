# Pretraining Large Language Models with NVFP4

> 论文信息：arxiv 2509.25149 / NVIDIA / 2025-09-29 / 首次公开证明可以用 NVFP4（4-bit 浮点）完成大规模 LLM 预训练：12B 参数、10T token，效果对齐 FP8 baseline。

## 1. 背景与要解决的问题

FP8 训练已经被广泛采用（DeepSeek-V3 是标志性事件），下一个自然的问题是：**能不能再砍一半，用 4-bit 浮点（FP4）做预训练？** Blackwell 硬件已经原生支持 FP4 Tensor Core，峰值算力是 FP8 的两倍，理论上预训练成本可以再降一大截。

但 4-bit 训练的难度不是线性增加的：

- FP4（E2M1）只有 2 位指数、1 位尾数，动态范围和精度都极差；
- 训练是前向、反向、梯度累积、优化器状态的全链路过程，任何一环数值崩了都会发散；
- 模型越大、训练越长，误差累积越明显——此前没有人公开验证过"大模型 × 长 token 流"下的 4-bit 训练。

一句话：**FP4 的算力在硬件里，稳定性在算法里**，这篇论文补的就是后者。

## 2. 核心设计

论文的方法不是单点技巧，而是一套组合拳（摘要中明确列出四个组件）：

1. **Random Hadamard Transforms（RHT）压制块内异常值**：在量化前对张量做随机 Hadamard 变换，把个别异常大幅值的能量"打散"到整个块，使块内数值分布更均匀。这是 QuaRot/SpinQuant 一脉的旋转变换思想在训练场景的落地——变换是严格正交的，数学上不改算子语义，只改数值分布。
2. **二维量化方案（2D quantization）**：前向和反向使用一致的二维（块级）缩放表示，保证前向权重、激活与反向梯度在同一数值坐标系下，避免前后向量化网格错位引入的系统误差。
3. **随机舍入（Stochastic Rounding）**：对梯度做无偏估计。普通的 round-to-nearest 是有偏的，在梯度这种"大量小量累积"的场景里偏差会累积成收敛差距；随机舍入让舍入误差期望为零，是低比特训练稳定性的经典手段。
4. **选择性高精度层（selective high-precision layers）**：对数值敏感的层（如首尾层、部分归一化相关计算）保留高精度，其余全 FP4。这是低比特训练的标准做法——用很小的算力代价换掉大部分精度风险。

## 3. 关键数据

- 训练规模：**12B 参数模型、10T token**，论文称之为"迄今为止公开记录的最长 4-bit 精度训练"。
- 结果：NVFP4 预训练的**训练 loss 和下游任务精度与 FP8 baseline 相当**。
- 以上均来自论文摘要；摘要未给出具体的 loss 差值和 benchmark 分数，引用时注意不要超出这两个结论。

## 4. 计算/通信/显存三角取舍分析

- **计算**：FP4 Tensor Core 峰值是 FP8 的 2 倍，这是本文要兑现的红利。代价：RHT 变换、随机舍入、二维 scale 管理都是额外计算，且这些操作本身不容易完全融合进 GEMM，实际加速比必然小于理论 2 倍。
- **通信**：4-bit 权重/激活/梯度如果同步用于分布式通信（梯度 all-reduce、激活传输），通信量相对 FP8 再减半。摘要未明确说明通信侧是否也压到 4-bit，工程落地时这是下一个优化点。
- **显存**：权重、激活的存储可以受益，但 master weight、优化器状态（Adam 的 m/v）通常仍需高精度保留——和 FP8 训练一样，"显存减半"的宣传要打折扣。

核心取舍：**用一套算法基础设施（变换+舍入+混合精度）的复杂度，换整个训练流程位宽减半**。这笔账只有在大规模预训练（算力成本以亿计）时才划算。

## 6. 局限性与启发

局限性：

- 验证规模是 12B/10T token。更大模型（数百 B）或更长训练下是否仍然稳定，尚未公开验证。
- RHT、随机舍入、二维 scale 的组合意味着训练框架深度定制，不是开源社区开箱即用的方案。
- 摘要只对比了 FP8 baseline，没有报告与 BF16 的端到端 wall-clock 对比，实际训练加速比需看正文/后续工程复现。

启发：

- **旋转变换（Hadamard）正在从推理量化（QuaRot）走向训练量化**，这条技术线的通用性超出预期，值得系统掌握。
- 低比特训练的稳定性公式逐渐清晰：**正交变换打散异常值 + 无偏舍入 + 敏感层高精度**，这三件套大概率会出现在后续所有 4-bit 训练工作中。
- 硬件（Blackwell FP4）先行、算法跟进兑现的模式再次出现——关注新硬件发布时的"未兑现算力"是找研究方向的捷径。

## 7. 面试视角

**可能的问题**："FP4 预训练为什么不发散？NVIDIA 是怎么做到的？"

**一句话答案**：靠四件套——随机 Hadamard 变换压制块内异常值、二维量化保证前后向一致、随机舍入保证梯度无偏、敏感层保留高精度；用这套组合在 12B 模型 10T token 上做到了与 FP8 baseline 相当的 loss 和下游精度。
