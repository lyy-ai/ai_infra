# 2.3 经典算子实现 - Reduce

## 课程概述

Reduce（归约）是深度学习中最基础也最常用的算子之一：Softmax 需要求和/求最大值，LayerNorm 需要求均值和方差，Loss 计算需要全局累加。Reduce 的性能瓶颈通常是**全局内存带宽**和**线程间同步/通信**。

本节把 Reduce 算子从朴素实现逐步优化到高性能实现：全局内存原子加、共享内存树形归约、Warp Shuffle 优化、多级归约。学完本节后，你应该能够：

- 写出正确的 CUDA Reduce kernel，处理任意长度输入。
- 理解为什么树形归约比串行归约快。
- 使用 Warp Shuffle 在 Warp 内完成最后一级归约。
- 设计多级归约策略，处理大规模数据。
- 与 cuBLAS/Thrust 的 reduce 做对比分析。

---

## 1. Reduce 问题定义

输入：长度为 N 的数组 `x`，输出一个标量：

$$
out = \sum_{i=0}^{N-1} x_i
$$

Reduce 的关键挑战：

- 需要所有线程协作产生单一结果。
- 线程间需要交换部分和。
- 最终必须合并为全局结果。

---

## 2. 朴素实现：全局内存原子加

每个线程读取一段数据并累加到局部和，最后用 `atomicAdd` 写回全局内存。

```cuda
__global__ void reduce_atomic(const float* in, float* out, int N) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    int stride = gridDim.x * blockDim.x;
    float local_sum = 0.0f;
    for (int i = idx; i < N; i += stride) {
        local_sum += in[i];
    }
    atomicAdd(out, local_sum);
}
```

问题：所有 block 同时 `atomicAdd`，全局序列化，性能差。

---

## 3. 共享内存 + 树形归约

每个 block 先在共享内存中做树形归约，产生一个 block 级别的部分和，最后再用少量原子加合并。

```cuda
__global__ void reduce_shared(const float* in, float* out, int N) {
    __shared__ float sdata[256];
    int tid = threadIdx.x;
    int idx = blockIdx.x * blockDim.x + tid;

    // 加载到共享内存
    float local = 0.0f;
    for (int i = idx; i < N; i += gridDim.x * blockDim.x) {
        local += in[i];
    }
    sdata[tid] = local;
    __syncthreads();

    // 树形归约
    for (int s = blockDim.x / 2; s > 0; s >>= 1) {
        if (tid < s) {
            sdata[tid] += sdata[tid + s];
        }
        __syncthreads();
    }

    if (tid == 0) {
        atomicAdd(out, sdata[0]);
    }
}
```

优势：

- 每个 block 内部用共享内存归约，速度快。
- 全局原子加次数从 `N` 降到 `gridDim.x`。

---

## 4. Warp Shuffle 优化

当 block size 为 256 时，树形归约最后 5 步（128→64→32→16→8→4→2→1）中，后 5 步发生在同一个 Warp 内，可以用 Warp Shuffle 避免共享内存和同步。

```cuda
__inline__ __device__ float warp_reduce_sum(float val) {
    for (int offset = 16; offset > 0; offset /= 2) {
        val += __shfl_down_sync(0xFFFFFFFF, val, offset);
    }
    return val;
}
```

把 Warp Shuffle 接到共享内存归约后面：

```cuda
// 共享内存归约到每个 warp 一个部分和
for (int s = blockDim.x / 2; s > 32; s >>= 1) {
    if (tid < s) sdata[tid] += sdata[tid + s];
    __syncthreads();
}

float local = sdata[tid];
local = warp_reduce_sum(local);

if (tid % 32 == 0) {
    atomicAdd(out, local);
}
```

---

## 5. 多级归约

对于超大规模数据（如 billions 元素），单级 kernel 可能 grid 太大。可以做两级归约：

```text
Level 1: 每个 block 归约一部分数据 -> 产生 M 个部分和
Level 2: 一个 block 归约 M 个部分和 -> 最终结果
```

这样可以避免大量 block 同时 atomicAdd，并且 Level 2 可以用少量线程高效完成。

```cuda
// reduce.cu
#include <cuda_runtime.h>
#include <stdio.h>
#include <vector>
#include <numeric>

#define N (1024 * 1024)
#define BLOCK 256

__inline__ __device__ float warp_reduce_sum(float val) {
    val += __shfl_down_sync(0xFFFFFFFF, val, 16);
    val += __shfl_down_sync(0xFFFFFFFF, val, 8);
    val += __shfl_down_sync(0xFFFFFFFF, val, 4);
    val += __shfl_down_sync(0xFFFFFFFF, val, 2);
    val += __shfl_down_sync(0xFFFFFFFF, val, 1);
    return val;
}

__global__ void reduce_kernel(const float* in, float* out, int n) {
    __shared__ float sdata[BLOCK];
    int tid = threadIdx.x;
    int idx = blockIdx.x * blockDim.x + tid;

    float local = 0.0f;
    for (int i = idx; i < n; i += gridDim.x * blockDim.x) {
        local += in[i];
    }
    sdata[tid] = local;
    __syncthreads();

    for (int s = blockDim.x / 2; s > 32; s >>= 1) {
        if (tid < s) sdata[tid] += sdata[tid + s];
        __syncthreads();
    }

    local = sdata[tid];
    local = warp_reduce_sum(local);

    if (tid == 0) atomicAdd(out, local);
}

int main() {
    std::vector<float> h_in(N, 1.0f);
    float *d_in, *d_out;
    cudaMalloc(&d_in, N * sizeof(float));
    cudaMalloc(&d_out, sizeof(float));
    cudaMemcpy(d_in, h_in.data(), N * sizeof(float), cudaMemcpyHostToDevice);
    cudaMemset(d_out, 0, sizeof(float));

    reduce_kernel<<<(N + BLOCK - 1) / BLOCK, BLOCK>>>(d_in, d_out, N);

    float h_out = 0;
    cudaMemcpy(&h_out, d_out, sizeof(float), cudaMemcpyDeviceToHost);
    printf("GPU sum: %.1f, expected: %d\n", h_out, N);

    cudaFree(d_in);
    cudaFree(d_out);
    return 0;
}
```

## 7. 常见误区

### 7.1 “Reduce 就是不断加”

朴素累加会丢失精度。对大量浮点数求和，应使用 Kahan 求和或按树形/块规约减少误差累积。

### 7.2 “block size 越大越好”

对于 Reduce，block size 过大会导致每个线程处理数据太少，共享内存归约的同步开销占比上升。256 通常是 sweet spot。

### 7.3 “Shuffle 可以完全替代共享内存”

Shuffle 只能在一个 Warp 内通信。跨 Warp 通信仍需共享内存。

---

## 8. 本节小结

1. Reduce 的核心挑战是线程协作与数据合并。
2. 全局原子加最简单但性能最差，仅适合小规模或教学。
3. 共享内存树形归约大幅减少原子操作次数。
4. Warp Shuffle 进一步优化 Warp 内归约，减少同步和共享内存访问。
5. 多级归约适合超大规模数据。
