# 2.10 Hopper 与 Blackwell 新特性

## 课程概述

2022 年发布的 Hopper（H100）和 2024 年发布的 Blackwell（B200/GB200）是 AI 时代的两代主力 GPU。它们不只是"算力翻倍"的数字游戏，而是引入了一批改变 kernel 写法和集群架构的新特性：FP8/FP4 低精度 Tensor Core、TMA 硬件异步搬运、Thread Block Cluster 与分布式共享内存、Warp Specialization 编程范式，以及 NVL72 级别的超大规模 scale-up 互联。

本节把两代架构的关键新特性拆开讲清楚，并分析它们对 AI Infra 的深远影响。学完本节后，你应该能够：

- 说出 H100 相对 A100 的关键规格提升（FP8 算力、HBM3、NVLink 4.0）。
- 解释 TMA 为什么能解放线程与寄存器，以及它对 kernel 写法的影响。
- 解释 Thread Block Cluster / DSMEM 如何扩大"共享内存域"。
- 说明 Warp Specialization 的生产者-消费者模型，以及它为什么是 Hopper 高性能 kernel 的主流写法。
- 解释 FlashAttention-3 如何在 H100 上把峰值利用率从约 35% 提到约 75%。
- 说明 Blackwell 的 FP4/MXFP6/MXFP4、双 die 封装、NVLink 5 与 NVL72 对 MoE 训练推理的意义。

---

## 1. 背景与动机：架构演进背后的不可能三角

GPU 架构的每一次演进，本质上都是在**计算 / 通信 / 显存**这个不可能三角上重新分配筹码：

- 计算侧：摩尔定律放缓，纯靠制程提频提密度越来越贵，于是转向**低精度**（FP16 → FP8 → FP4）换取单位晶体管的算力。
- 显存侧：模型规模增速远超单卡显存增速，HBM 带宽成为 decode 阶段的硬约束。
- 通信侧：单卡装不下就得多卡，多卡之间的互联带宽决定并行策略的设计空间。

Hopper 和 Blackwell 的所有新特性，都可以放进这个三角里理解。下面按代际展开。

## 2. Hopper H100（2022-2024 主力）

### 2.1 关键规格

| 项目 | H100 SXM | 备注 |
| --- | --- | --- |
| Tensor Core | 第四代 | 新增 FP8 支持 |
| FP8 dense 算力 | 约 1979 TFLOPS | E4M3/E5M2 两种格式 |
| FP8 sparse 算力 | 约 3958 TFLOPS | 结构化稀疏 |
| FP16/BF16 dense 算力 | 约 989 TFLOPS | FP8 恰好是其 2 倍 |
| 显存 | 80GB HBM3 | 带宽约 3.35 TB/s |
| 互联 | NVLink 4.0 | 约 900 GB/s |

FP8 的两种格式分工明确：**E4M3**（4 位指数 3 位尾数）精度高、范围小，用于前向的权重与激活；**E5M2**（5 位指数 2 位尾数）范围大、精度低，用于反向的梯度。FP8 把每元素字节数从 2 降到 1，同时让算力翻倍、显存占用和带宽压力减半——在不可能三角的三个边上同时获益，代价是需要精细的量化与缩放管理（per-tensor / per-block scaling）。

### 2.2 TMA（Tensor Memory Accelerator）

TMA 是 Hopper 引入的**硬件级异步批量数据搬运单元**。在 Ampere 时代，global → shared 的拷贝要靠每个线程发 `cp.async` 指令，占用线程指令槽和寄存器来计算地址、处理越界。TMA 把这件事整个 offload 到一个专用硬件引擎：

- **一个线程发起，整个 tile 搬完**：线程只需构造一个多维 tensor 描述符（形状、stride、tile 大小），TMA 引擎负责后续所有地址生成与搬运。
- **越界处理在硬件中完成**：描述符声明了 tensor 的真实边界，tile 越界部分自动填充，kernel 里不再需要 mask 分支。
- **解放线程与寄存器**：省下的寄存器可以扩大计算 tile 或提高 occupancy。
- **配合 mbarrier 异步等待**：数据到达后由 mbarrier 通知，实现真正的"搬运与计算重叠"。

对 kernel 写法的影响是结构性的：数据搬运从"所有线程的职责"变成"一条描述符 + 一次发起 + 一次等待"，为 Warp Specialization 铺平了道路。

### 2.3 Thread Block Cluster 与 Distributed Shared Memory（DSMEM）

Hopper 允许把多个 thread block 组成 **cluster**：可移植的 cluster 大小最多 8 个 block（硬件上限 16 个），cluster 内的 block 可以**直接读写彼此的 shared memory**，这就是 Distributed Shared Memory。

意义在于**扩大了"共享内存域"**：原本 228KB 的片上共享内存只服务于一个 block，现在一个 cluster 可以共享约 1.8MB（8 block）级别的片上存储。对 GEMM 这类算子，相邻 block 需要相同的 A/B tile，DSMEM 允许 tile 在 cluster 内只从 HBM 加载一次再互相分发，直接削减了 L2/HBM 的流量。

### 2.4 Warp Specialization

传统 kernel 里每个 warp 都是"搬数据 → 算 → 搬数据 → 算"的循环，搬运延迟只能靠软件流水线部分隐藏。Hopper 上高性能 kernel 的主流写法改为 **warp specialization（warp 分工）**：

```text
生产者 warp（少数）：专职发 TMA 搬运，填满 shared memory 的多级缓冲
消费者 warp（多数）：专职从 shared memory 取数、调用 Tensor Core 计算
两者之间：用 mbarrier 做满/空信号同步，形成多级流水
```

CUTLASS 3.x 把这一范式产品化为 **cooperative**（所有 warp 既生产又消费，但角色在循环内分时切换）与 **pingpong**（两组消费者 warp 交替计算，一组等待 TMA 时另一组在算）两种 schedule。配套脚本 `warp_specialization_sim.py` 用离散事件模型演示了这种分工对 SM 利用率的提升。

### 2.5 FlashAttention-3：新特性的集大成者

FA3 是检验 Hopper 新特性价值的最佳案例：

- **FA2 在 H100 上只达到约 35% 的峰值利用率**——FA2 是为 A100 设计的，没有用上 TMA 与异步能力，GEMM 与 softmax 之间的串行依赖让 Tensor Core 大量空转。
- **FA3 通过 TMA + warp specialization + GEMM-softmax 流水重叠，达到约 75% 的峰值利用率**，相对 FA2 接近翻倍。
- **FP8 版 FA3** 进一步提速，但 FP8 的精度问题在 attention 中格外敏感：Q/K/V 的离群值会被量化放大。FA3 采用 **block 量化**（每个 tile 独立缩放因子）与**非相干处理（incoherent processing，乘随机正交矩阵打散离群值）**来缓解量化误差。

FA3 也印证了一个趋势：**吃满新硬件红利的 kernel，其手写复杂度大幅上升**——这正是 2.9 节中"Triton 价值上升、但极致场景仍需手写"判断的来源。

## 3. Blackwell（B200/GB200，2024-2025）

### 3.1 关键规格与新特性

| 项目 | B200 | 相对 H100 的变化 |
| --- | --- | --- |
| 封装 | 双 die，约 2080 亿晶体管 | 两颗 die 以超高速互连封装为一颗 GPU |
| Tensor Core | 第五代 | 新增 FP4 与微缩放格式 |
| 低精度格式 | FP4（E2M1/E3M0）、MXFP6/MXFP4 | FP8 之上再砍一半位宽 |
| 显存 | HBM3e，容量与带宽进一步提升 | 缓解 decode 带宽瓶颈 |
| 互联 | NVLink 5 | 每 GPU 约 1.8 TB/s，是 NVLink 4.0 的 2 倍 |

**MXFP6/MXFP4 微缩放格式**的关键设计：不再对整个 tensor 用一个缩放因子，而是**每 32 个元素共享一个缩放因子**，细粒度缩放让 4-bit/6-bit 精度在实际模型上可用。这延续了"用更精细的量化管理换取计算/显存/带宽三重收益"的路线。

### 3.2 NVL72：机柜级 scale-up 域

Blackwell 最大的结构性变化不在单卡，而在整机柜：**NVL72 把 72 个 GPU 用 NVLink 5 全互联成一个巨型 scale-up 域**，柜内任意两个 GPU 之间都能以接近单跳 NVLink 的带宽通信。

对比 Hopper 时代：一台 DGX H100 只有 8 个 GPU 组成 NVLink 域，跨机必须走 InfiniBand（带宽差一个数量级）。NVL72 把这个高速域扩大了 9 倍。

**对 MoE 专家并行（EP）的意义**：MoE 模型的 EP 需要频繁的 all-to-all 通信（每个 token 被路由到不同专家）。在 8 卡时代，EP 度数稍大就必须跨机，all-to-all 走 IB 成为瓶颈；在 NVL72 内，**EP=64 甚至更高的 all-to-all 可以完全在机柜内完成**，通信不再出柜。这直接改变了大 MoE 模型（如 DeepSeek 类架构）的并行策略设计：scale-up 域负责 EP，scale-out 网络（IB/RoCE）只承担 DP/PP 的低频通信。

## 5. 工程实践：新特性如何改变日常工作

1. **FP8 训练与推理已成标配**：H100 时代 FP8 训练需要精细的 scaling 策略（delayed scaling、per-tensor scale 的 amax 历史），框架层（Transformer Engine）已封装；Blackwell 的 MXFP4 把同样思路推到 4-bit。对 Infra 工程师的要求是理解量化误差的来源与缓解手段，而不是只会开关开关。
2. **kernel 开发门槛提高，Triton/CUTLASS 价值上升**：TMA 描述符、mbarrier、warp specialization 的手写复杂度远超 Ampere 时代的 cp.async 流水线。这造成两个后果：极致 kernel 集中在少数团队（FA3、CUTLASS），其余人转向 Triton（编译器逐步接入新特性）——呼应 2.9 节的分层格局。
3. **并行策略设计要跟着 scale-up 域走**：8 卡时代 EP 度数保守；NVL72 时代可以把 EP 开大、把 MoE 的 all-to-all 留在柜内。集群规划时，"哪些通信必须留在 NVLink 域内"成为拓扑设计的第一性问题。
4. **decode 吞吐看带宽，不看算力**：低精度时代算力过剩、带宽稀缺，decode 阶段的理论上限是"带宽 ÷ 每 token 激活参数字节数"。评估硬件代际收益时，先算这笔账（见配套脚本）。

## 7. 面试高频问题

**Q1：H100 的 FP8 为什么重要？两种格式怎么用？**

一句话答案：FP8 让 Tensor Core 算力翻倍（约 989 → 1979 TFLOPS）且每元素字节数减半，计算/显存/带宽三重获益；E4M3 用于前向权重激活，E5M2 用于反向梯度。

展开：E4M3 有 3 位尾数精度高但动态范围小，适合分布相对集中的前向张量；E5M2 有 5 位指数范围大，能容纳梯度中的大离群值。FP8 的代价是需要 scaling 管理（per-tensor 或更细粒度），量化误差控制不好会导致训练 loss 翘头，这就是 Transformer Engine 等框架存在的意义。

**Q2：TMA 解决了什么问题？**

一句话答案：把 global↔shared 的批量搬运 offload 到专用硬件引擎，一个线程发一条描述符就能搬整个 tile，解放线程指令槽与寄存器，并硬件化处理越界。

展开：Ampere 时代每个线程都要发 cp.async、算地址、处理边界，这些开销占用本可用于计算的寄存器与指令发射带宽；TMA 用多维 tensor 描述符描述全局张量，硬件自动完成地址生成、越界填充与搬运，数据到达通过 mbarrier 通知。它是 warp specialization（专职搬运 warp）和 FA3 高利用率的基础。

**Q3：Thread Block Cluster 和 DSMEM 有什么用？**

一句话答案：让 cluster 内（可移植最多 8 个）block 直接互访 shared memory，把"共享内存域"从一个 block 扩大到整个 cluster，减少重复从 L2/HBM 取数。

展开：GEMM 中相邻 block 常需相同的 A/B tile，没有 DSMEM 时每个 block 各自从 L2 加载；有了 cluster，tile 可以只加载一次再在 block 间分发，降低 L2/HBM 流量。代价是 cluster 对调度有约束（必须整 cluster 同时驻留），编程复杂度也上升。

**Q4：什么是 warp specialization？为什么 Hopper 上它成为主流？**

一句话答案：把 warp 分成生产者（专职 TMA 搬运）与消费者（专职计算）两类，用 mbarrier 形成多级流水，让搬运与计算真正重叠。

展开：传统写法中每个 warp 搬算交替，计算单元在等待数据时空转；warp specialization 把等待集中到少数生产者 warp，消费者 warp 几乎不停顿地打 Tensor Core。CUTLASS 3.x 的 cooperative/pingpong schedule 是这一范式的工程化实现，FA3 达到约 75% 峰值利用率也依赖于此。

**Q5：FA3 为什么比 FA2 快这么多？**

一句话答案：FA2 为 A100 设计、没用上 Hopper 的异步能力（约 35% 峰值利用率），FA3 用 TMA + warp specialization + GEMM-softmax 流水重叠达到约 75%，另有 FP8 版本进一步提速。

展开：FA2 中 softmax 与 GEMM 串行，Tensor Core 在 softmax 阶段空转；FA3 把两个 GEMM 与 softmax 交错流水，让 Tensor Core 与特殊函数单元（exp）同时忙。FP8 版本用 block 量化和非相干处理（incoherent processing，随机正交变换打散离群值）控制量化误差。

**Q6：NVL72 对 MoE 模型意味着什么？**

一句话答案：72 个 GPU 全互联成一个 scale-up 域，MoE 专家并行的 all-to-all 通信可以完全在机柜内完成，不再需要走低速的跨机网络。

展开：MoE 的 EP 每步都要 all-to-all 分发 token，8 卡 NVLink 域时代 EP 度数受限于域大小，跨机走 IB 带宽差一个数量级；NVL72 把高速域扩大 9 倍，EP=64+ 成为可行配置，scale-out 网络只承担 DP/PP 的低频通信。这是集群拓扑影响模型并行设计的典型案例。

## 8. 本节小结

1. Hopper H100 的核心升级：第四代 Tensor Core 支持 FP8（dense 约 1979 TFLOPS，为 FP16 的 2 倍）、HBM3 约 3.35 TB/s、NVLink 4.0 约 900 GB/s。
2. TMA、Cluster/DSMEM、warp specialization 三件套改变了高性能 kernel 的写法：搬运硬件化、共享内存域扩大、warp 分工流水化。
3. FlashAttention-3 是新特性价值的试金石：约 35% → 约 75% 的峰值利用率，FP8 版配合 block 量化与非相干处理。
4. Blackwell 的核心升级：第五代 Tensor Core 支持 FP4 与 MXFP6/MXFP4、双 die 约 2080 亿晶体管、NVLink 5 每 GPU 约 1.8 TB/s、NVL72 机柜级 scale-up 域。
5. 对 AI Infra 的总影响：低精度改变成本结构，scale-up 域扩大改变并行策略，kernel 手写复杂度上升使 Triton/CUTLASS 的分层价值更加凸显。
6. 一切演进都可以放回计算/通信/显存不可能三角中理解：低精度买计算和显存，NVLink 买通信，新特性买"把三者 overlap 起来"的能力。
