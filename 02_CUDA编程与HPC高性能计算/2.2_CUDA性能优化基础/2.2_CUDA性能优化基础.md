# 2.2 CUDA 性能优化基础

## 课程概述

CUDA kernel 的性能通常受限于两类资源：**显存带宽**和**计算能力**。一个 memory-bound 的 kernel，就算用再复杂的算法，也可能跑不满 SM；而一个 compute-bound 的 kernel，则需要充分压榨 Tensor Core、FMA、SFU 等计算单元。

本节把 CUDA 性能优化的基础技术拆开：内存访问优化、共享内存预取、Warp Shuffle、Occupancy、同步与原子操作。这些技术是后面 Reduce、GEMM、Attention 等经典算子实现的前置知识。

学完本节后，你应该能够：

- 判断一个 kernel 是 memory-bound 还是 compute-bound。
- 用合并访问和共享内存预取优化内存型 kernel。
- 使用 Warp Shuffle 在 Warp 内做高效通信，避免共享内存和同步。
- 估算 Occupancy，并根据资源限制调整 block size 和寄存器使用。
- 正确选择原子操作和同步原语，避免数据竞争和过度同步。

## 1. 内存访问优化

### 1.1 合并访问（Coalesced Access）

合并访问是 CUDA 优化的第一课。理想情况下，一个 Warp 内的 32 个线程访问一段连续的全局内存，硬件可以把这些请求合并为少量 cache line 传输。

```text
Thread 0 -> addr + 0
Thread 1 -> addr + 4
Thread 2 -> addr + 8
...
Thread 31 -> addr + 124
```

这种情况下，128 字节的访问可能只触发 2 个 64B cache line 请求，带宽利用率最高。

反例：

```text
Thread 0 -> addr + 0
Thread 1 -> addr + 4096
Thread 2 -> addr + 8192
...
```

每个线程访问不同 cache line，带宽利用率低。

### 1.2 共享内存预取（Shared Memory Tiling）

对于需要多次复用全局内存数据的场景，可以先把数据从全局内存加载到共享内存，后续线程从共享内存读取。

```text
全局内存 -> 共享内存 -> 计算
   一次高延迟访问      多次低延迟访问
```

典型应用：矩阵乘法分块、卷积 im2col、stencil。

### 1.3 向量化加载

使用 `float4`、`int4` 等向量类型一次加载多个元素，减少指令数量和访存事务数。

```c
float4 vec = reinterpret_cast<float4*>(gmem)[idx];
```

## 2. Warp Shuffle 通信

### 2.1 什么是 Warp Shuffle

Warp Shuffle 是 Kepler 架构引入的指令，允许同 Warp 内线程直接交换寄存器数据，无需经过共享内存。

### 2.2 常用指令

```c
__shfl_sync(mask, var, srcLane);      // 从指定 lane 读取
__shfl_up_sync(mask, var, delta);     // 从 lane - delta 读取
__shfl_down_sync(mask, var, delta);   // 从 lane + delta 读取
__shfl_xor_sync(mask, var, laneMask); // 蝴蝶交换
```

### 2.3 优势

- 不需要共享内存。
- 不需要 `__syncthreads()`。
- 适合 Reduce、Scan、矩阵乘法累加等 Warp 内通信场景。

## 3. Occupancy 与资源分配

### 3.1 影响 Occupancy 的因素

每个 SM 上的资源是有限的：

| 资源 | 典型值（A100） |
| ---- | -------------- |
| 最大驻留 Warp 数 | 64 |
| 最大驻留线程数 | 2048 |
| 最大共享内存 | 164 KB |
| 寄存器文件 | 256 KB |

如果每个线程用 64 个寄存器，每个 block 256 线程，则一个 block 用 16KB 寄存器，一个 SM 最多同时驻留 4 个 block（1024 线程），Occupancy = 1024/2048 = 50%。

### 3.2 如何提高 Occupancy

- 减少寄存器使用（`--maxrregcount` 或 `launch_bounds`）。
- 减少共享内存使用。
- 调整 block size 到 128/256。
- 注意：高 Occupancy 不一定意味着高性能，关键看是否隐藏了内存延迟。

## 4. 同步与原子操作

### 4.1 同步原语

```c
__syncthreads();              // Block 内所有线程同步
__syncwarp(mask);             // Warp 内同步（默认 mask=0xffffffff）
__threadfence();              // 全局内存顺序保证
__threadfence_block();        // Block 内顺序保证
```

### 4.2 原子操作

```c
atomicAdd(addr, val);
atomicMax(addr, val);
atomicCAS(addr, compare, val);
```

原子操作全局序列化，性能较低。减少原子操作的方法：

- 先在共享内存做局部累加，再一次性写回全局内存。
- 使用 Warp Shuffle 在 Warp 内规约，减少原子次数。

```cuda
// coalesced_vs_stride.cu
#include <cuda_runtime.h>
#include <stdio.h>

#define N (1024 * 1024)

__global__ void coalesced_read(const float* in, float* out, int stride) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    int total_threads = gridDim.x * blockDim.x;
    float sum = 0.0f;
    for (int i = idx; i < N; i += total_threads) {
        int access_idx = (stride == 1) ? i : (i * stride) % N;
        sum += in[access_idx];
    }
    out[idx] = sum;
}

int main() {
    float *d_in, *d_out;
    cudaMalloc(&d_in, N * sizeof(float));
    cudaMalloc(&d_out, 1024 * sizeof(float));

    cudaEvent_t start, stop;
    cudaEventCreate(&start);
    cudaEventCreate(&stop);

    for (int stride : {1, 32, 1024}) {
        cudaEventRecord(start);
        coalesced_read<<<(N + 255) / 256, 256>>>(d_in, d_out, stride);
        cudaEventRecord(stop);
        cudaEventSynchronize(stop);
        float ms = 0;
        cudaEventElapsedTime(&ms, start, stop);
        printf("stride=%4d: %.3f ms\n", stride, ms);
    }

    cudaFree(d_in);
    cudaFree(d_out);
    return 0;
}
```

## 6. 常见误区

### 6.1 “共享内存一定比全局内存快”

共享内存快的前提是 bank conflict 少、复用率高。如果每个线程只读一次，不如直接合并访问全局内存。

### 6.2 “Occupancy 越高性能越高”

高 Occupancy 有助于隐藏延迟，但核心瓶颈可能是显存带宽或计算单元。如果 kernel 已经是 compute-bound，再提高 Occupancy 收益很小。

### 6.3 “原子操作可以无限用”

原子操作全局序列化，大量线程同时原子加会导致严重性能下降。应先在局部（共享内存/Warp Shuffle）规约。

## 7. 本节小结

1. 内存访问优化是 CUDA 性能调优的核心：合并访问、向量化加载、共享内存预取。
2. Warp Shuffle 可以在 Warp 内高效通信，避免共享内存和同步。
3. Occupancy 受寄存器、共享内存、block size 限制，需要权衡。
4. 同步和原子操作要慎用，过度同步和原子竞争会显著降低性能。
