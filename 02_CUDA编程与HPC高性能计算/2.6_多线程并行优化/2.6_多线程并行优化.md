# 2.6 多线程并行优化

## 课程概述

GPU 并不是高性能计算的唯一战场。在很多推理和训练场景中，CPU 仍然是关键执行单元：数据预处理、后处理、控制流、内存拷贝、某些算子（如 embedding lookup、NMS、后处理解码）在 CPU 上运行反而更高效。掌握 CPU 多线程并行优化，是完整 HPC 能力的必要组成。

本节把 CPU 多线程优化拆开：OpenMP 编程、NUMA 感知优化、CPU SIMD 向量化。学完本节后，你应该能够：

- 用 OpenMP 并行化循环，并理解线程调度、归约、原子操作。
- 识别 NUMA 架构对内存访问延迟的影响，做绑核与内存分配优化。
- 使用 SSE/AVX/AVX-512 或编译器自动向量化提升 CPU 吞吐。
- 判断一个算子是否适合 CPU 多线程优化。

## 1. OpenMP 多线程编程

### 1.1 基本并行化

OpenMP 通过编译指令（pragma）把串行代码并行化：

```cpp
#include <omp.h>

#pragma omp parallel for
for (int i = 0; i < N; ++i) {
    c[i] = a[i] + b[i];
}
```

### 1.2 线程数控制

```bash
export OMP_NUM_THREADS=16
```

```cpp
omp_set_num_threads(16);
```

### 1.3 常见子句

| 子句 | 作用 |
| ---- | ---- |
| `private(x)` | 每个线程有独立的 x |
| `shared(x)` | 所有线程共享 x |
| `reduction(+:sum)` | 每个线程维护局部 sum，最后合并 |
| `schedule(static, chunk)` | 静态分块 |
| `schedule(dynamic, chunk)` | 动态分块，负载不均时用 |
| `collapse(2)` | 合并两层循环并行 |

### 1.4 归约示例

```cpp
float sum = 0.0f;
#pragma omp parallel for reduction(+:sum)
for (int i = 0; i < N; ++i) {
    sum += a[i];
}
```

## 2. NUMA 感知优化

### 2.1 什么是 NUMA

NUMA（Non-Uniform Memory Access）架构下，每个 CPU socket 有自己的本地内存。线程访问本地内存快，访问远端 socket 的内存慢。

```text
Socket 0: CPU 0-15, Memory 0
Socket 1: CPU 16-31, Memory 1

Thread on CPU 0 accessing Memory 1 -> slow (cross-socket)
Thread on CPU 0 accessing Memory 0 -> fast (local)
```

### 2.2 NUMA 优化策略

1. **绑核（Affinity）**：把线程绑定到特定 CPU，避免 OS 调度导致跨 socket 访问。
2. **本地内存分配**：用 `numactl --membind` 或 `libnuma` 在本地节点分配内存。
3. **避免伪共享**：多个线程修改同一 cache line 的不同变量，导致缓存一致性流量。

### 2.3 OpenMP 绑核示例

```cpp
#pragma omp parallel
{
    int tid = omp_get_thread_num();
    cpu_set_t cpuset;
    CPU_ZERO(&cpuset);
    CPU_SET(tid, &cpuset);
    pthread_setaffinity_np(pthread_self(), sizeof(cpuset), &cpuset);
}
```

或使用 `numactl`：

```bash
numactl --cpunodebind=0 --membind=0 ./program
```

## 3. CPU SIMD 向量化

### 3.1 SIMD 概述

SIMD（Single Instruction, Multiple Data）让一条指令同时处理多个数据：

| 指令集 | 宽度 | 单指令 float 数 |
| ------ | ---- | --------------- |
| SSE    | 128 bit | 4 |
| AVX2   | 256 bit | 8 |
| AVX-512 | 512 bit | 16 |

### 3.2 编译器自动向量化

```cpp
#pragma GCC ivdep
for (int i = 0; i < N; ++i) {
    c[i] = a[i] + b[i];
}
```

编译选项：

```bash
g++ -O3 -march=native -ffast-math -o main main.cpp
```

### 3.3 手写 SIMD（AVX2 示例）

```cpp
#include <immintrin.h>

void add_avx2(const float* a, const float* b, float* c, int N) {
    int i = 0;
    for (; i + 8 <= N; i += 8) {
        __m256 va = _mm256_loadu_ps(a + i);
        __m256 vb = _mm256_loadu_ps(b + i);
        __m256 vc = _mm256_add_ps(va, vb);
        _mm256_storeu_ps(c + i, vc);
    }
    for (; i < N; ++i) c[i] = a[i] + b[i];
}
```

```cpp
// openmp_numa_simd.cpp
#include <omp.h>
#include <immintrin.h>
#include <iostream>
#include <vector>

void add_avx2(const float* a, const float* b, float* c, int N) {
    int i = 0;
    for (; i + 8 <= N; i += 8) {
        __m256 va = _mm256_loadu_ps(a + i);
        __m256 vb = _mm256_loadu_ps(b + i);
        __m256 vc = _mm256_add_ps(va, vb);
        _mm256_storeu_ps(c + i, vc);
    }
    for (; i < N; ++i) c[i] = a[i] + b[i];
}

int main() {
    const int N = 1024 * 1024;
    std::vector<float> a(N, 1.0f), b(N, 2.0f), c(N);

    #pragma omp parallel for
    for (int i = 0; i < N; ++i) {
        c[i] = a[i] + b[i];
    }

    float sum = 0.0f;
    #pragma omp parallel for reduction(+:sum)
    for (int i = 0; i < N; ++i) {
        sum += c[i];
    }

    add_avx2(a.data(), b.data(), c.data(), N);

    std::cout << "OpenMP threads: " << omp_get_max_threads() << ", sum: " << sum << std::endl;
    return 0;
}
```

## 5. 常见误区

### 5.1 “OpenMP 加一句 pragma 就能加速”

并行化有 overhead：线程创建、同步、负载均衡。如果循环体很小，并行化反而更慢。需要保证每个线程有足够工作量。

### 5.2 “NUMA 对推理没影响”

在多 socket 服务器上，如果 CPU 后处理算子跨 socket 访问内存，延迟可能翻倍。绑核和本地内存分配能显著改善。

### 5.3 “手写 SIMD 一定比编译器向量化好”

现代编译器向量化能力很强。手写 SIMD 只在特定场景（如复杂 reduction、特殊数据布局）下有优势，且可移植性差。

---

## 6. 本节小结

1. OpenMP 是 CPU 多线程并行化的快速入口，注意线程数、调度、归约、原子操作。
2. NUMA 架构下，绑核与本地内存分配对性能影响显著。
3. SIMD 向量化可提升 CPU 吞吐，但要避免手写过度复杂。
4. CPU 优化常与 GPU 协同：数据预处理、控制流、不适合 GPU 的算子可考虑 CPU 优化。
