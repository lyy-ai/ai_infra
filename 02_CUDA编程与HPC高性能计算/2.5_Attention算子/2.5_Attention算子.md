# 2.5 Attention 算子

## 课程概述

Attention 是大语言模型的核心算子，也是推理和训练中最主要的性能瓶颈之一。标准 Self-Attention 的显存复杂度是 $O(N^2)$，计算复杂度是 $O(N^2 d)$，在长序列场景下很容易把 GPU 算力和显存带宽打满。

本节把 Attention 算子的演进拆开：FlashAttention V1/V2/V3、Flash-Decoding、PagedAttention、FlashInfer。学完本节后，你应该能够：

- 解释标准 Self-Attention 的内存墙问题。
- 说明 FlashAttention 的 Tiling 和 Online Softmax 思想。
- 区分 FlashAttention V1/V2/V3 的优化差异。
- 理解 Flash-Decoding 如何加速长序列 decode。
- 说明 PagedAttention 的 KV Cache 分块管理机制。
- 了解 FlashInfer 的可组合 Attention 引擎设计。

---

## 1. 标准 Self-Attention

### 1.1 计算公式

$$
O = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V
$$

其中：

- $Q, K, V \in \mathbb{R}^{N \times d}$
- $S = QK^T \in \mathbb{R}^{N \times N}$
- $P = \text{softmax}(S) \in \mathbb{R}^{N \times N}$
- $O = PV \in \mathbb{R}^{N \times N} \cdot \mathbb{R}^{N \times d} = \mathbb{R}^{N \times d}$

### 1.2 内存墙问题

标准实现需要显式构造 $N \times N$ 的 Attention Score 矩阵：

```text
S = QK^T     -> N x N
P = softmax(S) -> N x N
O = PV       -> N x d
```

当 $N$ 很大时（如 32K、128K），$N \times N$ 矩阵会占用大量显存，并且导致 HBM 读写成为瓶颈。

---

## 2. FlashAttention V1

### 2.1 核心思想

FlashAttention 的核心是 **Tiling + Online Softmax + Recompute**，避免显式构造完整的 $N \times N$ 矩阵。

### 2.2 Tiling

把 Q、K、V 按行/列分成小块（Tile），每次只加载一小块到 SRAM（共享内存/寄存器），计算局部的 Attention 结果，然后逐步累加。

### 2.3 Online Softmax

Softmax 的分母是所有元素的指数和。如果不保存完整矩阵，无法一次性计算 softmax。Online Softmax 通过维护**局部最大值**和**局部指数和**，在分块计算中逐步修正结果。

$$
m_{new} = \max(m_{old}, m_{tile})\\
l_{new} = e^{m_{old} - m_{new}} \cdot l_{old} + \sum_{i \in tile} e^{x_i - m_{new}}
$$

### 2.4 重计算（Recompute）

反向传播时不保存 $N \times N$ 的 $P$ 矩阵，而是重新计算 $S$ 和 $P$。虽然增加了计算量，但大幅减少了显存占用和 HBM 访问。

---

## 3. FlashAttention V2

FlashAttention V2 主要在 V1 基础上做了工程优化：

### 3.1 减少非 matmul 工作量

- 优化了 Online Softmax 的流水线。
- 减少了 Warp 间的同步和数据搬运。

### 3.2 更好的 Warp 划分

把 Q 的 tile 分给不同 Warp，每个 Warp 独立计算自己的输出，减少跨 Warp 通信。

### 3.3 支持更多序列长度和 head dim

V2 在不同 shape 下的性能更稳定，支持更长的序列。

---

## 4. FlashAttention V3

FlashAttention V3 进一步优化了 Hopper 架构：

- 利用 **Tensor Core FP8** 加速。
- 支持 **TMA（Tensor Memory Accelerator）** 异步加载。
- 使用 **WGMMA（Warp Group Matrix Multiply Accumulate）** 提升吞吐。
- 更强的动态调度能力。

---

## 5. Flash-Decoding / FlashDecoding++

### 5.1 Decode 阶段的瓶颈

在 LLM 推理的 decode 阶段，每次只生成一个 token，但 Key/Value 序列很长。标准 Attention 需要加载所有 K/V，导致：

- 计算量小，但内存访问量大。
- 一个 query 对应大量 key，无法有效利用 GPU 并行。

### 5.2 Flash-Decoding 思想

把 Key/Value 分成多个块（chunk），每个 chunk 用一个 thread block 并行计算局部 softmax，最后合并结果。

```text
q (1 x d) 与 k_i (B x d) 计算 -> local attention output
多个 local output 通过 online softmax 合并 -> 最终 output
```

这样可以用更多线程并行加载 K/V，提高吞吐。

---

## 6. PagedAttention

### 6.1 KV Cache 管理问题

在 LLM serving 中，每个请求需要一个 KV Cache。传统方式按最大长度连续分配，导致：

- 显存碎片。
- 无法共享前缀。
- 动态 batch 调度困难。

### 6.2 PagedAttention 思想

把 KV Cache 分成固定大小的 block（如 16 tokens），像操作系统虚拟内存一样管理。这样可以：

- 按需分配 block，减少碎片。
- 不同请求共享 prefix block。
- 支持动态调度、抢占、重计算。

```text
请求 A: [block0, block1, block3, block5]
请求 B: [block0, block1, block4]
                  ^ 共享 block0/block1
```

---

## 7. FlashInfer

FlashInfer 是一个可组合 Attention 引擎，目标是：

- 统一 Mask、KV layout、page table 等抽象。
- 支持 Batch Decode、Batch Prefill、Append KV 等操作。
- 用户只需组合不同 primitive，无需手写每种 Attention 变体。

```text
FlashInfer primitives:
  - single_query_kv_attention
  - batch_prefill
  - batch_decode
  - append_kv_cache
```

## 9. 常见误区

### 9.1 “FlashAttention 减少了计算量”

FlashAttention 没有减少 FLOPs，反而因为重计算增加了计算量。它的优势是**减少 HBM 访问**，把计算强度提升到片上 SRAM 能承载的范围。

### 9.2 “FlashAttention 适合所有序列长度”

对于短序列，FlashAttention 的 Tiling 开销可能反而不如朴素 Attention。通常在 N ≥ 1K 时收益明显。

### 9.3 “PagedAttention 只和 vLLM 相关”

PagedAttention 的核心是分块 KV Cache 管理，这种思想已经被多种推理框架采用，不局限于 vLLM。

---

## 10. 本节小结

1. 标准 Attention 需要 $O(N^2)$ 显存，FlashAttention 通过 Tiling + Online Softmax 避免显式构造完整矩阵。
2. FlashAttention V1 提出核心思想，V2 优化 Warp 划分和非 matmul 开销，V3 针对 Hopper 引入 FP8/TMA/WGMMA。
3. Flash-Decoding 解决 decode 阶段 K/V 长序列加载瓶颈。
4. PagedAttention 通过 block 化 KV Cache 管理显存、减少碎片、支持共享。
5. FlashInfer 提供可组合的 Attention primitive，降低手写变体成本。
