# 2.4 经典算子实现 - GEMM

## 课程概述

GEMM（General Matrix Multiply，通用矩阵乘法）是深度学习计算的核心。Transformer 中的 Attention、MLP，卷积中的 im2col+GEMM，都高度依赖 GEMM 的性能。NVIDIA 的 cuBLAS 和 CUTLASS 已经把 GEMM 优化到了极致，但理解手写 GEMM 的优化过程，是进入 HPC 算子开发的第一步。

本节把 GEMM 从数学原理到硬件实现拆开：矩阵乘法计算特性、Tile Blocking、Shared Memory Tiling、Tensor Core/WMMA、与 cuBLAS 性能对比。学完本节后，你应该能够：

- 解释为什么 GEMM 需要分块（Tiling）才能充分利用显存带宽和计算。
- 实现一个基于 Shared Memory Tiling 的 SGEMM。
- 理解 Tensor Core 的 m16n8k16 矩阵乘模式。
- 使用 WMMA API 调用 Tensor Core。
- 分析手写 kernel 与 cuBLAS 的差距。

## 1. 矩阵乘法数学原理

C = A × B，形状分别为 M×K、K×N、M×N：

$$
C_{m,n} = \sum_{k=0}^{K-1} A_{m,k} \cdot B_{k,n}
$$

朴素实现中，每个线程计算 C 的一个元素，需要读取 A 的一行和 B 的一列。计算强度：

$$
\text{arithmetic intensity} = \frac{2 \cdot M \cdot N \cdot K}{M \cdot K + K \cdot N + M \cdot N} \approx 2N \quad (\text{当 } M,N \gg K)
$$

如果每个元素只访问一次 A/B，全局内存访问次数为 `M*K + K*N`，计算量为 `2*M*N*K`。当 M,N,K 较大时，计算强度足以隐藏内存延迟，但前提是**数据必须留在片上**。

---

## 2. 为什么需要 Tiling

### 2.1 无 Tiling 的问题

每个线程读取 A 的一行（K 个元素）和 B 一列（K 个元素），写入 C 一个元素。全局内存访问量为 `M*N*2K`（忽略 C 的写回）。

如果 K 很大，每个元素只被计算线程使用一次，没有复用，带宽成为瓶颈。

### 2.2 Tile Blocking

把 C 分成大小为 BM×BN 的块，每个 block 负责一个 Tile。block 内线程协作：

- 把 A 的 BM×BK 子块加载到共享内存。
- 把 B 的 BK×BN 子块加载到共享内存。
- 每个线程计算自己负责的子块内的部分和。
- 沿 K 维度滑动，复用加载到共享内存的数据。

```text
C_tile (BM x BN) = sum over K tiles: A_tile (BM x BK) * B_tile (BK x BN)
```

这样，A_tile 被 BN 个线程复用，B_tile 被 BM 个线程复用。

## 3. Shared Memory Tiling

### 3.1 算法流程

```text
For each C_tile (BM x BN) assigned to this block:
    Initialize accumulators in registers (TM x TN per thread)
    For k_step = 0 to K/BK:
        Load A_tile (BM x BK) from global to shared memory
        Load B_tile (BK x BN) from global to shared memory
        __syncthreads()
        For kk = 0 to BK:
            Each thread loads A_frag from shared memory (TM elements)
            Each thread loads B_frag from shared memory (TN elements)
            accumulators += A_frag * B_frag (outer product)
        __syncthreads()
    Write accumulators back to C_tile in global memory
```

### 3.2 线程分工

- block size = 256 threads。
- 每个 block 负责 128×128 的 C_tile。
- 每个线程负责 8×8 的子块（TM=8, TN=8）。
- 一个 block 计算 128×128 = 256×(8×8)，刚好 256 线程。

## 4. Tensor Core 与 WMMA

### 4.1 为什么需要 Tensor Core

Tensor Core 是专门用于矩阵乘累的硬件单元，每个 Tensor Core 每周期可以完成：

```text
D = A * B + C
```

其中 A: m16×k8(fp16/bf16) 或 m16×k16(int8)，B: k×n8，C/D: m16×n8。

### 4.2 WMMA API

```cuda
#include <mma.h>
using namespace nvcuda::wmma;

fragment<matrix_a, 16, 16, 16, half, col_major> a_frag;
fragment<matrix_b, 16, 16, 16, half, col_major> b_frag;
fragment<accumulator, 16, 16, 16, half> c_frag;

wmma::load_matrix_sync(a_frag, A + offset, lda);
wmma::load_matrix_sync(b_frag, B + offset, ldb);
wmma::mma_sync(c_frag, a_frag, b_frag, c_frag);
wmma::store_matrix_sync(C + offset, c_frag, ldc, mem_col_major);
```

### 4.3 Tensor Core vs CUDA Core

- CUDA Core：每个 SM 每周期完成少量 FMA。
- Tensor Core：每个 SM 每周期完成一个 16×16×16 的矩阵乘累加。
- FP16 Tensor Core 吞吐通常是 FP32 CUDA Core 的 8~16 倍。

## 5. 与 cuBLAS 性能对比

手写 GEMM 通常只能达到 cuBLAS/CUTLASS 的 30%~70%，原因：

- cuBLAS 有专家调优的调度、padding、swizzle、split-k 等。
- 针对具体 GPU 架构（SM 数量、显存带宽、L2 cache 大小）做优化。
- 使用 PTX/SASS 级优化，如 `ldmatrix`、`mma.sync.aligned`、double buffer。

但作为学习，手写 GEMM 可以帮助理解：

- 为什么 CUTLASS 的分层抽象如此设计。
- 如何定位自己的 kernel 是带宽还是计算瓶颈。
- 何时值得手写，何时应该直接调用 cuBLAS。

```cuda
// sgemm_tiled.cu
#include <cuda_runtime.h>
#include <stdio.h>

#define BM 128
#define BN 128
#define BK 8
#define TM 8
#define TN 8

__global__ void sgemm_tiled(const float* A, const float* B, float* C,
                            int M, int N, int K) {
    __shared__ float As[BM][BK];
    __shared__ float Bs[BK][BN];

    int tx = threadIdx.x;
    int bx = blockIdx.x, by = blockIdx.y;

    // 每个线程负责 TM x TN 的子块
    int thread_row = tx / (BN / TN);
    int thread_col = tx % (BN / TN);

    float acc[TM][TN] = {0.0f};

    // A/B 在全局内存中的起始位置
    const float* A_block = A + by * BM * K;
    const float* B_block = B + bx * BN;

    int num_k_tiles = (K + BK - 1) / BK;

    for (int kt = 0; kt < num_k_tiles; ++kt) {
        // 协同加载 A_tile 到共享内存
        for (int i = tx; i < BM * BK; i += blockDim.x) {
            int r = i / BK;
            int c = i % BK;
            int a_row = by * BM + r;
            int a_col = kt * BK + c;
            As[r][c] = (a_row < M && a_col < K) ? A[a_row * K + a_col] : 0.0f;
        }
        // 协同加载 B_tile 到共享内存
        for (int i = tx; i < BK * BN; i += blockDim.x) {
            int r = i / BN;
            int c = i % BN;
            int b_row = kt * BK + r;
            int b_col = bx * BN + c;
            Bs[r][c] = (b_row < K && b_col < N) ? B[b_row * N + b_col] : 0.0f;
        }
        __syncthreads();

        // 计算 TM x TN 子块
        for (int kk = 0; kk < BK; ++kk) {
            float a_frag[TM], b_frag[TN];
            for (int i = 0; i < TM; ++i) a_frag[i] = As[thread_row * TM + i][kk];
            for (int j = 0; j < TN; ++j) b_frag[j] = Bs[kk][thread_col * TN + j];
            for (int i = 0; i < TM; ++i)
                for (int j = 0; j < TN; ++j)
                    acc[i][j] += a_frag[i] * b_frag[j];
        }
        __syncthreads();
    }

    // 写回 C
    for (int i = 0; i < TM; ++i) {
        for (int j = 0; j < TN; ++j) {
            int c_row = by * BM + thread_row * TM + i;
            int c_col = bx * BN + thread_col * TN + j;
            if (c_row < M && c_col < N) {
                C[c_row * N + c_col] = acc[i][j];
            }
        }
    }
}

int main() {
    int M = 1024, N = 1024, K = 1024;
    size_t size_A = M * K * sizeof(float);
    size_t size_B = K * N * sizeof(float);
    size_t size_C = M * N * sizeof(float);

    float *d_A, *d_B, *d_C;
    cudaMalloc(&d_A, size_A);
    cudaMalloc(&d_B, size_B);
    cudaMalloc(&d_C, size_C);

    dim3 block((BM / TM) * (BN / TN));
    dim3 grid((N + BN - 1) / BN, (M + BM - 1) / BM);
    sgemm_tiled<<<grid, block>>>(d_A, d_B, d_C, M, N, K);

    printf("SGEMM tiled kernel launched: grid=(%d,%d), block=%d\n", grid.x, grid.y, block.x);

    cudaFree(d_A);
    cudaFree(d_B);
    cudaFree(d_C);
    return 0;
}
```

## 7. 常见误区

### 7.1 “手写 GEMM 能打败 cuBLAS”

一般不能。cuBLAS 经过数年优化和针对具体架构调优。手写 GEMM 的价值在于学习和特定小场景的定制。

### 7.2 “Tile 越大越好”

Tile 越大，共享内存占用越多，每个 SM 能同时驻留的 block 越少，Occupancy 下降。需要权衡复用率和资源占用。

### 7.3 “Tensor Core 一定比 CUDA Core 快”

Tensor Core 适合矩阵乘累加密集场景。如果精度要求 FP32，或者矩阵形状不满足 m16n8k16 的倍数，需要先 padding，可能引入额外开销。

---

## 8. 本节小结

1. GEMM 计算强度高，但需要 Tiling 把数据复用提升到片上。
2. Shared Memory Tiling 是手写 GEMM 的核心优化。
3. 线程分工设计决定寄存器压力和并行效率。
4. Tensor Core/WMMA 可以大幅提升 FP16/BF16/INT8 GEMM 吞吐。
5. 手写 GEMM 与 cuBLAS 对比时，要关注具体 shape、精度、是否用 Tensor Core。
