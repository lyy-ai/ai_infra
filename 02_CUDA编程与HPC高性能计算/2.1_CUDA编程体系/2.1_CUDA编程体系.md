# 2.1 CUDA 编程体系

## 课程概述

CUDA 是 NVIDIA GPU 的并行计算平台与编程模型。掌握 CUDA 编程体系是理解深度学习推理与训练性能优化的基础：无论是手写 kernel、调优 PyTorch/TVM 生成的 CUDA 代码，还是与 cuBLAS/cuDNN/TensorRT 打交道，都离不开对 Grid/Block/Thread、内存层级、Warp 执行模型的理解。

很多初学者把 CUDA 理解成“在 GPU 上写 C++”，但 CUDA 与普通 C++ 最大的区别在于**线程组织模型和内存层级**。GPU 是 SIMT（Single Instruction, Multiple Threads）架构，成千上万个线程以特定层级执行同一段代码，访问不同层级的内存。忽略这些特性，写出来的 kernel 可能只有 CPU 级别的性能。

本节把 CUDA 编程体系拆开：线程组织模型、内存模型、Warp 执行模型、关键优化概念、Kernel Launch 配置。学完本节后，你应该能够：

- 画出 CUDA 的 Grid/Block/Thread 层级，并正确计算线程索引。
- 解释全局内存、共享内存、寄存器、常量内存的位置、速度与作用域。
- 说明 Warp 是最小调度单位，以及为什么分支发散会损害性能。
- 识别 Bank Conflict、Coalesced Access、Occupancy 对性能的影响。
- 选择合适的 Kernel Launch 配置（block size、grid size、共享内存大小）。

## 1. CUDA 线程组织模型

### 1.1 Grid / Block / Thread

CUDA 程序启动一个 kernel 时，会生成一个由线程组成的网格：

```text
Grid: 一个 Kernel Launch 产生的所有线程
  ├── Block (0,0)        Block (1,0)        ...
  │     ├── Thread(0,0)  Thread(0,0)
  │     ├── Thread(1,0)  Thread(1,0)
  │     └── ...          ...
  └── Block (0,1)
        └── ...
```

- **Grid**：整个 kernel 的所有线程，最多三维（gridDim.x, gridDim.y, gridDim.z）。
- **Block**：一组线程，最多三维（blockDim.x, blockDim.y, blockDim.z），一个 Block 内的线程可以通过共享内存和 `__syncthreads()` 协作。
- **Thread**：单个执行单元，有唯一的线程索引 `threadIdx`。

### 1.2 线程索引计算

一维：

```c
int idx = blockIdx.x * blockDim.x + threadIdx.x;
```

二维：

```c
int row = blockIdx.y * blockDim.y + threadIdx.y;
int col = blockIdx.x * blockDim.x + threadIdx.x;
int width = gridDim.x * blockDim.x;
int idx = row * width + col;
```

### 1.3 Block 大小选择

- 一个 Block 的线程数通常是 32 的倍数（Warp 大小）。
- 常见选择：128、256、512、1024。
- 受限于寄存器、共享内存、最大线程数（通常 1024/block）。

## 2. CUDA 内存模型

```text
┌─────────────────────────────────────┐
│           Host（CPU）内存             │  可访问，通过 cudaMemcpy 与 Device 交互
├─────────────────────────────────────┤
│         Global Memory（全局内存）      │  所有线程可访问，容量大，延迟高（几百 cycle）
├─────────────────────────────────────┤
│         Constant Memory（常量内存）    │  只读，缓存，适合广播式读取
├─────────────────────────────────────┤
│        Shared Memory（共享内存）       │  同 Block 内线程共享，低延迟（~30 cycle）
│           分为 32 个 bank            │  需要避免 Bank Conflict
├─────────────────────────────────────┤
│        Registers（寄存器）             │  每个线程私有，最快，数量有限
└─────────────────────────────────────┘
```

### 2.1 全局内存

- 所有线程可访问，容量等于显存。
- 访问延迟高，但通过 Coalesced Access（合并访问）可以高效利用显存带宽。
- 合并访问条件：相邻线程访问相邻地址。

### 2.2 共享内存

- 同 Block 内所有线程可访问。
- 通常 48KB~164KB/SM（取决于架构），可按 4B 划分为 32 个 bank。
- 适合 Tile 分块、数据复用、线程间通信。

### 2.3 寄存器

- 每个线程私有，数量由 SM 决定。
- 寄存器溢出会导致数据放到 Local Memory（全局内存的一部分），性能急剧下降。

### 2.4 常量内存

- 只读，有常量缓存，适合广播读取。
- 若线程访问不同地址，会串行化，反而慢。

## 3. Warp 执行模型

### 3.1 Warp 是最小调度单位

- 一个 Warp 固定包含 32 个线程。
- 同一个 Warp 内的线程执行相同的指令。
- Warp 内的线程以 lock-step 方式执行。

### 3.2 线程发散（Branch Divergence）

```c
if (threadIdx.x % 2 == 0) {
    // path A
} else {
    // path B
}
```

Warp 内线程走不同分支时，硬件会串行执行两个路径，另一个路径的线程被 mask 掉。虽然结果正确，但性能下降。

优化方法：

- 让同一 Warp 内线程尽量走同一路径。
- 按 Warp 对齐数据或任务分配。

## 4. 关键优化概念

### 4.1 Coalesced Access（合并访问）

全局内存访问模式：

```text
理想：Thread i 访问地址 base + i * 4
      访存请求可被合并为少量 cache line 传输

糟糕：Thread i 访问地址 base + i * 1024
      每个线程触发独立 cache line，带宽利用率低
```

### 4.2 Bank Conflict（存储体冲突）

共享内存按 32-bit 划分为 32 个 bank。若同一 Warp 内多个线程同时访问同一 bank 的不同地址，会触发 bank conflict，访问被串行化。

避免方法：

- 按 32 间隔访问（pad）避免冲突。
- 例如共享内存矩阵转置时，在行主序写入后按列读取需要 padding。

### 4.3 Occupancy（占用率）

Occupancy = 每个 SM 上实际驻留的 Warp 数 / 最大可驻留 Warp 数。

影响因素：

- 每个线程的寄存器数量。
- 每个 Block 的共享内存大小。
- 每个 Block 的线程数。
- 最大并发 Block 数限制。

高 Occupancy 不一定代表高性能，但可以隐藏内存延迟。

## 5. Kernel Launch 与执行配置

### 5.1 启动语法

```c
kernel<<<grid_dim, block_dim, shared_mem_bytes, stream>>>(args...);
```

- `grid_dim`：Grid 维度。
- `block_dim`：Block 维度。
- `shared_mem_bytes`：动态共享内存大小（静态共享内存由 `__shared__` 声明）。
- `stream`：CUDA Stream，默认 0。

### 5.2 配置示例

```c
// 一维配置
add_kernel<<<(N + 255) / 256, 256>>>(d_a, d_b, d_c, N);

// 二维配置（图像处理）
dim3 block(16, 16);
dim3 grid((W + 15) / 16, (H + 15) / 16);
img_kernel<<<grid, block>>>(d_img, W, H);
```

```cuda
// thread_indexing.cu
#include <cuda_runtime.h>
#include <stdio.h>

__global__ void indexing_kernel(int* out, int width, int height) {
    int col = blockIdx.x * blockDim.x + threadIdx.x;
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    if (row < height && col < width) {
        int idx = row * width + col;
        int block_id = blockIdx.y * gridDim.x + blockIdx.x;
        int thread_id = threadIdx.y * blockDim.x + threadIdx.x;
        out[idx] = block_id * 10000 + thread_id;
    }
}

int main() {
    const int W = 32, H = 16;
    int* d_out;
    cudaMalloc(&d_out, W * H * sizeof(int));

    dim3 block(16, 8);
    dim3 grid((W + block.x - 1) / block.x, (H + block.y - 1) / block.y);
    indexing_kernel<<<grid, block>>>(d_out, W, H);

    int h_out[W * H];
    cudaMemcpy(h_out, d_out, W * H * sizeof(int), cudaMemcpyDeviceToHost);
    for (int i = 0; i < W * H; ++i) {
        if (i % W == 0) printf("\n");
        printf("%6d ", h_out[i]);
    }
    printf("\n");
    cudaFree(d_out);
    return 0;
}
```

## 7. 常见误区

### 7.1 “线程数越多越快”

线程数过多会导致寄存器压力和低 Occupancy。需要平衡 block size、共享内存、寄存器。

### 7.2 “共享内存一定快”

共享内存虽然低延迟，但有 bank conflict 风险，且容量有限。滥用共享内存不一定比全局内存合并访问快。

### 7.3 “分支发散无所谓”

Warp 内分支发散会导致串行执行，性能显著下降。应尽量避免同一 Warp 内走不同分支。

## 8. 本节小结

1. CUDA 线程组织为 Grid/Block/Thread，线程索引计算是 kernel 正确性的基础。
2. 内存层级从高到低：全局内存、常量内存、共享内存、寄存器。
3. Warp 是最小调度单位，32 个线程 lock-step 执行，分支发散会损害性能。
4. 合并访问、避免 bank conflict、合理 Occupancy 是 CUDA 性能优化的关键。
5. Kernel Launch 需要配置 grid、block、共享内存、stream。
