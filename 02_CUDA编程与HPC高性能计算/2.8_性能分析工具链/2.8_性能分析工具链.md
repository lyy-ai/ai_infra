# 2.8 性能分析工具链

## 课程概述

性能优化不能只靠直觉，必须用工具说话。CUDA/HPC 领域有成熟的性能分析工具链，从系统级到 kernel 级、从 CPU-GPU 交互到指令级，都有对应工具。

本节把性能分析工具链拆开：Nsight Systems、Nsight Compute、PyTorch Profiler、Roofline 模型。学完本节后，你应该能够：

- 使用 Nsight Systems 分析 CPU-GPU 交互全链路。
- 使用 Nsight Compute 下钻单个 kernel，解读 SOL 面板。
- 使用 PyTorch Profiler 定位 Python 层的瓶颈。
- 用 Roofline 模型判断 kernel 是 compute-bound 还是 memory-bound。

---

## 1. Nsight Systems

### 1.1 定位

Nsight Systems 是**系统级**性能分析工具，关注：

- CPU 线程调度。
- CUDA kernel launch 时序。
- Host-Device 内存拷贝。
- Stream/Event 同步。

### 1.2 常用命令

```bash
nsys profile -o report ./program
nsys-ui report.nsys-rep
```

### 1.3 典型分析场景

```text
Timeline 上发现 kernel 之间存在大量空白：
  → CPU launch overhead 高？
  → 内存拷贝阻塞了 compute？
  → 同步点过多？
```

### 1.4 关键指标

- **CPU call stack**：哪些函数在 launch kernel。
- **CUDA API timeline**：cudaLaunchKernel、cudaMemcpy、cudaStreamSynchronize 耗时。
- **GPU busy gap**：GPU 空闲时间段及其原因。

---

## 2. Nsight Compute

### 1.1 定位

Nsight Compute 是**kernel 级**性能分析工具，关注单个 CUDA kernel：

- 内存带宽利用率。
- 计算单元利用率。
- Occupancy、寄存器压力、共享内存 bank conflict。
- Warp stall reason。

### 1.2 常用命令

```bash
ncu -o profile ./program
ncu-ui profile.ncu-rep
```

### 1.3 SOL（Speed Of Light）面板

SOL 面板告诉你 kernel 离理论峰值有多远：

| 指标 | 含义 |
| ---- | ---- |
| Memory SOL | 显存带宽利用率 |
| Compute SOL | 计算单元利用率 |
| SM SOL | SM 整体利用率 |

解读：

- **Memory SOL 高，Compute SOL 低** → memory-bound，优化方向：合并访问、共享内存、减少数据搬运。
- **Compute SOL 高，Memory SOL 低** → compute-bound，优化方向：更多 FMA、Tensor Core、减少分支。

### 1.4 常用 Metrics

```bash
ncu --metrics \
  sm__throughput.avg.pct_of_peak_sustained_elapsed,\
  dram__throughput.avg.pct_of_peak_sustained_elapsed,\
  l1tex__t_sectors_pipe_lsu_mem_global_op_ld.sum,\
  smsp__warps_active.avg.pct_of_peak_sustained_elapsed \
  ./program
```

## 3. PyTorch Profiler

### 3.1 定位

PyTorch Profiler 适合分析 Python 层和 PyTorch 算子层：

- 哪些算子耗时最长。
- CPU/GPU 时间比例。
- 内存分配曲线。

### 3.2 使用方式

```python
from torch.profiler import profile, ProfilerActivity

with profile(activities=[ProfilerActivity.CPU, ProfilerActivity.CUDA]) as prof:
    model(input)

print(prof.key_averages().table(sort_by="cuda_time_total"))
prof.export_chrome_trace("trace.json")
```

### 3.3 关键指标

- `cpu_time_total`
- `cuda_time_total`
- `self_cuda_memory_usage`
- `aten::` 算子热点

## 4. Roofline 模型

### 4.1 模型定义

Roofline 模型用两条线描述硬件性能上限：

- **Memory bandwidth roof**：$y = \beta \cdot I$
- **Compute peak roof**：$y = \pi$

其中：

- $I$：计算强度（FLOPs/Byte）。
- $\beta$：峰值显存带宽。
- $\pi$：峰值算力。

### 4.2 判断瓶颈

```text
若 kernel 落在 memory-bound 区域：
  → 优化数据搬运，提升 I

若 kernel 落在 compute-bound 区域：
  → 优化计算，提升 FLOPs/s
```

### 4.3 计算强度计算

以 SGEMM 为例：

$$
I = \frac{2 \cdot M \cdot N \cdot K}{M \cdot K + K \cdot N + M \cdot N} \text{ [FLOPs/Byte]}
$$

```python
# roofline_calc.py
"""计算并绘制简单 Roofline 模型"""
import numpy as np
import matplotlib.pyplot as plt


def plot_roofline(peak_tflops, peak_bw_tbs, save_path="roofline.png"):
    I = np.logspace(-2, 4, 500)  # FLOPs/Byte
    memory_roof = peak_bw_tbs * I  # TFLOPs
    compute_roof = np.full_like(I, peak_tflops)
    attainable = np.minimum(memory_roof, compute_roof)

    plt.figure(figsize=(8, 6))
    plt.loglog(I, memory_roof, "--", label=f"Memory Bandwidth {peak_bw_tbs} TB/s")
    plt.loglog(I, compute_roof, "--", label=f"Compute Peak {peak_tflops} TFLOPs")
    plt.loglog(I, attainable, "-", label="Attainable Performance", linewidth=2)
    plt.xlabel("Arithmetic Intensity (FLOPs/Byte)")
    plt.ylabel("Performance (TFLOPs/s)")
    plt.title("Roofline Model")
    plt.legend()
    plt.grid(True, which="both", ls="--")
    plt.savefig(save_path)
    print(f"Roofline plot saved to {save_path}")


def main():
    # A100 参考值
    peak_tflops = 312  # TFLOPS FP16/FP32 mixed
    peak_bw_tbs = 2.0  # TB/s
    plot_roofline(peak_tflops, peak_bw_tbs, "2.8_性能分析工具链/roofline.png")

    # 示例：计算一个 SGEMM 的计算强度
    M = N = K = 4096
    flops = 2 * M * N * K
    bytes_moved = (M * K + K * N + M * N) * 4  # FP32
    intensity = flops / bytes_moved
    print(f"SGEMM {M}x{N}x{K} intensity: {intensity:.2f} FLOPs/Byte")
    print(f"Memory-bound threshold: {peak_tflops / peak_bw_tbs:.2f} FLOPs/Byte")
    if intensity < peak_tflops / peak_bw_tbs:
        print("This kernel is likely MEMORY-BOUND")
    else:
        print("This kernel is likely COMPUTE-BOUND")


if __name__ == "__main__":
    main()
```

## 6. 常见误区

### 6.1 “Nsight Systems 和 Nsight Compute 二选一”

两者互补：Systems 看全局时序和交互，Compute 看单个 kernel 内部。通常先用 Systems 定位慢 kernel，再用 Compute 下钻。

### 6.2 “Memory SOL 100% 就是最优”

Memory SOL 高只说明带宽打满，但不一定是好事。如果 kernel 本可以 compute-bound，却因为算法设计导致 memory-bound，仍有优化空间。

### 6.3 “Roofline 只算理论值”

Roofline 是设计阶段的快速判断工具，但最终性能还要看具体实现、Occupancy、bank conflict、同步等细节。

## 7. 本节小结

1. Nsight Systems 用于分析系统级 timeline：kernel launch、memcpy、同步。
2. Nsight Compute 用于下钻单个 kernel：SOL、memory/compute 利用率、stall reason。
3. PyTorch Profiler 适合 Python/PyTorch 层的热点分析。
4. Roofline 模型帮助快速判断 kernel 是 compute-bound 还是 memory-bound。
