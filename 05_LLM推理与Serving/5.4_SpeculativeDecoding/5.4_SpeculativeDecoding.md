# 5.4 Speculative Decoding（投机解码）

## 课程概述

在前面的课程中，我们学习了如何通过 **PagedAttention**、**KV Cache 管理** 和 **Continuous Batching** 提升 LLM 推理的吞吐。但这些优化本质上都着眼于**更好地利用现有计算资源**。

本节课将介绍另一种完全不同的加速思路：**Speculative Decoding（投机解码）**，它通过让模型一次尝试生成多个 token，再用大模型并行验证，从而打破传统自回归“一次只生成一个 token”的限制。

学完本节后，你将能够：

1. 理解 Speculative Decoding 的核心思想：用小模型（Draft）快速猜测，用大模型（Target）并行验证。
2. 掌握 Rejection Sampling 算法，理解为什么它能保证生成分布与原始大模型完全一致。
3. 了解 Medusa、EAGLE-2 等免 Draft 模型或动态 Draft Tree 的进阶方案。
4. 清楚 Speculative Decoding 的收益边界：什么场景下加速明显，什么场景下反而会变慢。
5. 通过模拟代码直观感受 Speculative Decoding 的加速效果。

---

## 1. 为什么需要 Speculative Decoding？

### 1.1 LLM 推理的瓶颈

在 Decode 阶段，LLM 每步只生成一个 token。这意味着：

- 每次 forward 都要读取整个模型的权重。
- 大部分时间消耗在内存访问（memory-bound）上，而不是计算本身。
- 生成 N 个 token 需要 N 次完整的模型 forward。

如果我们能让大模型一次验证多个候选 token，就可以用更少的 forward 次数生成同样多的 token，从而显著加速。

### 1.2 关键观察

**观察 1：小模型生成速度快，但质量低。**  
一个小模型（如 7B）的推理速度可能是大模型（如 70B）的 3-5 倍，但生成的 token 质量不如大模型。

**观察 2：大模型验证多个 token 的成本与验证一个 token 相近。**  如果候选 token 已经在 KV Cache 中，大模型一次 forward 可以计算所有候选位置的 logits，成本增加很小。

**观察 3：小模型猜对的 token 可以直接被大模型接受。**  即使小模型只有 60-80% 的准确率，只要猜对一部分，整体 forward 次数就能减少。

### 1.3 核心思想

Speculative Decoding 的基本流程：

1. 使用**小模型（Draft Model）**快速自回归生成 K 个候选 token。
2. 将这 K 个候选 token 一次性输入**大模型（Target Model）**。
3. 大模型并行计算每个候选位置的 logits，判断哪些候选 token 可以接受。
4. 使用 **Rejection Sampling** 保证接受后的联合分布与直接用大模型生成一致。
5. 从第一个被拒绝的位置重新采样一个 token，然后继续下一轮。

## 2. Speculative Sampling 经典框架

### 2.1 Draft Model + Target Model

```
Step 1: Draft Model 生成 K 个候选 token
        ┌──┐ ┌──┐ ┌──┐ ┌──┐
Draft:  [d1] [d2] [d3] [d4] [d5] ... [dK]
        └──┘ └──┘ └──┘ └──┘

Step 2: Target Model 并行验证这 K 个 token
        ┌────────────────────────────────────┐
Target: [p1(d1)] [p2(d2)] [p3(d3)] ... [pK(dK)]
        └────────────────────────────────────┘
        (每个位置计算候选 token 的概率)

Step 3: 从第一个 token 开始逐个 Rejection Sampling
        Accepted: [d1] [d2]
        Rejected:  [d3] → 重新采样
        Result:    [d1] [d2] [x3]
```

### 2.2 算法流程

设：
- $p$ 是 Target Model 的分布（我们想要的真实分布）。
- $q$ 是 Draft Model 的分布（近似分布）。
- $\gamma = K$ 是 Draft Model 每次生成的候选 token 数。

**算法步骤：**

1. 使用 Draft Model 自回归生成 $\gamma$ 个候选 token：$x_1, x_2, \ldots, x_\gamma$。
2. 将这 $\gamma$ 个候选 token 输入 Target Model，得到每个位置 $i$ 的分布 $p_i(x)$ 和 $q_i(x)$。
3. 对于 $i = 1$ 到 $\gamma$：
   - 以概率 $\min\left(1, \frac{p_i(x_i)}{q_i(x_i)}\right)$ 接受 $x_i$。
   - 如果接受，继续检查下一个 token。
   - 如果拒绝，从分布 $p'_i(x) = \mathrm{normalize}\left(\max(0, p_i(x) - q_i(x))\right)$ 中重新采样，并停止本轮。
4. 如果所有 $\gamma$ 个 token 都被接受，再从 $p_{\gamma+1}(x)$ 中额外采样一个 token。
5. 将接受的 token 和重新采样的 token 作为新的前缀，重复步骤 1。

### 2.3 直观理解

- Draft Model 越接近 Target Model，候选 token 被接受的概率越高，加速比越大。
- 如果 Draft Model 和 Target Model 完全相同，所有候选 token 都会被接受，每轮生成 $\gamma+1$ 个 token。
- 如果 Draft Model 很差，大部分候选 token 会被拒绝，但第一个拒绝位置的重新采样保证分布正确。

## 3. 正确性保证：Rejection Sampling 分布无偏

### 3.1 为什么需要 Rejection Sampling？

直接使用 Draft Model 生成的 token 会引入偏差，因为 Draft Model 的分布 $q$ 不等于 Target Model 的分布 $p$。我们需要一种方法，让最终接受的 token 序列严格服从 $p$ 的分布。

### 3.2 Rejection Sampling 的数学原理

考虑单个 token 的接受/拒绝过程：

**接受概率：**

$$
\alpha(x) = \min\left(1, \frac{p(x)}{q(x)}\right)
$$

**拒绝后的修正分布：**

$$
p'(x) = \frac{\max(0, p(x) - q(x))}{1 - \sum_{x'} \min(p(x'), q(x'))}
$$

**最终输出 token 的分布：**

$$
P(\text{output} = x) = q(x) \cdot \alpha(x) + \left(\sum_{x'} q(x') \cdot (1 - \alpha(x'))\right) \cdot p'(x)
$$

### 3.3 证明分布无偏

我们需要证明 $P(\text{output} = x) = p(x)$。

**情况 1：$p(x) \leq q(x)$**

此时 $\alpha(x) = 1$：

$$
\begin{aligned}
P(\text{output} = x) &= q(x) \cdot 1 + \text{const} \cdot p'(x) \\
\text{其中 } p'(x) &= \frac{\max(0, p(x) - q(x))}{\text{const}} = 0
\end{aligned}
$$

所以 $P(\text{output} = x) = q(x) \geq p(x)$？这看起来不对，我们需要更仔细地分析。

**完整的正确性分析：**

对于每个 token，接受 $x$ 的概率为：

$$
P(\text{accept } x) = q(x) \cdot \min\left(1, \frac{p(x)}{q(x)}\right) = \min(q(x), p(x))
$$

如果接受，输出就是 $x$。

如果拒绝（概率为 $1 - \sum_{x'} \min(p(x'), q(x'))$），则从修正分布 $p'(x)$ 中采样：

$$
p'(x) = \frac{p(x) - \min(p(x), q(x))}{1 - \sum_{x'} \min(p(x'), q(x'))}
$$

因此，最终输出 $x$ 的总概率为：

$$
\begin{aligned}
P(x) &= \min(p(x), q(x)) + \left(1 - \sum_{x'} \min(p(x'), q(x'))\right) \cdot p'(x) \\
&= \min(p(x), q(x)) + \left(1 - \sum_{x'} \min(p(x'), q(x'))\right) \cdot \frac{p(x) - \min(p(x), q(x))}{1 - \sum_{x'} \min(p(x'), q(x'))} \\
&= \min(p(x), q(x)) + p(x) - \min(p(x), q(x)) \\
&= p(x)
\end{aligned}
$$

**证毕。** 最终输出 token 的分布严格等于 Target Model 的分布 $p(x)$。

### 3.4 序列级正确性

上述证明针对单个 token。对于多个 token 的序列，Speculative Decoding 采用链式条件分布：

$$
P(x_1, x_2, \ldots, x_k) = P(x_1) \cdot P(x_2 | x_1) \cdot \ldots \cdot P(x_k | x_1, \ldots, x_{k-1})
$$

由于每个 token 的条件分布都保持不变，整个序列的联合分布也与 Target Model 一致。

### 3.5 接受率的期望

每个 token 的期望接受概率为：

$$
\mathbb{E}[\alpha] = \sum_{x} \min(p(x), q(x))
$$

这就是 $p$ 和 $q$ 之间的**总变差距离（Total Variation Distance）** 相关量。Draft 和 Target 越接近，接受率越高。

## 4. Medusa：多头解码，免 Draft 模型

### 4.1 传统 Speculative Decoding 的问题

传统 Speculative Decoding 需要两个模型：

1. **Draft Model**：需要额外加载和运行。
2. **Target Model**：原有的大模型。

这带来了额外开销：

- 需要维护两个模型的 KV Cache。
- Draft Model 需要额外显存。
- Draft 和 Target 的分布差异可能较大，接受率不高。

### 4.2 Medusa 的核心思想

**Medusa**（Cai et al., 2024）提出：在 Target Model 上附加多个**解码头（Decoding Heads）**，直接预测未来多个 token，而不需要额外的 Draft Model。

```
Input: [t1, t2, t3]

Target Model: 生成 hidden state h3

Medusa Head 1: 预测 t4
Medusa Head 2: 预测 t5
Medusa Head 3: 预测 t6
...
Medusa Head K: 预测 t_{3+K}
```

### 4.3 Medusa 的验证方式

Medusa 的验证过程与传统 Speculative Decoding 类似：

1. 用 Medusa Heads 预测未来 K 个 token。
2. 将这 K 个 token 输入 Target Model 的原始输出头（LM Head）。
3. 计算每个位置的概率，进行 Rejection Sampling。
4. 接受或拒绝候选 token。

由于 Medusa Heads 是附加在 Target Model 上的，它们共享主模型的前向传播，额外开销很小。

### 4.4 Medusa 的优缺点

**优点：**

- 不需要单独的 Draft Model。
- 显存占用比传统 Speculative Decoding 小。
- 训练和部署相对简单。

**缺点：**

- 需要额外训练 Medusa Heads。
- 预测准确率通常不如一个好的 Draft Model。
- 对长序列的预测能力有限。

## 5. EAGLE-2：动态 Draft Tree

### 5.1 EAGLE 系列简介

**EAGLE（Extrapolation Algorithm for Greater Language-Model Efficiency）** 是一种基于**特征级 extrapolation** 的投机解码方法：

- EAGLE-1：使用 Target Model 的倒数第二层特征来训练一个轻量级 Auto-regressive Decoder，预测未来 token。
- EAGLE-2：在 EAGLE-1 基础上引入**动态 Draft Tree**，进一步探索多个可能的未来路径，提升接受率。

### 5.2 动态 Draft Tree

传统 Speculative Decoding 每次只生成一条线性候选序列：

```
Path 1: t4 → t5 → t6 → t7
```

但语言生成是分支的，一个 token 后面可能有多个合理的后续 token。EAGLE-2 构建一个**树形结构**来同时探索多个候选路径：

```
        t4
       /  \
     t5    t5'
    /  \    \
  t6   t6'  t6''
```

### 5.3 EAGLE-2 的优势

1. **更高的接受率**：通过探索多个分支，找到更容易被 Target Model 接受的路径。
2. **更充分利用验证**：Target Model 一次 forward 可以验证整个 Draft Tree 中的多个节点。
3. **更好的长序列预测**：树形结构可以捕获更复杂的未来依赖。

### 5.4 EAGLE-2 的代价

1. **实现复杂**：需要构建和维护 Draft Tree，以及高效地验证树中节点。
2. **训练成本**：需要训练一个特征级 decoder。
3. **内存开销**：维护多个候选路径需要更多 KV Cache 或计算资源。

## 6. 收益边界：什么场景下不赚？

### 6.1 收益来源

Speculative Decoding 的收益主要来自：

$$
\text{Speedup} \approx \frac{\gamma \cdot \alpha_{\text{avg}}}{1 + \text{Draft overhead}}
$$

其中：
- $\gamma$：每次 Draft 生成的候选 token 数。
- $\alpha_{\text{avg}}$：平均接受率。
- Draft overhead：运行 Draft Model 的额外成本。

### 6.2 加速明显的场景

| 场景 | 原因 |
|------|------|
| **Draft 和 Target 分布接近** | 接受率高，每个 Target forward 验证更多 token |
| **生成简单、确定性内容** | 如代码、模板、常见短句，Draft 容易猜对 |
| **Target Model 很大** | Target 验证成本相对固定，减少 Target forward 次数收益大 |
| **序列长度较长** | 减少 forward 次数的累积收益显著 |
| **Draft Model 很快** | Draft overhead 小，即使接受率一般也有收益 |

### 6.3 不赚甚至变慢的场景

| 场景 | 原因 |
|------|------|
| **Draft 和 Target 分布差异大** | 接受率很低，大部分候选 token 被拒绝 |
| **生成内容高度不确定** | Draft 难以预测，每个 token 都需要重新采样 |
| **Target Model 本身很小** | Target 验证成本不高，减少 forward 次数收益有限 |
| **Draft Model 很慢** | Draft overhead 抵消了验证收益 |
| **候选数 γ 设置不当** | γ 太大导致验证成本增加；γ 太小收益有限 |
| **短序列生成** | 减少的 forward 次数有限 |
| **Batch 很大** | 验证多个候选的内存和计算成本增加 |
| **KV Cache 或显存受限** | 维护 Draft 和 Target 两个 KV Cache 压力大 |

### 6.4 关键参数选择

| 参数 | 作用 | 过大/过小 |
|------|------|----------|
| $\gamma$（候选数） | 每次 Draft 生成的 token 数 | 过大：验证成本增加，接受率下降；过小：收益有限 |
| Draft Model 大小 | 影响 Draft 质量和速度 | 过大：速度慢；过小：接受率低 |
| Temperature | 影响生成分布的确定性 | 高温：分布分散，接受率低；低温：分布集中，接受率高 |

## 7. 代码实践：Speculative Decoding 模拟器

### 7.1 模拟器设计

本节提供一个纯 Python 模拟器，用于演示 Speculative Decoding 的核心逻辑：

- 用两个概率分布模拟 Draft Model 和 Target Model。
- Draft Model 生成 $\gamma$ 个候选 token。
- Target Model 并行验证，使用 Rejection Sampling。
- 统计平均接受率、加速比等指标。

对应脚本：`examples/speculative_decoding_simulator.py`

```bash
python examples/speculative_decoding_simulator.py
```

### 7.2 模拟器核心代码

```python
import numpy as np
import random


def generate_draft_tokens(draft_probs, gamma=5):
    """Draft Model 自回归生成 gamma 个候选 token。"""
    tokens = []
    for _ in range(gamma):
        token = np.random.choice(len(draft_probs), p=draft_probs)
        tokens.append(token)
    return tokens


def rejection_sampling(draft_tokens, draft_probs, target_probs, gamma=5):
    """
    Target Model 验证候选 token。
    返回被接受的 token 列表，以及是否全部接受。
    """
    accepted = []
    for i in range(gamma):
        x = draft_tokens[i]
        q_x = draft_probs[x]
        p_x = target_probs[x]

        # 接受概率
        alpha = min(1.0, p_x / q_x)
        if random.random() < alpha:
            accepted.append(x)
        else:
            # 从修正分布中重新采样
            corrected = np.maximum(target_probs - draft_probs, 0)
            corrected_sum = corrected.sum()
            if corrected_sum > 0:
                corrected /= corrected_sum
            else:
                corrected = target_probs
            new_token = np.random.choice(len(corrected), p=corrected)
            accepted.append(new_token)
            break

    return accepted


def speculative_decoding_step(draft_probs, target_probs, gamma=5):
    """执行一轮 Speculative Decoding。"""
    draft_tokens = generate_draft_tokens(draft_probs, gamma)
    accepted = rejection_sampling(draft_tokens, draft_probs, target_probs, gamma)
    return accepted


# 模拟 Draft 和 Target 的分布差异
vocab_size = 10000
draft_probs = np.random.dirichlet(np.ones(vocab_size) * 0.5)
# 让 Target 分布与 Draft 接近但不完全相同
target_probs = 0.8 * draft_probs + 0.2 * np.random.dirichlet(np.ones(vocab_size) * 0.5)
target_probs /= target_probs.sum()

# 运行多轮
accept_lengths = []
for _ in range(1000):
    accepted = speculative_decoding_step(draft_probs, target_probs, gamma=5)
    accept_lengths.append(len(accepted))

avg_accept = np.mean(accept_lengths)
print(f"Average accepted tokens per round: {avg_accept:.2f}")
print(f"Speedup vs autoregressive: {avg_accept:.2f}x")
```

### 7.3 模拟器输出解读

典型输出：

```
Average accepted tokens per round: 3.24
Speedup vs autoregressive: 3.24x
```

这表示平均每次 Target forward 可以生成 3.24 个 token，而传统自回归每次只能生成 1 个 token，理想加速比约为 3.24x。

实际加速比还需要考虑 Draft Model 的开销，所以通常低于这个理论值。

## 8. 代码实践：使用 transformers 进行 Speculative Decoding

### 8.1  transformers 内置支持

transformers 库已经内置了 `assistant_model` 参数支持 Speculative Decoding：

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

# 加载 Target Model（大模型）
target_model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-70b-hf",
    torch_dtype=torch.float16,
    device_map="auto",
)

# 加载 Draft Model（小模型）
draft_model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-hf",
    torch_dtype=torch.float16,
    device_map="auto",
)

tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-2-70b-hf")
inputs = tokenizer("The future of AI is", return_tensors="pt").to(target_model.device)

# 使用 assistant_model 进行投机解码
with torch.no_grad():
    outputs = target_model.generate(
        **inputs,
        assistant_model=draft_model,
        max_new_tokens=100,
        do_sample=True,
        temperature=0.7,
    )

print(tokenizer.decode(outputs[0], skip_special_tokens=True))
```

### 8.2 关键参数

| 参数 | 含义 |
|------|------|
| `assistant_model` | Draft Model |
| `num_assistant_tokens` | 每轮 Draft 生成的候选 token 数（默认 5） |
| `assistant_confidence_threshold` | Draft 置信度阈值，低于阈值提前停止 |

### 8.3 vLLM 中的 Speculative Decoding

vLLM 0.25.0 支持多种投机解码方法，例如 `draft_model`（使用独立小模型作为 Draft）和 `ngram`（基于已生成 token 的 n-gram 池进行投机，无需额外模型）。对应脚本已使用 `ngram` 作为默认方法，避免加载第二个模型。

```python
from vllm import LLM, SamplingParams

llm = LLM(
    model="/data/liyangyang/models/Qwen3.5-9B",
    dtype="float16",
    spec_method="ngram",      # 或 "draft_model"
    spec_tokens=5,            # 每轮投机 token 数
    # spec_model="/path/to/draft",  # draft_model 方法需要
)

sampling_params = SamplingParams(temperature=0.7, top_p=0.9, max_tokens=128)
outputs = llm.generate(prompts, sampling_params)
```

运行示例：

```bash
PATH=/data/liyangyang/qwen35_env/bin:$PATH python examples/vllm_speculative_decoding.py
```

### 9.3 选择建议

| 方案 | 适用场景 | 复杂度 |
|------|---------|--------|
| **传统 Speculative Decoding** | 有现成小模型、显存充足 | 中 |
| **Medusa** | 没有 Draft Model、希望快速部署 | 中 |
| **EAGLE-2** | 追求极致加速、可接受训练成本 | 高 |
| **Lookahead Decoding** | 完全免训练、使用 n-gram 池 | 低 |

## 10. 常见问题与排查

### 10.1 接受率很低怎么办？

- 检查 Draft Model 和 Target Model 是否使用相同的 tokenizer。
- 降低 temperature，使分布更集中。
- 增加 Draft Model 的大小或质量。
- 减少 `num_assistant_tokens`，避免验证过长序列。

### 10.2 Speculative Decoding 没有加速反而变慢？

- Draft Model 太慢或 Target Model 不够大，导致 overhead 抵消收益。
- 生成分布太分散，接受率过低。
- GPU 显存不足，两个模型无法同时加载。
- batch size 太大，验证成本增加。

### 10.3 输出与原始 Target Model 不一致？

- 检查是否使用了正确的 Rejection Sampling。
- 如果使用 transformers 内置实现，通常不需要担心正确性。
- 自定义实现时，确保修正分布计算正确。

### 10.4 如何选择 Draft Model？

- 理想情况：同系列的小模型（如 LLaMA-7B 作为 LLaMA-70B 的 Draft）。
- 也可以对 Target Model 进行量化或蒸馏得到 Draft。
- 在实践中，需要权衡 Draft 质量和速度。

## 12. 本节小结

1. **Speculative Decoding** 通过 Draft Model 快速猜测多个 token，再由 Target Model 并行验证，从而加速 Decode 阶段。
2. **Rejection Sampling** 保证了生成分布与直接使用 Target Model 完全一致，不会引入偏差。
3. **Medusa** 通过多头解码免除了独立的 Draft Model，适合显存受限或没有现成 Draft 的场景。
4. **EAGLE-2** 使用动态 Draft Tree 探索多个未来路径，进一步提升了接受率。
5. **Speculative Decoding 不是万能的**：Draft 和 Target 分布接近、Target 模型足够大、生成内容确定性高时收益最大；否则可能不赚甚至变慢。
