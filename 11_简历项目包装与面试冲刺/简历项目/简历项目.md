# 简历项目：简历模板与自查清单

## 一、AI Infra 简历项目模板

### 模板结构

```text
项目名称（一句话定位）
时间 | 角色

背景：<业务问题 + 平台/模型/约束，1 句>
职责：<负责的模块 + 技术栈关键词，2-4 句>
成果：<全部量化，1-2 句>
```

### 示例（可直接改写）

> **自动驾驶 MMBEV 模型端到端多平台部署优化** | 2024.03 - 2024.12 | 核心开发
> - 背景：MMBEV 感知模型在 Orin/A100/Ascend 部署时延迟 100ms 无法满足实时性要求，且跨平台兼容性差。
> - 职责：负责 HPC 算子开发与跨平台适配（CUDA kernel、TBE、warp reduce、算子融合）；基于 Laser 编译框架搭建一键编译流水线；基于 TVM Relax 实现内存池与 CUDA Graph Runtime 优化；完成 INT8 分层量化（per-channel、敏感层保护）；开发支持 6/8 路摄像头并行的专用推理引擎。
> - 成果：Orin 端到端延迟 100ms → 30ms，吞吐提升 3 倍，显存减少 30%，INT8 精度损失 < 1%，GPU 利用率 60% → 85%，通过量产验证。

## 二、四条黄金法则自查

| 法则 | 检查项 | ✓/✗ |
|------|--------|-----|
| 量化成果 | 每条 bullet 都有数字？延迟/吞吐/显存/精度至少一个？ | |
| 技术栈 | 关键词与目标 JD 重合度 > 70%？CUDA/TVM/TensorRT/vLLM/ZeRO 等出现？ | |
| 业务价值 | 能说清解决了什么业务问题？（实时性/量产/成本） | |
| 分层描述 | 背景→职责→成果结构清晰？没有大段流水账？ | |

## 三、常见扣分项

- ❌ "参与"、"协助"——看不出你的贡献，改成"负责"、"主导"。
- ❌ "提升了性能"——没有数字等于没说。
- ❌ 堆砌技术名词但说不出来做了什么——面试必死。
- ❌ 项目时间线冲突、数字前后不一致。
- ❌ 写了 vLLM/FlashAttention 但只会背名词——只写能讲 10 分钟以上的技术。

## 四、投递前最终检查

1. 用 `jd_keyword_matcher.py` 对目标 JD 跑一次匹配，重合关键词前置。
2. 每个项目准备 3 个"深挖故事"：最难的问题、最大的成果、最失败的一次尝试。
3. 数字全部能现场复算：30ms 怎么测的？3 倍吞吐怎么算的？
4. PDF 一页，技术栈加粗，量化数字加粗。
