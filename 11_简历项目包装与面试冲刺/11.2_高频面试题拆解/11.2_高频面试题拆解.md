# 11.2 各模块高频面试题拆解

## 本节目标

把 AI Infra 六大模块最高频的面试题逐一拆解，给出答题框架与得分点。每个问题都按「一句话答案 → 展开要点 → 可能的追问」组织。

---

## 一、算子开发

### Q1. GEMM 如何优化？

**一句话**：分块（tiling）提升数据复用 → 共享内存 → 寄存器分块 → Tensor Core → 向量化访存。

**展开**：
1. Naive GEMM：每个线程算一个 C 元素，global memory 反复读，带宽瓶颈。
2. Block Tiling：C 分成 BM×BN 块，A/B 对应块加载到 shared memory，数据复用 BM/BN 倍。
3. Thread Tiling：每个线程算 TM×TN 子块，用寄存器复用，进一步提升计算访存比。
4. 向量化：`float4` / `half2` 一次加载多元素。
5. Tensor Core：`wmma` / `mma.sync` 指令，算力从 CUDA Core 的几十 TFLOPS 提升到数百 TFLOPS。

**追问**：怎么选 tile size？→ 由 shared memory 容量、寄存器数量、occupancy 决定；实测调优。

### Q2. FlashAttention 原理是什么？

**一句话**：用分块 + 在线 softmax 避免把 N×N attention 矩阵写回 HBM，IO 从 O(N²) 降到 O(N)。

**展开**：
1. 标准 attention：QK^T 得到 N×N 矩阵写回 HBM，再读回做 softmax，再乘 V。显存 IO 主导。
2. FlashAttention：把 Q/K/V 按块加载到 SRAM，逐块计算 K^T、softmax 用 online rescaling（维护 running max 与 running sum），输出直接累加，不产生完整 N×N 矩阵。
3. 反向时用重计算（recompute）代替保存中间矩阵。

**追问**：为什么 N×N 不写回就快？→ HBM 带宽远低于 SRAM/寄存器；attention 是 memory-bound，不是 compute-bound。

### Q3. Bank Conflict 是什么，如何避免？

**一句话**：shared memory 分成 32 个 bank，同一 warp 内多个线程访问同一 bank 的不同地址会串行化。

**展开**：
- 32 个 bank，连续 4 字节地址依次映射到 bank 0~31。
- 同一 warp 访问不同 bank → 并行；访问同 bank 不同地址 → conflict，按倍数串行；广播（同地址）不冲突。
- 避免方法：padding（如 A[33] 代替 A[32]）、调整数据排布、swizzle。

**追问**：怎么发现 bank conflict？→ Nsight Compute 的 `l1tex__data_bank_conflicts` 指标。

## 二、编译器

### Q4. 图优化常见 Pass 有哪些？

**一句话**：常量折叠、死代码消除、算子融合、布局转换、公共子表达式消除。

**展开**：
- 常量折叠：编译期算出常量子图（如 shape 计算、position encoding）。
- 算子融合：conv+bn+relu、layernorm+gelu，减少 kernel launch 与中间 tensor 访存。
- 布局转换：按后端偏好 NCHW ↔ NHWC，配合融合减少 transpose。
- CSE：相同子图只算一次。

**追问**：融合的收益来源？→ 访存是主因：中间结果不落 HBM，全部在寄存器/shared memory 传递。

### Q5. TVM 架构是怎样的？

**一句话**：前端 IR（Relay/Relax）→ 图级优化 → 算子级调度（TE/TIR）→ 目标代码生成（CUDA/LLVM）。

**展开**：
- Relay：旧一代计算图 IR；Relax：新一代，原生支持动态 shape、与 VM 配合。
- TE/TIR：算子级 IR，schedule 原语（split/fuse/reorder/cache_read/vectorize/tensorize）。
- AutoTVM / MetaSchedule：搜索最优 schedule。
- Runtime：Graph Executor（静态）与 VM（支持动态控制流）。

**追问**：TVM 和 TensorRT 区别？→ TVM 开源可定制、自动生成 kernel；TRT 闭源但 NVIDIA 平台调优更充分。

### Q6. 动态 Shape 怎么处理？

**一句话**：能静态就静态（分桶编译），必须动态则用符号 shape + VM/动态 kernel + 内存动态分配。

**展开**：
1. 分桶：按常见 shape（batch 1/4/8、seq 512/2048）编译多个 engine，运行时选择。
2. 符号维度：Relax/ONNX 支持 symbolic dim，推导时传播符号关系。
3. 运行时：动态算子（dynamic kernel）+ 延迟内存分配 + workspace 上限预估。

**追问**：为什么 TensorRT 早期不支持动态 shape？→ kernel 选择和内存规划都在编译期完成。

## 三、Runtime

### Q7. 内存池怎么设计？

**一句话**：按 shape 分桶缓存 buffer，alloc 时先查缓存，free 时归还而不释放，消除推理期 cudaMalloc。

**展开**：
- 分桶策略：精确 shape 或按大小分档（减少碎片）。
- 生命周期：编译期做 liveness 分析，不同生命周期的 tensor 复用同一块内存。
- 碎片处理：定期整理 / 大块切分小块合并。

**追问**：内存池会带来什么问题？→ 常驻显存偏高；多模型/多流并发时需要 per-stream 池。

### Q8. CUDA Graph 的原理与限制？

**一句话**：把一串 kernel launch 录制为图，一次 launch 重放，消除 CPU launch overhead。

**展开**：
- 收益场景：小 kernel 多、launch 密集的静态子图。
- 限制：shape 必须固定；图内不能有 CPU-GPU 同步；动态分支不支持。
- 使用：`cudaStreamBeginCapture` / `cudaGraphLaunch`；vLLM、TensorRT、TVM Relax 都支持。

**追问**：capture 失败怎么排查？→ 检查流上是否有非法操作（同步、malloc）、检查 shape 动态性。

### Q9. Runtime 动态调度怎么做？

**一句话**：预处理/推理/后处理三级流水线 + 多流 overlap + 请求级动态 batching。

**展开**：
- 流水线：CPU 预处理与 GPU 推理并行，H2D/D2H 用独立 stream 隐藏拷贝。
- 动态调度：按请求到达情况组 batch（continuous batching 的思想），在延迟约束下最大化吞吐。

## 四、量化

### Q10. PTQ 和 QAT 的区别？

**一句话**：PTQ 训练后量化、快速但精度略差；QAT 训练时模拟量化、精度好但成本高。

**展开**：
- PTQ：校准集统计激活分布 → 定 scale → 量化。适合 INT8、快速落地。
- QAT：forward 中插入 fake-quant 模拟量化误差，反向仍 FP 训练。适合 INT4 或精度敏感场景。

**追问**：什么时候 PTQ 会崩？→ 激活有 outlier、模型对量化敏感（如小模型、attention softmax 后）。

### Q11. SmoothQuant 原理？

**一句话**：把激活的量化难度"转移"到权重上：除以平滑因子 s（激活）× 乘 s（权重），平滑激活 outlier。

**展开**：
- LLM 激活存在固定 channel 的 outlier（幅度 100x），per-tensor 量化时这些 channel 决定 scale，其余值精度被压缩。
- SmoothQuant：Y = (X·diag(s)⁻¹)·(diag(s)·W)，s = max(|X|)^α / max(|W|)^(1-α)，α 通常 0.5。
- 离线融合到前一层 LayerNorm/Linear 权重中，推理零开销。

### Q12. 量化精度怎么控制？

**一句话**：分层策略（敏感层保 FP16）+ per-channel/per-group + 校准集代表性 + 端到端指标把关。

**展开**：
1. 逐层敏感度分析：单层量化后看输出 diff，找出敏感层。
2. 粒度选择：weight per-channel 几乎无损；activation per-token/per-group 折中精度与开销。
3. 验证：tensor diff + 业务指标（NDS/NDCG/困惑度），不只信 tensor 级指标。

## 五、分布式训练

### Q13. ZeRO 原理？三个阶段的区别？

**一句话**：把优化器状态（S1）、梯度（S2）、参数（S3）分片到 DP 各 rank，用通信换显存。

**展开**：
- Baseline DDP：每 rank 存完整 16P（FP32 Adam：4P 参数 + 4P 梯度 + 8P 优化器）。
- ZeRO-1：优化器状态分片 → 每 rank 约 12P/N + 4P+4P。
- ZeRO-2：+梯度分片（reduce-scatter 代替 all-reduce）→ 约 8P+8P/N。
- ZeRO-3：+参数分片（forward 时 all-gather）→ 约 16P/N。
- 代价：通信量增加；ZeRO-3 每层 forward/backward 都要 gather。

**追问**：ZeRO-3 和 FSDP 什么关系？→ FSDP 是 PyTorch 原生实现的 ZeRO-3 思想。

### Q14. TP/PP/DP 拓扑怎么设计？

**一句话**：TP 放节点内（通信密集吃 NVLink），PP 跨节点（通信少），DP 填满剩余卡。

**展开**：
- 通信量：TP > DP > PP，所以 TP ≤ 单机 NVLink 数（通常 8）。
- 示例：64 卡 175B → TP=8（节点内）× PP=4 × DP=2。
- 显存校验：每层参数/TP × 层数/PP + 激活，单卡放得下。

### Q15. 训练显存怎么算？

**一句话**：混合精度 Adam 下 ≈ 16 字节 × 参数量 + 激活；激活 ≈ 34·b·s·h·L（字节，近似）。

**展开**：
- 参数 FP32 4P + 梯度 FP32 4P（或 FP16 2P）+ Adam m/v 8P（FP32）+ FP16 参数副本 2P ≈ 16P。
- 激活与 batch、seq_len、hidden、层数成正比；activation checkpointing 可降到开根号级别。

## 六、LLM 推理

### Q16. PagedAttention 原理？

**一句话**：把 KV Cache 按页（block）管理，像 OS 虚拟内存，消除显存碎片与预留浪费，vLLM 的核心。

**展开**：
- 传统：每个请求按 max_len 预留连续 KV 显存，利用率低、碎片多。
- PagedAttention：KV Cache 分成固定大小 block（如 16 token），逻辑上连续、物理上离散，通过 block table 映射；生成时按需分配新 block。
- 收益：显存利用率大幅提升 → 更大 batch → 吞吐提升 2-4 倍。

### Q17. Continuous Batching 是什么？

**一句话**：请求粒度的动态组批：每次迭代把完成的请求移出、新请求插入，不等整个 batch 结束。

**展开**：
- 静态 batching：等 batch 中最长请求生成完才释放资源，GPU 利用率低。
- Continuous（in-flight）batching：iteration-level 调度，LLM serving 吞吐提升数倍。
- 与 PagedAttention 配合：显存能动态分配，才有条件动态增删请求。

### Q18. KV Cache 怎么管理？

**一句话**：KV Cache 大小 = 2×层数×heads×head_dim×seq×batch×2字节，管理上靠分页分配、前缀复用、淘汰换出。

**展开**：
- 显存大头：7B 模型 FP16 每 token KV ≈ 0.5MB；长序列 + 大 batch 时 KV Cache 超过权重。
- 管理策略：分页（PagedAttention）、prefix caching（共享 prompt 前缀）、swap 到 CPU、量化 KV（INT8/FP8）。

### Q19. Speculative Decoding 原理？

**一句话**：用小模型（draft）一次猜 k 个 token，大模型（target）一次前向并行验证，接受前缀匹配部分，吞吐提升 2-3 倍且输出分布不变。

**展开**：
- LLM decode 是 memory-bound：一次只出 1 个 token，但读全部权重。
- 投机：draft 模型便宜地猜 k 个 token；target 一次 forward 同时验证 k 个位置；从第一个不匹配处截断，接受前面部分。
- 关键：验证是并行的，不增加 target 前向次数；数学上保证与 target 分布一致。
