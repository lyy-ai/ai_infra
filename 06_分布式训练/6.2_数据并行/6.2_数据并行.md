# 6.2 数据并行

## 课程概述

数据并行是分布式训练中最基础、最常用的并行策略。它的核心思想是：把训练数据切分成多份，分发到多张 GPU 上，每张 GPU 都保存一份完整模型，独立计算梯度后通过集合通信（通常是 AllReduce）同步平均梯度，然后各自更新模型。

本节把数据并行拆开：DataParallel（DP）、DistributedDataParallel（DDP）、FSDP。学完本节后，你应该能够：

- 解释 DP、DDP、FSDP 的区别和演进。
- 理解 DDP 的多进程架构和 AllReduce 梯度同步机制。
- 说明 FSDP 如何把 ZeRO-3 的思想集成到 PyTorch 中。
- 写出可用的 DDP 和 FSDP 训练脚本。

---

## 1. DataParallel（DP）

### 1.1 单进程多卡

DP 是 PyTorch 最早的数据并行方案，使用简单：

```python
model = nn.DataParallel(model, device_ids=[0, 1, 2, 3])
```

### 1.2 执行流程

```text
1. 主进程把输入数据 scatter 到多张卡
2. 每张卡独立 forward
3. 主进程 gather 所有输出
4. 主进程计算 loss，backward 时梯度先回传到主卡
5. 主卡 broadcast 梯度，各卡更新
```

### 1.3 为什么 DP 低效

- 单进程多线程，受 GIL 限制。
- 梯度同步发生在主进程，存在串行 bottleneck。
- 不支持多机。

DP 现在基本被 DDP 取代，仅在教学和简单 demo 中使用。

---

## 2. DistributedDataParallel（DDP）

### 2.1 多进程架构

DDP 为每张卡启动一个独立进程，避免 GIL：

```text
Rank 0: process 0 -> GPU 0
Rank 1: process 1 -> GPU 1
Rank 2: process 2 -> GPU 2
Rank 3: process 3 -> GPU 3
```

### 2.2 AllReduce 梯度同步

DDP 在 backward 过程中通过 ring-AllReduce 同步梯度，使各进程在 optimizer.step() 前拥有相同的平均梯度。

```text
每个进程：
  forward(local batch) -> compute local gradient
  DDP hooks: AllReduce gradients across ranks
  optimizer.step() -> update local replica
```

### 2.3 关键参数

- `world_size`：总进程数。
- `rank`：当前进程编号。
- `local_rank`：当前进程所在节点的 GPU 编号。
- `backend`：集合通信后端，通常是 `nccl`（GPU）或 `gloo`（CPU）。

### 2.4 DDP 启动方式

```bash
# torchrun 启动
python -m torchrun --nproc_per_node=4 train_ddp.py
```

## 3. FSDP（Fully Sharded Data Parallel）

### 3.1 FSDP 是什么

FSDP 是 PyTorch 原生的“完全分片”数据并行，本质上是把 DeepSpeed ZeRO-3 集成到 PyTorch 中。

### 3.2 与 DDP 的区别

| 特性 | DDP | FSDP |
| ---- | --- | ---- |
| 模型副本 | 每张卡完整模型 | 参数按 rank 分片，计算时 all-gather |
| 显存占用 | 高 | 低 |
| 通信量 | 一次 AllReduce | 多次 AllGather + ReduceScatter |
| 适用模型 | 单卡能放下 | 单卡放不下 |

### 3.3 FSDP 工作流程

```text
forward:  all-gather 参数 -> forward -> 释放参数
training: backward -> reduce-scatter 梯度 -> 释放梯度
optimizer: 每个 rank 更新自己分片的参数
```

### 3.4 配置关键

```python
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy

model = FSDP(model, auto_wrap_policy=transformer_auto_wrap_policy)
```

---

## 4. DP / DDP / FSDP 选型

| 场景 | 推荐方案 |
| ---- | -------- |
| 小模型，单机能放下 | DDP |
| 大模型，单卡放不下，但仍能单机多卡 | FSDP / ZeRO-3 |
| 超大模型，需要多机 | FSDP + TP/PP / DeepSpeed |
| 简单 demo/教学 | DP |

## 5. 代码实践

代码文件：`6.2_数据并行/train_ddp.py`

```python
# train_ddp.py
import os
import torch
import torch.distributed as dist
import torch.multiprocessing as mp
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.utils.data import DataLoader, TensorDataset
from torch.utils.data.distributed import DistributedSampler


def setup(rank, world_size):
    os.environ["MASTER_ADDR"] = "localhost"
    os.environ["MASTER_PORT"] = "12355"
    dist.init_process_group("nccl", rank=rank, world_size=world_size)
    torch.cuda.set_device(rank)


def cleanup():
    dist.destroy_process_group()


def run(rank, world_size):
    setup(rank, world_size)

    model = torch.nn.Linear(10, 1).to(rank)
    model = DDP(model, device_ids=[rank])

    dataset = TensorDataset(
        torch.randn(128, 10),
        torch.randn(128, 1),
    )
    sampler = DistributedSampler(dataset, num_replicas=world_size, rank=rank)
    loader = DataLoader(dataset, batch_size=16, sampler=sampler)

    optimizer = torch.optim.SGD(model.parameters(), lr=0.01)
    loss_fn = torch.nn.MSELoss()

    for epoch in range(2):
        sampler.set_epoch(epoch)
        for x, y in loader:
            x, y = x.to(rank), y.to(rank)
            optimizer.zero_grad()
            pred = model(x)
            loss = loss_fn(pred, y)
            loss.backward()
            optimizer.step()
        if rank == 0:
            print(f"rank {rank}, epoch {epoch}, loss {loss.item():.4f}")

    cleanup()


def main():
    world_size = 2
    mp.spawn(run, args=(world_size,), nprocs=world_size, join=True)


if __name__ == "__main__":
    main()
```

## 6. 常见误区

### 6.1 “DDP 就是 n 个独立训练”

DDP 中各进程不是独立的，梯度会通过 AllReduce 同步。最终各进程的模型参数保持一致。

### 6.2 “FSDP 比 DDP 快”

FSDP 主要是为了省显存，通信量通常比 DDP 大。在单卡能放下模型时，DDP 往往更快。

### 6.3 “数据并行 scale 永远线性”

当 batch size 增大、模型较小、通信成为瓶颈时，扩展性会下降。通常需要增大 local batch size 或调整通信策略。

---

## 7. 本节小结

1. DP 已过时，DDP 是数据并行的标准实现。
2. DDP 使用多进程 + AllReduce，避免 GIL 和单进程 bottleneck。
3. FSDP 在 DDP 基础上对参数、梯度、优化器状态做分片，适合大模型。
4. 选择 DP/DDP/FSDP 的关键是单卡是否能放下模型。
