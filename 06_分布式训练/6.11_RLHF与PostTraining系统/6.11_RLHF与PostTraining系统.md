# 6.11 RLHF 与 Post-Training 系统

## 课程概述

预训练的格局逐渐收敛之后，模型能力差距越来越由 post-training 决定：SFT 之后的 RLHF/RLVR、以及以 GRPO 为代表的强化学习方法（DeepSeek-R1 是标志性成果），成为能力提升的主路径。对 Infra 来说，这意味着一个新战场：**post-training 把"训练系统"和"推理系统"耦合在同一套流程里**——每一轮迭代都要先用推理引擎批量生成（rollout），再用训练框架更新权重，再把新权重同步回推理引擎。只懂训练或只懂推理，都撑不起一个高效的 RLHF 系统。

学完本节后，你应该能够：

- 画出 PPO 的四模型组成，并解释 GRPO 为什么能去掉 critic。
- 描述一次 RLHF 迭代的完整流程与各阶段的系统归属。
- 分析三大系统难题：权重同步、rollout 长尾、colocate vs 分离。
- 对比 verl / OpenRLHF / TRL / NeMo-Aligner 的设计取舍。
- 解释为什么 rollout 占 50-80% 耗时，以及这对能力模型的要求。

---

## 1. 背景与动机：Post-Training 为什么是新 Infra 战场

预训练的系统问题（6.1-6.9 节）本质上是"一种计算模式"：固定的前向+反向，规则的张量流，可以用 TP/PP/DP/ZeRO 一套方法论打天下。

RLHF 完全不同。一次迭代里混合了两种性格迥异的负载：

| 负载 | 系统特征 | 优化目标 |
| ---- | -------- | -------- |
| rollout 生成 | 自回归解码、显存瓶颈在 KV cache、长度不可预知 | 吞吐（tokens/s）、长尾延迟 |
| actor 训练 | 前向+反向、显存瓶颈在优化器状态、计算规整 | MFU、并行效率 |

推理优化（持续批处理、PagedAttention、投机采样、FP8）和训练优化（3D 并行、ZeRO、通信重叠）是两个独立发展了多年的技术栈，RLHF 要求它们在同一批机器上交替甚至同时运行，中间还要搬运数百 GB 的权重。这就是新战场。

---

## 2. 核心原理

### 2.1 PPO 的系统组成：四个模型

经典 RLHF（PPO）同时在场四个模型：

| 模型 | 角色 | 负载类型 |
| ---- | ---- | -------- |
| Actor（策略模型） | 生成 response，被训练 | 训练（前向+反向） |
| Critic（价值模型） | 估计状态价值，被训练 | 训练（前向+反向） |
| Reference Model | 提供 KL 散度基准，防跑偏 | 仅推理（前向） |
| Reward Model | 给 response 打分 | 仅推理（前向） |

四个模型通常是同量级的大模型，显存与调度压力可想而知。PPO 的批评者直指 critic：价值函数难训、占一份完整训练态的显存和计算。

**GRPO 的简化**：去掉 critic，对同一个 prompt 采样一组（G 个）response，用**组内相对优势**（每个 response 的 reward 减去组均值、除以组标准差）替代价值函数估计。省掉 critic 的一整份显存与计算，工程上大幅简化，已成为主流（DeepSeek-R1 为代表）。数学上是拿估计方差换系统效率——组内多样本平均恰好把方差压了回来。

### 2.2 一次迭代的完整流程

```text
┌─────────────────────────────────────────────────────────┐
│ 1. Rollout:   actor 当前权重加载到推理引擎 (vLLM/SGLang)，│
│               对一批 prompt 批量生成 response            │
│ 2. Reward:    reward model 打分（RLVR 则由验证器算分）    │
│ 3. Advantage: 组内相对优势计算（GRPO）/ GAE（PPO）        │
│ 4. Train:     actor 训练 step（FSDP/Megatron）            │
│ 5. Sync:      新权重从训练框架同步回推理引擎              │
└─────────────────────────────────────────────────────────┘
```

第 1 步是推理系统的活，第 4 步是训练系统的活，第 5 步是两个世界的接缝——三大系统难题都藏在这条流水线里。

### 2.3 难题一：权重同步

训练框架和推理引擎对同一份权重的**分片布局不同**：

- FSDP 把参数 flatten 后按 rank 均分；Megatron 按 TP/PP 切矩阵；
- vLLM/SGLang 按自己的 TP/PP 布局组织权重，且为推理优化（如 KV cache 友好的 layout）。

同步一次权重需要：**gather（从训练分片聚合成完整张量）→ reshape/重分片（转换成推理布局）→ 传输到推理实例（NCCL 广播）→ 推理引擎热加载**。数百 GB 的权重，朴素实现（过 CPU、串行 gather）每次同步要数十秒甚至更久。优化手段：

- **分桶流水**：把权重切成多个 bucket，gather 完一桶就立刻广播一桶，通信与 gather 重叠；
- **GPU-GPU 直传**：跳过 CPU 内存中转，训练 GPU 经 NCCL 直接发到推理 GPU（同机走 NVLink）。

### 2.4 难题二：rollout 长尾

一个 batch 内 response 长度差异巨大（有的几十 token，有的几千 token）。如果静态批处理——等整批全部生成完再进入下一阶段——**该轮耗时由最慢的请求决定**，其余算力空等。这带来：

- 负载不均：长尾请求拖住整个 pipeline；
- 必要性：**partial rollout**（超长请求允许跨轮继续生成，不必等它完结）、**动态/持续批处理**（完成一条立刻补一条新 prompt，保持引擎满载）。

### 2.5 难题三：colocate vs 分离

训练实例和推理实例怎么放？

| 方案 | 优点 | 缺点 |
| ---- | ---- | ---- |
| Colocate（同卡复用） | 省机器；权重同步走本机 NVLink，快 | 训练与推理切换时要 offload/重建状态；峰值显存紧张（训练态 + KV cache 抢显存） |
| 分离部署 | 各自独立优化，简单清晰 | 机器利用率低（rollout 时训练卡闲置，反之亦然）；权重同步跨机传输 |

**verl 的 hybrid engine** 是 colocate 路线的代表：训练与推理在同一批卡上交替运行，通过 **3D-HybridEngine** 做权重 resharding——训练时的 FSDP/TP 分片在切换到推理时原地重分片成推理引擎的布局，避免全量 gather 的开销；切换间隙把训练侧优化器状态 offload 到 CPU，给推理的 KV cache 腾显存。

## 3. 计算/通信/显存 tradeoff 分析

| 决策 | 省什么 | 费什么 |
| ---- | ------ | ------ |
| GRPO 去掉 critic | 一份训练态显存与计算 | 优势估计方差增大，靠组内采样数弥补 |
| Colocate 同卡复用 | 机器数量、权重同步时间 | 显存峰值（offload 开销）、调度复杂度 |
| 分离部署 | 工程简单、峰值显存宽松 | 双份机器、跨机权重同步 |
| 动态批处理 | rollout 长尾空等 | 调度器复杂度、KV cache 管理压力 |
| partial rollout | 长尾请求不再堵轮次 | 实现复杂、陈旧样本引入 off-policy 偏差 |
| 分桶流水同步 | 同步墙钟时间 | 实现复杂度 |

不变的主线：**每个选择都是在算力（机器数/MFU）、通信（权重同步/采样传输）、显存（训练态 vs KV cache）之间挪筹码**。

## 4. 对比表格：主流 RLHF 框架

| 框架 | 出品方 | 架构要点 | 训练后端 | 推理后端 | 特点 |
| ---- | ------ | -------- | -------- | -------- | ---- |
| verl | 字节跳动 | HybridFlow 编程模型（数据流图表达 RL 流程）、3D-HybridEngine 权重重分片 | FSDP / Megatron | vLLM / SGLang | colocate 同卡复用，灵活可编程 |
| OpenRLHF | 开源社区 | Ray 调度 + vLLM 推理 + DeepSpeed 训练，组件化拼装 | DeepSpeed | vLLM | 上手快，生态组合式 |
| TRL | HuggingFace | 轻量库，与 transformers 生态无缝 | transformers/PEFT | 内置/vLLM | 研究与中小规模实验首选 |
| NeMo-Aligner | NVIDIA | NeMo 体系内的对齐模块 | Megatron-Core | TensorRT-LLM | 与 NVIDIA 栈深度绑定 |

共同趋势：**训练后端 + 推理后端解耦、中间用高效的权重同步与数据传输粘合**，差别在于耦合程度（colocate 的深度）和编程抽象。

## 5. 工程实践

### 5.1 耗时占比经验

一轮 RLHF 迭代中，**rollout 通常占 50-80%**。原因：自回归生成逐 token 解码，吞吐受 KV cache 与调度限制，远低于训练的矩阵乘吞吐；GRPO 还要求每 prompt 采一组（如 8-16 条）response，生成量再放大一个数量级。

直接推论：**推理引擎优化能力直接决定 RLHF 吞吐**——持续批处理、投机采样、FP8 推理每提升一分，整轮迭代就快一分。这就是为什么"推理优化能力"在 post-training 时代比纯训练时代更值钱：训练的 MFU 优化空间已接近榨干，而 rollout 侧还有巨大余地。

- 对比三档优化：无优化（静态批处理 + 过 CPU 权重同步）、开启动态批处理、再叠加权重同步分桶流水化；

## 6. 常见误区

### 6.1 "RLHF 系统就是训练系统加个 reward model"

rollout 占一半以上耗时，且权重同步、长尾调度都是推理侧问题。把它当训练系统做，上限就是 50% 利用率。

### 6.2 "去掉 critic 是纯粹占便宜"

GRPO 用组内相对优势替代价值函数，估计方差更大，需要足够的组内采样数压住方差。省显存是真的，零代价是假的。

### 6.3 "colocate 一定比分离好"

colocate 省机器但要付出 offload 开销和峰值显存压力，小模型或显存宽裕时分离部署反而省心高效。选择取决于模型规模与机器预算。

### 6.4 "权重同步就是 NCCL broadcast 一下"

布局转换（FSDP flatten/TP 分片到推理布局）才是真正的工作量；朴素的过 CPU 串行同步在百 GB 级权重上是数十秒级的纯浪费。

## 7. 面试高频问题

**Q1：PPO 里有哪几个模型？GRPO 改了什么？**

一句话：PPO 有 actor、critic、reference、reward 四个模型；GRPO 去掉 critic，用同一 prompt 一组 response 的组内相对优势替代价值函数。

展开：critic 需要完整训练态（参数+梯度+优化器状态），去掉它直接省一份显存与计算；组内多样本平均把优势估计的方差压回来。GRPO 因 DeepSeek-R1 成为主流，是"拿统计换系统效率"的典型案例。

**Q2：RLHF 一轮迭代的流程是什么？**

一句话：rollout（推理引擎批量生成）→ reward 打分 → advantage 计算 → actor 训练（FSDP/Megatron）→ 权重同步回推理引擎。

展开：rollout 用 vLLM/SGLang 追求吞吐；reward 可以是 reward model 也可以是 RLVR 的规则验证器；训练侧只有 actor（GRPO 下）；权重同步是训练与推理两个世界的接缝，也是工程难点集中地。

**Q3：权重同步为什么难？怎么优化？**

一句话：训练框架（FSDP flatten/TP 分片）与推理引擎的权重布局不同，同步要 gather + reshape + 广播，百 GB 级权重朴素实现要数十秒。

展开：优化三板斧——分桶流水（gather 一桶发一桶，通信与处理重叠）、GPU-GPU 直传（跳过 CPU，走 NVLink/NCCL）、原地 resharding（verl 3D-HybridEngine，分片直接转布局不做全量 gather）。

**Q4：rollout 长尾是什么问题？怎么解？**

一句话：静态批处理下整轮耗时由最长 response 决定，短请求完成后算力空等；解法是持续批处理 + partial rollout。

展开：持续批处理让完成的序列立刻被新 prompt 替补，引擎保持满载；partial rollout 允许超长请求跨轮续写，不堵当前轮。代价是调度复杂度与轻微 off-policy 偏差。

**Q5：colocate 和分离部署怎么选？**

一句话：colocate 省机器且权重同步快，但要处理显存切换与峰值压力；分离简单但资源利用率低。

展开：verl hybrid engine 代表 colocate 深度优化路线（同卡复用 + 权重原地 resharding + 优化器状态 offload）；机器预算充足或模型较小时分离部署的工程性价比更高。

**Q6：RLHF 里哪个阶段最耗时？对团队能力意味着什么？**

一句话：rollout 通常占一轮的 50-80%，推理引擎优化（持续批处理、投机采样、FP8）直接决定 RLHF 吞吐。

展开：预训练时代最值钱的是训练 MFU 优化；post-training 时代训练侧的优化空间已接近榨干，rollout 侧（推理系统能力）成为吞吐瓶颈，这也是"推理优化能力更值钱"的直接原因。

---

## 8. 本节小结

1. Post-training 把训练系统与推理系统耦合在同一流程里，成为新的 Infra 战场；PPO 四模型（actor/critic/reference/reward），GRPO 去掉 critic 成为主流。
2. 一轮迭代五环：rollout → reward → advantage → train → 权重同步，两头分属两个技术栈，接缝处是工程难点。
3. 三大系统难题：权重同步（布局转换 + 分桶流水 + GPU 直传）、rollout 长尾（持续批处理 + partial rollout）、colocate vs 分离（显存压力 vs 资源利用率）。
4. 框架格局：verl（HybridFlow + 3D-HybridEngine）、OpenRLHF（Ray+vLLM+DeepSpeed）、TRL（轻量）、NeMo-Aligner（NVIDIA 栈）。
5. rollout 占 50-80% 耗时，推理优化能力在 post-training 时代直接等于 RLHF 吞吐。
