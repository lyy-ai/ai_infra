# 6.3 ZeRO 系列（DeepSpeed）

## 课程概述

ZeRO（Zero Redundancy Optimizer）是 DeepSpeed 提出的核心优化技术，它的基本思想是：**在数据并行中消除模型状态（参数、梯度、优化器状态）的冗余复制**。传统 DDP 中每张卡都保存一份完整模型状态，而 ZeRO 把这些状态切分后分散到所有卡上，计算时再按需收集。

本节把 ZeRO 系列拆开：ZeRO-1/2/3/Offload 的原理、通信代价、选型指南。学完本节后，你应该能够：

- 解释 ZeRO 的“用通信换显存”思想。
- 区分 ZeRO-1/2/3 分别切分哪些状态。
- 估算各级 ZeRO 的显存节省和额外通信量。
- 根据模型大小和集群拓扑选择 ZeRO 级别。

---

## 1. ZeRO 核心思想

### 1.1 数据并行中的冗余

传统 DDP 中，每张卡都保存：

```text
参数 P
梯度 G
优化器状态 OS（Adam: m, v）
```

如果 P 有 10B 参数，每张卡上的模型状态就是 $16P$ = 160GB（FP32 Adam）。

ZeRO 问：既然所有卡上的模型最终一致，为什么不能只让每张卡保存 $1/N$ 的模型状态？

### 1.2 切分对象

ZeRO 按三个层级逐步切分：

| 级别 | 切分内容 | 每张卡冗余 |
| ---- | -------- | ---------- |
| ZeRO-1 | 优化器状态 | 参数 + 梯度 |
| ZeRO-2 | 优化器状态 + 梯度 | 参数 |
| ZeRO-3 | 优化器状态 + 梯度 + 参数 | 无 |

---

## 2. ZeRO-1：优化器状态切分

### 2.1 原理

每张卡只保存 $1/N$ 的优化器状态。optimizer.step() 时，每个 rank 只更新自己那部分参数。

```text
参数 P:     每张卡完整保存
梯度 G:     每张卡完整保存（backward 后 AllReduce）
优化器 OS:  每张卡 1/N
```

### 2.2 显存节省

显存从 $16P$ 降到 $4P + 4P + 8P/N = 8P + 8P/N$。

当 N 很大时，约等于 $8P$（节省一半）。

### 2.3 通信

- 梯度 AllReduce 不变。
- optimizer.step() 后需要 AllGather 更新后的参数分片。

---

## 3. ZeRO-2：+ 梯度切分

### 3.1 原理

梯度也按 rank 分片。backward 时不再做完整 AllReduce，而是做 ReduceScatter：每张卡只得到自己负责那部分梯度。

```text
参数 P:     每张卡完整保存
梯度 G:     每张卡 1/N
优化器 OS:  每张卡 1/N
```

### 3.2 显存节省

显存从 $16P$ 降到 $4P + 4P/N + 8P/N = 4P + 12P/N$。

当 N 很大时，约等于 $4P$（节省 75%）。

---

## 4. ZeRO-3：+ 参数切分

### 3.1 原理

参数也按 rank 分片。forward/backward 时，需要把当前层需要的参数 all-gather 到所有卡上；计算完即可释放。

```text
参数 P:     每张卡 1/N
梯度 G:     每层 backward 后 reduce-scatter
优化器 OS:  每张卡 1/N
```

### 4.2 显存节省

当 N 很大时，模型状态显存约等于 $16P/N$，加上激活值。可以训练远大于单卡显存的模型。

### 4.3 通信代价

- forward：每层 AllGather 参数。
- backward：每层 AllGather 参数 + ReduceScatter 梯度。
- optimizer.step()：AllGather 更新后参数。

通信量明显高于 DDP 和 ZeRO-1/2。

---

## 5. ZeRO-Offload

### 5.1 思想

不仅把状态切分到多卡，还把优化器状态和计算卸载到 CPU 内存甚至 NVMe 硬盘上。

```text
GPU:  参数分片（ZeRO-3） + 激活值
CPU:  优化器状态 + 部分计算
NVMe: 更大规模的优化器状态
```

### 5.2 适用场景

- GPU 显存极小但 CPU/NVMe 容量大。
- 训练速度可以牺牲，但需要能跑起来。
- 微调大模型（LoRA + Offload）。

### 5.3 代价

CPU-GPU 数据传输带宽远低于 NVLink/PCIe，训练速度会显著下降。

---

## 6. 选型指南

| 场景 | 推荐 |
| ---- | ---- |
| 单卡能放下模型，想多卡加速 | DDP |
| 模型较大，优化器状态吃显存 | ZeRO-1 |
| 模型更大，梯度也吃显存 | ZeRO-2 |
| 单卡放不下参数 | ZeRO-3 |
| 显存极小，能接受慢速 | ZeRO-Offload |
| PyTorch 原生 | FSDP ≈ ZeRO-3 |

```python
# zero_memory_estimator.py
"""估算不同 ZeRO 级别下的显存占用"""

def estimate_zero_memory(params_b, world_size, hidden, seq_len, batch_size, num_layers):
    P = params_b * 1e9 * 4 / 1e9  # FP32 params in GB
    G = P  # gradients FP32
    OS = 2 * P  # Adam m + v

    # activation: roughly 2 * batch * seq * hidden * layers * 4B (simplified)
    act = 2 * batch_size * seq_len * hidden * num_layers * 4 / 1e9

    ddp = P + G + OS + act

    z1 = P + G + OS / world_size + act
    z2 = P + G / world_size + OS / world_size + act
    z3 = P / world_size + G / world_size + OS / world_size + act

    return {
        "DDP": ddp,
        "ZeRO-1": z1,
        "ZeRO-2": z2,
        "ZeRO-3": z3,
        "activation": act,
    }


def main():
    params_b = 7
    world_size = 8
    hidden = 4096
    seq_len = 2048
    batch_size = 1
    num_layers = 32

    mem = estimate_zero_memory(params_b, world_size, hidden, seq_len, batch_size, num_layers)
    print(f"Model: {params_b}B, world_size: {world_size}")
    for k, v in mem.items():
        print(f"  {k:12s}: {v:8.2f} GB")


if __name__ == "__main__":
    main()
```

## 8. 常见误区

### 8.1 “ZeRO-3 一定比 DDP 好”

ZeRO-3 通信量大，只有在单卡放不下模型时才必须使用。能放下模型时，DDP 通常更快。

### 8.2 “ZeRO-Offload 能让任何模型跑起来”

理论上是的，但速度会极慢。Offload 是无奈之举，不是性能方案。

### 8.3 “FSDP 和 ZeRO 没关系”

FSDP 就是 PyTorch 原生的 ZeRO-3 实现，思想完全相同。

---

## 9. 本节小结

1. ZeRO 的核心是消除数据并行中的模型状态冗余。
2. ZeRO-1 切分优化器状态，ZeRO-2 加梯度切分，ZeRO-3 加参数切分。
3. ZeRO-Offload 把状态卸载到 CPU/NVMe，适合极小显存场景。
4. 选择 ZeRO 级别要权衡显存、通信量和训练速度。
