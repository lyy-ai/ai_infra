# 6.1 分布式训练总论

## 课程概述

大模型时代，单个 GPU 的显存和算力已经无法满足训练需求。GPT-4、Claude、Llama 等模型的训练都依赖大规模分布式集群。理解分布式训练不仅是算法工程师的要求，也是 AI Infra 工程师的核心能力。

本节把分布式训练的总论拆开：为什么需要分布式训练、训练状态显存分析、并行策略全景。学完本节后，你应该能够：

- 估算一个模型在训练时的显存占用。
- 解释为什么模型参数、梯度、优化器状态会快速吃满显存。
- 区分数据并行、模型并行、混合并行三种基本策略。
- 为不同规模的模型和集群选择合适的并行策略。

---

## 1. 为什么需要分布式训练

### 1.1 单卡显存极限

以 GPT-3 175B 为例：

| 训练状态 | 显存占用（FP32） |
| -------- | --------------- |
| 参数 | 175B × 4B = 700 GB |
| 梯度 | 175B × 4B = 700 GB |
| 优化器状态（Adam: m + v） | 2 × 175B × 4B = 1400 GB |
| **合计** | **~2800 GB** |

单卡显存通常为 24GB、40GB、80GB，远远放不下。即使使用混合精度（FP16），也需要约 1.4TB 显存，必须分布式。

### 1.2 单卡算力极限

训练大模型不仅需要显存，还需要大量计算。GPT-3 在 8x V100 上需要数年时间，只有分布式多卡并行才能缩短到可接受范围。

---

## 2. 训练状态显存分析

### 2.1 训练状态组成

训练时显存主要用于：

```text
显存 = 模型参数 + 梯度 + 优化器状态 + 激活值 + 临时缓冲区
```

- **模型参数（Params）**：W。
- **梯度（Gradients）**：∇W，每个参数一个梯度。
- **优化器状态（Optimizer States）**：Adam 需要保存一阶矩 m 和二阶矩 v。
- **激活值（Activations）**：前向传播中间结果，用于反向传播。
- **临时缓冲区（Workspace）**：kernel 临时空间。

### 2.2 显存占用估算

假设模型参数量为 $P$，使用 Adam + FP32 参数 + FP16 梯度：

$$
\text{显存} \approx 4P \text{ (params)} + 4P \text{ (grads)} + 8P \text{ (Adam states)} + \text{activations}
$$

即参数相关状态约为 $16P$。若使用 FP16 参数 + FP32 master weight + Adam：

$$
\approx 2P + 4P + (2P + 4P) \cdot 2 + \text{activations} = 18P + \text{activations}
$$

### 2.3 不同精度下的参数显存

| 精度 | 每参数字节数 | Adam 总状态（参数+梯度+状态） |
| ---- | ----------- | ----------------------------- |
| FP32 | 4 | 16P |
| FP16 + FP32 master | 2 + 4 | 18P |
| BF16 + FP32 master | 2 + 4 | 18P |
| INT8 | 1 | 更小，但训练不常用 |

## 3. 并行策略全景

### 3.1 数据并行（Data Parallelism, DP）

把**数据**切分到多张卡，每张卡保存完整模型副本。

```text
数据 batch -> 切分为 N 份 -> 每张卡计算梯度 -> AllReduce 平均 -> 每张卡独立更新
```

优点：实现简单，扩展性好。

缺点：每张卡都保存完整模型，模型大小受单卡显存限制。

### 3.2 模型并行（Model Parallelism, MP）

把**模型**切分到多张卡，每张卡只保存部分参数。

类型：

- **张量并行（Tensor Parallelism, TP）**：按矩阵维度切分单层参数。
- **流水线并行（Pipeline Parallelism, PP）**：按层切分模型。

优点：可以训练超大模型。

缺点：通信量大，实现复杂，并行度有限。

### 3.3 混合并行

实际训练中通常组合使用：

```text
3D 并行 = 数据并行 (DP) + 张量并行 (TP) + 流水线并行 (PP)
```

- TP 在节点内（NVLink 高速）。
- PP 跨节点或节点内。
- DP 在更大的机器组之间。

```python
# memory_estimator.py
def estimate_training_memory(params_b, batch_size, seq_len, hidden,
                             optimizer="adam", precision="fp16"):
    """估算训练显存占用（单位 GB）"""
    P = params_b * 1e9
    bytes_per_param = 4 if precision == "fp32" else 2

    # 参数 + 梯度 + 优化器状态
    param_mem = P * bytes_per_param / 1e9
    grad_mem = P * 4 / 1e9  # 梯度通常 FP32
    opt_mem = P * (8 if optimizer == "adam" else 4) / 1e9

    # 激活值估算：每层大约 2 * batch * seq * hidden * layers
    # 简化为 2 * batch * seq * hidden * sqrt(P/hidden^2) 或自定义
    layers = max(1, int((P / (hidden * hidden * 12)) ** 0.5))
    act_mem = 2 * batch_size * seq_len * hidden * layers * 4 / 1e9

    total = param_mem + grad_mem + opt_mem + act_mem
    return {
        "params": param_mem,
        "gradients": grad_mem,
        "optimizer": opt_mem,
        "activations": act_mem,
        "total": total,
    }


def main():
    for params_b in [1, 7, 70, 175]:
        mem = estimate_training_memory(
            params_b=params_b,
            batch_size=1,
            seq_len=2048,
            hidden=4096,
            optimizer="adam",
            precision="fp16",
        )
        print(f"\nModel: {params_b}B parameters")
        for k, v in mem.items():
            print(f"  {k:12s}: {v:8.2f} GB")


if __name__ == "__main__":
    main()
```

### 实验建议

- 改变 batch size 和 sequence length，观察激活值占比变化。
- 对比 FP32 和 FP16 下的参数状态显存。
- 估算自己项目模型的单卡显存需求。

## 5. 常见误区

### 5.1 “显存不够就加卡”

加卡解决的是分布式问题，但如果并行策略选择不当，通信开销可能吃掉算力收益。需要先分析瓶颈是显存还是计算。

### 5.2 “数据并行和模型并行二选一”

实际大模型训练几乎总是混合并行。DP 处理大数据集，TP/PP 处理大模型。

### 5.3 “参数量等于显存占用”

训练时显存占用远大于参数本身。Adam + FP16 下，参数相关状态通常是 18 倍参数量，激活值还会进一步增加。

---

## 6. 本节小结

1. 分布式训练的驱动力：单卡显存和算力都无法满足大模型需求。
2. 训练显存 ≈ 参数 + 梯度 + 优化器状态 + 激活值。
3. 数据并行扩展数据，模型并行扩展模型，混合并行两者结合。
4. 选择并行策略前必须先做显存和通信分析。
