# 6.5 流水线并行

## 课程概述

流水线并行（Pipeline Parallelism, PP）是另一种模型并行方式：把模型按层切分成多个 stage，每个 stage 放到一张或多张 GPU 上，数据像流水线一样依次经过各个 stage。与 TP 切分单层不同，PP 切分的是**网络深度**。

本节把流水线并行拆开：GPipe、PipeDream/1F1B、气泡率分析与优化。学完本节后，你应该能够：

- 解释流水线并行与模型按层切分的关系。
- 说明 GPipe 的 fill-flush 方式和气泡问题。
- 解释 1F1B 调度如何提高流水线利用率。
- 计算不同 pipeline 配置下的气泡率。
- 为给定模型和集群选择合适的 pipeline stage 数。

---

## 1. 流水线并行基础

### 1.1 按层切分

假设模型有 8 层，4 张 GPU：

```text
GPU 0: Layer 0, 1
GPU 1: Layer 2, 3
GPU 2: Layer 4, 5
GPU 3: Layer 6, 7
```

输入数据先经过 GPU 0 的层，再传到 GPU 1，依次类推。

### 1.2 与 TP 的区别

| 特性 | 张量并行 TP | 流水线并行 PP |
| ---- | ----------- | ------------- |
| 切分维度 | 单层参数 | 层（深度） |
| 通信频率 | 每层都通信 | stage 间通信 |
| 通信量 | 激活值（大） | 激活值（较小） |
| 并行度 | 受矩阵维度限制 | 受层数限制 |
| 气泡 | 无 | 有 |

---

## 2. GPipe

### 2.1 fill-flush 方式

GPipe 把一批数据（micro-batch）切分成更小的 micro-batches，送入流水线：

```text
Forward:
  GPU 0: [m1, m2, m3, m4]
  GPU 1:      [m1, m2, m3, m4]
  GPU 2:           [m1, m2, m3, m4]
  GPU 3:                [m1, m2, m3, m4]

Backward:
  GPU 3: [m4, m3, m2, m1]
  GPU 2:      [m4, m3, m2, m1]
  ...
```

Forward 全部完成后再做 backward。

### 2.2 气泡问题

由于必须等所有 micro-batch 的 forward 完成后才开始 backward，导致 GPU 在 pipeline 填充和排空阶段有大量空闲时间，称为**气泡（bubble）**。

气泡率：

$$
\text{Bubble Rate} = \frac{(P - 1)}{M} \times \frac{t_{forward}}{t_{forward} + t_{backward}}
$$

其中 $P$ 是 stage 数，$M$ 是 micro-batch 数。

---

## 3. PipeDream / 1F1B 调度

### 3.1 1F1B（One Forward One Backward）

每个 GPU 完成一个 micro-batch 的 forward 后，尽快做对应 micro-batch 的 backward，而不是等所有 forward 完成。

```text
GPU 0: f1 f2 f3 f4 b1 b2 b3 b4
GPU 1:    f1 f2 f3 f4 b1 b2 b3 b4
GPU 2:       f1 f2 f3 f4 b1 b2 b3 b4
GPU 3:          f1 f2 f3 f4 b1 b2 b3 b4
```

这样可以减少气泡，但需要在 forward 阶段保存更多激活值。

### 3.2 激活值 vs 气泡的权衡

- GPipe：气泡大，激活值少（保存的 micro-batch 少）。
- 1F1B：气泡小，激活值多（每个 stage 都需要保存多个 micro-batch 的激活）。

---

## 4. 气泡率分析与优化

### 4.1 影响气泡的因素

- **stage 数 P**：P 越大，fill/flush 时间越长。
- **micro-batch 数 M**：M 越大，气泡越小，但激活显存越大。
- **forward/backward 时间比**：通常是 1:2。

### 4.2 优化策略

1. **增加 micro-batch 数**：用更多小 micro-batch 填满流水线。
2. **交错 forward/backward**：1F1B 或 interleaved 1F1B。
3. **减少 stage 数**：在显存允许的情况下，减少 PP stage。
4. **Activation checkpointing**：用计算换显存，支持更多 micro-batch。

```python
# pipeline_bubble_calc.py
"""计算 GPipe 和 1F1B 的流水线气泡率"""

def gpipe_bubble_rate(num_stages, num_micro_batches):
    # 简化为: forward + backward 全部完成后才能 backward
    return (num_stages - 1) / num_micro_batches


def one_f_one_b_bubble_rate(num_stages, num_micro_batches):
    # 1F1B 中，每个 stage 的空闲时间近似为 stage-1 个 micro-batch
    return (num_stages - 1) / (num_micro_batches + num_stages - 1)


def main():
    for P in [2, 4, 8, 16]:
        for M in [4, 8, 16, 32]:
            gpipe = gpipe_bubble_rate(P, M)
            f1b1 = one_f_one_b_bubble_rate(P, M)
            print(f"P={P:2d} M={M:2d} | GPipe bubble={gpipe:.2%} | 1F1B bubble={f1b1:.2%}")


if __name__ == "__main__":
    main()
```

## 6. 常见误区

### 6.1 “PP 比 TP 通信少就一定更好”

PP 有气泡问题，micro-batch 数少时 GPU 利用率低。TP 和 PP 通常组合使用。

### 6.2 “micro-batch 越多越好”

micro-batch 越多气泡越小，但激活显存和通信 overhead 也会增加。

### 6.3 “GPipe 已经过时了”

GPipe 在教育和小规模场景仍有价值，大规模训练通常用 1F1B 或 interleaved 1F1B。

---

## 7. 本节小结

1. 流水线并行按层切分模型，适合模型很深但每层能放下的场景。
2. GPipe 使用 fill-flush，气泡大但实现简单。
3. 1F1B 交错 forward/backward，气泡小但激活显存大。
4. 气泡率受 stage 数、micro-batch 数、forward/backward 比例影响。
