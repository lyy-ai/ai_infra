# 6.6 3D 并行与混合训练策略

## 课程概述

当模型大到必须同时使用数据并行、张量并行、流水线并行时，就需要把它们组合成**3D 并行**。3D 并行的目标是在显存、通信、计算之间找到最佳平衡，让大规模集群高效训练超大模型。

本节把 3D 并行与混合训练策略拆开：3D 并行组合设计、混合精度训练、梯度累积、Activation Checkpointing。学完本节后，你应该能够：

- 设计 TP + PP + DP 的组合拓扑。
- 解释混合精度训练的原理和 Loss Scaling。
- 使用梯度累积在有限显存下模拟大 batch。
- 评估 Activation Checkpointing 的收益和代价。

## 1. 3D 并行组合

### 1.1 三种并行的定位

| 并行方式 | 扩展对象 | 通信特点 | 典型部署 |
| -------- | -------- | -------- | -------- |
| 数据并行 DP | 数据/batch | AllReduce 梯度 | 跨节点 / 大集群 |
| 张量并行 TP | 单层参数 | AllGather/ReduceScatter | 节点内（NVLink） |
| 流水线并行 PP | 层/深度 | P2P 激活值 | 节点间 / 节点内 |

### 1.2 3D 并行世界 size

假设总卡数：

$$
N = N_{TP} \times N_{PP} \times N_{DP}
$$

- $N_{TP}$：张量并行组大小。
- $N_{PP}$：流水线 stage 数。
- $N_{DP}$：数据并行副本数。

### 1.3 拓扑设计原则

```text
1. 先确定 TP 大小：通常等于节点内 GPU 数（如 8），受 NVLink 限制。
2. 再确定 PP 大小：根据模型层数和单卡能放下的层数决定。
3. 最后 DP 扩展：剩下的卡做数据并行。
```

示例：

```text
模型: 70B
集群: 8 节点 × 8 GPU = 64 卡
设计: TP=8 (节点内), PP=4 (跨节点), DP=2
      -> 总卡数 = 8 × 4 × 2 = 64
```

## 2. 混合精度训练

### 2.1 FP16 / BF16 / FP8

| 精度 | 优点 | 缺点 |
| ---- | ---- | ---- |
| FP16 | 显存省一半，Tensor Core 加速 | 动态范围小，容易 underflow |
| BF16 | 动态范围接近 FP32，无需 Loss Scaling | 精度略低 |
| FP8 | 显存省 75%，Hopper 支持 | 需要 per-tensor/per-channel scaling |

### 2.2 Loss Scaling

FP16 下小梯度容易变成 0，导致模型不收敛。Loss Scaling 在 backward 前把 loss 乘以一个 scale factor，放大梯度：

```python
loss = loss * scale
loss.backward()
# 检查梯度是否 inf/NaN，然后 unscale
optimizer.step()
```

动态 Loss Scaling 会在 inf/NaN 时自动调整 scale。

### 2.3 PyTorch AMP

```python
from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler()
with autocast():
    output = model(input)
    loss = criterion(output, target)

scaler.scale(loss).backward()
scaler.step(optimizer)
scaler.update()
```

## 3. 梯度累积

### 3.1 思想

把一个大 batch 拆成多个小 micro-batch，每个 micro-batch 计算梯度但不更新参数，累加多个 micro-batch 后再执行 optimizer.step()。

```python
for i, (x, y) in enumerate(loader):
    loss = model(x, y) / accumulation_steps
    loss.backward()
    if (i + 1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
```

### 3.2 收益

- 有效 batch size = micro_batch_size × accumulation_steps × DP size。
- 不增加单卡显存。

### 3.3 代价

- 训练时间延长（每个 effective batch 需要更多 forward/backward）。
- batch normalization 类层效果可能受影响。

## 4. Activation Checkpointing

### 4.1 思想

前向传播时不保存所有中间激活值，只保存部分 checkpoint；反向传播时重新计算被释放的激活值。

```text
显存收益：~30%~50%
计算代价：~20%~30% 额外 forward 计算
```

### 4.2 实现

PyTorch 原生支持：

```python
torch.utils.checkpoint.checkpoint(layer, x)
```

Megatron-LM 中按 Transformer 层做 checkpoint。

### 4.3 与 PP 的关系

流水线并行本身就会保存多个 micro-batch 的激活值，因此 activation checkpointing 对 PP 尤为重要。

```python
# parallel_topo_design.py
"""设计并验证 3D 并行拓扑"""

def design_3d_topology(total_gpus, layers, hidden, params_b, tp_pref=8):
    """简单启发式：先定 TP，再定 PP，最后 DP"""
    tp = min(tp_pref, total_gpus)
    remaining = total_gpus // tp

    # 假设每层 hidden 维度的参数大致相等，PP 尽量让每 stage 层数平衡
    # 这里简化：PP 取 remaining 的因数中不超过层数/2 的最大值
    pp_candidates = [p for p in range(1, remaining + 1) if remaining % p == 0 and p <= layers]
    pp = max(pp_candidates)
    dp = remaining // pp

    return tp, pp, dp


def main():
    total_gpus = 64
    layers = 80
    hidden = 8192
    params_b = 175

    tp, pp, dp = design_3d_topology(total_gpus, layers, hidden, params_b)
    print(f"3D Parallel Design for {total_gpus} GPUs, {params_b}B model:")
    print(f"  TP={tp}, PP={pp}, DP={dp}")
    print(f"  total GPUs = {tp * pp * dp} (check: {tp * pp * dp == total_gpus})")
    print(f"  layers per PP stage = {layers // pp}")


if __name__ == "__main__":
    main()
```

## 6. 常见误区

### 6.1 “3D 并行就是简单地把三种并行堆起来”

3D 并行需要精心设计通信组、数据 layout、micro-batch 调度。错误的组合可能导致通信爆炸或 GPU 利用率低。

### 6.2 “梯度累积可以无限增加有效 batch size”

梯度累积增加的是 batch size 但也会增加训练时间，并且对于某些统计层（如 BatchNorm）效果不佳。

### 6.3 “Activation Checkpointing 一定加速训练”

Checkpointing 是用计算换显存，通常会减慢训练。只有在显存成为瓶颈时才使用。

---

## 7. 本节小结

1. 3D 并行 = TP × PP × DP，拓扑设计需要权衡通信和显存。
2. 混合精度训练（FP16/BF16/FP8）可以加速并省显存，但需要 Loss Scaling。
3. 梯度累积用时间换 batch size，不增加单卡显存。
4. Activation Checkpointing 用计算换显存，适合长序列和 PP。
