# 6.4 张量并行与序列并行

## 课程概述

当模型大到单卡连一层参数都放不下时，数据并行和 ZeRO-3 的扩展性会受限于通信量。此时需要**模型并行**把单层参数切分到多张卡上。张量并行（Tensor Parallelism, TP）是最常用的模型并行方式，它把矩阵乘法按维度切分，让每张卡只保存部分权重。

序列并行（Sequence Parallelism, SP）则是在 TP 的基础上，进一步把激活值沿序列维度切分，减少 long-context 训练时的显存峰值。

本节把 TP 和 SP 拆开：张量并行原理、TP 的通信约束、序列并行、GQA/MQA 下的切分策略。学完本节后，你应该能够：

- 解释张量并行如何把 MLP 和 Attention 按维度切分。
- 说明为什么 TP 通常限制在节点内（NVLink）。
- 理解序列并行如何减少激活显存。
- 为 GQA/MQA 设计合理的 TP 切分策略。

---

## 1. 张量并行原理

### 1.1 一维张量并行

以线性层 $Y = XA$ 为例：

- 输入 $X$ 形状：$[B \times S, H]$。
- 权重 $A$ 形状：$[H, 2H]$。
- 输出 $Y$ 形状：$[B \times S, 2H]$。

按列切分 $A$：

$$
A = [A_1, A_2] \quad \Rightarrow \quad Y = [XA_1, XA_2]
$$

每张卡保存 $A_1$ 或 $A_2$，forward 后 AllGather 输出。

按行切分 $A$：

$$
A = \begin{bmatrix} A_1 \\ A_2 \end{bmatrix} \quad \Rightarrow \quad Y = X_1 A_1 + X_2 A_2
$$

输入需要按特征维度切分，forward 后 AllReduce 输出。

### 1.2 MLP 中的 TP

Transformer MLP：

$$
Y = \text{GeLU}(X W_{up}) \cdot W_{down}
$$

- $W_{up}$ 通常按列切分，$W_{down}$ 按行切分，中间激活值不需要全局 AllGather。
- 最终只需要一次 AllReduce。

### 1.3 Attention 中的 TP

Multi-Head Attention：

$$
Q = X W_Q, \quad K = X W_K, \quad V = X W_V
$$

- 按 head 切分：每个 rank 负责部分 attention head。
- 输出投影 $W_O$ 按行切分，最后 AllReduce。

---

## 2. 为什么 TP 不能跨机

### 2.1 通信模式

张量并行每层都需要 AllGather 或 AllReduce，通信频率很高。

- 节点内：NVLink 带宽可达 600~900 GB/s（A100 NVLink）。
- 节点间：InfiniBand 通常 200~400 Gbps（~25~50 GB/s），远低于 NVLink。

### 2.2 跨机 TP 的代价

TP 的通信与计算密度之比：

$$
\frac{\text{通信量}}{\text{计算量}} \propto \frac{1}{B \cdot S}
$$

Batch size 和 sequence length 越大，通信占比越小；但跨机带宽低，仍然会严重拖慢训练。

### 2.3 实际排布

```text
Node 0 (8 GPUs): TP=8
Node 1 (8 GPUs): TP=8
跨节点: PP 或 DP
```

---

## 3. 序列并行（Sequence Parallelism）

### 3.1 激活值显存问题

在长序列训练中，激活值随 sequence length 线性增长。即使参数能放下，激活值也可能爆显存。

### 3.2 序列并行思想

在 MLP 和 LayerNorm 等不需要跨序列通信的算子中，把输入沿序列维度切分到 TP group 内的多张卡上。

```text
输入: [B, S, H]
TP group: 8 卡
每卡: [B, S/8, H]
```

Attention 仍然按 head 切分，但 activation 的 layout 和 SP 对齐。

### 3.3 SP + TP 的收益

- LayerNorm/Dropout 的激活显存减少为 $1/TP$。
- MLP 的输入输出 AllGather 可以合并，减少通信。

---

## 4. GQA / MQA 下的 TP 切分

### 4.1 GQA / MQA 简介

- MHA：每个 head 有独立的 Q/K/V。
- GQA（Grouped Query Attention）：多组 Q 共享一组 K/V。
- MQA（Multi-Query Attention）：所有 Q 共享一组 K/V。

### 4.2 切分策略

- **MHA**：Q/K/V 都按 head 切分，自然支持 TP。
- **GQA**：Q 按 group 切分，K/V 需要复制到所有相关 rank。
- **MQA**：K/V 不重复复制，需要在 TP group 内广播。

GQA/MQA 减少了 KV Cache，但 TP 切分时需要额外处理 K/V 的广播/收集。

```python
# tp_column_row_sim.py
"""模拟张量并行的列切分与行切分"""
import numpy as np


def column_parallel_linear(X, W, world_size):
    """按列切分权重，每张卡计算一部分输出，最后 all-gather"""
    H_out = W.shape[1]
    split = H_out // world_size
    local_outputs = [X @ W[:, i * split:(i + 1) * split] for i in range(world_size)]
    return np.concatenate(local_outputs, axis=-1)


def row_parallel_linear(X, W, world_size):
    """按行切分权重，输入也切分，最后 all-reduce"""
    H_in = W.shape[0]
    split = H_in // world_size
    local_outputs = [X[..., i * split:(i + 1) * split] @ W[i * split:(i + 1) * split, :]
                     for i in range(world_size)]
    return sum(local_outputs)


def main():
    B, S, H_in, H_out = 2, 8, 16, 32
    X = np.random.randn(B * S, H_in).astype(np.float32)
    W = np.random.randn(H_in, H_out).astype(np.float32)

    Y_ref = X @ W
    Y_col = column_parallel_linear(X, W, world_size=4)
    Y_row = row_parallel_linear(X, W, world_size=4)

    print("column parallel max diff:", np.max(np.abs(Y_ref - Y_col)))
    print("row parallel max diff:", np.max(np.abs(Y_ref - Y_row)))


if __name__ == "__main__":
    main()
```

## 6. 常见误区

### 6.1 “TP 就是数据并行”

TP 是模型并行，切分的是单层参数；数据并行切分的是数据。TP 的通信更频繁，通常只在节点内使用。

### 6.2 “序列并行只影响 Attention”

序列并行主要优化的是 MLP 和 LayerNorm 的激活显存，Attention 的并行方式仍然是 TP（按 head）。

### 6.3 “GQA 下 TP 和 MHA 一样简单”

GQA/MQA 的 K/V 共享会导致 TP 切分时需要广播 K/V，增加了通信复杂度。

---

## 7. 本节小结

1. 张量并行按矩阵维度切分参数，每层需要 AllGather/AllReduce。
2. TP 通信频繁，通常限制在节点内（NVLink），跨机会严重拖累性能。
3. 序列并行沿序列维度切分激活，减少 long-context 显存。
4. GQA/MQA 的 TP 切分需要额外处理 K/V 共享。
