# 6.7 训练框架实战

## 课程概述

理解了分布式训练的理论后，最终要落实到具体框架上。工业界最常用的三个框架是：Megatron-LM、DeepSpeed、PyTorch FSDP。它们分别代表了张量/流水线并行、ZeRO 优化、原生数据并行的三种路线。

本节把训练框架实战拆开：Megatron-LM、DeepSpeed、PyTorch FSDP 的核心实现与配置。学完本节后，你应该能够：

- 说明 Megatron-LM 的 TP、PP、3D 并行实现方式。
- 配置 DeepSpeed 的 ZeRO-1/2/3/Offload。
- 使用 PyTorch FSDP 训练大模型。
- 根据模型规模选择合适的框架和配置。

## 1. Megatron-LM

### 1.1 定位

Megatron-LM 是 NVIDIA 开源的大规模语言模型训练框架，核心优势是**张量并行（TP）和流水线并行（PP）**的高效实现。

### 1.2 核心抽象

- **Tensor Parallel（TP）**：基于 `fused_attention` 和 `fused_mlp`，按列/行切分 Linear 层。
- **Pipeline Parallel（PP）**：提供 interleaved 1F1B 调度。
- **Sequence Parallel（SP）**：配合 TP 沿序列维度切分激活。
- **3D 并行**：TP × PP × DP 的组合。

### 1.3 关键组件

```text
megatron/core/
  ├── tensor_parallel/          # TP 层实现
  ├── pipeline_parallel/        # PP 调度
  ├── distributed/              # 初始化、通信组
  └── transformer/              # Transformer 层
```

### 1.4 启动方式

```bash
python pretrain_gpt.py \
  --tensor-model-parallel-size 8 \
  --pipeline-model-parallel-size 4 \
  --num-layers 80 \
  --hidden-size 8192 \
  --num-attention-heads 64 \
  --seq-length 2048 \
  --global-batch-size 1024 \
  --micro-batch-size 1
```

## 2. DeepSpeed

### 2.1 定位

DeepSpeed 是微软开源的分布式训练优化库，核心优势是 **ZeRO 系列** 和 **Offload**。

### 2.2 关键特性

| 特性 | 说明 |
| ---- | ---- |
| ZeRO-1/2/3 | 优化器状态/梯度/参数切分 |
| ZeRO-Offload | CPU/NVMe 卸载 |
| DeepSpeed-MoE | MoE 模型训练 |
| DeepSpeed-Inference | 推理优化 |
| DeepSpeed-Compression | 压缩与量化 |

### 2.3 JSON 配置示例

```json
{
  "train_batch_size": 1024,
  "gradient_accumulation_steps": 16,
  "optimizer": {

    "allgather_partitions": true,
    "reduce_scatter": true
  },

}
```

### 2.4 启动方式

```bash

```

## 3. PyTorch FSDP

### 3.1 定位

FSDP 是 PyTorch 原生的完全分片数据并行，对应 DeepSpeed ZeRO-3。

### 3.2 核心参数

```python
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy

model = FSDP(
    model,
    auto_wrap_policy=transformer_auto_wrap_policy,
    mixed_precision=torch.bfloat16,
    device_id=torch.cuda.current_device(),
)
```

### 3.3 与 DeepSpeed 对比

| 特性 | DeepSpeed | PyTorch FSDP |
| ---- | --------- | ------------ |
| ZeRO-3 | ✅ | ✅ |
| Offload | ✅（CPU/NVMe） | 部分支持 CPU |
| Pipeline Parallel | 需配合其他框架 | 不支持 |
| Tensor Parallel | 需配合 Megatron | 不支持 |
| 生态 | 成熟，文档丰富 | 原生，与 PyTorch 生态集成好 |

---

## 4. 选型建议

| 场景 | 推荐框架 |
| ---- | -------- |
| 超大规模 GPT（>100B），需要 TP+PP | Megatron-LM |
| 需要 ZeRO-3/Offload，单卡放不下 | DeepSpeed 或 FSDP |
| 中大规模，偏好原生 PyTorch | FSDP |
| MoE 训练 | DeepSpeed-MoE |
| 已有 Megatron 代码，想加 ZeRO | Megatron-DeepSpeed 组合 |

```python
# fsdp_example.py
import torch
import torch.nn as nn
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy
import functools


def get_simple_transformer():
    layer = nn.TransformerEncoderLayer(d_model=256, nhead=8, dim_feedforward=1024, batch_first=True)
    return nn.TransformerEncoder(layer, num_layers=4)


def main():
    torch.distributed.init_process_group("nccl")
    local_rank = int(os.environ["LOCAL_RANK"])
    torch.cuda.set_device(local_rank)

    model = get_simple_transformer().cuda(local_rank)
    model = FSDP(
        model,
        auto_wrap_policy=functools.partial(transformer_auto_wrap_policy, transformer_layer_cls={nn.TransformerEncoderLayer}),
        mixed_precision=torch.bfloat16,
        device_id=torch.cuda.current_device(),
    )

    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-5)
    input = torch.randn(2, 128, 256).cuda(local_rank)
    output = model(input)
    loss = output.sum()
    loss.backward()
    optimizer.step()
    print(f"rank {torch.distributed.get_rank()} done")


if __name__ == "__main__":
    main()
```

## 6. 常见误区

### 6.1 “Megatron 只能做 TP”

Megatron 支持 TP + PP + DP 的 3D 并行，是最完整的超大规模训练框架之一。

### 6.2 “DeepSpeed 比 FSDP 更好”

两者各有优劣。DeepSpeed 生态更成熟，Offload 支持更好；FSDP 与 PyTorch 集成更原生，代码侵入性小。

### 6.3 “FSDP 不能做混合并行”

FSDP 本质是 ZeRO-3 数据并行，不支持 TP 和 PP。需要混合并行时，通常用 Megatron-FSDP 或 Megatron-DeepSpeed 组合。

---

## 7. 本节小结

1. Megatron-LM 强项是 TP 和 PP，适合超大规模 GPT。
2. DeepSpeed 强项是 ZeRO 系列和 Offload，适合显存受限场景。
3. PyTorch FSDP 是原生 ZeRO-3 实现，适合中大规模原生 PyTorch 项目。
4. 框架选择取决于模型规模、集群拓扑、团队生态。
